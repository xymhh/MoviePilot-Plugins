# MoviePilot-Plugins

MoviePilot 自用插件市场（个人 fork 版）——提供 **115网盘STRM助手**（P115StrmHelper，V3 线，含「整理跳过语义」补丁）与 **网盘订阅助手**（CloudSubscribe，V2 线）两个插件。

插件市场源地址（仓库根地址，`main` 分支）：

```
https://github.com/xymhh/MoviePilot-Plugins
```

上游：[`odomu/MoviePilot-Plugins`](https://github.com/odomu/MoviePilot-Plugins)，本 fork 在其基础上做跨盘转存（尤其夸克→115）优化。

## 沿革：2026-10-11 先撤下、当天恢复

| 内容 | 现状 |
| --- | --- |
| 115网盘STRM助手（P115StrmHelper，V3 线） | **已恢复并重新发布 2.8.77** —— 源码 `plugins.v3/p115strmhelper` + `package.v3.json` 索引 + Release + 单测工作流全部回来 |
| 配置备份 / 保种空间守护 / Telegram 自动签到 / 综艺正片守卫 | **已撤下**（索引此前已剔除，随后连源码一并删除），请用上游 [`zkmydgth/MoviePilot-Plugins`](https://github.com/zkmydgth/MoviePilot-Plugins) |

**为什么先撤后恢复**：撤下时判断「上游用配置项就能覆盖」，实机跑下来确认**覆盖不了**——三项都开了，整理仍会在「媒体库存在同名且质量更好」处报失败：

- **媒体库目录的「覆盖模式」= 按大小**：决定"库里同名文件更好时是否跳过"。取值 `always` / `size` / `never` / `latest`，在 MoviePilot 的媒体库目录配置里，不在插件配置页。
- **插件内「自动删除低质量源文件」**（`auto_delete_inferior_source_enabled`，默认关）：按大小裁决失败时，把源盘那份低质量文件删掉。
- **插件内「媒体库已存在时拦截整理」**（`transfer_intercept_exists_enabled`，默认关）：首次入库场景下，媒体服务器里已有就不再整理。

问题在于：官方（DDSRem 2.8.76）走到这个分支时仍把结果写成**失败整理记录**，而同源唯一索引会把该路径原来的**成功记录替换成失败**——于是同一文件被整理队列反复重投、反复推失败通知，日志里就是：

```
整理失败，失败阶段：文件转移
媒体库存在同名文件，且质量更好
下一步：检查源文件和目标存储，修复后重新整理
```

本 fork 2.8.77 改成**跳过语义**：只记日志与通知、不写失败记录（保留原成功记录）、不发 `TransferFailed`、不登记智能体重试，并在「库里更好」这一原因下删除低质量源文件。

> ⚠️ 坑：`从不`（`never`）模式的失败消息同样是「媒体库存在同名文件…」，**也会命中「自动删除低质量源文件」的触发条件**（消息含「同名文件」即删源），这一路径不比较质量。要"只在库里更好时才删源"，覆盖模式请用**按大小**。

历史决策与验收证据保留在 `docs/`（见文末文档索引）。

## 安装

1. 打开 MoviePilot 的插件市场设置：V3 在「插件」页 →「插件市场」标签 → 右下角齿轮（`mdi-store-cog`，仅 admin 可见）；V2 在「设定 → 插件市场」
2. 添加插件源 `https://github.com/xymhh/MoviePilot-Plugins`（必须是仓库根地址，raw 链接无效）→ 保存 → 点「同步插件源」
3. **115网盘STRM助手**：搜「115网盘STRM助手」安装（本仓库版本 2.8.77，高于官方 2.8.76，可直接覆盖已装的官方版）；装好后绑 115 账号、按需开「接管网盘整理 / 自动删除低质量源文件」
4. **网盘订阅助手**：搜「网盘订阅助手」安装，然后到配置页完成：扫码绑夸克、绑目标网盘 115、填中继缓存目录（别用容器内 `/tmp`，改成挂载的本地盘路径）、开需要的搜索渠道，跑一条订阅验证
5. **片名自动订阅**（1.6.28 起，默认开）：在 Telegram 等渠道的对话框里发一个片名，插件**不立刻建订阅**，只登记候选并把消息原样交回平台（让平台先出候选列表）；你在候选里选定后，平台会走「候选选定 → 搜索资源」，插件**在这个入口接管**：按**你点选的那一项**（优先取你的原始输入，其次取该选项的 TMDB 身份与官方片名）建订阅、立刻搜网盘并转存入库，回执「已按你在平台候选中选定的《xx》创建订阅」，平台侧不再出现「未搜索到需要的资源！」。匹配三级：TMDB 身份相同 → 归一化后同名 → 模糊同名（相似度 ≥ 0.85、片名 ≥3 字、类型相容），覆盖「机智医生生活」vs 官方名「机智的医生生活」这类差一字输入；候选记录 15 分钟过期、命中即消费；识别不出或非影视（闲聊、命令、问句）不登记。**只要用户真的点了候选**（1.6.33 起「点选即接入」），就用登记表里最近一条未消费记录接入，不再要求片名对得上；1.6.34 起同时兼容平台改名后的入口类名（`MediaInteractionChain`），并在 `SearchChain.process` 这一层用「栈/参数形状」识别点选调用兜底，避免平台再改名后静默失效。开关在插件配置页「片名自动订阅」（`title_subscribe_enabled`）

6. **手动订阅补缺集季**（1.6.29 起，默认开）：对话框发片名选定候选、或在 MP 里手动建订阅时，插件**不再只订第 1 季**，而是按媒体库缺集情况**为每个缺集季各建一条订阅**（默认跳过特辑 S00；已完整的季不建订阅，避免触发网盘洗版）。配置页「片名自动订阅」区块三个控件：`subscribe_all_missing_seasons`（总开关，关掉恢复旧行为）、`subscribe_skip_season_zero`、`subscribe_season_limit`（最多补建季数，0=不限）；显式指定季号（如 `season=2`）时保持单季不展开

7. **媒体库一级目录按类型分层**（1.6.31 起，**默认关**）：插件产出的目录默认是 `<媒体库目录>/<二级分类>/…`（如 `外语电影`、`国产剧`）。想让插件媒体库对齐总媒体库的 `电影/剧集` 分层，到配置页「转存设置 → 媒体库目录结构」打开「按媒体类型建一级目录」，落点变成 `<媒体库目录>/电影/<二级分类>/…`、本地 STRM 变成 `<本地媒体根路径>/剧集/<二级分类>/…`；一级目录名可自定义（`type_folder_movie` / `type_folder_tv`）。**不改** MP「设定 → 目录」的任何配置，平台整理行为不受影响；只对开关打开后的新转存生效，历史目录不迁移

## 运维与排障

| 现象 | 处理 |
| --- | --- |
| 市场里搜不到本仓库插件 | 本仓库 V3 插件读 `package.v3.json`、V2 插件读 `package.v2.json`（V3 宿主对 v2 条目也兼容）；确认填的是仓库根地址、齿轮按钮要用管理员账号可见，并点过「同步插件源」 |
| 整理失败：失败阶段=**文件转移**，消息「媒体库存在同名文件，且质量更好」 | 官方 2.8.76 及更早会把它记成失败并**替换掉该路径原成功记录**，导致同一文件被反复重投 → 更新到本仓库 **2.8.77**（跳过语义版） |
| 已装官方 2.8.76，市场却看不到 2.8.77 | 确认已把本仓库源加进插件市场设置并「同步插件源」；本版版本号高于官方，正常会显示为可更新 |
| 跨盘转存（夸克→115）慢到几十 KB/s | 1.6.22 起固定 16MB 分片 + 115 分片并发 PUT（配置项「115 上传分片并发」0–16，`0` = 关闭并回退单流顺序上传，失败自动回退）；并发不要开太大，夸克有风控 |
| 转存"实际成功却报失败" | 1.6.18 起修复后处理终态未落库导致的假失败；升级到最新版 |
| 想换旧版本 | Release 资产按 `cloudsubscribe_v<版本>.zip` 命名，可在本仓库 Releases 里下载对应版本 |
| 对话框发片名只回「未搜索到资源」 | 升级到 **1.6.28** 并确认配置页「片名自动订阅」为开；1.6.25 把网盘候选塞进平台搜索的玩法已被用户判定方向错误并整条回退 |
| 发片名后在候选里选定，**只**看到插件的「已创建订阅《xx》」 | 设计如此（1.6.28）：点选入口被插件接管，平台那次搜索被跳过，所以不再有平台那句「未搜索到需要的资源！」；订阅已建好、网盘搜索已排队，查插件日志里该订阅的搜索记录即可 |
| 发片名后点了候选，却既没订阅也没回执 | 升级到 **1.6.34**。三层旧问题都在这一条路上：(a) 1.6.27 钩子挂错位置；(b) 1.6.28~1.6.33 点选接入器挂的类名 `InteractionChain` 在平台 v3.1.x 已改名 `MediaInteractionChain`，导入失败被吞掉 → 接入器从未装上（**日志里搜不到 `媒体点选接管器已安装` 就是这个症状**）；(c) 登记名与点选项名对不上（发「画江湖」、点选「画江湖之不良人」）时旧版不消费记录。1.6.33 起「点选即接入」，1.6.34 起自动识别平台新类名并加 process 层兜底。自查顺序：`代码版本=1.6.34` → `媒体点选接管器已安装：MediaInteractionChain._search_media_resources` → `已登记片名候选` → `片名候选命中（tmdbid/title/fuzzy/sole）`；若日志里连 `媒体点选接管器已安装` 都没有，说明平台没重载新代码，重启一次 MP 容器再看 |
| 更新到新版后点选仍无反应，怀疑没生效 | 看插件日志首行 `插件初始化：代码版本=x.y.z`：不是最新版说明平台没重载；`媒体点选接管器已安装` 缺失说明挂载失败（WARNING 里带原因，1.6.34 起不再静默）|
| 选定候选后**只**建了第 1 季订阅 | 1.6.28 及更早的已知限制（`add(season=None)` 被平台兜底成 S1）→ 升级到 **1.6.29**；若升级后仍只订一季，查插件日志有没有「手动订阅按缺集季展开」，并确认配置页「手动订阅补齐缺集季」为开、该剧在媒体库确实存在缺集季 |
| 网盘媒体库里二级分类（外语电影/国产剧…）直接堆在根目录，想分出 `电影/剧集` 一层 | 升级到 **1.6.31**，配置页「转存设置 → 媒体库目录结构」打开「按媒体类型建一级目录」；**不要**去开 MP 目录条目的「媒体库类型子目录」——那会连带改变平台本地总媒体库的整理层级（多出一层、且一级名固定为 `电影`/`电视剧`，与总库的 `剧集` 不一致），因为同一条目录配置两边共用 |
| 打开一级目录开关后，旧资源还在原来的路径 | 设计如此：开关只对之后的新转存/新整理生效，历史目录不自动搬迁（要迁移需自己在网盘/本地搬目录） |
| 「手动资源」对话框粘贴**阿里云盘 / 移动云盘**分享链接，报「第 N 行资源无效：无法解析有效的 XX 分享链接」 | 1.6.31 及更早的已知 bug：手动转存的校验只认 `share_code`，而这两个来源的解析结果用的是别的键名，**任何**链接都会被判无效 → 升级到 **1.6.32**。与链接格式、账号凭据、跨盘设置都无关（凭据可在配置页「账号」处点刷新自查） |
| 阿里云盘分享转存时提示需要访问码 | 分享本身带提取码：把「提取码: xxxx」和链接一起粘贴（1.6.32 起支持这种附言写法，也可写成 `?pwd=xxxx`） |
| （已结案）订阅搜到阿里云盘资源却转存不成 | 不是插件问题，也不是配置问题：阿里云盘对第三方程序**封锁了分享直链**（取下载地址接口返回 HTTP 410），跨盘转存拿不到源。用户 2026-10-13 决定**放弃**这条线；阿里云盘作为**目标盘**（115 → 阿里云盘）不受影响 |
