# CloudSubscribeX CLI（宿主机命令行客户端）调研与架构

> 日期：2026-11-02　状态：实施中　目标版本：v1.9.23
> 目标：给插件加一个**零依赖**的命令行客户端，让「体检 / 总览 / 历史 / 追更 / 账本 / 重复订阅 / 同步控制」不用打开网页就能做，也让 AI 代理与脚本能自主跑端到端验证。

## 1. 为什么做（问题）

现状：插件 95 个 HTTP 路由（`core/api/registration.py`），全部只能从 Vue 前端或 MoviePilot 页面点。后果：

| 场景 | 现在的做法 | 代价 |
| --- | --- | --- |
| 发版后验收 | 用户手动开页面、截图回传 | 一轮 5–10 分钟，且截图丢字段 |
| 线上排障 | 让用户点开「状态胶囊 → 体检」念给我听 | 信息有损，用户烦 |
| 回归验证 | 我写一次性 Python 脚本调 `/api/...`，用完即弃 | 每版重写一遍，且认证逻辑每次重踩 |
| 自动化/告警 | 无 | 只能人工盯 |

## 2. 现成方案对比（先搜轮子）

| 方案 | 形态 | 复用度 | 结论 |
| --- | --- | --- | --- |
| **typer / click** | 参数与帮助自动生成 | 复用参数解析 | 需 `pip install`，插件运行环境与宿主机不保证；CLI 要跨环境跑，**否** |
| **argparse（标准库）** | 子命令 + help | 够用 | 零依赖，**选它** |
| **cyclopts** | 新式 CLI 框架 | 注解驱动 | 额外依赖，收益不足，否 |
| 115-media-hub `cli.py` | 同仓库 CLI，走面板 HTTP API | 思路可借鉴 | 它有自己的 API 层，CS 已有 `/api/v1/plugin/CloudSubscribeX/*`，结构不同，**只借鉴设计** |
| MP 自带 `mp` 命令 / openapi | 平台级 CLI | 不管插件业务 | 覆盖不到插件语义，否 |

结论：**标准库 `argparse` + `urllib.request` 自研**，约 450 行，零依赖、单文件、可直接 `python3 cli.py` 跑。

## 3. 架构

### 3.1 边界

```
宿主机 / AI 代理 / 脚本
        │  HTTPS + Bearer JWT
        ▼
python3 cli.py <命令>  ──►  MoviePilot  /api/v1/plugin/CloudSubscribeX/<path>
                                      │
                                      ▼
                              插件既有 API 层（不改一行）
```

CLI **不新开后端接口、不改插件逻辑**，纯客户端。插件侧零改动 = 零回归风险。

### 3.2 认证（两级）

1. `--token` / `MP_TOKEN`：直接用 MoviePilot 的 JWT。
2. `--username` + `--password` / `MP_USER` + `MP_PASSWORD`：POST `/api/v1/login/access-token` 换 token，缓存到
   `~/.config/cloudsubscribex/token.json`（权限 600），过期自动重登一次。

不落任何明文密码到磁盘；缓存只存 token 与过期时间。

### 3.3 命令集（首批 8 个 + 逃生口）

| 命令 | 后端 | 说明 |
| --- | --- | --- |
| `doctor` | GET `/doctor` | 一键体检，9 项红绿灯（✔/⚠/✖ + 修复指引） |
| `overview` | GET `/overview` | 仪表盘聚合：订阅数、流水统计、最近任务 |
| `history` | GET `/page_data` | 历史记录，支持分页/关键字/状态过滤 |
| `progress` | GET `/page_data` → `subscribes_progress` | 追更进度表：卡片级总集/已入库/缺集 |
| `ledger` | GET `/ledger/list` | 同步作业账本 |
| `duplicate` | GET `/duplicate/list` | 重复订阅检测结果 |
| `sync start\|stop\|pause on\|off` | POST `/sync/start` 等 | 触发/停止/暂停同步 |
| `raw GET\|POST <path>` | 任意 | 逃生口：`raw GET /runtime --param foo=bar`，新接口不依赖 CLI 升级 |

### 3.4 输出与退出码

- 默认人类可读（表格 / 键值 / 红绿灯），`--json` 输出原始 JSON，`--quiet` 只输出核心值（便于 `$(cli ...)`）。
- 退出码：`0` 成功 / `1` 接口返回失败 / `2` 参数错误 / `3` 认证失败 / `4` 网络不可达。
- 表格宽度按终端宽度截断（`shutil.get_terminal_size`），中文按显示宽度对齐（`unicodedata.east_asian_width`）。

### 3.5 配置来源优先级

命令行参数 > 环境变量（`MP_URL` / `MP_TOKEN` / `MP_USER` / `MP_PASSWORD`） > 配置文件 `~/.config/cloudsubscribex/config.json`。

### 3.6 失败与回滚

- CLI 是纯客户端，删除 `cli.py` 即回滚，插件侧无残留。
- 网络异常：3 次指数退避重试（0.5s/1s/2s），仅对 GET 重试，POST 不重试（避免重复转存）。

## 4. 验收标准

1. `python3 cli.py --help` 列出 8 个命令；每个命令 `--help` 可用。
2. 对本地 stub 服务器（模拟 MP 路由）跑通全部命令：成功渲染、`--json` 直出、错误码正确。
3. 认证：token 直给 / 用户名密码登录 / 缓存命中 / 过期自动重登，四条路径都有用例。
4. 中文表格对齐正确（`牧神记` 这类 3 汉字 vs ASCII 混排不乱）。
5. 零第三方依赖：`python3 -c "import cli"` 在纯净环境通过。
6. 新增 `tests/test_cli.py`，接入现有 `unittest discover` 全绿。

## 5. 不做（明确划界）

- 不做交互式 TUI（`--watch` 之类）。
- 不做配置写入（`config/save` 涉及 150+ 字段，改配置仍在 UI）。
- 不打包成 pip 包 / 单文件二进制（保持 `python3 cli.py` 直跑）。
