## 1. 范围（用户已定）

| 决策 | 结论 |
| --- | --- |
| 是否删旧文件 | **删**（新文件转存成功后删旧） |
| 判据 | 分辨率优先，同分辨率看体积；有最小增益阈值 |
| 生效范围 | **只对新入库生效**：转存那一刻遇到「同集已有版本」才比较；不做存量全量洗版 |

明确不做：不开 `enable_cloud_upgrade`、不碰候选搜索阶段的挑文件逻辑、不加 115 Range 码率探测（后续可插）、电影侧择优（本次只做剧集）。
生效范围补充：开关默认关闭，用户开启后只影响「转存那一刻命中同集已有版本」的场合；不做存量全量洗版。

## 3. 判定规则（`compare_quality`）

输入：`new_name`、`new_size`、旧版列表 `[(name, size), ...]`、`min_gain_percent`、`min_gain_mb`。
旧版取「最好的一条」= 按 `(分辨率, 体积)` 排序取最大。

```
res(name) = 2160/1440/1080/720/576/480/360，识别 2160p/4K/UHD/8K/1080p/720p…
旧体积未知(<=0)  → upgrade（有体积就算改善）
res_new > res_old：
    new_size >= old_size * 0.6 → upgrade「分辨率 1080p→2160p」
    否则 keep「分辨率更高但体积仅 X%，疑似伪 4K/片段」
res_new < res_old           → keep「分辨率 720p 低于现有 2160p」
res 相同 或 两侧都解析不出：
    need = max(old_size*(1+min_gain_percent/100), old_size + min_gain_mb*1MiB)
    new_size >= need → upgrade「体积 1.2 GB → 2.6 GB（+117%）」
    否则 keep「体积增益不足（1.2 GB → 1.25 GB）」
```

默认值：`min_gain_percent=10`、`min_gain_mb=200`、分辨率提升允许体积缩小系数 `0.6`（内部常量，不暴露）。

## 4. 配置项

| key | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `quality_prefer_enabled` | bool | `false` | 总开关：入库时按「分辨率 > 体积」择优 |
| `quality_min_gain_percent` | int | `10` | 同分辨率下，体积至少多 10% 才算更好 |
| `quality_min_gain_mb` | int | `200` | 同分辨率下，体积至少多 200 MB（与上一项同时满足） |
| `quality_ignore_rename_template` | bool | `true` | 择优时忽略「现有文件已符合命名模板」这条拦截 |

属性名：`_quality_prefer_enabled` / `_quality_min_gain_percent` / `_quality_min_gain_mb` / `_quality_ignore_rename_template`。

## 5. 流程

```
匹配到候选文件 E01（带 name/size）
  → dedup_versions = 列目录得到的现有版本
  → _episode_dedup_decision(..., new_file_name)
       ├ quality_prefer_enabled? → compare_quality()
       │     ├ upgrade → action=replace, reason="分辨率/体积更优…"
       │     └ keep    → action=skip,    reason="现有版本更优…"（写历史 status=跳过）
       └ 否则走原逻辑（评分 → 模板命名 → 体积兜底）
  → replace：转存新文件 → 成功后 _apply_episode_dedup() 删旧 → 写历史 + 通知
```

## 6. 失败与回滚

- 比较器纯函数无副作用；算不出来（name/size 缺失）时返回 `keep`，即「维持现状」，不会误删。
- 删旧失败：`file_id` 定位不到 → `episode_dedup_miss` warning，继续写入，不阻塞（已有行为）。
- 新文件转存失败 → 不进入删旧分支（删旧在成功之后），库内旧文件保留。
- 全局回滚：把 `quality_prefer_enabled` 关掉即回到 1.7.87 行为，无需回退版本。

## 7. 并发与限流

- 决策在单订阅的转存循环内同步执行，不新增网络请求（体积/文件名都已在内存里）。
- 删旧复用现有 `cloud_mutations.delete_file()`，与既有判重替换同一条限流通道，不额外加并发。

## 8. 验收标准

1. 单测：`tests/test_quality_compare.py` 覆盖分辨率提升/下降、同分辨率达标/不达标、体积未知、文件名无分辨率、伪 4K 拦截、旧版多条取最优。
2. 决策接入：开关关闭时行为与 1.7.87 完全一致（回归测 `test_episode_dedup*` 全绿）。
3. 真机：把某部有 720P 的剧集重下一集，日志出现「分辨率 720p→1080p」并删旧，Emby 里该集换成新文件。
