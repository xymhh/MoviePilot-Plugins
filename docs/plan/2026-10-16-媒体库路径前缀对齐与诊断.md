# 1.6.53 任务书：媒体服务器路径前缀对齐 + 搜索不再静默 0 条

> 上游投诉：用户插件「洗版 → 媒体服务器内容」搜索始终返回 `已读取 0 个媒体库内容`

## 一、实测证据（真机，MP v3 + Emby Docker）

1. 第一次修复：`local_resource_path` 由 `/downloads` 改为 `/strm/115网盘`，已生效（读回确认）。
2. 搜索仍然 0 条：`/media/content?server=emby&keyword=美人余` → `已读取 0 个媒体库内容`；换 `沙丘` 同样 0 条。
3. 但 MP 库里确实有该条目（用插件自身只读接口 `/resource/detail` POST 验证，返回）：

   ```json
   {"server":"emby","library":"652310","item_id":"655616","title":"美人余","year":"2026",
    "item_type":"电视剧","media_type":"tv",
    "path":"/media/strm/115网盘/剧集/国产剧/美人余 (2026) {tmdb-294446}"}
   ```

   → TMDB 身份（`media_source`/`media_id`）正常，问题只出在**路径**。

## 二、根因

- Emby 容器把 STRM 目录挂在 `/media/strm`，MP 容器里是 `/strm`，同一份数据两个前缀。
- `handlers/sync/history.py:1591-1603` 的 `_configured_media_path()` 要求条目路径**字面量**落在 `local_resource_path` 之下，不做任何前缀翻译 → 抛 `ValueError("媒体服务器条目路径不在插件配置的媒体根路径中")`。
- `list_media_server_content()`（`handlers/sync/history.py:1614-1733`）逐条 `continue`，既不记日志也不上报 → 前端只看到「已读取 0 个媒体库内容」（静默丢弃）。
- 插件里已有的 `media_server_path_mappings` 只喂给 `MediaServerNotifier`（`handlers/notification/media_server.py:360-380`），**没有**用在搜索 / 洗版这条链上。

## 三、需求

### R1 前缀对齐（让开箱可用）

在 `_configured_media_path()` 内加「媒体条目路径 → 本地路径」解析，顺序：

1. **原样命中**：路径字面量已落在 root 之下且存在 → 直接通过（保持既有行为，最高优先级）。
2. **显式映射**：解析插件配置 `media_server_path_mappings`（逐行 `A=B`，形如 `/media/strm=/strm`，格式沿用 `handlers/notification/media_server.py` 的解析实现），替换前缀后再校验。
3. **尾部对齐兜底**：从右往左逐级丢弃原路径前缀段，尝试让剩余部分落到 root 之下；命中必须**同时**满足：结果在 root 之下、结果 `exists()`、被丢弃的前缀段非空。命中后 `logger.info`：
   「媒体服务器路径前缀自动对齐：<原路径> → <修正路径>（Emby 挂载点与本地不一致，可在插件设置→媒体服务器路径映射中写 `/media/strm=/strm` 消除推断）」。

三种方式都失败 → 抛原有 `ValueError`，错误信息里带上原路径、当前 root、以及「可配置 media_server_path_mappings」的提示。

**硬约束**：只做前缀翻译，不做 basename 模糊匹配；不得放宽「结果必须存在」检查；不得放宽「路径必须在 root 之下」的安全边界（防误删/误洗版到库外）。

### R2 搜索不再静默 0 条

`list_media_server_content()` 统计并在返回里新增 `diagnostics`（向后兼容，只加不删）：

- `matched`：按关键词 / TMDB 从 MP 库命中标题的原始行数；
- `dropped_no_identity`：因缺 TMDB 身份被丢的条数；
- `dropped_path`：因路径不在根 / 不存在被丢的条数，附首个示例路径与首个错误原因；
- `root`：当前 `local_resource_path`；`mappings`：当前配置的映射。

`message` 在「0 条结果且 `dropped_path>0`」时给可执行中文提示，例如：
「已读取 0 个媒体库内容：命中标题 1 条，均因路径前缀与媒体根不一致被丢弃（示例 `/media/strm/115网盘/…`）。请在插件设置→媒体服务器路径映射中填 `/media/strm=/strm`。」

前端：搜索返回 0 条时把该 `message` 展示出来（复用现有提示通道，不新增弹窗样式）。

### R3 测试与质量

- 新增单测（`tests/`，沿用现有 unittest 风格）：
