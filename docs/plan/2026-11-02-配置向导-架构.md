# 配置向导化 — 架构（2026-11-02）

> 状态：已实现，v1.9.19 发布（逻辑校验见 `docs/test/2026-11-02-配置向导逻辑校验.mjs`）
> 依赖：`docs/plan/2026-11-02-配置向导-调研.md`

## 1. 形态

`Config.vue` 增加一个 `mode`：`wizard` | `expert`，默认由「首次运行判定」决定。

- **不改后端**：向导沿用既有 `POST plugin/CloudSubscribeX/config/save`（全量提交）。
- **不改专家模式**：切回 expert 就是今天的样子，零回归风险。
- **入口**：配置页头部「向导」按钮；未配置网盘时自动进入向导。

## 2. 三步（只挑最小必填集）

| 步 | 标题 | 字段来源 | 判定通过 |
| --- | --- | --- | --- |
| 1 | 连网盘 | `basic.enabled`（启用插件）+ `basic.cloud_drive`（选网盘）+ `options.driverSchemas[id === cloud_drive].groups`（该网盘凭据，动态） | `cloud_drive` 非空 |
| 2 | 落地位置 | `organize.organize_source_path`（整理源目录，带目录选择器）+ `organize.organize_after_transfer`（转存后自动整理） | 目录非空 |
| 3 | 完成 | 保存 + 自动跑 `/doctor` 展示结果 + 「去启用搜索渠道 / 去加订阅」的下一步 | 保存成功 |

字段**按 key 从既有 section 里取**，`pickFields(keys)` 遍历所有 section 的 groups，
取到即用；取不到该字段只跳过，不报错（防止未来删字段把向导搞崩）。

## 3. 状态与数据流

```
config (reactive, 已由 load 填充)
   ↓ pickFields / driverSchemas
wizardStep (0..2)  →  stepSection = {value:'wizard', groups:[...]}
   ↓
<ConfigSection :section="stepSection" :config="config" :options="options" :api="api" />
   ↓
保存 → save() 既有实现 → 成功后 runDoctor() → 展示 counts
```

## 4. 首次运行判定

`shouldOpenWizard = !config.cloud_drive || !config.enabled`（仅在打开配置页时判一次，
用户手动切到专家模式后本次会话不再自动跳）。

## 5. 失败与降级

- `/doctor` 调用失败 → 第 3 步只显示「保存成功」，不给红绿灯（不阻塞完成）。
- 目录选择器（`openDirectoryPicker`）复用既有事件，不改实现。
- 动态 schema 缺失（后端没下发 driverSchemas）→ 第 1 步只显示网盘选择 + 提示。

## 6. 验收标准

1. 清空 `cloud_drive` 打开配置页 → 自动进向导，三步走完能保存。
2. 走完第 3 步能看到体检红绿灯，且与直接调 `/doctor` 结果一致。
3. 点「专家模式」→ 与 v1.9.18 完全一致的界面，所有字段可编辑、可保存。
4. 老用户（已有网盘配置）打开配置页 → 默认专家模式，不弹向导。

## 7. 需求变更纪律

新增向导字段 = 在 `WIZARD_STEPS[].keys` 里加 key，不改结构；文档没写的步骤不加。
