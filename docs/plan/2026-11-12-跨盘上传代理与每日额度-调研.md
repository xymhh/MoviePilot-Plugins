# 跨盘上传 115 代理 + 每日 900G 上限 — 调研

> 状态：进行中 2026-11-12 → 验收见 `../test/`、结论见 `../summary/`
> 硬规矩：动第一行代码前先产出本篇 + 架构篇，缺一不写码、不委派、不建仓库。

## 一、目标与边界

给 `moviepilot-plugins-cs`（CloudSubscribeX v1.9.74）的跨盘转存加两件事：

1. 真实上传 115 时可设置代理（默认空=直连），只作用于 115 上传/API，源盘下载保持直连。
2. 每日真实上传字节数上限，硬上限 900 GB，按 `settings.TZ` 自然日累计，超限跳过本次并等次日。

边界：不改 `cross_transfer_rapid_miss_action` 语义（用户自行切 `fallback`「回落普通上传」）、不动整理/STRM/通知链路、不借 CloudDrive2（见架构篇决策）。

## 四、结论：① 拼装（不自研、不改造、不借外部服务）

- **代理**：复用本仓 `validate_proxy_address`/`build_proxy_url`/`normalize_proxies` 解析配置 → 在 `drive/p115/client.py:358` 构造 `P115ClientWithTimeout` 时把 `proxies` 注入底层 HTTP 客户端；`drive/p115/upload.py` 的 `_new_session()`（源盘下载）保持直连不注入。
- **额度**：复用 `core/storage.py` 的 `runtime.load/save` 存按天计数，按 `settings.TZ` 自然日 key，任务开始前预检、上传成功后原子累加。
- **不选②改造**：不去 fork/改 p115client；**不选③自研**：不自己写代理协议、不自己写配额服务 —— 「别人没有的那一段」是**插件业务侧的按天额度与跳过闭环**，这段必须落在插件内，但实现是拼装已有件，不是自研轮子。
- **不引入新依赖**（`requirements.txt` 不动）。

## 五、已核实的工程约束

- 版本双写：`__init__.py` 现为 `1.9.74`，`package.v2.json` 仍是 `1.9.71` → 新版必须同一次提交双写 `1.9.75`。
- 测试基线：`pytest --collect-only` = **1383 tests**（旧记忆里的 1291/1155 已过期）。
- 前端产物 `dist/` 随源码入库；CI 的 pnpm 重建会覆盖手改 dist。
- 改代码里的默认值**不会覆盖用户已存配置值**（仅当键不存在时生效），新键天然满足。
- 发布只走「改代码 → 推 GitHub → CI 出 Release → 市场拉取」，**禁止本地打包上传覆盖容器内插件**。
