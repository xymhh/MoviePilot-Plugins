## 范围修订（实施期，2026-10-13）

实施中发现「静默跳过」不只发生在校验环节，**校验通过、文件也列出来了但内容与目标季/集不匹配**的
分支同样只打 `logger.debug` 然后跳过（`television.py` 两处、`movie.py` 两处），
用户线上日志里同样什么都看不到。既然本次目标是「跳过要可见」，追加第三类
`KIND_MISMATCH`（中文「内容不匹配」）覆盖这 4 个采集点，采集点与汇总机制与 invalid/empty 完全一致，
**不改变任何跳过行为、不升级任何日志级别**。

## 需求（本次实现）

1. **采集**：一次同步运行内，把被跳过的候选资源记下来，两类都要：
   - `invalid` — 分享链接失效（`check_share_status` 返回 `is_valid=False`）**（主目标）**；
   - `empty` — 分享链接有效但列不出可处理文件（`_validated_resource_files` 里
     「分享链接无内容」分支）**（同一静默出口，顺带覆盖；否则用户的原始症状可能仍然无输出）**。
   - 每条记录：`kind`、`provider`（中文名，如 `115网盘` / `光鸭网盘` / `Magnet 链接`）、
     `reason`（`status.status_text` 或 `无可用文件`）、`reference`
     （**必须脱敏**：用现有 `_resource_log_reference(share_url)`，不得打印完整 URL 或 token）。
   - 同一次运行内按 `(kind, provider, reference)` **去重**；**线程安全**（同步任务会并发跑多个订阅）。
2. **汇总输出**（只在有跳过记录时输出；无记录时文案与现状**逐字一致**）：
   - **日志**（`transferred_count` 任意都打，紧跟 `core/services/sync.py:1064` 的完成日志后）：
     `本次跳过 2 个候选资源：分享链接失效 1、无可用文件 1（115网盘 1、光鸭网盘 1）`
     段式：`本次跳过 {总数} 个候选资源：{按类型}（{按网盘}）`；只有一类时省略另一类，如
     `本次跳过 1 个候选资源：分享链接失效 1（光鸭网盘 1）`。
   - **通知**：只扩充 `core/services/sync.py:~1090-1096` 那条**已存在**的「执行完成」通知，追加一行：
     `被跳过的候选：分享链接失效 1 个（115网盘）、无可用文件 1 个（光鸭网盘）。`
     原句 `本次同步未发现需要转存的新资源。` 保持不变，新行加在其后（换行分隔）。
   - `transferred_count > 0` 的**成功**任务：只写日志，**不新增通知**（不打扰用户）。
   - `self._notify` 为假：不发通知，日志照旧。
3. **生命周期**：一次运行开始清零，运行结束取用后清零；不得跨运行串味（两次相邻运行的统计不能叠加）。

## 建议实现（可微调，但接口语义必须一致）

1. 新文件 `core/services/skip_stats.py`：
   ```python
   class SkipStatsCollector:
       """一次同步运行内被跳过的候选资源统计（线程安全、可去重）。"""
       KIND_INVALID = "invalid"   # 分享链接失效
       KIND_EMPTY = "empty"       # 分享链接无可用文件
       def record(self, kind: str, provider: str, reason: str = "", reference: str = "") -> None
       def reset(self) -> None
       def take(self) -> Dict[str, Any]   # 返回汇总并清零
   ```
   `take()` 返回结构至少包含：`total`、`by_kind: Dict[str, int]`、`by_provider: Dict[str, int]`，
   并提供 `is_empty()` / 文案生成（`summary_text()` 之类，输出上面的段式字符串，空统计返回 `""`）。
2. **宿主挂载**：`__init__.py` 的插件类里放运行期唯一实例（与 `self._sync_context` 同一区域，
   例如 `init_plugin` 里 `self._skip_stats = SkipStatsCollector()`；类属性可留 `_skip_stats = None` 兜底）。
   组件侧统一用 `getattr(self, "_skip_stats", None)` 取（`OwnerDelegator` 会沿 owner 链委托到插件），
   取不到就静默跳过 —— **统计失败绝不能影响转存主流程**。
3. **采集点**（`handlers/sync/resources.py`）：
   - `_validate_resource_url` 的失效分支：在现有 `logger.debug` **之后**增加一条 `invalid` 记录
     （`logger.debug` 原样保留，不升级级别）。
   - `_validated_resource_files` 的「分享链接无内容」分支：增加一条 `empty` 记录。
   - `provider` 中文名用现成的 `search/types.py:172 resource_type_name(...)`（与候选摘要
     `光鸭网盘 1（可用 1）` 同一套命名）；拿不到就退化为 `未知来源` / 传进来的 `resource_label`。
4. **汇总点**（`core/services/sync.py`）：
   - `sync_subscribes(...)` 进入运行体（`lock_acquired` / 队列判断之后，真正开始处理前）调用 `reset()`；
   - `:1064` 完成日志后取一次汇总打 info 日志；
   - `:1090-1096` 通知文案里带上同一份汇总；
   - 运行 `return` 前（含「已停止」早退分支）`take()` 清账，保证不跨运行残留。

## 接口约束

- 不新增对外 API、不改前端（本次无 UI 改动）、不改 `/api/v1/plugin/CloudSubscribe/**` 返回结构。
- 不改 `check_share_status` / 任何 Provider 行为；只加采集点。
- 不改「跳过」语义：一个候选失效**不得**中断任务、不得抛异常，其余候选要继续处理。
- 通知渠道沿用现有 `self.post_message(mtype=self._notification_type, ...)`，遵守 `self._notify`。

## 禁止事项

- 禁止把失效 debug 升级成 warning / error（第 1 项本次不做）。
- 禁止把跳过记录写进历史表（第 2 项本次不做）。
- 禁止打印完整分享 URL / cookie / token（脱敏只走 `_resource_log_reference`）。
- 禁止改动与本需求无关的文件、禁止顺手重构、禁止新增第三方依赖。
- 禁止改 `package.v2.json` 里 CloudSubscribe 的 `id` / `name` / `author` / `system_version`；
  只允许动 `version` 与 `history`。
