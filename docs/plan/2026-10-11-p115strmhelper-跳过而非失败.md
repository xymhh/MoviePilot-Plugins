# 任务书：库内更优时标记「跳过」而非「失败」，并删除低质量源文件

- 仓库：`zkmydgth/MoviePilot-Plugins`（V3 插件线），目标插件 `plugins.v3/p115strmhelper`（P115StrmHelper 2.7.25）
- 日期：2026-10-11
- 状态：已完成 2026-10-11（用户选定方案 1：不写失败记录 + 删低质量源文件）→ 实施任务书 `2026-10-11-p115strmhelper-跳过而非失败-实施任务书.md`；验收证据 `../test/2026-10-11-p115strmhelper-跳过语义-单测与静态检查.md`

## 1. 用户诉求

整理时若「媒体库存在同名文件，且质量更好」，当前会在整理记录里被记成**失败**；
期望：标记为**跳过**，并且跳过之后**删除低质量源文件**。

## 2. 根因（已核实到行）

插件整理接管路径自己写整理历史，不走宿主（MoviePilot V3）的覆盖跳过裁决：

- `plugins.v3/p115strmhelper/helper/transfer/handler.py:708`、`:720`（`handler_linked_batch.py:362`、`:374` 同构）
  → 命中「目标质量更好 / 覆盖模式=never」时设 `skip_reason`；
- 随后 `handler.py:685`、`:732` 把 `skip_reason` 塞进 `task_failures`（和真正的失败共用一个通道）；
- `handler.py:944-945` 归入 `failed_tasks` → `handler.py:1893` `_record_fail()` 构造
  `TransferInfo(success=False, message=skip_reason, overwrite_skipped 未设)` → `add_transfer_fail()` 落一条**失败记录**。

宿主 MoviePilot V3 对这种情况有专门语义（`/tmp/mp-core` 只读核对）：

- `app/modules/filemanager/transhandler.py:588/601/620`：核心同类裁决统一带 `overwrite_skipped=True`；
- `app/chain/transfer/filter.py:705-734` `_is_overwrite_declined()`：
  `overwrite_skipped == True` **且**同源路径已有成功整理记录 → 判定为「正常裁决，非故障」；
- `app/chain/transfer/settlement.py:408-450`：命中该判定时**不写失败历史**（保留原成功记录）、
  不发失败事件/通知、不触发重试，只把任务置为「未入库」；
  否则才走 `add_transfer_fail()` + 失败通知 + 失败计数；
- 历史表 `app/db/models/transferhistory.py` 有唯一索引 `ux_transferhistory_src_storage(src, src_storage)`：
  同源写失败记录会 **replace 掉原成功记录** → 该路径此后长期处于失败态，每次新事件都重试并重推失败通知。
  （这正是用户看到「失败」且反复出现的机制。）
- 宿主的「跳过」语义只存在于执行回执：`app/chain/transfer/request.py:620-650` 中
  `info.overwrite_skipped` → item `state="skipped"`；**整理记录表本身没有「跳过」状态**（`status` 仅真/假）。

## 3. 目标行为（对齐宿主语义）

1. 命中「库内同名文件质量更好 / never 不覆盖」：
   - 不归类为失败，走新的**跳过通道**（`task_skips`），与真失败分离；
   - 构造 `TransferInfo(success=False, overwrite_skipped=True, message="已跳过：媒体库存在同名文件，且质量更好")`；
   - **同源已有成功记录 → 不写整理历史**（保留原成功记录），不发 `TransferFailed` 事件、不发失败通知、不登记 AI 重试；
     否则（无同源成功记录）沿用宿主语义写一条失败记录并带 `overwrite_skipped=True`（阶段=「覆盖策略」，不可重试）；
   - 任务置为「未入库」（与宿主 `jobview.fail_task` 一致），保证整理队列收尾、不被其它步骤拖住；
   - 日志 + 插件通知明确「已跳过」，与其他失败区分。
2. 跳过之后删除低质量源文件：受现有开关 `auto_delete_inferior_source_enabled`
   （`core/config.py:846`，现描述「按大小整理失败时」→ 改为「按大小整理跳过时」）控制；
   开关关闭时保留源文件并在日志/通知里说明原因。
3. 覆盖两条实现路径：`helper/transfer/handler.py`（常规）与 `helper/transfer/handler_linked_batch.py`（关联文件名批量）。

## 4. 改动清单

- `helper/transfer/handler.py`
  - `_batch_move_or_copy()` 新增 `task_skips` 收集，返回值由 `(failed, success)` 变为 `(failed, skipped, success)`；
  - 调用方 `_batch_process...()` 收集 `skipped_tasks` 并调用新增 `_batch_record_skips()`；日志统计补「跳过: N」；
  - 新增 `_record_skip()` / `_batch_record_skips()`：按第 3 节语义写历史或不写历史、删源文件、收尾任务组。
- `helper/transfer/handler_linked_batch.py`：同构修改。
- `core/config.py`：`auto_delete_inferior_source_enabled` 描述文案更新。
- `tests/`：新增跳过语义单测（用 `tests/_stub_host` + `sys.modules` 假宿主，风格对齐 `tests/test_transfer_classify.py`）：
  - 质量更优 → 进跳过通道、`overwrite_skipped=True`、message 以「已跳过」开头；
  - 同源有成功记录 → 不调用 `add_transfer_fail`；
  - 开关开 → 调用源文件删除；开关关 → 不删。
- `version.py` / `package.v3.json`：2.7.25 → 2.7.26（发布走 `plugins-release.yml`）。

## 5. 验收标准

1. 新增单测在宿主 stub 下通过；CI（`test-p115strmhelper-v3.yml`，Python 3.14）绿；

4. 不回归：真失败（目录创建失败、移动失败等）仍写失败记录并通知。
