## 1. 背景

插件 CloudSubscribeX 里有一条「跨盘中继」分支：当夸克→115 转存遇到秒传未命中时，把整份文件交给外部中继服务（`cross_transfer_relay_*`）下载并上传，或「一律走中继」。用户决定**彻底删除该功能**，只保留原有的本机下载/秒传路径。

## 2. 必须删除的东西

### 2.1 后端

| 位置 | 内容 |
| --- | --- |
| `plugins.v2/cloudsubscribex/core/relay.py` | 整个文件删除（`RelayClient`、`RelayError`、`probe_health`） |
| `plugins.v2/cloudsubscribex/core/transfer.py` | 参数 `relay_client/relay_max_bytes/relay_timeout_seconds/relay_fallback_local/relay_connections/relay_always`、属性 `_relay_*`、方法 `_relay_transfer` / `_relay_transfer_locked`、变量 `relay_active`/`relay_tried`、所有 `if relay_active ...` 分支、`import` 行 |
| `plugins.v2/cloudsubscribex/core/drive_manager.py` | 构造 `RelayClient`、探测健康、传参给 transfer 的相关代码 |
| `plugins.v2/cloudsubscribex/core/config.py` | 默认值里的 8 个 `cross_transfer_relay_*` 键 |
| `plugins.v2/cloudsubscribex/__init__.py` | `from .core.relay import probe_health`、`_cross_transfer_relay_*` 类属性、`_log_relay_state()` 及其调用、配置读取映射 |

### 2.2 前端

- `frontend/cloudsubscribex/src/config/fields/transfer.js`：删除「跨盘中继」整组字段（`cross_transfer_relay_enabled/url/token/max_file_gb/timeout_minutes/threads/always/fallback_local`），保留同组其它字段（如 `cross_transfer_rapid_miss_action`）。
- 若其它 `src` 文件里还有 relay 文案/开关，一并删除。
- **必须重新构建 dist**：`cd frontend/cloudsubscribex && npm install --no-audit --no-fund && npm run build`（先看 `package.json` 里的脚本名），产物写回 `plugins.v2/cloudsubscribex/dist`。构建后 `grep -ri relay plugins.v2/cloudsubscribex/dist` 必须为空。

### 2.3 测试与文档

- 删除 `tests/test_cross_transfer_relay.py`。
- 修 `tests/test_sync_job_ledger.py`、`tests/test_cross_transfer_progress.py` 等文件中引用 relay 的用例（改成不依赖 relay 的等价断言，不要为了过测而弱化原本的覆盖点）。
- `docs/` 下的历史记录**不要删**（它是决策轨迹），只允许在最新一篇 plan/summary 里追加一节说明「中继已于 2026-10-29 移除」。

## 3. 必须保持的行为（回归红线）

1. `cross_transfer_rapid_miss_action` 语义不变：`abort` = 秒传未命中就中止且不下载整份；其它取值仍走本机下载 → 上传。
2. 本机下载→上传路径的进度上报（`_update(..., phase=..., progress=...)`）、断点/停止事件、失败重试与账本记录逻辑不变。
3. 跨盘判定（`source_provider == "quark"`、`target.supports(...)`）里与中继无关的判断（如 `RAPID_UPLOAD`、`FILE_QUERY`）保持原样。
4. 配置项总数减少 8 个，其余键一个都不能少（`core/config.py` 默认值 + 前端字段要一一对齐）。
