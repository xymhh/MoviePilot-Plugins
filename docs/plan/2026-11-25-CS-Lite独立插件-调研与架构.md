# CS Lite 独立插件（调研与架构）

> 用户决策（2026-11-25）：「这样处理不行，直接做 lite 版插件」——放弃 1.36.x 的
> `cs_lite_mode` 开关路线，改为**独立插件**：只保留「搜索渠道+跨盘转存、渠道签到、
> 榜单订阅」，整理/STRM 完全交给 P115StrmHelper，两者不共享任何存储注册。

## 一、为什么独立插件比「开关」更干净（复盘 1.36.0/1.36.1）

| 问题 | 开关路线 | 独立插件 |
| --- | --- | --- |
| 存储适配器 | 靠早退跳过注册，仍在同一进程里 patch MP 的 `_storage_schemas` | 代码不存在，物理上不可能冲突 |
| 服务注册 | 子配置会把 `_strm_*` 写回 True，要在多个时点反复压（1.36.0 就漏了一次） | 服务清单里根本没有 STRM/整理条目 |
| 维护 | 两个模式共用一个 12.4 万行插件，任何改动都要考虑双模式 | 一个瘦插件，改哪个算哪个 |
| 卸载/回退 | 关开关 | 直接卸载 |

代价：代码复制（约 60% 复用），两份代码会分叉。可接受——Lite 只是「搜索/转存/签到/榜单」，
这三块半年内不会有大改。

## 三、架构（独立插件）

```
plugins.v2/cloudsublite/          # 新插件目录，类名 CloudSubscribeLite
├── __init__.py                   # 入口：只有搜索/转存/签到/榜单的初始化
├── core/  drive/  search/  subscribe/  handlers/  utils/
├── dist/                         # 前端只留「渠道管理 / 签到 / 设置」
└── README.md
package.v2.json                   # 同一市场仓库新增 CloudSubscribeLite 条目
```

要点：
1. **不注册任何 MP 存储**，不改 `_storage_schemas`；
2. **不注册任何 STRM/整理定时服务**（服务清单只有：订阅同步、榜单自动订阅、签到、缓存巡检）；
3. 跨盘转存终点 = 用户配置的目录（默认 115 的 `/转存`），落盘后**不整理**，
   由 MP（存储=115网盘Plus）或 P115StrmHelper 接手；
4. 失败即删本地（1.35.6 已实现，沿用）；
5. 版本从 **1.0.0** 起。

## 四、分三批交付（每批可独立验收）

| 批次 | 内容 | 验收 |
| --- | --- | --- |
| P1 | 骨架 + 搜索渠道 + 跨盘转存（含下载腿/上传腿/目标目录） | MP 能装能跑；渠道页 15 源可测；一次夸克→115 转存落盘成功，且不触发任何整理 |
| P2 | 渠道签到（115/夸克/天翼/光鸭 + 定时 + 通知） | 四个渠道签到成功；定时服务可见 |
| P3 | 榜单订阅（豆瓣/猫眼/TMDB/Netflix + 规则 + cron） | 自动订阅跑一轮，产生候选并转入 P1 的转存链 |

## 五、明确不做

- 不做整理台、整理漏斗、STRM 生成/校准、重复扫描、回收站恢复、MP 整理触发；
- 不做「115网盘CS版」存储适配器；
- 不复制 CS 的测试夹具（Lite 只带针对性测试）。
