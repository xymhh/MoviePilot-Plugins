# 2026-10-16 同源并发互删（中继/暂存竞态）与分享季号错配 — 修复任务书

> 状态：已完成 2026-10-16，已随 1.6.47 发布（代码 + 25 例单测 + 文档；证据见 [../test/2026-10-16-同源并发互删与季号错配单测.md](../test/2026-10-16-同源并发互删与季号错配单测.md)，复盘见 [../summary/2026-10-16-同源并发互删与季号错配.md](../summary/2026-10-16-同源并发互删与季号错配.md))

## 1. 背景与现场

CloudSubscribe（`plugins.v2/cloudsubscribe`，版本 1.6.45/1.6.46）跨盘转存 夸克网盘 → 115 网盘，
2026-10-16 07:44–08:01 出现一批失败：

| 现象 | 次数 | 日志原文（截断） |
| --- | --- | --- |
| Gopeed 下载完成但校验不到文件 | 6 | `Gopeed 任务失败（第 1/3 次），重新取链并重建任务：7.mp4；…原因：Gopeed 任务完成但本机未见文件：/downloads/cloud-transfer-93f9aa47….bin` |
| 夸克取链失败 | 24 | `夸克取链失败：code=21001 file not found [1bd69d1e6801471689567cc1507ccb9f]`（drive-pc/PC-UA、drive/PC-UA、drive/网页-UA 三通道全失败） |
| 内置下载器文件消失 | 1 | `[Errno 2] No such file or directory: '/downloads/cloud-transfer-ab867fec….bin'` |
| 暂存文件找不到 | 1 | `跨盘临时文件尚未可见：夸克网盘 /moviepilot/转存/1.mp4` |

结果：8 条历史记录 `阶段=failed`（极恶老大 7 条 + FX战士久留美 1 条）。

## 2. 根因（已定案，主 agent 已核对线上数据与源码）

**同一源文件被并发转存多次，任务之间互相删文件。**

### 2.1 为什么会并发转存同一文件

同一份资源（同一分享）被三个订阅（极恶老大 S01/S02/S03）各自认领，且同一文件被匹配到不同季：

- 历史记录证据（`plugin/CloudSubscribe/page_data`）：`4.mp4` 同一 `cache_key=bff31b2e2df8f4689ae593cd51a2a52b`
  同时出现在 `S03E04`（失败）、`S02E04`（成功）、`S01E04`（成功）；`6.mp4` 同一 `cache_key=6724613e…`
  出现在 S01/S02/S03E06。三者分享同为 `https://pan.quark.cn/s/5d092c87fddd`。
- 日志证据：07:42:47 三个订阅（S01/S02/S03）同秒创建，07:42:53 同秒并发搜索，随后并发转存。
- 该分享根目录名（只读预览实测）= **`21806-极恶老大 S2`** → 它其实是 **第二季**资源；
  S01/S03 的认领全部是错配（同一文件不可能同时是三季的同一集）。

### 2.2 为什么并发就炸（三层）

1. **中继文件互删**：`core/transfer.py` 的 `_cache_key()` 只由「源盘 + sha1/md5/size/文件名」决定，
   `_cache_path()` = `<下载目录>/cloud-transfer-<cache_key>.bin`。同一文件的所有任务共用同一路径；
   而每个任务走到终态都会 `_delete_cache_path()`（成功 `:1478`/`:1558`、取消 `:1569`、abort `:1573`、失败 `:1585`）
   → 兄弟任务正在写或正要校验的文件被删 → 「本机未见文件」/`No such file or directory`。
2. **Gopeed 自动改名掩盖**：Gopeed 的 HTTP 下载器 `AutoRename()` 恒为 true
   （`internal/protocol/http/fetcher_manager.go:69-71`），建任务时若目标路径已存在，
   `pkg/download/downloader.go:1837-1860` 会 `CheckDuplicateAndRename` 改成 `… (1).bin`；
   而插件只按原路径校验（`core/gopeed.py:299-301`）→ 必然「未见文件」；
   失败重试传 `preserve_partial=True`（`core/transfer.py:1049`、`:1443`）→ 残留不清理 → 重试继续失败。
3. **夸克暂存互删**：暂存路径为「转存目录 + 分享内相对路径」（同名同路径），
   先完成任务的 `finally: _cleanup_cross_transfer_staging()` 删掉暂存文件
   → 兄弟任务取链 `code=21001 file not found`。

### 2.3 已排除

- 夸克分享本身有效（21001 是自家暂存被删导致，不是分享失效）。
- Gopeed 路径映射配置正确（`gopeed_path_prefix=/app/Downloads=/downloads`），中继磁盘空间检查未触发。
- `TransferManager.create()` 无同 `cache_key` 去重/加锁；并发上限只有全局信号量
  `cross_transfer_max_concurrent`（线上 4）。

## 3. 改动要求

### A. 中继/暂存竞态（必须）

**A1. 同 `cache_key` 串行 + 中继文件引用计数（`core/transfer.py`）**

- 抽出纯函数 `_task_cache_key(task: dict) -> str`（由 `task["source_key"]` 与 `task["source_file"]` 调 `_cache_key()`），
  供锁与路径共用；**不得改动 `_cache_key()` 的算法与 `cloud-transfer-<key>.bin` 命名**。
- `_run()` 改成薄包装：先取该 `cache_key` 的进程内锁（`dict[str, threading.Lock]` + 一把守卫锁），
  再调用现有函数体（原 `_run` 逻辑整体下沉为 `_run_locked()`，含原 `_transfer_slots` 的 acquire/release 与 try/finally）。
  这样同一 `cache_key` 的任务严格串行，第二个任务排在第一个之后。
- 引用计数：`create()` 时对 `cache_key` 计数 +1，任务终态 -1；
  **只有计数归零时才允许 `_delete_cache_path()` 删除中继文件**；计数 > 0 时保留（连同 `.meta.json`），
  让后续同 `cache_key` 任务走已有的 `_validate_complete_cache()` 复用完整缓存，避免重复下载。
- 语义边界：`cancel()`（停止清空中继，1.6.44 行为）与显式清缓存（`delete_cache()` / `/cache/clear` / 云缓存清理）
  也必须遵守引用计数：**使用中的中继文件不删**（返回值/日志里说明跳过数量）。任务取消时若还有别的任务在用，保留文件。
- 不要改变任务的对外状态机与 `_public()` 字段。

**A2. 暂存文件引用计数（`handlers/sync/service.py` 的跨盘暂存流程）**

- 转存到夸克暂存目录 `/moviepilot/转存/...` 的清理，改为「同一暂存路径的引用计数归零才删」；
  计数对象用暂存文件的绝对路径字符串。A1 的串行已经消除大部分并发，这里做兜底。

**A3. Gopeed 残留清理与校验容忍（`core/gopeed.py`）**

- 建任务前：删除目标路径的残留（`cloud-transfer-<key>.bin` 本体 + `.meta.json` + `.parts.json` + `.tmp` 变体，
  以及同目录下 `cloud-transfer-<key>*.bin` 形式的 Gopeed 改名副本，如 `… (1).bin`）。
  删除范围必须严格限定在 `cloud-transfer-` 前缀 + 本任务 `cache_key`，**不得**用宽泛通配删别人文件。
- 校验阶段（`_wait_task` 的 `done` 分支 / `_verify_result`）：精确路径不存在时，
  允许匹配同目录 `cloud-transfer-<key>*.bin` 的候选，取大小等于期望值者视为成功；
  仍不存在才抛「本机未见文件」。
- 「本机未见文件」异常文本改为可诊断信息，包含：期望路径、Gopeed 侧映射后的目录、以及一句提示
  （「同源任务并发」或「Gopeed 容器目录与下载目录不是同一宿主目录，检查 gopeed_path_prefix 与挂载」）。

### B. 分享季号错配（必须）

**B1. 目录季号守卫（`utils/file_matcher.py`）**

- 新增守卫：若文件所在**分享目录/相对路径**（取 `_relative_path` / `relative_path` / `parent_path` / `cloud_path`）
  含显式季号标记且与目标季冲突（复用既有 `MediaFileParser.contains_other_season(text, season)`），
  则该文件不得进入候选：`episode_from_file()` 的 title-less 兜底路径与 `episode_candidates()`
  的 loose/loosest 匹配路径都要先过守卫。
- 只做「冲突则拒绝」，**无季号信息时行为保持不变**（不能因为这条改动让混淆文件名的正常场景失效）。
- 命中拒绝时打一条 `logger.debug`（含相对路径、目标季、识别到的季号），便于排查。
- 新增配置开关 `cross_season_path_guard`（默认 `True`），走既有配置机制（`core/config.py` 默认值 + 前端配置项/`ui_options` 暴露），
  允许用户关闭。
