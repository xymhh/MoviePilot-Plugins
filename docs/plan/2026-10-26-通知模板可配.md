# NOTIFY_TEMPLATE — CS 通知模板可配（UI 编辑）

> 状态：已实施 1.7.72（plugins.v2/cloudsubscribex/utils/notify_template.py，六类通知文案可配）

## 目标
把 CS 硬编码的通知文案抽成模板，用户可在插件 UI 里编辑；默认值参考 MP 风格。

## 现状盘点
`post_message` 调用点（10 处，文案全硬编码）：
- `handlers/sync/notify.py:131` 转存/跨盘/洗版完成（唯一带聚合列表的）
- `core/services/sync.py:524,675,789,1040,1270` 配置错误/无订阅/登录失败/任务停止/同步完成
- `core/services/checkin.py:581,626` 签到结果与汇总
- `core/services/organize.py:1073` 整理完成
- `core/subscribe/service.py:264` 榜单自动订阅
- `core/api/media_library.py:128` 深度联动删除

## 方案
1. 新增 Jinja2 模板渲染工具 `utils/notify_template.py`（渲染失败回退默认文案，绝不让通知发不出去）
2. 6 类模板配置项（后端 `core/config.py` + 前端 textarea）：
   - `notify_template_transfer` / `_cross_transfer` / `_upgrade`
   - `notify_template_checkin`
   - `notify_template_organize`
   - `notify_template_delete`
3. 变量：
   - 通用 `{{ time }}`、`{{ count }}`、`{{ action }}`
   - 转存类 `{{ items }}`（每项 `title`/`year`/`season`/`episodes`/`episodes_text`/`type`/`image`）
   - 签到类 `{{ provider }}`/`{{ success }}`/`{{ lines }}`
   - 整理类 `{{ source }}`/`{{ groups }}`/`{{ ready }}`/`{{ done }}`/`{{ skipped }}`/`{{ failed }}`
4. 默认值 = MP 风格（emoji + 结构化），行为与现在一致

## 待确认
- 覆盖范围：只做转存/洗版/签到 3 类，还是全部 6 类
- 模板语法：Jinja2（支持循环）vs 简单占位符替换
