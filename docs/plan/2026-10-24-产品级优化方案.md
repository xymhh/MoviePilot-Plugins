## 1. 结果可解释性：资源账本

**问题**：用户只知道"没转存"，不知道"为什么"。原因只写在容器日志里。

**实现**

| 位置 | 内容 |
| --- | --- |
| `core/services/candidate_ledger.py` | 按天 JSONL 落盘（`<数据目录>/ledger/candidate-ledger-YYYY-MM-DD.jsonl`），保留 14 天，写入失败只记 debug |
| `core/services/skip_stats.py` | `record()` 增加 `resource_title` / 订阅上下文；**去重键与汇总口径完全不变** |
| `handlers/sync/*.py` | 8 处跳过调用点补传 `resource_title`；`_validate_resource_url` 增加同名参数 |
| `core/services/sync.py` | `_take_skip_stats()` 统一落账本，覆盖正常结束 / 中断 / 异常三条路径；清理任务每天最多一次 |
| `core/api/ledger.py` | `GET /ledger/list`（天数 + 类型 + 关键词 + 分页）、`GET /ledger/summary`（按类型/来源/天聚合） |
| 前端 `CandidateLedgerPanel.vue` | 新页签「资源账本」：筛选、汇总 chip、表格、分页 |

**额外收益**：mismatch 的 `reason` 现在带实际根目录名，例如
`分享根目录与订阅标题不符（根目录：更新至08集 / 小城良方(3)）`。
下一轮扫描后即可判断是"真换片"还是"装饰太多导致误杀"，不必再翻日志。

## 2. 缓存可观测

**问题**：曾出现 169 条 `Failed to set key ... Can't pickle CloudFile`，无人察觉。
根因（旧类对象进 Redis）已在 1.7.30 的编码层修掉，11:03 后 0 条复现；缺的是**可见性**。

**实现**：`utils/cache.py` 增加进程内计数（`encode_ok/encode_skip/decode_fail/hit/miss`
+ `hit_rate`），`GET /cache/stats` 暴露，账本页底部一行展示。
编码失败不再是静默 debug，而是可观测数字。

## 3. 标题匹配容错

**问题**：104 个资源因「分享根目录与订阅标题不符」被跳过，其中大量疑似误杀
（`小城良方(3)`、`玉簟秋(29)`、emoji 包裹的标题）。

**实现**：`FileMatcher._title_similar_enough()` —— 精确包含判断全部失败后，
用 `difflib.SequenceMatcher` 兜底：normalize 后长度 ≥3 且相似度 ≥0.75 放行
（4 字中文至少 3 字一致）。防空转：长度 <3 不参与。

**验证**（单测 + 手工样本）

| 根目录 | 目标 | 结果 |
| --- | --- | --- |
| `🔥🔥【更新至23集】【伟大的长征 (2026)】【4K…】` | 伟大的长征 | 放行 ✓ |
| `伟大的长征 4K` | 伟大的长征 | 放行 ✓ |
| `▁▂▃▅▆▇▉现在就出发 1-4季【4K】` | 伟大的长征 | 拦截 ✓ |
| `私.行` / `玉-癫-囚 (2026)` | 伟大的长征 | 拦截 ✓ |
| `伟大的長征【4K】`（繁体） | 伟大的长征 | 拦截 ⚠ 已知限制 |

**已知限制**：简繁差异未做转换（相似度 0.72 < 0.75）。宁可继续跳过，也不降低阈值
误放不相关内容。若后续需要，引入轻量简繁映射表再评估。

## 4. 重复订阅治理

**问题**：同一部剧可能有多张订阅卡片，同步只处理最早创建的一张，其余静默跳过。

**实现**：`_deduplicate_subscribes()` 把重复组挂到插件实例；
`GET /duplicate/list` 列出、`POST /duplicate/pause` 暂停（`state=S`，只改状态不删数据）。
保留项（`keep_id`）在服务端强制排除，避免误操作把所有卡片停掉。每次暂停写账本
（`kind=duplicate_paused`）。前端账本页顶部提示 + 一键暂停。

**安全边界**：不做后台静默批量暂停，必须用户点按钮。
