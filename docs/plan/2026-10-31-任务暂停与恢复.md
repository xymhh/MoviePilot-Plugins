# 任务暂停与恢复（1.8.7）

> 状态：已实现并发布 1.8.7 → ../test/2026-10-31-任务暂停与恢复-验收.md

## 为什么

1.8.5 起转存走 `sync_jobs` 账本 + 租约（TTL 120s，心跳 15s），进程被打断后
2 分钟租约过期 → `retry_wait` → 退避后重新认领，**每次认领 attempt+1，上限 3**。
更新插件/重启 MP 会打断正在跑的作业，反复更新会把作业打到死信。

需求：更新前能「先别接新活」，等当前文件跑完再更新；更新完再恢复。
所以暂停必须满足：

- 不打断正在写的文件（打断只能靠「停止」）；
- 暂停期间不认领新作业、**不消耗 attempt**；
- 暂停状态持久化，重启后仍生效（否则更新期间自动恢复 = 白点）。

## 设计

### 全局暂停（主要入口）

- 落在 `runtime_records`，命名空间 `sync_pause`，键 `global`，
  payload `{paused, updated_at, actor, reason}`；读失败一律按「未暂停」处理
  （不能因为读库失败把整个转存停掉）。
- 闸门两处（单一判据 `SyncHandler._sync_paused()`，3 秒缓存）：
  1. `_transfer_file` 入口：暂停时直接 `return False`，日志「转存已暂停，跳过本次转存」；
  2. 跨盘批次 `batch_stop_requested()`：与 stop/system-stopped 同级，批次干净退出，
     不写失败、不消耗次数。
- 接口：`GET /sync/pause` 读，`POST /sync/pause {"paused": bool}` 写。

### 单任务暂停

- 状态机新增 `paused`：`queued/retry_wait → paused`、`paused → queued`、
  `paused → canceled`；`paused` 不在 `claim()` 的可认领集合里，也不进 `_ACTIVE_JOB_STATES`。
- `pause()` 不碰 `attempt`；`resume()` 清 `next_retry_at` 与租约、保留 `attempt`。
- 运行中（transferring/verifying/finalizing）**不允许**暂停，返回「当前状态无法暂停」，
  页面只给「停止」。
- 接口：`POST /tasks/pause`、`POST /tasks/resume`，body `{job_id}` 或 `{job_key}`。

## 任务中心展示

- 顶部按钮「暂停转存 / 恢复转存」+ 暂停时的黄色横幅（说明不打断当前文件、更新前可先暂停）。
- 行按钮：`queued/retry_wait` 给「暂停」，`paused` 给「恢复」，运行中给「停止」。
- 筛选新增「已暂停」；暂停任务状态显示「已暂停」（不占用六状态契约里的任何一个）。
- `GET /tasks` 响应新增 `paused: {paused, updated_at, actor, reason}`。

## 不做（本次范围外）

- 暂停时不阻断订阅扫描/搜索（仍会搜索，只是不转存）；下一轮再评估，避免一次改动过大。
- 不提供「定时自动恢复」。
- 点击更新插件时自动暂停（MP 没有插件更新前钩子）。
