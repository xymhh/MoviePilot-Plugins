# 网盘订阅助手：媒体库一级目录按类型分层（1.6.31）任务书

> 状态：已完成 2026-10-12 → ../summary/2026-10-12-媒体库一级目录开关.md

## 背景（用户原话的诉求）

用户的 115 网盘「媒体库目录」下，插件产出的目录**直接是二级分类**：`外语电影`、`国产剧`、`日韩剧`…
而用户的总媒体库是分层的：`电影/…`、`剧集/…`。两边结构不一致，用户希望插件媒体库也按
「一级 = 媒体类型（电影/剧集）、二级 = 分类」分层，且**不要**动 MoviePilot「设定 → 目录」的配置
（那是全局的，会连带改变本地总媒体库的整理行为）。

## 现状（改前，源码结论）

- `handlers/sync/naming.py::_platform_classified_root` 是**网盘媒体库目录**与**本地媒体根路径**共用的
  分类根计算入口：它把宿主 `TransHandler.get_dest_dir` 的结果当作落点，只把目录条目的 `library_path`
  替换成用户填的网盘/本地根，其余字段（含 `library_type_folder` / `library_category_folder`）原样沿用。
- 因此用户侧「一级目录缺失」的根因是那条目录条目的 `library_type_folder`（媒体库类型子目录）为关；
  打开它零代码改动即可，但**同一条目录配置两边共用**，平台本地总媒体库的整理层级会跟着多一层，
  且一级目录名固定为 `电影` / `电视剧`（`MediaType.MOVIE.value` / `MediaType.TV.value`），
  与用户总媒体库的 `剧集` 命名不一致 —— 所以不采用该路径。

## 方案（本次实现）

插件内新增独立开关，只改插件产出的目录层级：

| 配置项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `type_folder_enabled` | bool | `False` | 「按媒体类型建一级目录」总开关 |
| `type_folder_movie` | str | `电影` | 电影一级目录名（可自定义） |
| `type_folder_tv` | str | `剧集` | 剧集一级目录名（可自定义） |

开关打开后：

- 网盘：`<媒体库目录>/电影/<二级分类>/<片名 (年份)>/…`
- 本地：`<本地媒体根路径>/剧集/<二级分类>/…`（STRM 与网盘结构保持一致）
- 关闭时行为与 1.6.30 **完全一致**。

实现要点：

1. `naming.py::_platform_classified_root` 在返回前调用 `_with_type_folder`：把一级目录名插到
   **根目录之后的第一个位置**（保持宿主已给出的分类层级不变），并做幂等保护 ——
   宿主若已给出同名首级目录（例如目录条目本来就开了 `library_type_folder`），不再插一层。
2. 兜底分支（宿主 `DirectoryHelper` 不可用时）原本拼 `<根>/电影|电视剧`，启用开关时改用**配置的目录名**，
   避免出现 `剧集/电视剧` 叠层。
3. 平台分类根缓存 key 加入一级目录名，防止改名后命中旧缓存。
4. 配置读取三处同步：`__init__.py`（类属性 + `init_plugin` 解析）、`handlers/sync/service.py`（任务期读取）、
   `core/config.py`（配置页默认值）；前端 `frontend/cloudsubscribe/src/config/fields/transfer.js`
   新增「媒体库目录结构」分组（开关 + 两个目录名 + 说明）。

- [x] 本地 STRM 根同样分层（`/strm/剧集/…`）
- [x] 兜底分支不出现 `剧集/电视剧` 叠层

## 禁止事项

- 不得修改 MoviePilot「设定 → 目录」的任何配置，也不得改变平台自身整理行为。
- 不得在开关关闭时改变任何目录层级（默认行为必须与 1.6.30 逐字一致）。
- 不迁移历史已入库目录（不自动搬文件），只影响开关打开后的新转存/新整理。
