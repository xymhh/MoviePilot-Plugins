# 同集重复入库治理（1.33.0）任务书

> 状态：已完成 2026-11-24（版本 1.33.0）→ [验收](../test/2026-11-24-同集重复入库治理-验收.md)｜[总结](../summary/2026-11-24-同集重复入库治理.md)
> 触发：用户报「怎么一直在入库重复的媒体」。现网实测 85 组重复 .strm，
> 48 组「同集两份不同视频」、37 组「同一视频两个 .strm」、46 组至少一份
> .strm 已对不上任何 115 视频；Emby 侧 `无声的回响` 同步结果
> `{1: [1,2,3,4,4,4,5,6]}`（E04 三次）。

## 一、事实（已核实）

1. **存量重复全部早于 1.31.0**：Doctor X 的重复 .strm 写于 10-25 / 11-01，
   无声的回响 E04 三份写于 11-21 05:00 / 05:07；而「写新 .strm 时清同集旧
   兄弟」（`handlers/sync/strm_duplicates.py:315`）随 **v1.31.0（11-22 18:27）**
   才发。今天新写的 .strm（宝珠 E13/E14、十万狂花 E15）全部单一命名。
2. **存量不会自愈**：增量扫描对已存在的 .strm 直接 `skipped` 跳过
   （`utils/strm_export.py:167`），兄弟清理只在「写新文件」时触发，所以
   14146 条路径里那 85 组永远留着。
3. **同集被反复真实转存**（仍在发生）：无声的回响 S01E07 今天 15:09 /
   16:00 / 16:17 传了三次（4694MB mkv → 4820MB mp4 → 272MB mkv），
   宝珠 S01E13 两次（3370MB 4K + 788MB 1080p）。两条原因：
   - 漏斗去重只管在途：`_active_filter()` = queued/processing/failed，
     **done/held 释放去重键**（`core/database/repositories.py:917`）；
   - 落盘名带 hash 不覆盖（`core/transfer.py:1258`），上传时后缀被剥掉
     写回同名，`.mkv` 与 `.mp4` 又落成两个文件。
4. `TargetWriter.commit` 已按**精确文件名** probe（同大小同校验和才
   `reused`，否则 `conflict`），但同集不同扩展名（`.mp4` vs `.mkv`）
   探不到。

## 二、范围（三处）

### A 存量自愈：陈旧 .strm 清扫（`utils/strm_export.py`）

- 增量/全量扫描时用同一份 115 目录树算出**期望的 .strm 路径全集**；
  本地镜像目录下凡是不在全集里的 .strm，就是「115 里已经没有对应视频」
  的陈旧指针，直接删（只删本地指针，不动网盘视频）。
- 安全阀：一次要删的比例超过 **30%** 时判定目录树导出不完整，整轮放弃并记
  warning（宁可不删）。
- 删除的路径回传给调用方登记 Emby 删除屏蔽（1.31.6 的防深度删除连锁）。
- 不碰「同集多份都还存在」的组——那涉及删哪个视频，留给重复扫描页人工决定。

### B 入队时间窗：同集近期已入库不再转存（`core/database/repositories.py` + `handlers/sync/service.py`）

- 新增 `FunnelQueueRepository.find_recent_done(...)`：同 (media_type, tmdb_id,
  season, episode) 在 N 秒内**已 done** 的行。
- `enqueue(..., recent_done_window_seconds=0)`：窗口 > 0 且本次不是洗版
  （`is_upgrade=False`）时，命中近期 done 行直接返回该行、`created=False`。
- `SyncHandler._resolve_funnel_duplicate_enqueue` 增加 done 分支：
  记「同集 N 小时内已入库（行 #X），第二份跳过」，弹出第二份 pending，
  返回 False（不进重试、不写失败）。
- 配置 `funnel_recent_done_window_hours`：默认 **12**，`0` 关闭，clamp 0~168。
  洗版与手动提交不受影响（洗版由 is_upgrade 放行；手动提交走同一窗口，
  但同一集在 12 小时内被手动再点一次属于用户明确意图，故 `source=manual`
  也放行）。

### C 上传前查重：同集同大小/更大版本直接复用（`core/target_writer.py`）

- `_probe_with_service` 在精确名未命中时，再按**去扩展名的同名主干**查一次
  目标目录（`list_files_recursive`）。
- 找到同主干且大小 ≥ 本次的文件 → 返回 `reused`（不重复上传、不覆盖），
  日志写明「同集已有同大小或更大版本」。
- 只找到更小的同主干文件 → 记 warning（本次仍上传，重复由扫描页收尾），
  不自动删任何云盘文件。

## 三、明确不做

- 不自动删 115 上的视频（包括「更小版本」），删除一律留给扫描页人工确认。
- 不改洗版判定与 coexist 命名。
- 不做「同一集只允许一个 .strm」的强制唯一化：不同视频的多份留给人工。

## 四、验收

1. 新增单测：A 三例（删陈旧/保留期望/比例超限放弃）、B 两例（窗口内跳过、
   洗版放行）、C 两例（同主干更大→reused、更小→继续上传）。
2. 旧代码反证：新测试在 stash 后必须失败。
3. 全量 pytest 与基线逐条比对（基线 2972 passed / 13 failed 全在
   `test_strm_redirect.py`），lint 0 error，前端无改动（不需要重建）。
4. 版本 1.32.0 → **1.33.0**（`__init__.py` / `package.v2.json` / history）。
