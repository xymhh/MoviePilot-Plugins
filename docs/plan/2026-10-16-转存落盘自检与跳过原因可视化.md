# 转存落盘自检 + 记录 landed 字段 + 跳过原因可视化（1.6.52）

> 状态：待实施（任务书，2026-10-16 用户「要」→ 先出任务书过目再动手）
> 时间：2026-10-16｜对象：`plugins.v2/cloudsubscribex`｜上游版本基线：1.6.51（main 已发布）
> 来源：用户「站在你的角度，当前插件有哪些可以优化改进的地方」→ review 8 项，用户拍板做前 3 项

## 0. 一句话目标

**把「转存成功」的定义从「接口返回成功」收紧成「目标季目录里真有这个文件」**，并把判定结果落成显式字段，同时让判重跳过这件事在 UI 上看得见。

## 1. 背景与根因（为什么必须做）

### 1.1 真机故障链（2026-10-16 已定性，证据在 `docs/plan/2026-10-16-判重只信实测存在.md`）

订阅《反恐特警组：放逐者》补齐缺集 → 跑完网盘里仍只有 `S01E04.mp4`，E01/E02/E03 全盘没有。

1. 这三集历史上留下 `status=成功` 的转存记录，但记录里 **`cloud_dir` 为空、`file_name` 还是源文件名**（查无落盘痕迹）；
2. 该记录被写进 **MP 整理历史**（`handlers/sync/platform_history.py` 只认 `status==成功`）；
3. 下一轮判重把 MP 整理历史当基线（`handlers/sync/baseline.py::_build_episode_baseline`）→ 幻影版本；
4. → 判重 skip（日志「按季集判重跳过：同评分且候选文件未更大」）→ **缺失集永远补不上**。

### 1.2 1.6.51 只治了下游

1.6.51 在`episode_dedup.py` 加了**存在性校验**（历史条目必须能在目标季目录找到同名文件或同 `file_id`，否则按缺失处理），并让「跳过」合并不再覆盖成功记录的落盘信息。

**但源头还在生产假成功**：转存接口返回 `success=True` 那一刻就直接写 `status=成功`，没有任何「文件到底在不在」的确认。于是 4 个下游各自要防：

| 下游 | 现在怎么防 |
| --- | --- |
| 判重基线 | 1.6.51 的存在性校验（`episode_dedup.py::_collect_episode_versions`） |
| 洗版基线 | 同一份基线数据，靠同一道校验 |
| MP 整理历史 | 靠 `platform_history.py` 只写 `status==成功`（**假成功照样是「成功」**） |
| 历史页 / 重转入口 | 靠启发式判断「可疑成功」（`cloud_dir` 为空 或 `file_name == source_file_name`） |

### 1.3 形状歧义（为什么要有显式字段）

「跳过」记录和「成功但没落盘」记录长得**一模一样**：

- 跳过记录：`status="跳过"`, `cloud_dir=""`（`handlers/sync/television.py:590-605`）
- 假成功记录：`status="成功"`, `cloud_dir=""`

因此「哪些成功是可信的」只能猜。加一个显式 `landed` 字段可以一次替掉所有启发式，也给 UI 和重转入口一个可靠依据。

## 3. 设计

### 3.1 新增落盘校验（复用 1.6.51 已有能力，不额外打网盘）

复用 `handlers/sync/episode_dedup.py::_season_dir_files(subscribe, mediainfo, season)` —— 它已经返回 `(是否拿到实测数据, 目录路径, 文件条目)`，带 TTL 缓存（`_season_listing_cache`），且 `verified=False` 明确表示「拿不到实测数据」。

新增（建议新文件 `handlers/sync/landed.py` + mixin）：

```python
def verify_landed_items(
    self, subscribe, mediainfo, season: int, items: List[Dict[str, Any]]
) -> Dict[str, Dict[str, Any]]:
    """批量核对转存结果是否真落在目标季目录。

    items: [{"file_id": str, "target_name": str, "target_dir": str}]
    返回: {key: {"landed": Optional[bool], "reason": str, "actual_file_id": str}}
      - landed=True  : file_id 命中目录，或（file_id 取不到时）同名文件命中
      - landed=False : 目录实测成功（verified=True）但找不到该文件
      - landed=None  : 拿不到实测数据（verified=False）→ 调用方必须维持旧行为
    """
```

判定优先级：`file_id` 精确命中 → 同名（`target_name`）命中 → 都没有且 `verified=True` → `landed=False`。
`reason` 取值：`file_id_match` / `name_match` / `missing_in_dir` / `listing_unavailable`。

**一次列目录覆盖整批**：同一次任务内同一季所有条目共用这次 list（走 `_season_dir_files` 的缓存），禁止逐文件列目录。

### 3.2 接点 A：即时转存路径（跨盘/直转/ED2K 之外的成功）

`handlers/sync/television.py:712-745`（消费 `_transfer_episode_items` 结果、构造 `history_item` 处）：

- 批内 `success=True` 且 **`pending_key` 为空**的条目 → 先批量自检，再决定 `status`；
- 自检通过 → 现状不变（`成功`/`升级`），补 `landed=True` + `verified_at`；
- 自检不通过 → `status="待确认"`、`landed=False`、`landed_reason="missing_in_dir"`、**WARN 日志**，并且：
  - 不计入 `completed_missing_episodes` / `success_episodes` / `batch_success_episodes`（既不当作已补齐，也不发「转存成功」通知）；
  - **不写进 MP 整理历史**（同 1.6.51 对跳过的处置）；
- 拿不到实测数据（`landed=None`）→ **完全维持 1.6.51 行为**（照样记「成功」），只加一条 DEBUG/INFO 说明未校验；
- `pending_key` 非空的条目（离线/中继下载中）走 3.3。

### 3.3 接点 B：离线/中继的 finalize 路径

三处把记录标成「成功」的地方都要过闸：

| 位置 | 说明 |
| --- | --- |
| `handlers/sync/history.py::_mark_offline_history_status_batch`（`if status == "成功"` 分支，~`:1184`） | 标记前自检；不通过 → `status="待确认"`、不进 `platform_records` |
| `handlers/sync/history.py::reconcile_orphan_finalize_records`（~`:1216`） | 兜底修复路径，同样过闸 |
| `handlers/sync/postprocess.py:2102` / `:2318`（`status="成功"` 构造处） | 完成后处理写成功记录处，同样过闸 |

**注意**：`_mark_offline_history_status_batch` 的 `_record_platform_transfer_histories(platform_records)` 只收「成功」记录 → 只把 `landed is not False` 的记录放进去。

### 3.4 记录字段（向后兼容）

在 `handlers/sync/history.py::_build_transfer_history_item` 的产物里新增（由调用方传入，缺省不写）：

- `landed`: `True` / `False` / 不写（=未知，等同现状）
- `verified_at`: `"%Y-%m-%d %H:%M:%S"`
- `landed_reason`: 见 3.1

**老记录没有这些字段** → 一律按「未知」处理，行为与 1.6.51 逐字节一致。

## 4. 接口约束（硬要求）

1. `_episode_dedup_decision`（判重决策）**逻辑不动**；`_season_dir_files` 的返回值语义与缓存键**不动**（只复用）。
2. **拿不到实测数据（`verified=False`）一律不改状态**、不产生「待确认」——网络抖动不能变成脏记录风暴。
3. 「待确认」不能被当成「失败」：不发失败通知、不触发重试循环、不写 MP 整理历史、`failed_count` 不计。
4. **不新增自动重转**：自检不通过只标记；补齐由用户手动重转 / 下一轮订阅扫描（按目录实测判重）决定。
5. 组织与命名路径不变（`_platform_target` / `_resolve_resource_season_dir` 不动）；不动 1.6.42 起的点选路径边界。
6. 新增字段全部**可选、向后兼容**；老记录不迁移、不批量改写。
7. 日志：新增结论日志走 INFO/WARN，含季集 + 目标文件名 + 原因；**不得打印网盘凭据/cookie**。
8. 网盘请求纪律：同一任务同一季**只允许一次列目录**（复用缓存），自检不得逐文件查接口。
