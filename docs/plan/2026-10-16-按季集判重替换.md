# 任务书：CloudSubscribe 按「剧集身份 + 季集」判重替换（1.6.48）

> 状态：进行中（2026-10-16）
> 背景见 `docs/summary/2026-10-16-洗版为何没替换.md`（待写）

## 1. 背景与问题

用户库里同一集出现 4 个版本（`正相反的你与我 S01E01`）。根因：**整条链路判重的单位都是文件名/路径**，命名模板一变，同一集就算成不同文件：

- MP 整理链：覆盖判定按目标**全路径**（`/tmp/mpv3/app/modules/filemanager/transhandler.py:517-600`，`get_item_strict(target_file)`），无同名文件就直接写入。
- 插件：不走 MP 整理链（自己 `_cloud_mutations.move_file` 直写云盘），存在性检查只认**完全相同的目标文件名**（`handlers/sync/postprocess.py:1571`、`handlers/sync/movie.py:204`）；非洗版路径**永不替换**。
- 电影侧 `_find_cloud_movie_file`（`handlers/sync/naming.py:592`）最终仍是 `path.stem == expected_stem`（`:624`）。
- 115 云盘侧同名不覆盖，自动加 `(1)`。

用户诉求（2026-10-16 03:50）：**改成按「剧集名 + 第几集」判重**——能入库的都已有 tmdbid 与季集，不必依赖文件名。

## 2. 目标

转存/入库前，以 **（剧集身份 tmdbid/订阅名/年份 + 季 + 集）** 为键判断「该集库里是否已有版本」，不再以文件名/路径为键：

1. 命中同集，且**新资源不差于**已有版本 → **删旧文件 + 写入新文件**（真替换）。
2. 命中同集，且新资源**差于**已有版本 → **跳过**，不新增版本，历史记 skipped（原因：同集已有更优版本）。
3. 未命中 → 按现有逻辑正常写入。

## 3. 判重数据源（两路取并集）

1. **目标目录扫描**（主，覆盖所有来源，含老模板遗留 / 手动入库）：
   - 目标目录 = 模板渲染出的 `Season xx` 目录（剧集）/ tmdbid 目录（电影），用现有 `_cloud_directories.list_directory`。
   - 对目录内视频文件用 `MetaInfoPath`（或现有 `FileMatcher.episode_from_file`）解析 season/episode；与本次目标**季集相同**的即为旧版本候选。
2. **插件既有基线**（辅，覆盖文件名里没有季集的情况）：
   - `handlers/sync/baseline.py:179 _build_episode_baseline`（键 = tmdbid + 订阅名 + 年份 + 季，数据源 = MP 整理历史 + 插件历史 + Emby 每集媒体 `handlers/notification/media_server.py:131`）。
   - 基线里带 `file_id` / `cloud_dir` / `file_name`，用于精确定位与删除。

两路结果按 `file_id`（无则按 `目录+文件名`）去重。

## 4. 评分与替换决策

- 复用现有评分：`_get_mp_rule_score` / `rule_scoring.py`（保持与 `_should_upgrade_candidate` 同一套评分口径，避免两套标准）。
- 比较：新资源评分 **≥** 旧版本评分 → 替换；**<** → 跳过。
- 同评分时沿用 `upgrade_mode` 语义（`largest`：新的更大才替换；`smallest`：更小才替换）。

## 5. 删除范围与安全要求

- 旧文件**包含非插件转存的产物**（老模板遗留、手动入库）——用户 2026-10-16 明确同意删除。
- 每次删除必须：写日志（含被删文件完整路径 + 旧/新评分）+ 汇总进本轮通知（列出删除清单）。
- 删除失败或定位不到（无 `file_id` 且名字无法解析季集）时：**不阻塞写入**，记 warning 并继续（避免把可用的新文件丢掉）；但要留可检索日志关键字 `episode_dedup_miss`。
- 新增开关 `episode_dedup_enabled`（默认 `true`，配置页可见）便于一键回退。

## 6. 电影侧

- `_find_cloud_movie_file`（`naming.py:592`）：把 `path.stem == expected_stem` 改为「该 tmdbid 目录内任一视频文件即视为已有版本」；再按第 4 节决策替换/跳过。
- 目录已由 tmdbid 决定，风险可控；仍需 `episode_dedup_enabled` 开关与删除日志。

## 7. 明确不做（禁止扩大范围）

- 不动订阅搜索/扫描/点选等**非入库路径**（1.6.25、1.6.42 的教训）。
- 不改 MP 本体；不依赖 MP 私有 API 的新增入口。
- 不改现有洗版（`_should_upgrade_candidate`）语义与门槛，只把判重键从文件名换成季集。
- 不引入对 Emby/Jellyfin 的**强依赖**（拿不到就退化为目录扫描）。

## 8. 验收标准

1. 单测覆盖：同集已有更优 / 更差 / 无记录 / 无 `file_id` 需靠目录解析兜底 / 电影目录内多版本 / 老命名（`- 第 1 集` 这类无 SxxExx）解析 / 开关关闭时不删。
2. 全量既有单测通过（允许保留既有 p115client 环境失败项），lint 0 error。
3. 真机 e2e：对已有 4 个版本的《正相反的你与我》S01E01 触发一次转存 → 历史显示替换、云盘该集只剩 1 份（含被删清单日志）。
4. 版本号 1.6.48，README/排障表更新，提交推送并出 Release。
