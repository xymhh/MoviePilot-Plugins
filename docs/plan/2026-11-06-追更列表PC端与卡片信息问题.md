## 0. 背景

用户在 PC 端打开「追更列表」看不到订阅卡片，随后追加反馈 4 个界面问题。本文按用户原话逐条落账，含已复现证据与拟定改法，等用户点名后按条施工。

## 1. P0｜PC 端卡片全部塌成 2px（已复现 + 已验证修法）

**现象**：1600×900 下 81 张卡片全部只剩一条 2px 横线，内容被裁掉；手机 390px 正常（138px/张）。

**实测数据**（Playwright 打线上页，`tmp_task/hub_pc*.py`）：

| 视口 | 卡片数 | 单卡高度 | `.card-inner` 高度 |
| --- | --- | --- | --- |
| 1600×900 | 81 | **2px** | 32px（= 上下 padding，内容 0） |
| 390×844 | 81 | 138px | 136px |

**根因**：`frontend/cloudsubscribex/src/components/dashboard/MediaHub.vue` 样式块里 `.card-inner { height: 100% }`，而 `.media-card` 是**自动行高的 grid 单元**。PC 端 `.hub-pane` 给 `.media-grid` 施加了确定高度，百分比高度在 auto 行里形成「行高 0 → 卡片 0 → 子元素 100% = 0」的自洽塌陷；手机端 grid 高度不受限，百分比退化成 auto 所以不复现。1.9.48 改卡片布局后引入。

**已验证修法**（浏览器注入后卡片 2px → 196px，截图 `tmp_task/hub_1600_fixed.png`）：

```css
.media-grid { grid-auto-rows: max-content; align-content: start; }
.media-card { display: flex; }
.media-card .card-inner { height: auto; flex: 1 1 auto; }
```

**验收口径**：PC 1600 / 1280 / 1024 三档卡片高度 ≥180px、无重叠；手机 390 仍为 138px 不回退；同一行卡片等高。

## 4. P0｜「已播/入库/缺集」口径错误：1-2 集实际存在却显示不存在

**用户原话**：「最重要的是这部剧 1-2 集是存在的，却显示不存（在）」。

**待用户补一条信息**：剧名（或卡片截图）。拿到后按以下顺序核：

1. 前端 `aired_episodes` 来自 `POST /aired_counts`（TMDB `episodes[].air_date`，只取已开播）→ 是否把 E1/E2 的开播日期判空导致「已播」偏小；
2. `libraryCount()` / `hasMissing()` 用的是订阅进度的 `library` 集号集合 → 是否 E1/E2 在库但被 TMDB 集号/季号映射错位（多季、特别篇、期号换算）；
3. 抽屉「追更记录」里 E1/E2 是否真有成功记录 → 区分「确实没入库」与「入库了但没算进去」。

**验收口径**：以 Emby 实际目录列举 + 订阅进度接口两边对账，E1/E2 在库时卡片不得显示缺失；补一条单测覆盖「库内有 E1/E2、TMDB 未给开播日」场景。
