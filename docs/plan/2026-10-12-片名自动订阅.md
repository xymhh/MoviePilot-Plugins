# 片名自动订阅（CloudSubscribe 1.6.26）

> 状态：已完成（代码 + 单测 + lint + CI），真机验收见 ../test/2026-10-12-片名自动订阅单测.md
> 关联：本方案取代 [2026-10-12-MP平台资源源接入.md](2026-10-12-MP平台资源源接入.md)（该方案已整条回退）

## 1. 用户要的链路

在 Telegram 等渠道的对话框里**直接发一个片名** → 直接建订阅 → 插件自己的订阅接管（搜索网盘 → 转存 → 入库）接着干，不要绕到「平台搜索结果」里。

上一版（1.6.25）把网盘候选伪装成站点搜索结果塞进 MoviePilot 的搜索列表，被用户判定方向错误：平台搜索是平台的语义，插件不该污染它。回退后改成本方案。

## 2. 实现位置

`plugins.v2/cloudsubscribe/core/hook/message.py` 里的 `MessageRoutingHook` —— 它已经包装了 `MessageChain._handle_message_core`（此前只处理「消息里的网盘链接直达转存」），现在在链接分支之后追加一条**片名分支**。

判定顺序：

1. 先试链接分支（`_message_payload`）：消息里有 115/夸克/磁力等链接 → 走原有直达转存；
2. 否则试片名分支（`_title_payload`）：命中才算接管；
3. 都不命中 → 调原始 `_handle_message_core`，平台流程（站点搜索/智能体）照旧。

## 3. 片名分支的触发与排除规则

必须同时满足：

- 开关 `_title_subscribe_enabled`（配置项「片名自动订阅」，默认 **开**）与插件总开关都开；
- 文本非空、不以 `/` 开头、不是 `CALLBACK:` 回调；
- 没有图片 / 文件 / 语音附件，`callback_data` 为空；
- 单行、长度 ≤ 40，不含 `/` `\`；
- 不含 `?` / `？`（问句交回平台，避免"仙逆有吗"这类被当成片名）；
- 不含链接特征（`http` `magnet:` `ed2k://` `thunder://` `www.`）；
- 至少含一个字母或汉字（纯数字、纯符号不接管）。

命中后**先返回 True（消息被消费，平台不再搜站点）**，真正的工作丢进后台线程，避免阻塞消息链。

## 4. 处理流程（后台线程）

```
片名 → MetaInfo 解析（季号等）→ _recognize_media_once（TMDB 识别，带缓存）
  ├─ 识别不出 / 非影视 → 直接返回，不消费消息（交回平台）
  └─ 命中：
      ├─ 按 TMDB 身份查已有订阅（get_subscribe_by_media）
      │   ├─ 已订阅 → queue_subscribe_search(state="R") + 回执「已在订阅中，已触发一次搜索」
      │   └─ 未订阅 → SubscribeChain().add(..., media_source/media_id, season, exist_ok=True, message=False)
      │                → queue_subscribe_search(state="N") + 回执「已创建订阅《xx》[第 N 季]，正在搜索网盘资源」
      └─ 建订失败 → 回执失败原因
```

- 回执走 `_post_command_message`（与链接直达转存同一路径，回到消息来的渠道）。
- `message=False` 是为了不让 MoviePilot 再发一条「订阅已添加」，回执只由插件发一次。
- `exist_ok=True` + 前置查重：既避免重复建订，也避免把平台的「已存在」错误当成失败。
- 建/查完工后**立刻** `queue_subscribe_search`，不等平台的定时订阅搜索，用户几秒内就能收到资源结果。

## 5. 验收标准

1. 单测覆盖：判定规则（接受/各种拒绝）、建订成功、已订阅、识别失败、建订失败、异常吞掉、命令与链接不被接管、两个开关都关时 hook 不安装。
2. lint 0 error。
3. 真机：TG 发一个片名 → 收到「已创建订阅《xx》」→ 订阅列表出现该订阅 → 日志出现该订阅的网盘搜索 → 有资源则自动转存入库。
4. 不回归：TG 发命令、发链接、发问句的行为与 1.6.24 一致。

## 6. 不做的事

- 不改平台搜索结果（1.6.25 那套 `search_torrents` 模块与下载接管已全部删除）；
- 不自动改用户的 `takeover_new_subscribes` 等订阅接管开关；
- 不接管 `/` 开头的命令与智能体（`/ai` 前缀）消息。

## 2026-10-12 v1.6.27：方案 A —— 平台先出候选、用户选定后接入（覆盖上面第 3~6 节）

> 状态：已完成 2026-10-12 → 见 `../summary/2026-10-12-平台资源源回退与片名自动订阅.md` 文末「1.6.27 方案 A」节

**为什么改**：上面这套「发片名即识别即建订阅」在**同名片名**（不同年份/翻拍/不同季）下会按识别置信度替用户选一部建订，用户没有确认机会 —— 用户判定风险不可接受，要求「先看平台候选、自己点选，再接入网盘订阅」。

**改成什么（方案 A）**

1. 片名消息只**登记**不消费：`MessageRoutingHook._try_handle` 的片名分支返回 `False`（消息交回平台，由平台给出候选列表），把片名登记进新文件 `core/pending_titles.py` 的 `PendingTitleStore`（TTL 900s、最多 64 条、命中即消费、线程安全），并开后台线程做一次 TMDB 识别补齐 `title / year / mtype / season / tmdbid`（识别失败则只保留片名键，不打扰用户）。
2. 接管点挪到已有的 SearchChain 搜索拦截：`SubscriptionSearchHook._create_platform_search_wrapper` 在「平台搜索被阻止」分支里调用 `_dispatch_pending_title_search`，按**原函数签名**解析被搜索的媒体身份（`titles`/`media_id`/`media_source`/`mtype`/`season`，兼容 `**kwargs` 与 `meta`/`mediainfo` 对象），再 `consume` 匹配。
3. 匹配规则（宁漏不误建）：**归一化后完全同名**（去空白/标点、统一小写）或 **TMDB ID 完全相同**；类型已知且不同（movie vs tv）直接跳过；不做包含匹配（避免「斗罗大陆」命中「斗罗大陆2」）。
4. 命中后复用 1.6.26 的下游：按**选定结果**（搜索自带的 mediainfo/meta，缺失时按 id 兜底识别）查重 → 建订阅（`message=False`、`exist_ok=True`）→ `queue_subscribe_search` → 回执「已按你在平台候选中选定的《xx》创建订阅」。
5. 只有媒体身份、没有片名的搜索（`search_by_id` 常见）走**异步兜底**：后台 `_recognize_media_once` 出标题后再比对，绝不阻塞搜索调用（sync/async/stream 三种包装器都是「触发即返回」，实际建订在后台线程）。
6. 状态全在插件内部：新模块不依赖 app 运行时；hook 卸载（`close`）时清空登记表。

**已知代价（1.6.27 时接受，1.6.28 已消除）**：平台站点搜索仍被我们阻止，所以用户点选后会额外看到平台那句「未搜索到资源」，与插件回执并存。1.6.28 把接管点挪到点选真正的落点（`InteractionChain._search_media_resources`）后，平台那次搜索不再执行，这句提示也随之消失。

## 2026-10-12 追加：1.6.28 点选入口修正（1.6.27 的真实漏点）

> 状态：已完成 2026-10-12 → ../summary/2026-10-12-平台资源源回退与片名自动订阅.md

1.6.27 交付后真机复现「发片名 → 点候选 → 既不建订阅、也没有任何插件回执」。排查结论两条：

1. **钩子挂错位置**：点选走的是 `app/chain/interaction.py` 的 `_search_media_resources → SearchChain().process(mediainfo=…)`，而 1.6.27 只挂了 `search_by_id/search_by_title` 等 6 个公开入口 → 我们的代码根本没被调用，平台自己搜出 0 条并回「未搜索到需要的资源！」。
2. **匹配过严**：即便挂上，1.6.27 只认「归一化后完全同名 / TMDB 身份相同」；用户输入「机智医生生活」、官方名「机智的医生生活」，登记时 TMDB 识别又失败（16:52:45「未匹配到TMDB媒体信息」）→ 差一个「的」永远不相等。

**1.6.28 改动**：

- 挂 `SearchChain.process / async_process / async_process_stream`，语义为 **pending**：只有真的消费到片名候选才拦截并返回空结果，其余调用（订阅搜索、扫描等）原样透传。
- 挂 `InteractionChain._search_media_resources`（点选真正的落点）：命中登记 → 建订阅 + 排队网盘搜索 + 回执，并 `return None` 跳过平台搜索 —— 顺带消掉 1.6.27 那句「未搜索到资源」的已知代价。
- 点选身份优先取 `request.keyword`（用户原始输入），其次取点选项的 TMDB 身份与官方片名。
- `consume()` 增加一级**模糊同名**兜底：相似度 ≥ 0.85、两侧片名 ≥3 字、候选类型相容；命中级别写入日志（`片名候选命中（fuzzy 0.923）`）。
- 明确不做的事：不加「唯一记录兜底」——试做后既有单测（`test_unrelated_search_keeps_record`）立刻证明它会误消费无关搜索的记录，与「宁漏不误建」冲突，直接放弃。

**验收**：见 `../test/2026-10-12-片名自动订阅单测.md` 文末「1.6.28」节（11 个新用例 + 全量 + lint）。
