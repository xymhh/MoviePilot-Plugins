# 通知富信息 + 模板排版优化（1.7.75）

> 状态：已完成 2026-10-26 → ../summary/2026-10-26-通知富信息与排版.md

## 背景

1.7.72 把六类通知正文做成可编辑 Jinja2 模板，但模板拿到的数据本身就缺东西：
转存通知每行只有「剧名 S01 E09, E10」，没有**类型**、**大小**、**来源网盘**。
用户反馈「点进去看不出这是什么、多大、从哪来的」，只在 `message` 表里能看出转存次数，
正文信息量不足。同时旧默认模板的 `▫️` 前缀 + 空行位置偏散，需要更整齐的排版。

## 需求（2026-10-26 用户确认：「需要，但是图标换好看点，排版也优化一下」）

1. 通知每行补：媒体类型、文件大小、网盘来源（跨盘写「源 → 目标」）。
2. 标题行补合计大小。
3. 六类默认模板换更好看的图标与更紧凑的排版。
4. 老用户升级后要看到新排版，但不能覆盖用户自己改过的模板。

## 设计

### 数据层

`handlers/sync/history.py`

- `_detail_source_text(history_item)`：目标盘名取 `target_drive_name` → `cloud_drive_name`；
  有 `source_drive_name` 且与目标不同则输出 `源 → 目标`，否则只输出目标盘（如 `115网盘`）。
- `_detail_size(history_item, file_info=None)`：优先 `file_size`，其次 `size`（含 `file.size`）。
- `_append_tv_transfer_detail(..., size_bytes=0, source_text="")`：同季同类型合并时累加
  `size`，来源取首个非空。

调用点：

| 文件 | 改动 |
| --- | --- |
| `handlers/sync/movie.py` | 电影详情补 `size` / `source` |
| `handlers/sync/television.py` | 按 `notification_kind` 累加 `batch_detail_size`，记录 `batch_detail_source` |
| `handlers/sync/upgrade.py` | 洗版分支同样累加（`file_size` 来自 `candidate_size`） |

### 展示层

`handlers/sync/notify.py`

- `_media_type_icon`：电影 🎬 / 剧集 📺 / 动漫 🍿 / 未知 📦
- `_media_type_name`：`电视剧` → `剧集`、`动画` → `动漫`
- 行格式：`{kind 前缀}{图标} {标题} · {类型} · {大小} · {来源}`
  - kind 前缀：跨盘 `🔀 `、洗版 `⬆️ `、普通转存无前缀
  - 缺字段时依次省略，不会出现空的 `· ·`
- 标题行：`📦 本次转存 N 个文件 · 合计 X GB`（无大小时省略合计）
- 给模板多传一个 `total_size` 变量，供自定义模板使用

### 模板与迁移

`utils/notify_template.py`

- `DEFAULT_TEMPLATES` 六类全部重写（图标 + 紧凑行距）。
- 新增 `LEGACY_DEFAULT_TEMPLATES`（1.7.72–1.7.74 原值）与 `upgrade_legacy_templates(config)`：
  只有当前值**规范化后完全等于旧默认值**才替换，用户改过的不动。
- `__init__._ensure_notify_template_defaults` 在补全缺失键的同时执行上述升级，并分别打日志。

## 验收
