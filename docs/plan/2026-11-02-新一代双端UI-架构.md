> 日期：2026-11-02
> 目标：确立新一代双端自适应 Dashboard 的拓扑结构、响应式断点规范、状态层解耦协议与渐进式重塑路径。

## 一、系统角色与职责划分

```
┌────────────────────────────────────────────────────────┐
│               MoviePilot 宿主微前端容器                │
└──────────────────────────┬─────────────────────────────┘
                           │ (注入: api, pluginId, vuetify, theme)
┌──────────────────────────▼─────────────────────────────┐
│                 AppPage.vue (主控外壳)                 │
│  - 响应式视口监听 (useViewport)                        │

│  - 四大主看板导航 (TabNavigation: 底部栏/顶栏自适应)   │

       │              │              │              │
┌──────▼─────┐ ┌──────▼─────┐ ┌──────▼─────┐ ┌──────▼─────┐
│  追更看板  │ │  调度中心  │ │  转存台账  │ │  频道雷达  │

       └──────────────┴──────┬───────┴──────────────┘
                             │
       ┌─────────────────────▼─────────────────────┐
       │      Composables 状态与业务逻辑层         │
       │  - useSubscribes.js (追更与缺集计算)      │

       └─────────────────────┬─────────────────────┘
                             │ (零业务逻辑纯 API)
```

1. **主控外壳（`AppPage.vue`）**：负责全局视口感知、主题适配与看板调度，不再堆砌任何具体业务渲染。
2. **四大独立看板（展示组件）**：每个看板作为一个独立的 `.vue` 文件，纯靠 `props` 接收数据，`emit` 抛出动作，代码均控制在 250 行以内。
3. **状态层（Composables）**：所有接口请求、防抖节流、本地负缓存、聚合计算从组件中完全抽离，放入 `src/composables/`。

## 二、双端响应式设计系统（Mobile-First Token）

### 1. 视口断点协议
- **移动端（Phone: `< 640px`）**：
  - 导航模式：底部固定操作导航栏（Bottom Navigation）或顶部横向平滑滑动 Tab；
  - 布局形态：严格单列流（Single Column），内边距统一 `8px`~`12px`；
  - 交互热区：所有可点击控件最小高度 `44px`，防误触间隙 `8px`；
  - 数据呈现：次要字段自动隐入展开详情，严禁任何强行不换行撑爆。
- **平板 / 折叠屏（Tablet: `640px ~ 1024px`）**：
  - 布局形态：双列网格，海报卡片 3~4 列并排，横向数据列表单行自适应。
- **桌面宽屏（Desktop: `> 1024px`）**：
  - 布局形态：高密度看板，海报 5~6 列并排，充分发挥宽屏横向视野；
  - 悬浮增强：支持右键或 Hover 即时浮层，减少点击层级。

### 2. 视觉规范（Shadcn/Tabler 极简风）
- **色彩与边框**：中性灰度为主，全局边框统一为 `1px solid rgba(var(--v-border-color), 0.12)`；
- **状态表达**：
  - 成功：纯绿点 / 徽标（`#10b981`）；
  - 失败 / 阻塞：中性红徽标（`#ef4444`），失败为 0 时统一转为中性弱色（不抢占视线）；
  - 进行中：电光蓝徽标（`#3b82f6`）。
- **字体与层级**：单卡片内严格遵守 3 层信息衰减（主标题 14px 加粗 → 辅助元数据 12px 弱色 → 次要标签 10px 微标）。

## 三、四大看板接口与业务边界

### 1. 【追更看板】（MediaHub 重塑）
- **数据源**：`GET /page_data`（读 `subscribes_progress` 追更聚合）；
- **交互规范**：
  - 手机端：2 列海报卡片，点击底部滑出轻量详情抽屉（查看分集矩阵与手动补集）；
  - PC 端：4~6 列海报网格，悬浮显示未入库集数。

### 2. 【实时调度】（Runtime + TaskCenter 重塑）
- **数据源**：`GET /runtime` + `GET /tasks`；
- **交互规范**：
  - 上半部：轻量实时横幅（当前文件、主进度、当前速度 `45MB/s`、停止按钮）；
  - 下半部：常驻作业表（默认展示 `待处理/失败` 任务），支持一键批量重试。

### 3. 【转存台账】（HistoryTable 彻底重塑）
- **数据源**：`GET /page_data`（读 `history_groups`） + `GET /ledger/list`；
- **交互规范**：
  - 以作品为卡片单元：成功集数以绿色微标平铺，跳过集数以黄色徽标显示具体原因；
  - 点击右上角可唤出全网候选跳过账本弹窗。

### 4. 【频道雷达】（TgMonitor 重塑）
- **数据源**：`GET /tg/status` + `GET /tg/items`；
- **交互规范**：
  - 纯粹的单行 Feed 流，手机端自适应折叠为两层，支持一键转存、忽略与原消息直达。

## 四、安全与工程约束

1. **零功能回退**：原有的洗版、一键转存、手动添加、Emby 播放、目录创建等全部功能无损迁移；
2. **渐进式重写**：按看板逐个单文件实现并打包验证，新看板随时可无缝回滚；
3. **构建验证**：每个里程碑必须执行 `npm run build`、`check_frontend_entry.py` 与全量测试。
