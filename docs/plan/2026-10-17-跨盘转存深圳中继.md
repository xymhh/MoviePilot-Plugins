# 跨盘转存「深圳中继」方案（2026-10-17）

> 状态：讨论中（开关已落地，传输腿未实现）。用户已确认接受双地区同账号的使用风险。

## 背景（实测数据）

| 事实 | 数值 | 来源 |
| --- | --- | --- |
| 115 上传落点 | `oss-cn-shenzhen.aliyuncs.com` | `uplb.115.com/3.0/getuploadinfo.php` |
| 深圳机（阿里云 ECS，Debian 6.1，200M）→ 内网 OSS | `oss-cn-shenzhen-internal` 解析到 100.118.78.x | 用户 2026-10-17 在机上实测 |
| 深圳机上传实测 | **22 MB/s**（≈176 Mbps，200M 线路的 88%） | 用户 2026-10-16 实测 |
| 德国 MP → 115 上传 | 11–67 KB/s（社区口径：115 对海外 IP 限速约 2 MB/s） | 插件 1.6.x 排查记录 |
| 深圳机剩余磁盘 | 35 GB | 用户 2026-10-17 |
| 115 海外下载 | 不限速，约 50–60 MB/s | 社区经验 |

结论：**115 账号侧没有限速，瓶颈 100% 在跨境这一跳。** 22 MB/s 只在「深圳机 → 115 内网」成立，所以两条腿（下载源、上传 115）都必须发生在国内，才有意义。

## 决定性约束

`core/transfer.py` 的跨盘任务只带 `source_provider` + 源文件 id + sha1/size，**不带分享链接**；下载由本机的 drive 层完成。因此：

- 若中继只做「上传腿」（德国把文件推给深圳再上传）→ 德国→深圳仍是跨境，速率不会比德国→115 好，白做。
- 要让中继做「下载腿」，中继必须自带源盘客户端（115/夸克/阿里/百度），即复刻 `drive/` 层。

## 两条路

### S：深圳机跑第二个 MoviePilot（只做转存）— 推荐

- 复用现成插件与 drive 层：搜索 → 转存 → 秒传/上传 → 整理，全部在国内完成；上传走 115 内网（22 MB/s，上传腿提速约 300–2000 倍）。
- 代码量：0（只需在深圳机部署 MP + 本插件，配置同一 115 账号）。
- 代价：多一个 MP 容器（约 1–2 GB 内存 + 镜像）；订阅要在一处集中管理（建议深圳实例只做跨盘转存、关闭订阅创建与 Emby 相关动作；Emby 在德国，仅走 API，流量极小）；同账号双地区使用（已获用户接受，控制手段见下）。
- 部署清单：docker compose（MP + 插件）、115 cookie、目标目录映射、`cross_transfer_download_path` 指向 35 GB 盘、并发/限速。

### R：自建中继服务（HTTP 作业队列）

- 接口草案：`POST /jobs`（source/ target/ verify/）→ `job_id`；`GET /jobs/{id}` → 状态/进度；`DELETE /jobs/{id}`；`X-Token` 鉴权。
- 需要移植 drive 层（115/夸克/阿里/百度）到中继，并处理账号 cookie 分发、秒传探测、分片并发、临时盘清理。
- 代码量：1–2 天（含 Dockerfile、systemd/compose、文档、测试）。
- 收益与 S 相同，但多维护一套与插件平行的传输实现，长期有双份 bug 风险。

### N：维持现状

`cross_transfer_rapid_miss_action = abort`，秒传未命中即中止，零上传流量；代价是大量资源拿不到。

## 插件 UI 开关（已落地，默认全关）

| key | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `cross_transfer_relay_enabled` | switch | false | 总开关；开了但地址为空时强制视为关闭 |
| `cross_transfer_relay_url` | text | 空 | 中继地址（末尾斜杠自动去掉） |
| `cross_transfer_relay_token` | password | 空 | `X-Token` 鉴权，不进日志/历史 |
| `cross_transfer_relay_max_file_gb` | number | 25 | 超过即走本机原链路（35 GB 盘留余量）；0=不限 |
| `cross_transfer_relay_timeout_minutes` | number | 180 | 超时按失败处理 |
| `cross_transfer_relay_fallback_local` | switch | true | 中继失败是否回落本机慢链路 |

证据：`python scripts/lint.py --all` 611 文件 0 error；全量 497 例单测不变（2 例既有 p115client 环境失败）。

## 风险控制（双地区同账号）

- 同一时间只让一个出口做大批量传输（错峰）；并发压到 4–8，不打满 22 MB/s。
- 固定出口 IP（深圳机 EIP），固定 UA；不共用 cookie 到第三处。
- 定期看 115「登录终端/异常登录」；出现验证提示立即停一侧。
- 官方口径：风控主因是「未授权第三方工具」，封号条款针对「多人共用账号」——双 IP 并发最像共用，因此错峰是关键。
