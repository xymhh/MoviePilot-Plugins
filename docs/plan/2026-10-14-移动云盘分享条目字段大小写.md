# 1.6.41 任务书：移动云盘资源点预览「当前目录为空或未解析到文件」

> 状态：已完成 2026-10-14 → [复盘](../summary/2026-10-14-移动云盘分享条目字段大小写.md)
> 验收证据：[单测与线上复现](../test/2026-10-14-移动云盘分享条目字段大小写回归单测.md)
> 前置：1.6.40（域名识别修好，预览不再报「资源链接格式或类型无效」，但列表是空的）→ [1.6.40 复盘](../summary/2026-10-14-移动云盘caiyun链接识别.md)

## 背景（用户可见现象）

用户升级到 1.6.40 后重试同一批移动云盘资源（《美人余》），**预览弹窗能打开了**
（不再是 1.6.39 的「资源链接格式或类型无效」），但弹窗里显示：

```
资源内容预览 · 美人余 (2026) 2160p.WEB-DL.A…
[移动云盘] [移动云盘] [共 0 个项目]
当前目录为空或未解析到文件
```

用户反馈「还是」——即同一批资源仍然用不了，只是失败位置从「类型校验」挪到了「文件列表为空」。

## 线上复现（1.6.39 部署中，1.6.40 未更新）

```
POST /api/v1/plugin/CloudSubscribe/resource/search_resources
{"source":"pansou","title":"美人余","year":"2026","media_type":"tv","force_refresh":true}
→ 17 条候选：115 ×14，yun139 ×3，三条移动云盘链接形如
  https://yun.139.com/shareweb/#/w/i/2ygbc0FV4Nshu

POST /api/v1/plugin/CloudSubscribe/search/preview
{"resource_type":"yun139","url":"https://yun.139.com/shareweb/#/w/i/2ygbc0FV4Nshu","parent_id":""}
→ {"success":true,"message":"读取到 0 个项目","data":{"items":[],"count":0,...}}
```

`success: true` + `count: 0` 正是前端「当前目录为空或未解析到文件」分支
（`PreviewDialog` 只在 `items.length === 0 && !error` 时显示它）。

## 根因（字段大小写：`caID` / `coID`）

绕过插件、直连分享接口（复刻 `drive/yun139/share.py` 的 AES 加解密与请求头）实测：

```
POST https://share-kd-njs.yun.139.com/yun-share/richlifeApp/devapp/IOutLink/getOutLinkInfoV6
{"getOutLinkInfoReq":{"account":"","linkID":"2ygbc0FV4Nshu","passwd":"","pCaID":"root"}}
→ resultCode=0，data.lkName="The Lament of Autumn (2026)"
  data.caLst = [ { "caID": "FtARUxvxHKiIX_-YfPpxAiq7ZBQEPxw0i",
                   "caName": "The Lament of Autumn (2026)", ... } ]
  data.coLst = null
子目录（pCaID=<上面那个 caID>）→ coLst 11 个文件，形如
  { "coID": "FggsW7HtF6a0OP5enZEZA35f7EBJfRfyt", "coName": "第2集.iso",
    "coSize": 801308672, "coSuffix": "iso", ... }
```

接口字段是 **`caID` / `coID`（大写 D）**，而 `_share_node` 读的是 **`caId` / `coId`（小写 d）**：

```python
node_id = str((entry.get("caId") if is_directory else entry.get("coId")) or "").strip()
if not node_id or not name:
    return None          # ← 每个条目都在这里被丢掉
```

`entry.get("caId")` 恒为 `None` → `node_id` 为空串 → **每个条目都返回 None**：

| 出口 | 结果 |
| --- | --- |
| `list_share_directory`（预览调用） | 空列表 → 前端「当前目录为空或未解析到文件」 |
| `list_share_files`（转存调用） | 空列表 → 日志「移动云盘分享中没有可转存的文件」 |
| `check_share_status`（分享校验） | `file_count=0` |

即：1.6.40 把「类型校验」这一层修通了，下一层立刻撞上这个更早存在的字段名错位——
这条 139 链路**从来没有真正读出过目录**。

## 改法（最小改动）

1. `drive/yun139/share.py` 新增 `_entry_value(entry, *keys)`：按顺序取第一个非空字段，
   同时兼容线上的 `caID`/`coID` 与历史小写 `caId`/`coId`；
2. `_share_node` 改用它取节点 ID 与名称（文件大小 `coSize`、时间 `udTime` 本就同名，不动）；
3. `_list_node` 顺手把信封上的 `data.lkName` 记到 `self._share_title`，
   供 `check_share_status` 显示分享名（条目里没有该字段，原来恒为空串）。

**不动**：域名识别、请求体结构、转存链路（下载→上传）、资源类型口径。

## 验收标准

- 线上预览接口对上述三条 139 链接返回 ≥1 个项目（根目录 1 个子目录，可下钻到 11 个文件）；
- 新增回归测试以**线上真实键名**为 fixtures，在旧代码上必须失败（`git stash` 反证）；
- 全量单测除「本机缺 p115client」2 例外全绿；`scripts/lint.py --all` 0 error；
- 版本 1.6.40 → 1.6.41，CI 三绿 + Release 资产读回。

## 禁止事项

- 不改分享接口的加密/签名实现；
- 不把 `caId` 的历史兼容分支删掉（老接口仍可能返回小写）；
- 不在没有真机证据的情况下声称转存链路可用（见下方遗留风险）。

## 遗留风险（本版未验证）

转存走的是「下载到本地再上传」，下载地址来自 `dlFromOutLinkV3`。
从本容器直连该接口返回 `resultCode=200000401「IP鉴权失败、用户账号鉴权失败」`
——该接口绑定登录账号的会话/IP，**只能从 MoviePilot 所在机器发起**，
因此本版无法在站外验证下载地址解析；若用户重试转存失败，按 `docs/test/` 记录的方式取日志再定位。
