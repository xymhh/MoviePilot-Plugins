# 1.6.50：保留「已符合当前重命名格式」的现有版本（判重门槛）

> 状态：已完成 2026-10-16 → ../summary/2026-10-16-保留符合重命名格式的版本.md

## 背景

1.6.48 把判重键从「目标文件名」改成「剧集身份 + 季 + 集」，解决了「模板一改 / 手动入库 → 同一集重复转存」。

用户随后提出（2026-10-16）：

> 认第一集这种方式是不是太绝对了，应该按现有重命名规则来保留吧

澄清后用户选择 **B 方案**：*「已经按当前重命名模板命名的规范版，不该被评分更高的候选替换掉」*。

即：**现有版本文件名已符合「现有重命名规则」时 → 保留，不参与替换。**

## 需求冻结（用户口径）

1. 判据 = 现有文件名是否已由**当前** MP「重命名格式」渲染得出（= 符合现有重命名规则）；
2. 命中即 **skip**：不转存、不删旧、不写新，历史里写明原因；
3. 不改变其它任何判定（评分、`upgrade_mode`、coexist、开关）；
4. 可一键回退（配置项关闭后行为与 1.6.49 完全一致）。

## 设计

判据实现为**渲染幂等**：

```
render(现有文件名) == 现有文件名  →  已符合当前重命名规则
```

渲染走**与转存落位完全相同的那条路**（`_platform_rename_path` → MP `FileManagerModule.recommend_name`），
用文件自身的元数据回填模板；因此插件自己按模板写下的文件、以及用户手工整理成模板形态的文件都能命中，
而老命名（`… .第1集.mkv`）、老模板遗留、字段不全的名字渲染后会得到**不同的**名字 → 不命中，仍按评分走。

落点（覆盖所有「是否替换现有版本」的判定）：

| 位置 | 覆盖场景 |
| --- | --- |
| `handlers/sync/rule_scoring.py` `_version_matches_rename_template` / `_template_conformant_version` | 判据本体 |
| `handlers/sync/rule_scoring.py` `_should_upgrade_candidate(..., old_file_name=...)` | 单版本场景的统一入口 |
| `handlers/sync/episode_dedup.py` `_episode_dedup_decision` | 剧集按季集判重（订阅追更主路径） |
| `handlers/sync/episode_dedup.py` `_movie_dedup_decision` | 电影判重 |
| `handlers/sync/movie.py`（预览 / Magnet / 正式三处） | 电影网盘洗版候选 |
| `handlers/sync/postprocess.py` | 下载后洗版（Magnet / 离线） |
| `handlers/sync/upgrade.py`（预览 + 正式两处） | 历史/手动洗版 |

失败姿态：渲染抛异常或拿不到结果 → **回退原评分逻辑**（不阻断、不放行），日志 debug 记录。

## 配置

`prefer_template_named_version`（布尔，默认 **True**）
- 前端：配置页「洗版 → 洗版门槛」新增开关「保留符合重命名格式的版本」；
- 关闭后 = 1.6.49 行为（完全按评分 / 体积决定替换）。

## 已知副作用（用户已知悉并选择）

- 插件自己按当前模板写下的文件**不再被更高评分的候选洗版**（因为「已符合现有重命名规则」）。
- 想让洗版对它们继续生效 → 关掉该开关。
- 同集的**非**规范名旧版本仍按原逻辑处理（评分为准）。

## 禁止事项

- 不得改变判重键（仍是 剧集身份 + 季 + 集），不得退回「按目标文件名判重」；
- 不得在渲染失败时删除 / 替换任何文件（必须回退评分逻辑）；
- 不得把该门槛做成「默认关」。
