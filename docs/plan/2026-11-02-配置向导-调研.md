# 配置向导化 — 调研（2026-11-02）

> 阶段：第二阶段第 2 项（用户拍板顺序 2→1→3→4→5，Doctor 已完成）
> 状态：调研完成，架构见 `2026-11-02-配置向导-架构.md`

## 1. 问题

`Config.vue` 3137 行、12 个分组、150+ 个字段全平铺。新用户装完面对的第一屏是
「运行设置 / 跨盘转存 / 整理 / 订阅 / 签到 / TG / STRM / Emby / 网盘 / 搜索 / 升级 / 通知」，
真正必须先配的只有三件事：**选网盘并登录 → 指定落地目录 → 开插件**。
其余 90% 字段有默认值，配错一个还可能整条链路静默跳过。

## 2. 现成轮子盘点

| 候选 | 能力 | 差距 |
| --- | --- | --- |
| Vuetify `v-stepper` + `v-window` | 步骤条、步骤窗格、校验插槽 | 只有骨架，业务内容要自己组织 |
| 现有 `components/config/ConfigSection.vue`（1503 行） | 已支持 switch/number/text/select/二维码/目录选择/测试按钮等全部字段类型 | 需要 section 结构，不会自己挑字段 |
| 现有 `config/fields/*.js`（12 个模块） | 字段定义数据化、动态网盘/搜索 schema 来自后端 | 面向「全量平铺」，没有「最小必填集」概念 |
| 现有 `config/save` 全量保存 | 一次 POST 整个 config，返回净化后配置 | 无分步保存（不必须，最后一次提交即可） |
| Doctor 体检（v1.9.18） | 8 项红绿灯 + 修复指引 | 无「配完自动复查」入口 |
| 第三方插件向导式配置 | 通用步骤条 | 不懂本插件字段依赖（如 cloud_drive 决定凭据 schema） |

**结论：选 ① 拼装** —— 用 `v-stepper` 做壳，字段渲染完全复用 `ConfigSection`，
字段来源从既有 `config/fields` 里按 key 挑（不复制定义，避免两处漂移），
收尾直接调 `/doctor` 复查。自研部分只有：三步的字段白名单与「首次运行」判定。

## 3. 不做什么

- 不重写 `Config.vue` 的既有布局，专家模式原样保留（老用户零感知）。
- 不做分步保存（中途不落盘，最后统一保存，行为与现在一致）。
- 不做「全部字段向导化」，只做最小可用三件事。
