## 1. 背景（为什么改）

1.6.43 接入 Gopeed 后，夸克→115 跨盘中继下载实测 **1.6 MB/s**，等于 Gopeed 默认 16 连接 × 夸克单连接约 100KB/s。
用户在 Gopeed 全局把 http `connections` 改成 **256** 后，同一任务实测 **19.99 MB/s**（313 秒下载 6.2 GB / 共 12.3 GB）。
用户结论（已确认）：① 插件要能自己控制连接数，不依赖 Gopeed 全局设置；② 手动停止跨盘任务时，盘上不应残留中继文件。

已核实的外部事实（Gopeed v1.9.3 源码）：

- 默认连接数 16：`internal/protocol/http/fetcher_manager.go:69`（`DefaultConfig`）
- 任务级覆盖：`internal/protocol/http/fetcher.go:327-330` —— `opts.extra.connections > 0` 才覆盖全局
- 强制删除（连文件一起删）：`DELETE /api/v1/tasks/{id}?force=true`，见 `pkg/rest/api.go:155-165` 与
  `pkg/download/downloader.go:767-790`（`force && task.Meta.Res != nil` → `os.RemoveAll` / `SafeRemove`）

已核实的插件现状（本次要改的坑）：

- 停止只 pause，不删任务也不删文件：`core/gopeed.py:299 _stop_task()`（调用方一律传 `preserve_partial=True`）
- 插件侧缓存只在「未下完且无 `.parts.json`」时删：`core/transfer.py:1401-1408`（`except InterruptedError`）

## 2. 需求（用户已确认，三项均取推荐项）

- **A. 连接数可控**：新增配置 `gopeed_connections`（整数）。`0`（默认）= 不传 `extra`，沿用 Gopeed 全局设置；`>0` = 建任务时显式传 `opts.extra.connections`。
- **B. 手动停止即清空中继**：
  - B1 Gopeed 侧：停止时 `pause_task`（best-effort）后 `delete_task(force=True)` —— 连 Gopeed 的部分文件一起删。
  - B2 插件侧：取消时**无条件**删除本任务中继文件 `cloud-transfer-<hash>.bin` / `.bin.meta.json` / `.bin.parts.json`（含 `.tmp` 变体，直接复用 `_delete_cache_path`），**包括已下载完成的完整缓存**。
  - B3 范围仅限本任务的中继文件（可含 `cloud-transfer-*` 孤儿文件）；**禁止**清空整个 `cross_transfer_download_path` 目录（该目录里可能有用户其它文件，例如 `Shadow Punisher (2026)`）。

## 3. 接口契约（按此实现，勿自行发挥）

1. `core/config.py:185-188` 区块加默认值：`"gopeed_connections": 0,`（放在 `gopeed_path_prefix` 之后）
2. `__init__.py:184-188` 区块加表单字段：`_gopeed_connections: int = 0`，并加一行注释：`# 0=沿用 Gopeed 全局连接数；夸克建议 256`
3. `drive/quark/definition.py:160-168`：`create_quark_provider(QuarkDrive(...))` 里加 `gopeed_connections=...`。
   注意 `config_value()` 返回 `str`，取值要容错：空/非数字 → `0`（建议写一个小 helper 或就地 try/except）。
4. `drive/quark/provider.py:25-28` 加字段 `gopeed_connections: int = 0`；`drive/quark/provider.py:48-51` 与
   `drive/quark/files.py:70-73` 同样加字段并透传（files.py 的 `QuarkFileService` 由 provider 构造）。
5. `core/gopeed.py`：
   - `GopeedClient.create_task(url, headers, path, name, connections: int = 0)`：`connections > 0` 时
     `body["opts"]["extra"] = {"connections": int(connections)}`；`<= 0` 时**保持现有 body 形状不变**（不得出现 `extra` 键）
   - `GopeedClient.delete_task(task_id: str, force: bool = False)`：`force=True` → `DELETE /api/v1/tasks/{id}?force=true`
   - `GopeedDownloadService.__init__(..., connections: int = 0)` → 存 `self._connections`，`_download()` 里透传给 `create_task`
   - `_stop_task(task_id, preserve_partial)`：先 `pause_task`（异常只记 `logger.debug`），再**无条件** `delete_task(task_id, force=True)`（异常只记 `logger.debug`，不得改变「已停止」的判定）
   - `_discard_task(task_id, preserve_partial)`（**失败重试**路径）**语义不变**：`preserve_partial=True` 时什么都不做
   - `_wait_task` 里「任务完成 → `delete_task(task_id)`」保持不带 force（文件要留给后续上传）
6. `core/transfer.py`：
   - `except InterruptedError:` 分支（约 1401 行）：改成取消时**无条件** `self._delete_cache_path(Path(temporary_path))`（删掉 `not cache_complete` 与 `.parts.json` 两个条件）；`temporary_path` 为空时跳过
   - 同分支的 `_update(..., message=...)` 文案改为 `"任务已取消并已清理中继缓存"`
   - `except Exception`（失败）分支**保持原逻辑不变**（失败时仍按原条件保留可续传的缓存）

7. `__init__.py:855-860`（`_apply_sync_config` 的 gopeed 段）：**必须有接线**，否则配置页填 256 也永远是 0
   （1.6.36 的教训：配置有字段 ≠ 有接线）。写法带容错：

   ```python
   try:
       gopeed_connections = int(config.get("gopeed_connections", 0) or 0)
   except (TypeError, ValueError):
       gopeed_connections = 0
   # 0 = 沿用 Gopeed 全局连接数；>0 = 建任务时显式传给 Gopeed（夸克建议 256）
   self._gopeed_connections = max(0, gopeed_connections)
   ```

8. `frontend/cloudsubscribe/src/config/fields/transfer.js`：在 `gopeed_url`/`gopeed_token`/`gopeed_path_prefix` 之后加一个
   `number` 字段 `gopeed_connections`（label「Gopeed 连接数」，默认 0，`show` 条件与 `gopeed_url` 相同 = 跨盘开启且
   `config.cross_transfer_downloader === "gopeed"`，hint「0=沿用 Gopeed 全局连接数；夸克建议 256」）。
   `dist/` 不入库、由 CI 构建，所以只改源码即可。
