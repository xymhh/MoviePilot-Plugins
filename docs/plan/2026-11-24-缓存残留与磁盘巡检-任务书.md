# 缓存残留清理与磁盘水位巡检（1.32.0）任务书

> 状态：已完成 2026-11-24（版本 1.32.0）→ [验收](../test/2026-11-24-缓存残留与磁盘巡检-验收.md)｜[总结](../summary/2026-11-24-缓存残留与磁盘巡检.md)
> 触发事件：2026-11-24 德国 VPS 磁盘 91%（可用 11.1GB），`/opt/1panel/apps/moviepilot/downloads`
> 堆了 **38.16GB / 19 个文件**，插件侧没有任何机制清理它们。

## 一、事实（已核实）

1. 1.12.1 起跨盘下载**即用目标名落盘**（`… {tmdb-<id>} - SxxEyy - 第N集.mp4`），
   `cloud-transfer-<hash>.bin` 命名废弃。
2. `core/residue.py:42` 的 `RESIDUE_PATTERN` **只匹配 `cloud-transfer-<32位hash>` 前缀**；
   `core/residue.py:221` 明确写着「目标名落盘的文件、无伴随文件的普通文件一律不碰」。
   → 命名变更后，残留清理把整个新命名漏掉了。
3. 1.10.0 删掉了「保留期 / 清理间隔 / 磁盘压力」三项配置（`cross_transfer_residue_retention_hours`、
   `_interval_hours`、`_disk_free_pct` 在代码里已不存在，线上配置里仍是死键），
   `core/services/residue.py:67` 传的是 `min_age_seconds=60` + `disk_free_ratio=0`。
   → 连 1.8.8 那套兜底也不覆盖真名文件。
4. 失败形态：115 上传连续失败触发熔断（「连续失败 5 次后冷却」），MP 整理报
   「上传 u115cs 失败」→ 文件留在缓存目录；漏斗行 `_fail_row` 5 次后转 `held`
   （`handlers/sync/funnel.py:1230`），**不记录本地残留**，界面看不到。
5. 「整理队列 → 删除孤儿文件」（`handlers/sync/funnel.py:2164`）删的是**云盘**孤儿
   + 本地 `.strm`（按行 `file_id`），**不删本地 `/downloads` 文件**，且只在
   「提交前复查发现重复」时写 `orphan_location=`。→ 上传失败这条路它不管。
6. 插件**全程没有磁盘监控**：全仓无 `disk_free` 告警路径，只有
   `handlers/sync/transfer_ops.py:298` 把 `No space left on device` 翻成中文。
   → 盘满会连带 MP 的数据库 / Emby / STRM 全线故障，属于「撞墙才发现」。

## 二、范围（本版只做 P0 + P1）

### P0 真名媒体文件残留清理

- `core/residue.py::scan_residue` 新增参数 `real_name_min_age_seconds`（0 = 关闭）。
  命中条件**全部满足**才删：
  1. 扩展名属视频集合（`.mp4/.mkv/.ts/.m2ts/.mov/.avi/.flv/.webm/.wmv/.rmvb/.mpg/.mpeg`）；
  2. 不在 `active_names`（在途任务名）里；
  3. 没有同名 `.aria2` 伴随文件；
  4. `mtime` 早于门槛（默认 24 小时）。
- 新增结果字段 `real_name_deleted_files` / `real_name_freed_bytes` /
  `real_name_skipped_recent`，与旧 `cloud-transfer-*` 计数分开，日志可分辨。
- `core/services/residue.py`：
  - 从 `self._cross_transfer_real_name_retention_hours` 取门槛（默认 24h，0 关）；
  - 新增漏斗保护名单：`funnel_queue` 里 **queued / processing / failed** 行的
    `staging_name` / `file_name` 一律不删；**held 不保护**（held = 不再自动重试，
    本地副本再留 24h 就是纯占盘；删除时逐条 INFO 记名，便于追溯）；
  - 受现有开关 `cross_transfer_residue_cleanup` 控制。
- `core/config.py`：新增 `cross_transfer_real_name_retention_hours`，默认 **24**，
  合法区间 0~168（0 = 关），非法值回落默认；不新增废弃键。
- 前端 `frontend/cloudsubscribex/src/config/fields/transfer.js`：跨盘分组加一个
  `number` 字段（1~168，0 关闭），并把「立即清理残留」的提示文案改成
  「cloud-transfer-* 临时文件 + 超过保留期的真名媒体残留」。

### P1 缓存目录与磁盘水位巡检

- 新文件 `core/services/cache_watch.py`：`CacheWatchService.check()`。
  每轮量三样：缓存目录顶层文件总字节、所在分区剩余比例、剩余绝对值。
- 阈值（模块常量，暂不做 UI）：缓存目录 > **20GB** 或剩余 < **15%** → 发一条
  `NotificationType.Plugin` 通知（带数字、去哪个页面处理、常见原因「115 上传熔断」）；
  恢复后发一条恢复通知；同一状态 **12 小时**内不重复通知（状态落
  `<插件数据目录>/cache_watch_state.json`，读写失败静默降级为每轮都发）。
- 注册：`core/api/registration.py::_maintenance_services` 增加
  `CloudSubscribe_CacheWatch`（`IntervalTrigger(hours=6)`），入口走
  `_run_scheduled_task(task="cache_watch")`，异常交给 MP 记 ERROR。

## 三、明确不做

- 不改 `orphan_location` 语义（它指云盘孤儿，塞本地路径会让「删除孤儿文件」去删不存在的云文件）。
- 不做「上传失败即删本地文件」——重试窗口内复用有价值，24h 门槛已经覆盖。
- 不做自动清理 held 行的云盘侧、不动洗版/去重逻辑。
- 不新增 UI 页面（新配置只有一个字段，加在现有跨盘分组里）。

## 四、验收标准

1. 单测 `tests/test_cache_sweep_1_32_0.py` 全绿，且用 `git stash` 在旧代码上反证必失败：
   - 真名文件超龄 + 无保护 → 删且计数进 `real_name_*`；
   - 真名文件未超龄 / 在 `active_names` / 有 `.aria2` / 非视频扩展名 → 不删；
   - `real_name_min_age_seconds=0` → 整条路径关闭（回到旧行为）；
   - 漏斗 queued/failed 行指向的真名文件 → 不删；held 行 → 可删；
   - 巡检：超阈值报警一次、冷却期内不重发、恢复后发恢复通知。
2. 全量 `pytest` 无新增失败（记录基线与预存在失败用例名）。
3. `scripts/lint.py --all` 0 error；前端 `pnpm build` 通过、dist 入库。
4. 版本号三处同步为 **1.32.0**（`__init__.py` / `package.v2.json` / 更新说明）。
5. 真机验收在用户更新后由用户触发，主 agent 只提供精确验证命令与日志关键字。

## 五、风险

- 误删风险：真名文件 24h 门槛 + 在途保护 + 漏斗在途保护 + 扩展名白名单四道闸；
  最坏情况是删掉一个「已下载但 24h 都没被整理」的文件，属可重下的残留。
- 巡检通知可能打扰：12h 去重 + 恢复通知，避免每 6h 一条。
