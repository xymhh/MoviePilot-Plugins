## 四项修复（按日志占比排序）

### P0-1 平台缓存 pickle 崩（119 条 ERROR / 10h）

- 现象：`Failed to set key ... in region: cloudsubscribe:115:directories:...`，
  底层 `Can't pickle <class '...CloudFile'>: it's not the same object as ...`。
- 根因：`utils/cache.py` 用 MoviePilot 的 `TTLCache`（Redis + pickle）缓存插件
  数据类；插件热重载后，旧模块造的实例与新模块的类对象不是同一个对象，pickle 拒绝写入。
- 影响：目录 / 分享状态缓存整体失效 → 每轮重新列目录，白吃夸克/115 请求。
- 修法：按**类名**做 JSON 编解码（`CloudFile`、`DirectoryLookup`、
  `DirectoryListing`、`RapidUploadResult`、`ShareLinkStatus`），读不出的旧 pickle
  按未命中处理，缓存区加 `:v2` 后缀整区换代；顺带丢弃体积最大的 `native`。

### P0-2 候选白跑分享目录（118 条 WARNING / 10h，103 个不同链接）

- 现象：`分享根目录与订阅标题不符，已跳过`，每条都发生在 `list_share_files` 之后。
- 其中含「任素汐 找名字的人 电影 神探之痕迹 主题曲 (FLAC 24bit 48khz)」这类音乐分享。
- 修法：新增 `handlers/sync/candidate_filter.py`：
  音频/电子书强特征标题在列目录前直接判非影视；24h 内已判「标题不符」的
  (分享链接, 标题) 记入进程内负缓存（上限 4000 条，过期即清）。
  该守卫日志由 WARNING 降为 INFO（属正常过滤，不是异常）。

### P0-3 TG 监控 JSON 落盘竞态（2 次 / 10h）

- 现象：`TG 监控数据写入失败: [Errno 2] No such file or directory: 'items.tmp' -> 'items.json'`。
- 根因：`core/tg_monitor.py` 的 `_JsonStore.save` 固定用 `<name>.tmp`，两个写者
  （扫描线程 / 定时任务 / 热重载残留线程）互相抢文件。
- 修法：临时文件名按 pid + 线程 + 随机数唯一化，`os.replace` 原子提交，`finally` 清残留。

### P1-4 TG 自动匹配逐条 DEBUG 刷屏（144 行 / 10h）

- 「留待手动」「自动转存无新文件」每条一行；改为每轮汇总一行 + 最多 3 条样例。

## 明确不做（本批）

- **不改中继残留的 24h 保留策略**：日志显示清理机制在跑（01:02 删 4.6 GB、
  06:32 删 3.8 GB），剩余 8 组 11.55 GB 全部是 24h 内的可重试缓存，属预期而非泄漏。
  但 03:40 的「每日」清理在 10 小时日志里一次都没出现，只有「启动」触发的清理 ——
  单独记为待查项，不在 1.7.28 动。
- **不动 MP / gopeed 容器配置**：用户明确本轮只看插件。
