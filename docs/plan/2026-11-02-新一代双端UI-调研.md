# 新一代双端响应式 UI · 技术方案调研

> 日期：2026-11-02
> 项目：CloudSubscribeX（网盘订阅助手）
> 目标：彻底推翻现有缝补式 UI，引入成熟流行的现代 Dashboard 规范与响应式架构，实现 PC 宽屏高密看板与手机端自然流畅体验的完美统一。

---

## 一、调研背景与约束

现有前端（Vue 3 + Vuetify 3）存在三大根深蒂固的问题：
1. **历史包袱严重**：早期表格模式遗留了大量深度嵌套与穿透覆盖（如 `!important` 达 40 余处），任何微调都会引发 PC 与移动端互相拆台；
2. **移动端非原生设计**：未采用“移动优先（Mobile-First）”断点，而是 PC 做好后再打补丁，导致信息换行挤压、横向溢出；
3. **架构强耦合**：网络请求、数据过滤与 DOM 结构强行绑定在单文件（动辄 1000~2000 行），缺乏统一状态流。

**技术运行环境硬约束**：
- 插件运行于 MoviePilot 微前端体系内（Federation 挂载），宿主主包已提供 Vue 3 与 Vuetify 3 运行时；
- 插件自身打包为单入口静态资源（`dist/assets/`），不能引入重度依赖（如完整的全套厚重 CSS 框架与不兼容的运行时），必须保持极致轻量、启动毫秒级。

## 三、中英双语检索与验证证据

1. **英文检索**：
   - GitHub API: `search/repositories?q=vue3+responsive+dashboard+template`
   - 对比考察了 Shadcn-Vue 的 Design System 与 CSS 变量设计，其卡片边框、中性文字对比度、极简无阴影风格被确立为本次重构的主视觉规范。
2. **中文与本地检索**：
   - 对比 MoviePilot 官方 V3 前端源码布局规范（发现其内部大量采用 `v-card flat border rounded-lg` 风格）；
   - 审查本地已有前端实现：`MediaHub.vue` 的媒体抽屉与 `Config.vue` 的分类侧栏结构运行最稳定，值得提炼为公共骨架。

## 四、选型结论（三选一）

- 结论：**【① 拼装】（组合成熟方案）**
  - **核心内核**：复用宿主环境已有的 **Vuetify 3 核心组件池**（保证零运行时冲突、包体积最小、加载最快）；
  - **视觉系统**：拼装 **Shadcn-Vue 的 Design Token 与中性设计规范**（放弃老旧 Vuetify 渐变与厚重阴影，改用纯粹的中性底、微边框与大数字）；
  - **交互与布局**：拼装 **Tabler 的单行数据流（Stream List）** 与 **Jellyfin-Vue 的自适应海报网格**；
  - **状态管理**：采用 Vue 3 原生 **Composables（组合式函数）** 做彻底的逻辑与视图解耦。
