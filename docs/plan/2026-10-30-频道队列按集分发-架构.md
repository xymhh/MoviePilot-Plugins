## 线上现象（2026-10-30 12:39 实测）

| 指标 | 实测值 |
| --- | --- |
| `queued` 条数 | 74（覆盖 13 个订阅，最老等 24h，中位 17.6h） |
| 内存队列 `queue_pending` | 26（已 pop 但状态仍写 queued） |
| `failed` | 39（21「订阅搜索已停止」+18「SyncExecutionService」冲突） |
| 单个订阅排队条数 | 玉簟秋 19、尚公主 15、小城良方 14、茶是故乡浓 12 … |
| 近 24h 完成的订阅级转存 | 3 次（07:14 嫁金钗、11:03 伟大的长征、11:03 小城良方） |
| 在飞成本样本 | 小城良方 S01 洗版重下 E01–E06，4.2–4.3 GB/集，约 15 分钟/集 |

根因三条，均已定位到行：

1. **一条消息 = 一次整季作业**。`core/api/sync.py:679-680` 对手动转存强制
   `manual_upgrade=True` → `television.py:141-153` 直接进 `_process_tv_subscribe_upgrade`
   → `upgrade.py:158-215` 建立**整季**基线并按 `plan_upgrade_episode_order` 枚举全季集数。
   TG 链路从不传 `target_episodes`（`discovery.py:121-150` 只传 links/title），
   所以「E20 单集」也要把 E01–E20 全过一遍。
2. **去重键漏掉整包消息**。`tg_monitor.py:1342-1367` 的 `_quality_candidate_key` 对
   无集号的整季包返回 `None` → 不进 `occupied`、不参与跨批去重。74 条里 52 条无 key，
   同一部剧的 14 条不同分享各自排队（实测 `matched_dedupe_key` 全部为空）。
3. **缺集优先是死代码**。`__init__.py:1414` 取 `getattr(sub, "lack", 0)`，而订阅模型字段是
   `lack_episode` → 恒 0 → `tg_monitor.py:1618` 全部判成「订阅已齐，仅洗版」
   → 74/74 `queue_priority=1`。

## 数据结构变更

### 队列条目新增字段

```jsonc
{
  "id": "chan:12345",
  "matched_dedupe_key": [12, "season", 1, 0],   // 4 元组形状不变，kind 改成 season/movie
  "target_episodes": [19, 20],                  // 新增：本条消息覆盖的集数；缺省=不限
  "merged_into": "chan:12301",                  // 新增：本条目被合并到哪条
  "merged_from": ["chan:12344", "chan:12345"]   // 新增：合并进来的条目 id
}
```

- `kind` 由 `episode` 改为 `season`：同一订阅同一季只有**一个**队列单元。
  单集消息 `[sid,"season",s,0]`、整包消息同样 `[sid,"season",s,0]`；
  电影为 `[sid,"movie",0,0]`。旧条目里的 `"episode"` 键不再匹配新键，自然淘汰。
- `target_episodes` 只做**上界**，不做白名单：引擎内部仍按「缺集优先、其次洗版、
  洗版受 `upgrade_episode_limit` 截断」执行（`upgrade.py:33-63`）。

### 新增状态 `transferring`

被 worker 取走的条目立刻写 `transferring`，用于：

- 合并时不再把新链接塞进已开跑的作业（会丢）；
- `status.queued` 与 `queue_pending` 不再自相矛盾（74 vs 26）；
- 重启恢复：`_recover_queued_items` 把 `queued`/`transferring` 一起重新入队。

## 集数解析（`core/tg_match.py:parse_message_episode_scope`）

| 消息样例 | episodes | 说明 |
| --- | --- | --- |
| `小城良方 S01E20` | `[20]` | 单集 |
| `玉簟秋 19-20集` | `[19,20]` | 区间 |
| `尚公主 更至28集` | `1..28` | 更新进度 |
| `茶是故乡浓 全29集` | `1..29` | 整季包 |
| `现在就出发 更至10.18期` | `None` | 综艺按期/日期，不做集数推断 |
| 无任何集数信息 | `None` | 保持原行为（整季） |

解析失败一律回退 `None`（不限集），绝不因为解析错误而不转存。

## 调用链

```
tg_monitor._match_and_enqueue
  ├─ 命中 → target_episodes 解析 → 键 (sid,"season",s,0)
  │         ├─ 队列已有同键且非 transferring → 合并 links/目标集，本条记 merged
  │         └─ 否则 queued + 入队
  └─ _transfer_group（按订阅合并，链接切块上限 20）
        └─ _auto_transfer_tg_batch
              └─ submit_candidate(extra_payload={"target_episodes": [...], "resource_titles": {...}})
                    └─ SyncApi.api_vue_start_manual_sync(payload)
                          └─ sync_kwargs["target_episodes"]
                                └─ sync_subscribes(target_episodes=[...])
                                      └─ setattr(subscribe, "_target_episodes", set)
                                            └─ runtime.execute → process_tv_subscribe(target_episodes=...)
                                                  └─ upgrade.py: baseline 只取目标集
```

合并后的 `target_episodes` 取并集；并集为空则不下发该键（等价 `None`）。

## 失败与回滚

- 解析/合并异常一律降级为原行为（各自入队、不下发 target），只记 `logger.debug`。
- `target_episodes` 透传是新增可选参数，缺省 `None`，老调用点行为不变。
- 状态新增 `transferring` 需前端/接口兼容：`list_items` 按状态过滤，未知状态不会崩；
  界面把 `transferring` 归到「待处理」显示。
- 回滚：`git revert` 单提交；已写入的 `transferring` 条目在旧代码下会被
  `_recover_queued_items` 忽略——回滚时需手工把该状态批量改回 `queued`（见 test 文档排障表）。

## 不做（本期范围外）

- 不改「手动转存 = 洗版」这个既有语义（`sync.py:679`），只在集数维度收口；
- 不做失败自动重试/清理策略（另行处理 39 条 failed）；
- 不改动订阅本身的洗版开关与质量门槛（`upgrade_episode_limit` 仍由配置控制）。
