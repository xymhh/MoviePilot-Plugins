## 0. 一句话

在 CloudSubscribeX 插件内起一个**独立端口的 Emby 反向代理**，把播放请求 302 到 115 CDN，
让客户端直连、不吃 Emby 服务器带宽；其余请求透传，失败一律回落 Emby（最坏等于没装）。

## 2. 技术约束（硬性）

1. **不新增第三方依赖**。只能用：`starlette`、`uvicorn`（MP 必备，FastAPI 依赖）、`httpx`（MP 必备）、标准库。
2. **不引入 aiohttp / websockets / 任何新包**。
3. 单文件主实现不超过 600 行；纯逻辑抽到 `emby_proxy_rules.py`。
4. 代理进程**必须可独立启停**，异常不得影响插件其它功能（转存/订阅/STRM 照常）。
5. 端口占用、上游不可达、换链失败 → **记日志 + 降级**，绝不抛到插件主流程。
6. 所有代码风格与仓库现有 Python 一致（4 空格、类型注解、中文 docstring）。

## 3. 请求分流（核心逻辑，必须严格实现）

```
客户端 ──► CS 反代 (:3010) ──► Emby (上游 http://embyserver:8096)
                 └─ 命中「可直接播放」→ 302 到 115 CDN
```

| 条件（按顺序判定，命中即停） | 动作 |
| --- | --- |
| `path == "/"` | 302 到 `/web/index.html`（Emby 惯用跳转） |
| `path` 匹配 `(?:^|/)(?:emby/)?Items/[^/]+/PlaybackInfo/?$` | **改写响应体**（见 §4），其余透传 |
| `path` 含 `/emby/http` 且 query 含 `FakeDirectStream=true` | 取直链 → **302**；取不到 → 透传 |
| `path` 匹配 `(?:^|/)(?:emby/)?Videos/[^/]+/stream/?$` | 尝试 302（无 `FakeDirectStream` 时也试）；失败 → 透传 |
| `path` 匹配 `(?:^|/)(?:emby/)?Audio/[^/]+/(?:stream(?:\.[^/]*)?\|universal)/?$` | 同上 |
| 其余一切（`/web/*`、`/emby/Items`、图片、`/Users`…） | 透传 |

**透传要求**：保留 method、query、请求头（除 `Host`）、请求体；回传状态码、响应头（除 `Transfer-Encoding`/`Connection`/`Content-Encoding` 冲突项）、流式响应体（64KB chunk）。必须支持 `Range` 与 `HEAD`。

**WebSocket**：`/embywebsocket` 等升级请求 —— 第一版**不代理**，直接返回 400 并记 debug 日志（客户端会回落 HTTP 轮询，不影响播放）。代码里留 `# TODO(ws)` 注释。

## 4. PlaybackInfo 改写（关键技巧，来自 MediaRelay，MIT）

拿到上游 200 的 JSON 后，对 `MediaSources[]` 每一项：

```python
item["DirectStreamUrl"] = f"{origin}/Videos/{item['ItemId']}/stream?MediaSourceId={item['Id']}&Static=true&FakeDirectStream=true"
item["TranscodeReasons"] = []
item["SupportsTranscoding"] = False
item["SupportsDirectPlay"] = True
item["SupportsDirectStream"] = True
item["Protocol"] = "Http"
```

- `origin` = 客户端访问代理时用的 scheme+host（从请求 `Host` + `X-Forwarded-Proto` 推导）。
- 仅当该 MediaSource 的 `Path` 以 `.strm` 结尾时才改写；非 strm（真实文件、直连可播）**保持原样**。
- **`SupportsTranscoding=False` 会导致不能转码的设备直接播放失败** → 因此仅当 `.strm` 命中且能换链时才这样改；换链不可用（网盘客户端未初始化）→ 整个 PlaybackInfo 原样透传。
- 非 JSON / 非 200 → 原样透传。

## 5. 从流请求定位文件

```
请求 → MediaSourceId / ItemId
   ├─ MediaSourceId 命中 Path 缓存（LRU 2048、TTL 1h）→ Path
   └─ 未命中 → 调上游 `GET /emby/Items?Ids={id}&Fields=Path`（带 media_server_api_key）
        → 取 MediaSources[].Path 写缓存
Path 以 .strm 结尾 → 读文件内容（mtime+size 缓存，TTL 30min）
   ├─ 内容含 pickcode=（或能从 URL 路径解析 17 位 pickcode）→ 换直链
   ├─ 内容本身是 115 CDN 直链（含 `115.com`/`115cdn`）→ 直接 302
   └─ 其它 → 透传
```

**换链必须复用** `core/api/redirect.py` 的 `RedirectApi._resolve_link(pickcode, file_name)`（同 6h 缓存、同限流），
不得另写一套 115 直链逻辑。若该方法签名需要微调（例如拆出可复用的 classmethod），可改，但**不得改变其现有对外行为**，
`tests/test_strm_redirect.py` 必须继续全绿。

## 6. 配置项（`core/config.py` 默认值 + 表单字段）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `emby_proxy_enabled` | `False` | 总开关；关闭时不启动任何线程/端口 |
| `emby_proxy_port` | `3010` | 监听端口（0.0.0.0） |
| `emby_proxy_upstream` | `""` | 空 = 自动用 `media_server_host`（Emby 地址）；支持 `http://embyserver:8096` |
| `emby_proxy_allowed_clients` | `""` | 空 = 全放行；填 UA 子串（逗号分隔）则只对这些客户端 302，其余透传 |

复用现有配置键：`media_server_host`、`media_server_api_key`、`media_server_path_mappings`（路径前缀翻译：Emby 侧 `/media/strm` → MP 侧 `/strm`）。

## 7. 生命周期

- `init_plugin(config)` 末尾：`emby_proxy_enabled` 为真 → 起线程（`uvicorn.Server` + `asyncio` 事件循环，`daemon=True`），
  失败（端口占用/导入错误）→ `logger.error` 记录并置运行时状态 `failed`，**不 raise**。
- `stop_service()`：置停止标志 + `server.should_exit = True`，join 线程 ≤ 3s。
- 管理端点（`registration.py`）：
  - `GET /emby_proxy/status` → `{"enabled":bool,"running":bool,"port":int,"upstream":str,"stats":{"hit":N,"miss":N,"fallback":N,"error":N}}`
  - `POST /emby_proxy/restart` → 停再起，返回同上 status
  - 两个端点用 `auth: "bear"`。
