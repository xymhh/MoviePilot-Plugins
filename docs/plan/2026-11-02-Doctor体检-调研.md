# Doctor 一键体检 — 调研（2026-11-02）

> 阶段：第二阶段第 1 项（用户拍板顺序 2→1→3→4→5）
> 状态：调研完成，架构见 `2026-11-02-Doctor体检-架构.md`

## 1. 要解决的问题

用户报「这集没转存」时，现有手段只有翻 MoviePilot 容器日志（3MB+/天，几万行）。
真实卡点分散在：网盘凭据过期、TMDB 不可达、搜索源全灭、私有库读写失败、
订阅本身没缺集、定时服务没跑。**没有任何一处能把「现在哪一环坏了」直接说出来。**

## 2. 现成轮子盘点（先搜，别造）

| 候选 | 覆盖能力 | 差距 |
| --- | --- | --- |
| MoviePilot 原生「系统设置-基础设置-检查连接」 | 测 TMDB/站点/下载器连通 | 只测平台自身配置，不认插件私有库、订阅缺口、搜索源熔断；无修复指引 |
| MoviePilot `diagnostics.py`（日志里那条 42P01 就是它报的） | 记录 DB 驱动异常 | 只写日志不聚合，用户看不到 |
| 插件已有 `api_vue_test_search_source` / `test_search_proxy` | 单源搜索连通性 | 一次只测一个源，需手工逐个点 |
| 插件已有 `utils/cache.cache_stats()` | 缓存命中率/解码失败 | 藏在缓存层，无出口 |
| 插件已有 `history_overview` / `ledger` 缓存健康度 | 历史与候选池统计 | 分散在多个 Tab，不构成「体检」 |
| 第三方「插件体检」类插件 | 通用插件健康 | 不懂本插件业务口径（订阅 note、私有库、转存流水） |

**结论：选 ① 拼装** —— 不新造探测能力，只新增一层「聚合 + 判定 + 修复指引」：
- 数据来源：私有库 `store.repositories.*`、`SubscribeOper`、`cache_stats()`、
  `drive_manager` 注册表、`RequestUtils`（TMDB 探活）、PanSou health。
- 自研的只有：判定阈值（什么算红/黄）、修复指引文案、一次请求聚合全部结果。

## 3. 不做什么（防止范围膨胀）

- 不做自动修复（除跳转到配置页），只给「点哪里修」。
- 不测站点/PT 下载器（本插件不走 BT 主线）。
- 不做定时体检推送（后续可挂到现有通知通道，本期不做）。
