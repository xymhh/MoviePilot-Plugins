# 任务书：CS 插件跨盘上传 115 支持代理 + 每日 900G 硬上限

> 执行方：外部 ACP runner（opencode）。**本任务书自包含，不依赖对话上下文。**
> 项目根：`/app/working/workspaces/default/moviepilot-plugins-cs`（仓库 `xymhh/MoviePilot-Plugins`，公开，唯一市场源）。
> 必读：同目录 `2026-11-12-跨盘上传代理与每日额度-调研.md` 与 `-架构.md`（需求已冻结，不得超出）。

## 一、背景

`plugins.v2/cloudsubscribex`（CloudSubscribeX，当前 `plugin_version = "1.9.74"`）的跨盘转存，真实上传 115 时走 `drive/p115/client.py` 的 `P115ClientWithTimeout` + `drive/p115/upload.py` 的 `p115oss` 分片 / `requests.Session`。德国 VPS 直传阿里云 OSS 深圳很慢；用户已验证「上传走代理」可显著提速，并要求给插件加：

1. 上传 115 可设置代理（默认空=直连），**只作用于 115 上传/API**，源盘下载保持直连。
2. 每日真实上传字节数**硬上限 900 GB**，按 `settings.TZ` 自然日累计，超限跳过本次并等次日。

用户会自行把 `cross_transfer_rapid_miss_action` 从 `abort` 切到 `fallback`（「回落普通上传」），**该配置语义不许改**；新逻辑只在真实上传分支生效，秒传命中 0 字节不计数。

## 二、接口约束（照架构篇实现，不要自行发挥）

新增 4 个配置键（`core/config.py` 的 `DEFAULT_CONFIG`，默认关/安全值）：

| key | 默认 | 约束 |
| --- | --- | --- |
| `cross_transfer_upload_proxy` | `""` | 空=直连；http/https/socks4/socks5/socks5h |
| `cross_transfer_upload_proxy_username` | `""` | 可选 |
| `cross_transfer_upload_proxy_password` | `""` | 有密码必须有用户名 |
| `cross_transfer_daily_upload_limit_gb` | `900` | **clamp 1..900**，0/负数/超 900/非数字一律收敛到合法值 |

必须**复用**本仓现成轮子，不许重写：

- `utils/http_client.py`：`validate_proxy_address` / `build_proxy_url` / `normalize_proxies`（`__init__.py:1911-1924` 的 `search_proxy` 是解析→运行期注入的范式，照抄）。
- 代理注入点：`drive/p115/client.py:358` 构造 `P115ClientWithTimeout` 处，把 `proxies` 传给底层 HTTP 客户端；`drive/p115/upload.py::_new_session()`（源盘下载）**不注入**。
- 持久化：`core/storage.py` 的 `repositories.runtime.load/save`，namespace `cross_upload_quota`，key = `YYYY-MM-DD`，值 `{"bytes": int, "updated_at": iso}`。
- 按天口径：`core/services/checkin.py` 的 `pytz.timezone(settings.TZ)` + `strftime("%Y-%m-%d")`。
- UI：`frontend/cloudsubscribex/src/config/fields/transfer.js`，加在跨盘 section，`show: enabled("cross_transfer_enabled")`，参考 `:173-183` 的字段格式。

额度模块（新文件，位置自定但需在 `core/` 下）：

```
UploadQuota.date_key(now) -> "YYYY-MM-DD"
UploadQuota.used_bytes(date_key) -> int          # 缺键=0
UploadQuota.remaining_bytes() -> int
UploadQuota.can_start(size_bytes) -> (bool, reason)
UploadQuota.add(size_bytes) -> None              # 加锁、读改写原子
```

接缝：`core/transfer.py` 的真实上传分支（`:1787` `upload_from_link` 调用 / `:2052` `method` 回写附近）—— **任务开始前** `can_start(file.size)` 预检，不通过就跳过并写现有历史「跳过原因」字段；**上传成功后** `add(真实字节)`。失败/中断不累加；秒传命中和 `abort` 分支不计数。

失败行为：代理非法/解析抛错 → 回落直连 + WARN（不阻断）；额度读写异常 → fail-open + WARN；并发下允许轻微越界（不做分布式锁）。
