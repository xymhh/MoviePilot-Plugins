# 前端单入口收敛（Page → AppPage）—— 架构

- 日期：2026-10-27
- 版本：1.7.90
- 触发：MoviePilot 的 `nav_key=main` 只加载 `./AppPage`（`./Page` 仅作 fallback），
  而「频道监控」页签只存在于 `Page.vue` → 侧边栏进入看不到该页签；
  且 `Page.vue`(1048 行) 与 `AppPage.vue`(1204 行) 相似度 65%，每次改动要两处同步。

## 1. 目标

- `AppPage.vue` 成为唯一实现（订阅任务 / 历史记录 / **频道监控** / 网盘整理 / 资源账本）。
- `Page.vue` 退化为薄壳，只做兼容转发，不再持有业务逻辑。
- 加静态校验，防止两个入口再次分叉。

## 2. 为什么不是别的做法

| 方案 | 结论 |
| --- | --- |
| 只把 tg 页签补进 AppPage，保留两份实现 | 修好当前症状，双份代码继续漂移（否决） |
| 抽 PageShell + 页签注册表，两入口共用 | 长期最优，但要动 1000+ 行模板与全部抽屉，风险与工期高（列为后续可选项） |
| 单入口 + 薄壳（采用） | 改动集中在 3 处，兼容老 MP 对 `./Page` 的 fallback，回滚只 revert 一个 commit |

## 3. 改动清单

1. `src/components/AppPage.vue`
   - `TgMonitor` 用 `defineAsyncComponent` 懒加载（不打进首屏 chunk）；
   - 页签顺序：订阅任务 → 历史记录 → **频道监控** → 网盘整理 → 资源账本；
   - `v-show="mainTab === 'tg'"` 面板，传 `:api` / `:active`（`notify` 有默认值，省略）。
2. `src/components/Page.vue`
   - 全文替换为薄壳：
     ```vue
     <script>
     import AppPage from "./AppPage.vue"
     export default AppPage
     </script>
     ```
   - 保留 `./Page` expose，老 MoviePilot 走 fallback 时行为等同 AppPage。
3. 校验脚本 `scripts/check_frontend_entry.py`
   - 断言 `Page.vue` 不含 `v-tab`、包含 `export default AppPage`；
   - 断言 `AppPage.vue` 的页签集合 = `{tasks, history, tg, organize, ledger}`；
   - 在 CI 的 lint job 里跑（失败即红）。

## 4. 兼容与风险

| 风险 | 处理 |
| --- | --- |
| 老 MP 只加载 `./Page` 并监听 `close`/`switch`/`action` | 薄壳转发到 AppPage；AppPage 自带设置抽屉，不依赖这三个事件；老 MP 的监听只是收不到事件，不会报错 |
| `props.api` 类型：Page 允许 Function，AppPage 只声明 Object | AppPage 声明改为 `[Object, Function]`，与 MP 实际传参一致 |
| tg 页签首次点击才加载 TgMonitor | 懒加载 + `active` 控制轮询，未激活不请求 |
| 构建产物引用关系 | 构建后 grep dist 确认 Page chunk 只 re-export AppPage，不复制模板 |

## 5. 验收

- `npm run build` 通过；
- `python3 scripts/check_frontend_entry.py` 通过；
- 全量 pytest 不劣于基线（900 passed / 3 预存失败）；
- 真机：侧边栏「网盘订阅」可见 5 个页签，频道监控数据与 1.7.89 一致。
