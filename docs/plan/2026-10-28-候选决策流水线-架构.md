# 2026-10-28 候选决策流水线：全链路梳理与优化架构

> 状态：设计稿（待评审，未动代码）
> 触发：用户报「尚公主明明有 4G 一集的，入库的是 1G 多的」，且反馈「插件修修补补，脑子很乱」
> 范围：CloudSubscribeX 自身（`plugins.v2/cloudsubscribex`），不涉及 115/夸克驱动层

## 0 一句话结论

现在的问题不是某一个 bug，而是**「拦截判定」散落在 7 个阶段、13 个跳过点、3 类粗归因里，且洗版另有一套评分口径**。修一处必然破另一处。
优化方向：把候选相关的判断收敛成**一条决策流水线**（硬过滤 → 打分 → 与基线比较 → 决策），配上**一份可回放的决策账本**，让每次拦截能归因、能回归、能按损失排序。

## 3 病灶（按段，附证据）

**P1 段③ 归因为三类粗粒度，损失不可统计**
`skip_stats.py:17` 只有 `invalid / empty / mismatch` 三种；而 `television.py` 里有 13 处「已跳过」日志、21 个 `continue` 分支。账本因此只能回答「跳过了」，回答不了「按原因各损失多少集」。→ 优化只能靠翻日志猜，正是「越修越乱」的根源。

**P2 段③ 守卫是负向识别，且日志只报前 3 个根目录**
`utils/file_matcher.py:391` `share_title_mismatch` 的语义是「根目录不能证明是本剧 → 拦」，而不是「能证明是别的剧 → 拦」。反爬名（含 `@`/`#`/`丨`/异体字）必然命中。
同时 `television.py:610` 只打印 `sorted(roots)[:3]`，**真正导致拦截的根目录经常不在日志里**（账本里 `06.mkv / 07.mkv / 08.mkv` 就是这种"看起来无辜"的记录）→ 排障靠猜。

**P3 段③ 与段⑦ 是两套评分口径**
段③ 用 `matching + scoring` 选文件；段⑦ 另外用 `baseline + provider_score + upgrade_mode`（`upgrade.py:376`）比较。段③ 拦下的候选，段⑦ 永远看不到 → 洗版恒定输出「未发现可升级资源」，与库内质量长期偏低互为因果。

**P4 段⑤ 状态源有三份**
库内季集（`mediaserver.py`）、订阅 note（`completion.py`）、history 记录（`history.py`）各存一份。今日日志里 E11 出现 `not_written` ×3、`missing_in_dir` 警告、1.04GB → 1.57GB 反复写，就是三份状态对不齐的表现。

**P5 段④ 与段⑤ 的失败语义交织**
`target_writer` 的 `not_written / 写入后核验通过` 与 `transfer` 的中继回退、批间等待揉在一起，失败重试没有单一入口（`retry.py` 只是其中一条路）。

## 4 目标架构

### 4.1 一条决策流水线（每个候选走同一条路）

```
候选 → 硬过滤 → 打分 → 与基线比较 → 决策(转存/跳过) → 记账
```

- **硬过滤只保留 3 类，且必须是正向证据**：
  1) 链接失效；2) 无可用视频文件；3) **明确是另一部剧**（根目录含另一剧名 + 年份/集数范围冲突，或包内视频解析出的季集与目标季冲突）。
  非证据项一律不进判定：`apk/jpg/txt/url/nfo/7z` 等非视频文件名、纯集数文件名（`06.mkv`）、代号前缀（`SGZBRMY-07.mkv`）、以及「含 `@`/`#`/`丨` 等装饰符号且去掉符号后与标题字符有交集」的变体名。
- **打分**：分辨率 > 编码 > HDR > 体积，直接复用现有 `tg_quality_resolution_order / codec_order / hdr_order`，不再新增口径。
- **基线比较**：体积增益阈值（`quality_min_gain_mb / percent`）只在一处实现，段③ 与段⑦ 共用。

### 4.2 决策账本 v2（可回放）

每个候选一行：`candidate_id / 环节 / share_url / 标题 / 包内文件前 N 个 + 总大小 / 季集解析结果 / 硬过滤结论 / 分数 / 与基线的比较 / 最终决策 / 耗时`。
`kind` 从 3 类扩到约 10 类（失效、空包、另一剧、季冲突、无目标集、增益不足、体积上限、预算耗尽、转存失败、落盘失败）。
新增周报口径：**按 kind 统计"损失了多少集 / 多少 GB"**，据此排序修，而不是按报错修。

### 4.3 落盘真相源唯一化

以「115 实际文件 + Emby 季集」为准；history 与订阅 note 降级为派生视图，只用于展示与重试。
段⑤ 只允许写一个真相源，派生视图由事件重算。

### 4.4 开关收敛

线上 392 个配置键 → 3 个预设档（保守 / 均衡 / 激进）+ 高级项折叠。同等语义只留一个键（例：`prefer_template_named_version` 与 `quality_ignore_rename_template` 的边界写进预设，不再让用户组合）。
