# TG 频道监控判定链简化 —— 架构

- 日期：2026-10-27
- 版本：1.7.89
- 关联：`docs/plan/2026-10-27-TG频道判定链-调研.md`

## 1. 职责划分

| 组件 | 职责 |
| --- | --- |
| `ChannelMonitor._scan_async` | 只抓消息、抽链接、匹配、判定、入队；**不做任何转存** |
| `_TransferWorker`（`ChannelMonitor` 内部） | 从队列取条目，按订阅合并成批，串行调用一次手动同步 |
| `SyncApi.api_vue_start_manual_sync` | 既有手动转存链路（季集识别 → 缺集 → 洗版） |
| 前端「频道监控」页 | 展示状态；频道规则只剩 频道/启用/关键词/排除/回溯 |

## 2. 判定链（唯一）

```
新消息 → 抽网盘链接 → 标题清洗 → 匹配全部订阅（唯一高置信）
  ├─ 命中：画质择优（同集只留最优）
  │      └─ status=queued → 入队
  └─ 未命中：status=ignored（match_reason 写明差距）
```

- 不再有 `monitor_mode` / `auto_subscribe_ids` 两套开关；旧配置读取后归一化为
  `monitor_mode="subscriptions"`、`auto_transfer=True`，白名单字段保留但忽略。
- 画质择优落选条目也直接 `ignored`（reason `同集已有更优画质`），不再 `pending` 兜底。

## 3. 优先级：缺集 → 洗版

由既有转存链路保证：
- 普通订阅走 `process_tv_subscribe`（只补缺失集）；
- 洗版订阅走 `_process_tv_subscribe_upgrade`，其搜索集 = 基线集 ∪ 缺失集，
  缺失集没有基线分数，必然进入转存；已有集才参与画质比较。
- TG 侧不额外加 flag，避免与订阅自身 `best_version` 策略打架。

## 4. 队列与并发

```
scan() ──enqueue(item_id)──▶ Queue ──▶ worker(单线程)
                                  └─ 每轮取到空为止，按 subscribe_id 分组
                                     每组 ≤20 个链接 → 一次 manual sync
```

- 单 worker、串行、批内最多 20 链接（`api_vue_start_manual_sync` 上限 50 的安全余量）。
- 状态机：`queued → transferred / skipped / failed`；`ignored` 为终态。
- 失败不自动重试（避免死循环）；页面「转存」按钮仍可人工重试。
- 插件启动时把残留 `queued` 条目重新入队；`failed` 不自动重入。
- 扫描与 worker 共用 `_items_lock`，读写 JSON 池子走 `_load_items/_save_items` 加锁版本，避免互相覆盖。
- 队列长度上限 200，超出直接 `ignored`（reason `队列积压`），保证内存与 115 压力可控。

## 5. 数据与状态

| status | 含义 | 是否展示 |
| --- | --- | --- |
| `queued` | 已命中，等待转存 | 是（待转存） |
| `transferred` | 成功转存 | 是（历史） |
| `skipped` | 同步成功但无新文件（已有该集） | 是（历史） |
| `failed` | 转存失败（message 在 `auto_transfer_error`） | 是 |
| `ignored` | 未命中订阅 / 画质落选 / 队列积压 | 否（仅留 20 条排障） |

- `UNMATCHED_KEEP` 由 50 降为 20；`new_count` 只统计 `queued`。
- 池子上限不变（默认 500）。

## 6. 失败与回滚

- worker 单条/单批异常 → 该批 `failed` + 一句日志，worker 不死。
- 洗版通知详情写入加 `try/except`：通知失败只记 debug，不中断转存（修复
  `_append_tv_transfer_detail() got multiple values for argument 'notification_kind'` 导致的整条洗版中断）。
- 回滚：`monitor_mode` 字段仍在配置里；如需回退旧版，只影响匹配范围，不影响已转存数据。

## 7. 接口

- `tg/status` 新增 `queued_count`，`new_count` 语义改为待转存数。
- `tg/items` 返回结构不变，`status` 取值增加 `queued`。
- 配置项：`tg_channel_rules[].monitor_mode` / `auto_subscribe_ids` 保留解析但不再生效。
