| 项 | 值 |

### 2.1 上游任务列表：`dashboard/RuntimeCard.vue`（1186 行 / 33,935 B）

结构：`task-list` → 每任务一行 `task-row`，包含：

- **图标 + 标题 + 媒体类型 chip + 状态 chip**（`taskStatusColor`、`taskStatusBaseText`）
- **状态文案带耗时**：`taskStatusElapsed` / `taskElapsedText` / `formatDuration`
- **搜索阶段可视化**：`task.search_channels` 逐渠道 chip + 转圈 + 耗时（`channelIcon` / `channelTooltip` / `channelDisplayElapsed`），并有本地计时兜底 `localChannelStartTimes`
- **进度条**：`v-progress-linear`，支持确定/不确定两种（`hasDeterminateProgress` / `isProgressIndeterminate`），渐变色（`progressColors` / `progressStyle`）
- **可展开详情**（`v-expand-transition` + `isTaskExpanded`）：
  - 搜索渠道明细
  - `task.current_file` 当前文件
  - `postprocess_file_total/completed` 后处理进度
  - `postprocessSteps(task)` 后处理分步图标（`postprocessStepState` / `postprocessStepIcon`）
- **操作**：`canStop(task)` 才显示停止按钮；`emit("stop-task")`
- **空态**：`active` 时转圈「处理中」，否则勾选图标「暂无任务」

用到的 task 字段（16 个）：`current_file`、`download_pending_count`、`elapsed_seconds`、`phase`、`postprocess_active`、`postprocess_file_completed`、`postprocess_file_total`、`postprocess_progress`、`postprocess_steps`、`progress`、`search_active`、`search_channels`、`status`、`task_kind`、`transfer_active`、`transfer_pending_count`。

### 2.2 上游历史记录：`dashboard/HistoryTable.vue`（2109 行 / 65,066 B）

**核心设计：按 `group_key` 聚合**，不是逐条流水。

- `v-data-table-server`，`item-value="group_key"`，`show-expand`，服务端分页
- 分组列：媒体名称 23% / 目标网盘 10% / 资源类型 8% / 来源渠道 10% / 资源链接 8% / 汇总统计 15% / 完成时间 172px / 操作 112px / 展开 44px
- 筛选：资源类型、来源、任务类型、状态，四组 `v-chip-group` 多选
- 展开行内是 `detail-table` 逐条明细
- 移动端降级为 `v-expansion-panels`（accordion）
- 操作：查看媒体详情、洗版、补发汇总通知、Emby 播放、打开来源/资源链接、单集洗版、重试、删除

## 三、我方现状核实

### 3.1 任务列表：`components/RuntimeTaskStrip.vue`（**184 行 / 4,511 B**）

只有一个「浮条」：标题 + 状态 chip + 阶段文案 + 进度条 + 展开列表。**缺**：搜索渠道明细、后处理分步、耗时显示、单任务停止、确定/不确定进度区分、空态。

差距：**184 行 vs 1186 行**，能力缺失约 6 类。

### 3.2 历史记录：`components/dashboard/HistoryTable.vue`（**2055 行 / 65KB 级**）

**已与上游同架构**：`v-data-table-server` + `item-value="group_key"` + `show-expand` + 移动端 `v-expansion-panels`。

**我方还多出上游没有的能力**：
- 「重试全部失败（N 条）」「重试选中（N 条）」
- 「标记选中为成功（N 条）」——手动纠正待确认/待处理
- `failure_reason` / `failure_label` 悬浮提示

**我方比上游少的**：无（筛选维度、分组列、展开明细、操作按钮均已具备）。

**结论：历史记录不需要对齐，已在上游之上。**

## 五、结论：① 拼装（借鉴上游同源实现 + 复用我方现有件）

- **任务列表**：以 `odomu` 的 `RuntimeCard.vue` 为蓝本移植到我们的 `RuntimeTaskStrip.vue`（升级为完整卡片），复用我们已有的 `taskUtils.js`（`taskPhaseText` / `formatSize` / `formatSpeed` / `displayTotal` / `displayTransferred` / `taskProgress`）与 `useRuntimeData.js`（SSE + 快照）。
- **历史记录**：**不改**。已对齐上游且多出三项能力。
- 不引入新依赖、不新增 npm 包、不动后端数据结构（除非字段缺失，见架构篇）。

## 六、已核实的工程约束
