# 插件 ID 独立化：CloudSubscribe → CloudSubscribeX（1.6.49）

> 状态：已完成 2026-10-16 → [../summary/2026-10-16-插件ID独立化复盘.md](../summary/2026-10-16-插件ID独立化复盘.md)

## 1. 背景与问题

本 fork（`xymhh/MoviePilot-Plugins`）与上游 `odomu/MoviePilot-Plugins` 的插件**共用同一个插件 ID
`CloudSubscribe`**。MoviePilot 插件市场按「同 ID 只保留最高版本」合并（v3 `app/application/plugin/catalog.py:343-401`），
于是：

- MP 市场里「网盘订阅助手」出现两条记录：本 fork 的 `1.6.48`（已装、绑定源 `xymhh`）与上游的 `1.7.x`；
- 用户一旦点上游那条的「更新」，本 fork 的跨盘优化版就被**上游版本顶掉**；
- 两条记录作者/版本混在一起，用户也分不清哪条是自己的。

用户选定**方案 A：改插件 ID**（另一个选项「只改显示名/作者」不解决被顶掉的问题）。

## 2. 目标

1. 本 fork 有独立插件 ID，可与上游同名插件**并存安装、各自独立升级**，不再互相顶掉。
2. 老用户升级**不丢数据、不手工搬运**：配置、订阅登记、转存历史、签到记录全部自动迁移。
3. 迁移过程**安全**：不允许新旧两个插件同时执行转存/订阅。

## 3. 命名与元数据（用户已确认）

| 项 | 值 |
| --- | --- |
| 插件 ID | `CloudSubscribeX` |
| 显示名 | 网盘订阅助手（跨盘优化版） |
| 作者 | `xymhh（基于 odomu）` |
| 版本 | 1.6.49 起（沿用原版本号线，不跳号） |
| 源码目录 | `plugins.v2/cloudsubscribex` |
| 前端目录 | `frontend/cloudsubscribex` |
| Release 资产 | `cloudsubscribex_v<版本>.zip`，tag `CloudSubscribeX_v<版本>` |
| `plugin_config_prefix` | **保持 `cloudsubscribe_` 不变**（配置键/数据键无需重写） |

## 4. MP v3 侧事实（改动依据，均已读源码核对）

- 插件目录名 = 插件 ID 小写：`app/adapters/system/plugin/package.py:230-236` → 目录必须叫 `cloudsubscribex`。
- 前端产物按插件 ID 小写取：`/plugin/file/<plugin_id.lower()>/<dist>/remoteEntry.js`
  （`app/runtime/extensions/plugin/paths.py:81`）→ 目录/ID 改名后前端也必须一起改，且 federation `name` 与
  vite `outDir` 都跟随 ID 小写。
- **插件配置存在宿主数据库**（`PluginInstance.config_data`，`app/db/oper/plugininstance.py:244`），
  **不是** `config/plugins/<id>/config.json` 那种文件 → 单纯改目录名搬不走配置。
- 插件键值数据存在宿主主库表 `PluginData`（`app/db/oper/plugindata.py`，按 `plugin_id` 索引），
  SDK 的 `get_data/save_data(plugin_id=...)` 可跨 ID 读写（无 ACL）→ 插件能自己迁移。
- 插件私有 SQLite 库在 `config/plugins/<插件类名>/cloudsubscribe.db`（`core/storage.py` 用 `owner.get_data_path()`）。
- 宿主加载时会 `candidate.__name__ = instance.instance_id`（`app/runtime/extensions/plugin/loader.py:476`），
  所以插件类名与 ID 一致即可，数据目录名自动跟随。
- 公开 API 只能读插件数据（`GET /api/v1/plugin/runtime/{id}/data`）**不能写**，
  配置可读可写（`GET/PUT /api/v1/plugin/{id}`）→ 数据搬运必须由插件侧完成，不能靠外部脚本。

## 5. 改动面

1. `package.v2.json`：键 `CloudSubscribe` → `CloudSubscribeX`，`name`/`author`/`version`/`history` 同步。
2. 目录改名：`plugins.v2/cloudsubscribe` → `plugins.v2/cloudsubscribex`；`frontend/cloudsubscribe` → `frontend/cloudsubscribex`。
3. `__init__.py`：插件类 `CloudSubscribeX`、元数据改名、`legacy_plugin_id = "CloudSubscribe"`，
   `init_plugin` 第一件事调用迁移。
4. 新增 `core/legacy_migration.py`（`LegacyIdMigrator`）：迁移配置 / 数据键 / 私有 SQLite。
5. 前端：id 串（`pluginId` 默认值、API 路径、SSE 流路径）、`vite.config.js` 的 `outDir` 与 federation `name`。
6. CI：`.github/workflows/test-cloudsubscribe.yml` → `test-cloudsubscribex.yml`，路径过滤器同步。
7. tests：模块名与源码路径（`cloudsubscribe.` → `cloudsubscribex.`，`plugins.v2/cloudsubscribe/` → `plugins.v2/cloudsubscribex/`）。
   **不动**内部契约串：`plugin_config_prefix`、数据键、线程名、`__cloudsubscribe_owner__` 之类标记。
8. 文档：本目录三篇 + 根 `README.md` 排障表与插件 README。

## 6. 迁移设计（`LegacyIdMigrator`）

执行时机：`init_plugin` 最前（早于建库 `initialize()`，否则目标库已存在会让复制跳过）。

触发条件（全部满足才跑）：
1. 本插件当前配置为空（`config` 假值）；
2. 未迁移过（数据键 `legacy_id_migration` 不存在）；
3. 旧 ID `CloudSubscribe` 有配置可读。

搬运三样：
1. **配置**：`get_config(plugin_id="CloudSubscribe")` → `update_config(...)`，其中 `enabled` **强制置 False**；
2. **数据键**：`get_data(plugin_id="CloudSubscribe")` → 逐键 `save_data(key, value)`；
   宿主新版返回 ORM 行列表（`.key`/`.value`）、旧版返回 dict，两种都归一化；
3. **私有 SQLite**：`config/plugins/CloudSubscribe/cloudsubscribe.db` → `config/plugins/CloudSubscribeX/`，
   连同 `-wal`/`-shm` 同快照复制；**目标库已有内容则不覆盖**（本插件的库为准），仅 0 字节空文件才顶上。

留痕：数据键 `legacy_id_migration` 记录来源 ID、时间、配置项数、数据键数、是否复制了库。
迁移后写一条 INFO 日志：`已从旧插件 CloudSubscribe 迁移到独立 ID CloudSubscribeX（1.6.49）：…`。

为什么 `enabled` 要强制 False：迁移发生时旧插件**大概率仍在运行**，两个插件同时转存会互相踩
（同一集重复转存、互删中继文件——1.6.47 修的就是这个坑）。所以只搬数据，启用交给用户手动决定。

## 7. 用户侧切换步骤（写进 README 排障表）

1. MP 里装本 fork 的**新 ID 插件**（市场里显示「网盘订阅助手（跨盘优化版）」）；
2. 打开一次插件（或重载），看日志/数据键确认迁移完成（新插件会保持**停用**）；
3. 在 MP 里**停用或卸载**旧 ID 插件；
4. 手动**启用**新插件，确认订阅/历史/签到数据都在；
5. 旧 ID 插件不装即可；装着也不会互相干扰。

## 8. 验收标准

1. 全量单测通过（仅允许既有 p115client 环境失败），新增迁移单测覆盖：触发条件 5 例、数据搬运 3 例、SQLite 复制 4 例、留痕 1 例。
2. `scripts/lint.py --all` 0 error。
3. CI 三绿：`Test cloudsubscribex (V2)`、`Lint Python`、`Auto Release`（含前端 pnpm 构建）。
4. Release `CloudSubscribeX_v1.6.49`：资产名 `cloudsubscribex_v1.6.49.zip`、包内 `plugin_version=1.6.49`、
   包内目录名为 `cloudsubscribex`、dist 含 `remoteEntry.js`、zip sha256 与 `.sha256` 一致。
5. MP 市场里两条记录不再互相顶掉（用户真机验收）。

## 9. 禁止事项

- 不改 `plugin_config_prefix`、数据键、线程名、动作 ID 等内部契约（改了等于把旧数据全变孤儿）。
- 不删除旧 ID 的数据目录/配置（迁移是复制，不是搬走；用户可能还要回退）。
- 不在迁移里自动启用插件（会与旧插件同时转存）。
- 不手工编辑 `config/plugins/` 下的库文件，也不在测试里连真机数据。
