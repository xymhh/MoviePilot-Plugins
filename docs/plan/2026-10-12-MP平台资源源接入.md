# 任务书：把网盘候选接入 MoviePilot 搜索（`search_torrents` 插件模块）

> 状态：已实现（2026-10-12），验收记录见 ../test/2026-10-12-平台资源源单测.md

## 背景

用户反馈：在 MoviePilot（V3）里搜片名（含 TG 机器人搜索）永远只有 PT 站结果，
网盘订阅助手（CloudSubscribe）明明能搜到网盘资源，却不出现在平台搜索里。

根因（源码实证）：

* 平台插件资源源只认插件声明的 `search_torrents` 模块
  （契约 `app/runtime/extensions/module/contracts.py:544`，
  收集 `app/runtime/extensions/plugin/projection.py:95-130`）；
* 调用点：`app/chain/search/provider.py:458`（标题/手动搜索）、
  `app/chain/search/scan.py:124`（订阅补集搜索）、异步链路同契约；
* CloudSubscribe 此前**没有**声明该模块，所以平台搜索返回 0 条网盘候选。

## 目标

1. CloudSubscribe 声明 `search_torrents`（同步）+ `async_search_torrents`（异步）模块，
   把网盘搜索渠道的候选翻译成平台 `TorrentInfo` 返回；
2. 用户在平台搜索页/机器人里选中网盘候选后，下载动作必须交回插件的链接转存链路，
   绝不能让平台把 115/夸克/磁力分享链接当种子丢给下载器；
3. 保持可关闭：配置项 `mp_search_module_enabled`（默认开）、`mp_search_module_limit`（默认 20）。

## 接口约束（平台侧，不可改）

```python
# 插件声明
def get_module(self) -> Optional[Dict[str, Any]]:
    return {"search_torrents": ..., "async_search_torrents": ...}

# 平台调用签名（四参数必须齐备）
search_torrents(site: dict, keyword: str, mtype: MediaType | None, page: int) -> List[TorrentInfo]
```

* 返回对象必须是平台 `TorrentInfo`；字段按当前宿主字段集过滤（v2/v3 字段不同）；
* `page > 0` 直接返回空（网盘源只有一页）；
* 下载接管走 `ChainEventType.ResourceDownload`（`app/chain/download/submission.py:359`
  在下载器副作用之前应用，`event_data.cancel=True` 即中止并回传「下载被事件取消」）。

## 设计

1. **来源标记**：模块返回的 `TorrentInfo.site_name` 统一加前缀
   `网盘订阅助手｜`（`MoviePilotSearchModule.SITE_NAME_PREFIX`）。
   这既是 UI 上的来源标识，也是下载接管时的识别标记。
2. **搜索复用**：模块不新写搜索逻辑，直接复用插件的
   `search_platform_resources(session_id, subscribe_id, title, media_type, season, ...)`，
   再从候选缓存 `_agent_resource_cache` 取回真实链接（缓存里才有 `url`）。
3. **身份回填**：`search_platform_resources` 返回的 `media` 增加 `tmdb_id`，
   模块把它写进 `TorrentInfo.media_source=MediaSource.TMDB` / `media_id`，
   平台识别资源时可直接命中媒体，转存时也能直接定位 TMDB，免去人工选择。
4. **下载接管**：`PluginEventHandler.on_resource_download` 开头判断
   `MoviePilotSearchModule.is_cloud_resource(torrent)`：
   * 命中 → `submit_platform_links(resource_links=[enclosure], title=..., media_type=...,
     seasons=..., tmdb_id=..., detect_multiple=False)`，**无论成败都 `cancel=True`**；
   * 失败/异常 → `post_message` 通知用户，日志留痕；
   * 未命中 → 走原有订阅策略逻辑（行为不变）。
5. **降级**：搜索失败、媒体识别失败、候选无可用链接（需积分解锁）一律跳过并记日志，
   绝不让平台搜索整体失败。

## 禁止事项

* 不把真实链接写进日志（只记标题/来源/数量）；
* 不在平台搜索链路里做同步阻塞的重活以外的写操作（不发通知、不建订阅）；
* 不改平台源码，只改插件；
* 不动 PT/RSS 等既有订阅接管逻辑。

## 验收标准

1. `tests/test_mp_search_module.py`（模块映射/降级/开关）与
   `tests/test_mp_resource_download_handoff.py`（下载接管）全绿；
2. `scripts/lint.py --all` 0 error；
3. 全量单测无新增失败；
4. 真机：平台搜索出现 `网盘订阅助手｜*` 候选，选中下载后日志出现
   「平台搜索网盘候选已接管」，且 115 转存真实发生（用户侧核验）。
