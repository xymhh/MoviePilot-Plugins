### S2 重试退避 + 死信（让「重试」有节奏、有终点）

现状问题（已核对）：`sync_job_ledger.failure(retryable=True)` 直接把作业丢回 `retry_wait` 并清空租约（`sync_job_ledger.py:251-275`），
`claim()` 只要租约过期就立刻抢（`sync_jobs.py:85-117`）→ **重试无间隔**，一个坏源可以在几秒内烧完 3 次尝试；
而且烧完之后作业永久停在 `retry_wait`（`attempt == max_attempts` 后再也抢不到），**没有任何地方告诉用户它已经死了**。

要做：

1. `sync_jobs` 加 `next_retry_at INTEGER NOT NULL DEFAULT 0`（alembic 迁移，放
   `core/database/alembic/versions/`，用 inspector 判重、老库补列默认 0、可重复执行）
2. `claim()` 增加条件 `or_(SyncJob.next_retry_at == 0, SyncJob.next_retry_at <= timestamp)`
3. `failure(retryable=True)` 计算退避并写库：
   - `delay = min(BASE * 2 ** (attempt - 1), MAX_DELAY)`，`BASE = 60` 秒，`MAX_DELAY = 1800` 秒
   - `attempt` 取该作业当前 `attempt` 值（`claim()` 抢占时已 +1，所以第 1 次失败 `attempt=1` → 60s，第 2 次 → 120s，第 3 次 → 240s）
   - 到达或超过 `max_attempts` 时**不再进 retry_wait**，直接 `JOB_FAILED`，`last_error` 前缀 `dead_letter: `
4. 死信的两个出口：
   - 页面：`collect_tasks()` 里 `dead_letter=True` 当且仅当 `state == failed 且 last_error 以 dead_letter: 开头`，
     或者 `state == retry_wait 且 attempt >= max_attempts`（兼容迁移前遗留的老作业）
   - 人工重试：死信作业允许被重新入队（`reopen_*` 已有能力），重试后 `attempt` 归零、`next_retry_at` 归零
5. 常量集中在 `core/task_center.py` 或新建 `core/retry_policy.py`（推荐后者，纯函数 `backoff_delay(attempt)` 便于单测）
