# 1.9.76 真机冲突修复任务书（2026-11-12）

> 状态：已完成 → 验收见 `../test/`、结论见 `../summary/`
> 本次是 1.9.75 的 bugfix，复用 `2026-11-12-跨盘上传代理与每日额度-架构.md` 的冻结约束，不新增需求。

## 触发（用户真机）

更新 1.9.75 后把「秒传未命中处理」切到「回落普通上传」并配置代理，任务仍被拦在
`跳过：… 6 分钟前已确认未命中（115），24 小时内不再下载` → `秒传未命中：已清理中继缓存并记录 SHA1` → `阶段=aborted`
（`cloudsubscribex.log` 2026-11-12 13:28:25）；同日 13:17 日志另有
`115 上传代理已配置，但 p115client 未暴露可注入的会话，保持直连`。
用户更新/配置/重启均正确（`代码版本=1.9.75` 13:09 初始化、13:17 配置已应用），不是操作问题。

## 根因

1. `core/transfer.py:1599` 24h 负缓存读取判断**没有检查 `rapid_miss_action`**；另外 3 处 `raise RapidMissAborted`（1648/1724/2085）都带 `if rapid_miss_abort:`，只有这一处无条件 → fallback 也被历史 abort 负缓存拦住。
2. `core/transfer.py:2135-2148` 的 `except RapidMissAborted` 无条件 `_remember_rapid_miss()` 重写时间戳 → 每跳一次刷新 24h TTL，**自我续期，等 24 小时也不会恢复**。
3. `__init__.py` 的 `service_config_keys` 不含 `cross_transfer_*`，且其重建入口 `_refresh_platform_services()` 不重建 `CloudDriveManager` → 改配置后运行期 `_rapid_miss_action` 可能仍是初始化时的旧值。
4. 1.9.75 的代理注入按 `session/client/_session/http` 属性找 session，线上 p115client 走 `urllib3_future_request` 的模块级 request callable，没有这些属性 → 回落直连。

## 修复项（冻结，不得超出）

1. 负缓存读取只在 `self._rapid_miss_action == "abort"` 时生效。
2. `RapidMissAborted` 增加 `from_cache` 标志；命中负缓存时 `from_cache=True`；`except` 分支只在「abort + 非 from_cache」时写负缓存，杜绝 TTL 自我续期。
3. 新增 `CrossTransferTaskManager.set_rapid_miss_action()`，`_apply_plugin_config` 改配置后即时同步到运行期管理器，无需重启容器。
4. `P115ClientWithTimeout._apply_upload_proxies` 改为 **request 层注入**（`types.MethodType` 包装 `self.request`，每次请求 `kwargs.setdefault("proxies", proxies)`），保留 session 属性兜底，新增「115 上传代理已生效」日志。

## 明确不做（防止顺手加）

- **不设全局环境变量代理**：会让整个 MoviePilot 进程的 TMDB/TG/搜索 HTTP 一起走代理，风险不可控。
- **不改 p115oss 分片调用**：`oss_multipart_upload_part(..., **request_kwargs)` 是否接受 `proxies` 未在真机验证，盲传可能被底层 `urllib3_future_request.request` 抛 TypeError 打断上传；**分片 PUT 层本版仍未覆盖代理**，真机看日志确认 API 层生效后，若速度无改善再单独处理。
- 不改 `cross_transfer_rapid_miss_action` 的 abort/fallback 语义、不动 24h TTL 数值、不动整理/STRM/通知/历史。
- 不改 `requirements.txt`、不引入新依赖、不发文件给用户、不本地打包覆盖容器内插件。
