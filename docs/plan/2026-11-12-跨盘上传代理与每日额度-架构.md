> 状态：进行中 2026-11-12。**需求变更先改本文档再改码；文档里没写的功能不许顺手加。**

## 一、谁负责什么

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 配置定义 | `core/config.py` `DEFAULT_CONFIG` | 新增 4 个键的默认值（默认关/安全值） |
| 配置解析→运行期 | `__init__.py`（照 `search_proxy` 范式） | 校验并规范化代理，注入到 drive 初始化；无效值回落直连并 WARN |
| UI | `frontend/cloudsubscribex/src/config/fields/transfer.js` | 4 个字段，`show: enabled("cross_transfer_enabled")` |
| 代理注入 | `drive/p115/client.py:358` `P115ClientWithTimeout(...)` | 把 `proxies` 传给底层 HTTP 客户端；**只 115 上传/API** |
| 源盘下载 | `drive/p115/upload.py::_new_session` | **不注入代理**（保持直连） |
| 上传执行 | `core/transfer.py:1787`（`upload_from_link`）/`:2052`（method 回写） | 真实上传分支的接缝；秒传命中分支不计数 |
| 额度 | 新 `core/services/upload_quota.py`（或等价模块） | 按天累计、预检、原子累加、超限判定 |
| 持久化 | `core/storage.py` `repositories.runtime` | namespace `cross_upload_quota`，key = 自然日 |
| 外部依赖 | `p115client` / `curl_cffi` / `requests` | 原生 `proxies` 支持，不改依赖版本 |

## 二、接口（请求/响应字段）

新增配置键（全部**默认关/安全值**，不覆盖用户已存值）：

| key | 类型 | 默认 | 约束 |
| --- | --- | --- | --- |
| `cross_transfer_upload_proxy` | str | `""` | 空=直连；仅 http/https/socks4/socks5/socks5h；复用 `validate_proxy_address` |
| `cross_transfer_upload_proxy_username` | str | `""` | 可选 |
| `cross_transfer_upload_proxy_password` | str | `""` | 有密码必须有用户名（`build_proxy_url` 已校验） |
| `cross_transfer_daily_upload_limit_gb` | int | `900` | **clamp 1..900**，不允许 0/负数/超过 900 |

内部接口：

```
UploadQuota.date_key(now) -> "YYYY-MM-DD"          # pytz.timezone(settings.TZ)
UploadQuota.used_bytes(date_key) -> int            # runtime.load，缺键=0
UploadQuota.remaining_bytes() -> int               # limit_bytes - used_bytes
UploadQuota.can_start(size_bytes) -> (bool, reason)
UploadQuota.add(size_bytes) -> None                # 上传成功后原子累加，加锁
```

存储：`runtime.save("cross_upload_quota", "YYYY-MM-DD", {"bytes": int, "updated_at": iso})`。
旧日期数据不主动清理（读取只按当天 key，不做全表扫描）。

## 三、数据落在哪

- 唯一持久状态 = 按天累计字节数，落插件私有 SQLite 的 `runtime` 表（经 `core/storage.py`），**跨插件重载/容器重启保留**。
- 不写文件、不写 `agent.json`、不新增数据库表/迁移。
- 代理地址属配置，不落日志明文（日志只打「已启用上传代理」/「代理无效已回落直连」，不打凭据）。

## 四、失败与回滚

| 失败 | 行为 |
| --- | --- |
| 代理地址非法 / 解析抛错 | 回落直连 + `logger.warn`，**不阻断上传**，不写坏运行期状态 |
| 代理连不上 | 由现有上传重试/死信机制处理，不新增重试层 |
| 额度读写异常 | **不阻断上传**（fail-open），记 WARN；避免存储故障把整条链路打死 |
| 剩余额度 < 文件大小 | 任务**开始前跳过**，记「每日上传额度已满」，等次日自然日自动恢复；不下载、不占本地缓存 |
| 上传失败/中断 | 只累加**已成功上传**的字节（成功回调处），不预估、不重复计 |
| 秒传命中 | 0 字节，不计数、不占额度 |
| 回滚 | 4 个配置键清空/删掉即恢复原行为；代码可整体 revert，无 schema 变更 |

## 五、并发与限流

- 额度累加必须**加锁 + 读改写原子**（`cross_transfer_max_concurrent` 默认 2，可并发上传）；`add()` 内串行化。
- 预检在任务开始前按 `file.size` 判定；并发下可能出现「两个任务都通过预检、合计超限」—— 允许轻微越界（不超过单文件大小），**不做分布式锁**；`add()` 累加后若发现已超，下一次预检即拦截。
- 代理只加在 115 上传链路；源盘下载连接池 `_new_session(pool_size)` 不变。
- 不新增定时清理任务、不新增通知类型（超限用现有历史原因字段表达）。

## 六、明确不做（防止顺手加）

- 不做 CloudDrive2 旁路/FUSE 挂载（本轮实证：黑盒、无回调、MP 容器未挂 `/mnt/CloudNAS`）。
- 不改 `cross_transfer_rapid_miss_action` 的 abort/fallback 语义、不改 24h 负缓存。
- 不改整理 / STRM / 通知 / 历史列表结构，只复用现有「跳过原因」字段。
- 不改 `requirements.txt`、不引入外部配额库、不加前端新页面。
- 不发文件给用户、不本地上传覆盖容器内插件（发布只走仓库 → CI → 市场）。
