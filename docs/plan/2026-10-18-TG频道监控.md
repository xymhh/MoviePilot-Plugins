# TG 频道网盘资源监控（1.6.57）

> 状态：进行中（代码已完成，待在真实 MP 验证）

## 需求

用户希望直接监控 Telegram 上的网盘资源分享频道，把频道里发布的网盘分享链接接入
CloudSubscribeX 的转存链路，支持**私有频道**与**公共频道**，使用用户自己的 TG API。

## 为什么必须是「用户会话」而不是 Bot

Bot API 只能收到被拉进群/频道的消息，读不到频道历史，也无法加入私有频道。用户
自己有 api_id/api_hash，可以用 Telethon 登成一个普通 TG 账号，能读自己已加入的
任何频道（公开/私有），也能读到历史消息。

## 设计

1. **凭据**：`tg_api_id` / `tg_api_hash` / `tg_session`（StringSession）。
   设置页没有直接在配置里贴 session 的强制要求：可以点页面上的「登录 TG」，
   走「手机号 → 验证码 →（可选）两步密码」，成功后把 session 写回配置。
2. **频道**：多行列表，支持 `@username`、`t.me/xxx`、`-100...`、邀请链接。
3. **扫描**：后台线程按 `tg_monitor_interval_minutes` 轮询；每个频道记录最后处理的
   消息 id，只读新消息；首次按 `tg_monitor_scan_limit` 回溯最近 N 条。
4. **解析**：从消息文本抽取网盘链接（复用搜索渠道的域名表：115/夸克/阿里/天翼/
   移动/123/光鸭/UC/迅雷），另支持 magnet、ed2k；按链接去重，同一资源只入一条。
5. **入库**：`data/tg_monitor/items.json`，最多保留 `tg_monitor_max_items` 条。
   独立 JSON 而不是插件私有库：条目是消息级数据，放进 `CloudSubscribeDataStore`
   要加表迁移，收益不大。
6. **转存**：页面点「转存」→ 选目标订阅 → 复用 `sync/manual`（手动添加）流程，
   由它做季集识别、跨盘转存、整理。监控线程本身**不直接操作网盘**。

## 边界

- 不做「自动转存」：频道消息质量参差，先人工过一眼。
- 不解析频道里图片/文件形式的资源（只读文本消息）。
- 不代用户加入频道：私有频道需要用户自己先加入。
- TG 会话等同于账号权限，只存配置、不写日志/历史/通知。

## 验收

- 单测：链接抽取、频道写法归一、增量扫描去重、未启用时空跑。
- 真机：设置页登录 → 填频道 → 立即扫描 → 列表出现资源 → 转存到订阅成功。
