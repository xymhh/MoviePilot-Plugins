# 115 网盘整理台（手动 / 定时）

> 状态：已完成 2026-10-19 → [总结](../summary/2026-10-19-115网盘整理台.md)｜[测试证据](../test/2026-10-19-115网盘整理台验证.md)
> 范围选择：用户选 A —— 在 CloudSubscribeX 内做独立整理台，先替代 P115StrmHelper 的「转移整理」；STRM/生活事件全量接管暂不做。

## 目标

把 115 里已经下载/转存好的影视文件，按媒体识别结果移动到 MoviePilot 媒体库目录并改成平台命名。先预览、再执行；支持手动与定时；不删除任何网盘文件。

## 边界（A 方案）

- 做：扫描指定 115 目录 → 识别电影/剧集 → 生成目标路径 → 预览 → 批量重命名 + 移动 → 可选生成 STRM → 汇总。
- 不做：全量 STRM 校准（已有）、Emby 生活事件、跨盘转存、自动删除旧版本、网盘回收站清理。
- 不做「原地覆盖」：目标同名文件默认跳过；可选加 ` (2)` 后缀，绝不删目标端已有文件。
- 扫描只读；执行前必须由用户在前端勾选并确认。

## 关键行为

1. **扫描**：从源路径按目录 CID BFS 遍历，最多 `organize_max_files` 个视频，深度 `organize_max_depth`；只列目录，不写盘。
2. **分组**：源根目录下的第一层目录为一个作品包（松散文件按文件名标题分组）。剧集按 `SxxExx` / `第N集` / `EPxx` 解析季集；电影取包内最大视频为主视频。
3. **识别**：`MetaInfo(包名)` + `recognize_media`；识别失败或类型不明 → 标「待确认」，不执行。
4. **目标**：复用插件现有的 `_platform_target()`（DirectoryHelper + 分类 + 重命名模板），与自动转存落点一致；预览直接展示最终目录与文件名。
5. **冲突**：同一包内重复季集只保留最大文件；目标已存在按 `organize_conflict_policy` 跳过或加后缀；跨包目标重复标冲突。
6. **执行**：先在源目录批量重命名到目标名，再批量移动到目标目录；字幕按同名字幕/同季集关联，跟视频一起搬；失败逐项记录，不回滚已成功项。
7. **STRM**：移动成功后，若已启用 `strm_generate_enabled` 且配置本地资源根，复用 `_generate_strm()` 生成/更新 STRM。
8. **定时**：`organize_schedule_enabled` + `organize_schedule_cron`；默认关闭；开启后到点扫描并按 `organize_schedule_auto_execute` 决定是否自动执行。

## 配置项

| 键 | 默认 | 说明 |
| --- | --- | --- |
| organize_source_path | "" | 115 待整理源目录，如 `/待整理` |
| organize_max_files | 500 | 单次最多扫描视频数，1-5000 |
| organize_max_depth | 8 | 递归深度，1-20 |
| organize_include_subtitles | true | 随视频搬字幕 |
| organize_conflict_policy | skip | `skip` / `suffix` |
| organize_schedule_enabled | false | 定时整理开关 |
| organize_schedule_cron | "0 4 * * *" | 定时 Cron |
| organize_schedule_auto_execute | true | 定时扫描后自动执行 ready 项 |
| organize_schedule_notify | true | 完成后发通知 |

## 接口

- `POST /organize/scan` `{source_path?, max_files?, include_subtitles?}` → `{scan_id}`
- `GET /organize/status` → 扫描/执行状态、分组、设置
- `POST /organize/execute` `{keys?: []}` → 开始后台执行
- `POST /organize/stop` → 请求停止
- `GET /organize/history` → 最近 20 次执行摘要

## 验收

- 纯函数单测：递归扫描（含深度/上限/停止）、季集解析、分组、重复集保留最大、目标冲突。
- 服务单测：假 provider 执行 rename→move 顺序、字幕跟随、同名跳过、失败不回滚。
- 全量 `pytest` 通过（既有 2 例 p115client 环境失败除外）。
- 前端 `pnpm build` 通过，dist 入库。
- 真机：用户在 115 选一个待整理目录，预览目标路径正确，执行后用 Emby 能看到入库/STRM。
