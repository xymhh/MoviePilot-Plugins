# 判重只信「目标目录里有实物」的版本（1.6.51）

> 状态：已实现并发布 1.6.51（单测通过，真机复测待回报）→ [总结](../summary/2026-10-16-判重只信实测存在.md)｜[单测证据](../test/2026-10-16-判重存在性校验单测.md)
> 时间：2026-10-16｜对象：`plugins.v2/cloudsubscribex`

## 1. 现象（用户真机）

订阅《反恐特警组：放逐者》补齐缺失集，跑完网盘里**仍然只有 S01E04.mp4(679MB)**，E01/E02/E03 全盘没有。

插件日志 16:11–16:14 三集各一行：

```
按季集判重跳过：同评分且候选文件未更大
```

即：判重认为 E01/E02/E03「已有更优或同等版本」，于是跳过转存。

## 2. 根因链

1. 历史上这三集留下了 `status=成功` 的转存记录，但记录里 **`cloud_dir` 为空、`file_name` 还是源文件名 `01..mp4`**（查无落盘痕迹）；
2. 这些「成功」记录又被写成 **MP 整理历史**（`_platform_history_entries` 只认 `status==成功`）；
3. 下一轮判重把 MP 整理历史当基线（`handlers/sync/baseline.py` 的 `MoviePilot整理记录` 来源），**没有任何「文件还在不在」的校验**；
4. 于是 E01–E03 成了**幻影版本** → 判重 skip → 缺失集永远补不上（越跑越稳，永远不会自愈）。

同一个数据源还喂给洗版基线，所以幻影版本在洗版路径上同样会挡事。

## 3. 设计原则（用户要求）

> 「要健全代码的话，要留一条手动链路保底，完全依靠自动化难免会有问题。」

所以本次改动分两层：**自动判定收敛到「有实物才算存在」** + **保留/补齐人工兜底入口**。

## 4. 改动

### 4.1 自动层：历史版本必须能在目标季目录里找到实物

`handlers/sync/episode_dedup.py`

- 新增 `_season_dir_files()`：解析目标季目录 + 列目录，返回 `(是否拿到实测数据, 目录路径, 文件条目)`，判重扫描与此处共用，结果进 `_season_listing_cache`（TTL，随 `clear_runtime_cache` 清理）；
- `_scan_episode_versions_in_dir()` 改为消费该结果（行为不变）；
- `_collect_episode_versions()` 里，**基线中来源为 `MoviePilot整理记录` / `插件转存记录` 的条目**先过存在性校验，不通过就丢弃并打 INFO：
  - 通过：该集在目录扫描结果里（有实物）／记录里的文件名或 `file_id` 命中目录列表（文件名解析不出季集但文件确实在）／记录带 `cloud_dir` 且**不是**本季目录（媒体库等我们没扫的地方，不越权判定）；
  - 不通过：记录无 `cloud_dir`、文件名对不上、`file_id` 也不在 → **按缺失处理**，日志写明季集 + 来源 + 文件名；
  - **拿不到实测数据**（目录解析失败 / 列目录 `checked=False`）→ 保留条目，回旧口径，避免把网络抖动误判成「该集不存在」后重复转存。

### 4.2 手动层：保底入口

| 入口 | 位置 | 用途 |
| --- | --- | --- |
| **重新转存此记录**（本次新增对「可疑成功」开放） | 历史页记录行 | 跨盘「成功」但 `cloud_dir` 为空或文件名没换成目标名 → 不再回「跨盘任务已成功完成，无需重试」，而是允许人工重转 |
| 删除记录 | 历史页 | 删掉写错的记录（可选联动删网盘文件），下一轮按目录实测重新判定 |
| 手动同步 | 订阅页 | 重跑一次扫描/转存，缺集由目录实测决定 |
| 关闭「按季集判重替换」 | 配置页 | `episode_dedup_enabled=false` → 判重门整体放行，回到旧口径（最后兜底） |

### 4.3 防复发：跳过不再污染记录

`handlers/sync/history.py::append_history_records`

- 入参是「跳过」、当前记录是「成功」时：**保留**成功记录的落盘字段（`file_name` / `target_file_name` / `cloud_dir` / `cloud_file_id` / `cloud_drive_name` / `file_size`），不让跳过把成功记录改成「成功但没有文件」；
- 这条合并**不再写进 MP 整理历史**（假成功写进去就是下一轮的幻影来源）。

## 5. 不做的事

- 不改成「按 file_id 反查云盘」验证其它目录的版本（要多打一次网盘接口，本季目录已能覆盖 99% 场景）；
- 不因为「拿不准」就跳过转存（回退姿态与用户预期同向：拿不到数据 → 维持旧行为）；
- 不动 1.6.42 起「订阅搜索/扫描等非点选路径逐字节不变」的边界。
