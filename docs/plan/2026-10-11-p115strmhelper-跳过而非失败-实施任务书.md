- 仓库（本地工作副本）：`/app/working/workspaces/default/moviepilot-plugins`
- 插件源码：`plugins.v3/p115strmhelper`（P115StrmHelper 2.7.25，MoviePilot V3 插件线）
- 日期：2026-10-11
- 状态：已实施 2026-10-11（版本 2.7.26）→ 验收证据 `../test/2026-10-11-p115strmhelper-跳过语义-单测与静态检查.md`
- 实施偏差（主 agent 复核后收紧）：删除源文件的条件由「所有跳过」收窄为「仅原因=媒体库存在同名文件且质量更好」；never 模式与第三方插件拒绝覆盖的跳过只记日志与通知、保留源文件（避免误删更好版本）
- 用户已拍板：方案 1（跳过不写失败记录）+ 跳过即删低质量源文件 + 交付到 GitHub fork

## 1. 背景（为什么改）

插件「接管网盘整理」时，遇到媒体库已有同名文件且体积不小于源文件，会判定跳过
（`helper/transfer/handler.py:708` / `:720`，`helper/transfer/handler_linked_batch.py:339` / `:386`），
但把这条裁决塞进了**失败通道**：`task_failures` → `failed_tasks` →
`_record_fail()`（`handler.py:1877`）→ `add_transfer_fail()`。
MoviePilot V3 宿主自身对这种「覆盖跳过」有专门语义（`app/chain/transfer/filter.py:719-734`
`_is_overwrite_declined` + `app/chain/transfer/settlement.py:410-440`）：**不写失败记录**、不发失败通知、不重试。
叠加历史表唯一索引 `ux_transferhistory_src_storage(src, src_storage)`（同源写失败会 replace 掉原成功记录），
后果是该路径长期失败态、每次事件都重试并重推失败通知。

## 2. 目标行为（逐条可验收）

命中跳过（原因是「媒体库存在同名文件，且质量更好」或「媒体库存在同名文件，当前覆盖模式为不覆盖」）时：

1. **不写任何整理历史记录**（无论同源此前是否已有成功记录），不发 `EventType.TransferFailed` 事件，
   不登记 AI 智能体重试；原成功记录原样保留。
2. 日志：`【整理接管】已跳过（库内更优，不写失败记录）: {源路径} -> {目标路径}，原因: {原因}`。
3. **删除低质量源文件**：`StorageChain().delete_media_file(fileitem=task.fileitem)`；
   成功记 info、失败记 error（失败不阻断其它任务）；随后在 `configer.notify` 为真时发一条插件通知
   （`post_message(mtype=MessageType.Plugin, title="【整理接管】已跳过（库内已有更优文件）", text="...")`，文案含源路径与「质优文件已删除/删除失败」）。
4. 任务收尾：对跳过任务组调用
   `self._remove_completed_jobs(tasks_by_media, task_action="fail", check_method="is_done")`
   （宿主对覆盖跳过也是把任务置为「未入库」，此处保持一致）。
5. 汇总日志：`【整理接管】批量处理完成，成功: {x} 个，跳过: {y} 个，失败: {z} 个`。

## 3. 精确改动点

### A. `plugins.v3/p115strmhelper/helper/transfer/handler.py`

1. `_batch_move_or_copy()`（`:507`）
   - 在 `task_failures: Dict[str, str] = {}`（`:522` 附近）旁新增 `task_skips: Dict[str, str] = {}`；
   - `:685`、`:732` 两处 `task_failures[task_path] = skip_reason` → `task_skips[task_path] = skip_reason`，其余逻辑（`continue`）不动；
   - 结果组装（`:938` 起）：新增 `skipped_tasks: List[Tuple[TransferTask, str]] = []`；在
     `for task in tasks:` 判定链**最前面**插入
     ```python
     if task_path and task_path in task_skips:
         skipped_tasks.append((task, task_skips[task_path]))
         continue
     ```
     （必须早于 `task_failures` / `task_main_file_status` 判定）；
   - 日志（`:986`）补「跳过: {len(skipped_tasks)} 个」；
   - 返回签名（`:990`）`(failed_tasks, success_tasks)` → `(failed_tasks, skipped_tasks, success_tasks)`。
2. `process_batch()`（`:315`）
   - `failed_tasks` 声明处（`:340`）新增 `skipped_tasks: List[Tuple[TransferTask, str]] = []`；
   - 「批量移动/复制文件」段（`:366-375`）解包改三类：
     ```python
     if self._pan_transfer_linked_subtitle_audio():
         failed_in_step, skipped_in_step, remaining_tasks = self._linked_batch.batch_move_or_copy(remaining_tasks)
     else:
         failed_in_step, skipped_in_step, remaining_tasks = self._batch_move_or_copy(remaining_tasks)
     failed_tasks.extend(failed_in_step)
     skipped_tasks.extend(skipped_in_step)
     ```
     （其余步骤 create/rename 仍是两类返回值，不要改）；
   - `:424` 之前插入 `if skipped_tasks: self._batch_record_skips(skipped_tasks)`（顺序：先跳过、后失败）；
   - 汇总日志（`:428-433`）加「跳过: {len(skipped_tasks)} 个」。
3. 新增 `_batch_record_skips(self, skipped_tasks)`（放在 `_batch_record_failures` `:1836` 之前）：
   逐个 `try: self._record_skip(task, reason) except: logger.error(...)`；收尾调用 `_remove_completed_jobs`（见 §2.4）。
4. 新增 `_record_skip(self, task, reason)`：
   - **不要调用 `add_transfer_fail` / `add_transfer_success`**；不要发 `EventType.TransferFailed`；
   - 按 §2 的 2/3/4 实现；删除源文件与通知的写法参考 `__init__.py` 的
     `auto_delete_inferior_source`（`:2164`，用 `StorageChain().delete_media_file` + `post_message`）；
   - 全程 try/except 包裹，任何异常只记日志，不得让 `process_batch` 抛错。
