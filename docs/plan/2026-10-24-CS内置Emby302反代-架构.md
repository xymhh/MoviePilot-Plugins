# CS 内置 Emby 302 反代 — 架构 v1

> 时间：2026-10-24｜状态：待评审｜前置：`2026-10-24-CS内置Emby302反代-调研.md`

## 1. 部署形态

```
客户端 ──► CS 反代 (moviepilot-v3:3010) ──► Emby (embyserver:8096)
                 │
                 └─ 播放请求命中 strm → 302 到 115 CDN（客户端直连）
```

- 监听端口 `3010`（可配 `emby_proxy_port`），在 MP 进程内用 **uvicorn 子线程**启动，不新增容器/二进制。
- 开关 `emby_proxy_enabled`（默认关闭），关闭时进程不启动、零开销。
- 上游 `emby_proxy_upstream`（默认 `http://embyserver:8096`），**只允许配置里的目标**，防开放代理。
- 反向代理后，Emby 的访问地址需要从 `:8096` 改成 `:3010`（或反代/反代域名指向 3010）。

## 2. 请求分流

| 请求 | 处理 |
| --- | --- |
| `GET/HEAD /videos/{id}/stream` `.../stream.{ext}` `.../original` `.../stream` | ① 反查 Path → ② 若为 `.strm` 且取到 pickcode → ③ 换直链 → ④ **302** |
| 同上但取不到 pickcode / 非 strm / 直链失败 | 透传给 Emby（回落到现在的行为，不影响可播） |
| 含 `Transcode` 相关参数（`PlaySessionId` + `VideoCodec`/`MaxStreamingBitrate` 等）或客户端明确要求转码 | **透传**给 Emby（不 302，避免转码流被打断） |
| 其他任何路径（`/emby/Items`、`/web`、`/Users`…） | 透传（流式、保留 Range/状态码/关键头） |

Range 处理：302 响应不需要带 Range，CDN 直连后客户端自己发 Range（MediaWarp 同做法）。

## 3. 从播放请求定位文件（核心）

```
播放请求 URL  →  mediaSourceId / ItemId
   ├─ 有 mediaSourceId → Emby GET /emby/Items?Ids={id}&Fields=Path
   └─ 只有 ItemId      → Emby GET /emby/Items/{id}?Fields=Path
                          （或用已缓存的 PlaybackInfo）
Path 形如 /media/strm/追更/剧集/xxx/Season 1/xxx.S01E10.strm
   ├─ 读 strm 内容（带 mtime+size 缓存，30 分钟内不重读）
   ├─ 内容含 pickcode → 换直链（复用 core/api/redirect.py 的缓存逻辑）
   ├─ 内容含 115 直链/分享链接 → 直接 302
   └─ 其他 → 透传
```

优化：Emby 的 `Path` 查询结果按 ItemId 缓存（LRU 2048，TTL 1h）；strm 内容按路径缓存；直链沿用 redirect 的 6h 缓存。

## 4. 数据与配置

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `emby_proxy_enabled` | False | 开关 |
| `emby_proxy_port` | 3010 | 监听端口 |
| `emby_proxy_upstream` | `http://embyserver:8096` | 上游 Emby |
| `emby_proxy_allowed_clients` | 空 | 空=不限制；填 UA 子串则只对匹配的客户端 302，其余透传 |
| `emby_proxy_path_prefix` | 空 | 可选：只对指定路径前缀（如 `/media/strm/追更`）的 strm 生效 |

复用已有配置：`media_server_host`、`media_server_api_key`、`media_server_path_mappings`。

## 5. 失败与回滚

- 反代进程启动失败（端口占用）→ 记错误日志，插件其余功能不受影响。
- Emby 不可达 → 返回 502（与 MediaWarp 一致）。
- 换链失败 → **透传**给 Emby（用户最多回到"能播但不直连"，不会播不了）。
- 回滚：`emby_proxy_enabled=false` 立即停用；Emby 访问地址改回 `:8096`。

## 6. 并发与限流

- 反代是异步流式转发，单请求内存占用可控（chunk 64KB）。
- 直链换链走账号限流器（`min_interval 1.5s`），但**命中缓存时不消耗额度**；
  同一文件 6h 内只换一次，实测冷启动峰值 = 同时在播的文件数。
- 不做主动预热，避免对 115 产生额外请求。

## 7. 验收标准

1. 3 个样本文件（电影 1 + 剧集 2）在 Emby 里播放，`curl -I` 看客户端拿到 **302 + Location 指向 115 CDN**；
2. 关闭反代开关后 Emby 仍能通过 8096 正常播放（回滚可用）；
3. 直链换链在 6h 缓存下，连续播放同一文件只产生 1 次 115 请求；
4. Emby 的其他请求（首页、详情、图片）经 3010 正常，无 4xx/5xx 增多；
5. 转码场景（强制转码的设备）仍由 Emby 处理，不被 302 打断。
