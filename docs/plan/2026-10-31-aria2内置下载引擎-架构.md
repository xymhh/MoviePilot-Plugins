> 状态：**已实现并通过代码级验收（2026-10-31）** → 证据见 `../test/2026-10-31-aria2内置下载引擎-验收.md`；真机待验。

## 1. 组件与职责

```
plugins.v2/cloudsubscribex/
├── bin/aria2c-linux-x86_64.xz     # 静态二进制压缩包（dmesg00 v1.37.0，3.4MB→解开 9.2MB）+ COPYING + README
├── core/aria2/
│   ├── engine.py                  # 单例 daemon：找端口、拉起、探活、重启、退出清理
│   ├── rpc.py                     # 极简 JSON-RPC（urllib）：addUri/tellStatus/changeUri/…
│   ├── service.py                 # Aria2FileDownloadService：与 HttpFileDownloadService 同签名
│   └── binary.py                  # 二进制落地校验（sha256、chmod、--version 探针、架构判定）
└── core/transfer.py               # 唯一接缝：HttpFileDownloadService 内部按配置委派引擎
```

职责边界：

- **engine** 只关心进程：`aria2c --enable-rpc --rpc-listen-all=false --rpc-listen-port=<随机> --rpc-secret=<随机>`；生命周期跟插件（惰性启动，MP 重启后第一次用到再拉起）。
- **rpc** 只关心 HTTP：一条连接、超时 5s、把 aria2 的 errorCode 映射成插件异常。
- **service** 只关心"把 CloudFile 落到 local_path"：解析链接→addUri→轮询进度→换链→校验文件大小→清理。
- **接缝** 不动任何驱动代码：`drive/quark/files.py:81` 等 8 处已经都构造 `HttpFileDownloadService`，让它在内部决定用哪个引擎。

## 2. 接缝（唯一改动点）

```python
# core/transfer.py  HttpFileDownloadService
def __init__(self, resolver, timeout=300, concurrency=5, part_size=0,
             link_refresh_interval=30.0, link_max_age=1200.0, max_retries=6):
    ...
    self._aria2 = aria2_runtime()      # 模块级单例，由插件 __init__ 配置好
    if self._aria2.enabled:
        self._delegate = Aria2FileDownloadService(
            resolver, connections=self._aria2.connections, engine=self._aria2,
        )
```

- `aria2_runtime()` 读全局配置快照；未启用/不满足条件（非 x86_64、二进制缺失、探针失败）→ `enabled=False`，行为**与现在完全一致**。
- `download_file()` 首行：`if self._delegate: return self._delegate.download_file(...)`；`_delegate` 抛任何异常 → 记 `warning` + 清残留 + 走原实现（一次回落，不循环重试）。

## 3. 配置（新增，全部默认关/中性）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `cross_transfer_aria2_enabled` | `false` | 总开关。false 时一行代码都不走 aria2 |
| `cross_transfer_aria2_connections` | `64` | 每文件连接数（1–96）。实测 >96 反而更差（128 连接 6.30 vs 96 连接 11.91 MB/s） |
| `cross_transfer_aria2_max_concurrent` | `2` | 同时下载任务数（与 `cross_transfer_max_concurrent` 取小） |
| `cross_transfer_aria2_min_split_size` | `1M` | 分段下限；大文件按 `ceil(连接数)` 自动放大 |
| `cross_transfer_aria2_disk_cache` | `32M` | aria2 `--disk-cache`，只为减少 fsync 抖动 |

前端：跨盘设置页新增"下载引擎"分组（开关 + 4 个数字），不加新页面（守"功能边界清晰才独立成页"红线）。

## 5. 关键流程

### 5.1 下载

1. `resolver(file_item)` → `(url, headers)`（复用现有 `_LinkRefresher` 语义：30s 节流、20min 上限）。
2. `aria2.addUri([url], {split: N, max-connection-per-server: N, min-split-size, dir, out: 文件名, header: [...], continue: "true", file-allocation: "none", auto-file-renaming: "false"})` → `gid`。
3. 每 800ms `tellStatus(gid, [completedLength, downloadSpeed, status, errorCode])` → `progress_callback(completed, total)`。
4. `stop_requested()` 为真 → `forcePause` + `remove` + `removeDownloadResult` + 删 `.aria2`/半成品（`preserve_partial=True` 时保留）。
5. `status=complete` → 校验 `completedLength == file_item.size`（不符视为失败）→ 删 `.aria2` → 返回 `local_path`。

### 5.2 链接失效（本方案的核心价值之一）

`errorCode ∈ {3(资源不存在), 19(名称解析失败), 24(HTTP 授权失败)}` 或连续 3 次 `downloadSpeed=0` 且 `connections=0`：

1. `refresher.get(refresh=True)` 换新链接；
2. `aria2.changeUri(gid, 1, [], [new_url])`（gid 不变，已下载分片保留）；
3. 连续 2 次换链仍失败 → 判任务失败，按 5.3 回落。

### 5.3 回落

任一条件成立即回落内置下载器（只回落一次）：

- 二进制缺失/`--version` 探针失败/架构不是 x86_64；
- daemon 起不来或 RPC 连续 3 次超时；
- `addUri` 返回 `No URI to download` 等参数类错误；
- 下载失败且换链无效。

回落时打一条 `warning`（含 gid、errorCode、原因），并 `remove` 掉 aria2 任务、删 `.aria2` 控制文件，避免下一次误续传。

## 6. 并发与限流

- 单 daemon，全局 `--max-concurrent-downloads=cross_transfer_aria2_max_concurrent`；插件侧 `Semaphore(min(aria2_max_concurrent, cross_transfer_max_concurrent))` 再夹一次。
- 每任务连接数 ≤ 96（硬夹），总连接 ≈ 96 × 2 = 192，远低于上次实测导致降速的 640。
- daemon 独占进程，不占 MP 的线程池与 FD；MP 的 `ulimit -n 1024` 不再是瓶颈。

## 7. 失败与回滚

- **开关置 false** → 立刻回到原实现，无需重启（配置读取在每次构造 service 时发生）。
- **二进制损坏** → sha256 校验失败 → `enabled=False` + 一次性 error 日志，功能等同未启用。
- **升级** → 新二进制随包；旧副本在 `/config/.../bin`，版本不一致时覆盖。
- **卸载插件** → 目录随插件目录删除；不留系统级文件。

## 8. 验收标准

单测（pytest，本地）：

1. `rpc.py`：对本地 mock HTTP 服务跑通 addUri/tellStatus/changeUri/错误码映射。
2. `binary.py`：sha256 不符 → `enabled=False`；非 x86_64 → `enabled=False`。
3. `service.py`：正常完成 / 大小不符 / 换链后 changeUri / stop 语义 / 抛错时清理 `.aria2`（各 1 例）。
4. 接缝：`aria2_enabled=false` 时 `HttpFileDownloadService` 的请求序列与 1.7.114 完全一致（用现有 driver 单测回归即可证明）。

真机（1Panel 宿主 MP 容器，用户确认后执行）：

1. 取一个 ≥5 GB 夸克文件走跨盘，`aria2_enabled=true`：日志出现 daemon 启动 → addUri → 进度 → complete；落地文件 sha1 与源一致。
2. 同文件对比 `aria2_enabled=false`：耗时/速度记录在 `docs/test/`。
3. `docker kill` 掉 aria2c 子进程 → 下次任务自动重启 daemon（或按 5.3 回落），不挂死。
4. 断点续传：下到 30% 手动 `forcePause`，重启任务后 `completedLength` 从 30% 续。
