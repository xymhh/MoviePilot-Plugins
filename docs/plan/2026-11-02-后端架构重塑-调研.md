# 后端逻辑与架构系统重塑 · 方案调研

> 日期：2026-11-02
> 项目：CloudSubscribeX（网盘订阅助手）
> 目标：彻底治理后端“巨石代码（10.6万行）、780处裸异常捕获吞没错误、裸线程缺乏上下文调度、存储驱动割裂、数据库缺少版本迁移”等架构病疾，引入成熟优秀的开源模型与规范。

---

## 一、调研背景与现实痛点

经过全盘代码审计与近期真实生产排障，当前插件后端的架构痛点高度集中在以下 4 处：
1. **错误吞没风暴**：整库存在高达 **780 处 `except Exception`**，异常被静默返回空列表或降级为假成功，导致排障全靠盲猜日志；
2. **调度状态割裂**：使用 7 处裸 `threading.Thread` 与 57 处硬编码 `time.sleep()`，没有统一的任务上下文（`TaskContext`），停止任务无法安全取消，且缺乏全局并发与超时控制；
3. **网盘驱动未归一化**：115、夸克、阿里、移动云盘各自维护一套接口方法（`list_files`、`save_files`、`share_link`），返回值格式与异常类型不一；
4. **数据库无迁移链**：`cloudsubscribe.db` 仅依赖 `CREATE TABLE IF NOT EXISTS` 堆砌，字段升级靠临时的 `try-alter`，无法支撑长期演进。

## 四、选型与重塑结论（三选一）

- 结论：**【① 拼装】（汲取成熟模式拼装自洽体系）**
  - **调度上下文**：借鉴 **RQ 的 Job Context 契约**，在插件内实现零外部依赖的轻量 **`TaskContext`**（统一管控每次同步的 `run_id`、取消信号、超时预算与进度广播）；
  - **异常体系**：借鉴 **HTTP Status 规范**，建立层级化的结构化异常树（`NetworkError`、`AuthExpired`、`ResourceInvalid`、`MismatchError`），彻底淘汰 780 处裸捕获；
  - **存储抽象**：借鉴 **Alist 的统一 Driver 接口规范**，重塑 **`DriveStorageAdapter`**（标准化 `list_share`、`save_share`、`check_link` 输入输出与状态码）；
  - **版本迁移**：借鉴 **Alembic 的版本表思想**，自研 50 行极简 **`schema_version` 迁移器**，单表记录版本号与执行历史。
