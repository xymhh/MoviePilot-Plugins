# 历史记录与未转存账本统一重构 · 调研与架构设计

> 日期：2026-11-02
> 目标：彻底砍掉「历史记录」内割裂的二级切换（转存结果 vs 未转存原因），将分散的两套数据源（流水表与候选账本）融合为以媒体资产为中心的统一【转存台账】。

---

## 一、现状与病因剖析

### 1. 现状痛点
- `AppPage.vue` 内部用 `historyView`（`v-btn-toggle`）在 `HistoryTable` 与 `CandidateLedgerPanel` 之间来回切。
- 逻辑割裂：
  - 用户想看「转存成功了什么」在左边；
  - 想看「为什么某集没转存」必须切到右边，面对 2000 多条全局混合流水重新按片名搜索；
  - 左边 `HistoryTable` 虽统计了 `跳过 N 条`，但明细被埋在 tooltip 中，无法展开查看具体文件与原因。

### 2. 用户心智模型归位
- 用户的心智始终是**以剧集/电影为核心**：
  - 我在追《嫁金钗》，我想知道：**它转成了哪些集？缺的那几集为什么没转？**
  - 而不是把所有剧的成功打一包，把所有剧的跳过打另一包。

---

## 二、架构重塑设计

### 1. 彻底拔除二级 Toggle
- 移除 `AppPage.vue` 中的 `history-view-switch`（`转存结果` / `未转存原因`）；
- Tab 统一命名为 **【转存台账】**。

### 2. 统一台账视图设计
- 列表以**剧集/电影分组（Group）** 为主轴：
  - 卡片头部：片名、年份、海报缩略、统计胶囊（`成功 N` / `失败 N` / `跳过 N`）；
  - 展开详情行：**将流水与跳过原因混合按时序/集数清晰呈现**：
    - `成功项`（绿色）：集数、文件名、网盘来源、文件体积、入库时间；
    - `失败项`（红色）：报错摘要、重试按钮；
    - `跳过项`（中性/提示）：清晰的一句话跳过原因（如「资源集号与缺失不符：资源含 E01-E04，缺 E05」）。

### 3. 数据层聚合（后端或前端组合）
- 利用后端既有的 `history_groups` 与 `ledger/list` 接口，前端按 `(title, year)` 或 `tmdb_id` 在分组展开时聚合展示跳过明细；
- 避免全量拉取卡顿，展开卡片时按需按剧读取该剧的候选跳过账本。

---

## 三、验收标准
1. 二级 Toggle 彻底消失，转存台账单一入口；
2. 展开任意剧集卡片，能同时看到成功流水与跳过的具体集数与明确原因；
3. 构建通过（Vite build 正常），生产环境无控制台报错。
