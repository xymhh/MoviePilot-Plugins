# 任务书：跨盘转存「秒传未命中即中止」（CloudSubscribe 1.6.45）

> 状态：已完成 2026-10-15（代码 + 20 例单测 + 文档；证据见 [../test/2026-10-15-秒传未命中即中止单测.md](../test/2026-10-15-秒传未命中即中止单测.md)，复盘见 [../summary/2026-10-15-秒传未命中即中止.md](../summary/2026-10-15-秒传未命中即中止.md)）
> 背景：用户担心跨盘转存里「真上传」的流量会拖累 115 账号，要求：**不能秒传时，直接中止该任务、删掉上传任务、清理本地缓存**，不要真上传。

## 1. 目标

给 CloudSubscribe 加一个可配置行为：当跨盘转存**秒传未命中**时，可以**中止该文件的转存**（不产生任何真实上传流量），并清理本地中继缓存与目标盘残留；同时保留现有「回落普通上传」行为，由用户选择。

## 3. 需求（必须全部满足）

### 3.1 新配置项

`cross_transfer_rapid_miss_action`，类型 `select`，取值：

- `fallback`（默认，保持现状）：秒传未命中 → 回落普通上传。
- `abort`：秒传未命中 → **中止本文件转存**，不真实上传。

UI：`transfer.js` 的「转存控制」组内新增一项，标签「秒传未命中处理」，选项「回落普通上传（默认）」/「中止并清理（不上传）」，`hint` 说明「中止不会产生任何上传流量，也不会真正入库该文件」。`cols: 4`。

`core/config.py` 默认 `"fallback"`；`__init__.py` 增加 `_cross_transfer_rapid_miss_action: str = "fallback"` 与读取逻辑（非法值一律回退 `fallback`）。

### 3.2 `abort` 模式的行为

1. **先探测，后下载**：`abort` 模式下必须在**下载/上传之前**完成秒传探测：
   - 源文件自带可用校验和（115 用 `sha1`）→ 直接用该校验和探测，**零流量**；
   - 源文件没有校验和 → 若源 provider 支持 Range，允许用「远端 Range 计算校验和」方式探测（不落本地文件）；
   - 两者都不可用 → 允许「先下载到本地缓存再探测」，但**仍然禁止真实上传**（探测未命中即中止并清理）。
2. **探测实现**：p115 drive 新增「无本地文件的秒传探测」能力（例如 `try_rapid_upload_by_hash(checksum, size, save_path, target_name)`），内部复用 `upload_file_init` 的判定逻辑；**探测本身不得产生真实上传**，且探测过程中若在 115 侧创建了上传会话/临时分片，必须在返回前清理（复用 `oss_multipart_upload_cancel` 等既有钩子；没有残留就跳过）。
3. **未命中 → 中止并清理**：
   - 任务状态：`status="failed"`、`phase="aborted"`、`message="未命中秒传，已按设置中止（未上传任何数据）"`、`error` 用同样语义（供通知与历史展示），并新增区分字段（如 `abort_reason="rapid_miss"`，具体字段名自定，需能被前端/历史读取）。
   - **本地中继缓存必须删除**，即使 `cache_complete` 为真（这是与现状唯一的语义差别：现状保留完整缓存供重试）。
   - 目标盘（115）侧若已产生任何临时/分片文件，必须删除；本文件不得在目标盘留下残留。
   - 不进入自动重试；用户可在历史里手动重试（手动重试同样遵守 `abort` 语义）。
4. **命中 → 正常成功**（走既有秒传成功路径，日志/消息不变）。
5. **多文件任务**：单个文件中止不影响同一订阅下其它文件的转存。

### 3.3 `fallback` 模式

**行为逐字节不变**（含现有错误文案、缓存保留策略、边下边传路径）。改动不得影响 `fallback` 模式的任何可观测行为。

## 4. 验收标准

1. `abort` + 秒传命中：任务成功，`method="rapid"`，本地缓存删除（与现状一致）。
2. `abort` + 秒传未命中 + 源文件有 sha1：**不发生本地下载**、**不调用真实上传**（用 mock 断言 `upload_file`/分片上传未被调用）、任务 `failed`/`aborted`、缓存目录无本任务残留、目标盘无残留。
3. `abort` + 秒传未命中 + 源文件无校验和：允许下载，但同样不得真实上传，且缓存被删除。
4. `fallback` + 秒传未命中：与 1.6.44 行为一致（回落上传、成功则 `method="fallback"`；失败时缓存保留策略不变）。
5. 配置非法值 → 按 `fallback` 处理，不抛异常。
6. 单测：新增用例覆盖以上 1-5；`pytest` 全量通过（既有 2 例 `p115client` 环境相关失败可忽略，但不得新增失败）。
7. `ruff`/lint 无新增告警；`python -m compileall` 通过。
8. 文档：`docs/test/` 新增单测证据；`docs/summary/` 复盘；README 排障表补一条；`plugin_version` 升到 `1.6.45`。
