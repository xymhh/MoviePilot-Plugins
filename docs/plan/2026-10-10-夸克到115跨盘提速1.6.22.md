# CloudSubscribe 1.6.22：跨盘转存（夸克→115）提速与稳定性

> 状态：已完成 2026-10-10 → ../test/2026-10-10-1.6.22发布验收.md

## 背景（线上现场，2026-10-10）

用户在 MoviePilot V3 上跑「夸克订阅 → 转存 115 → 重命名入库」。跨盘转存实测：

| 现场证据 | 数值 |
| --- | --- |
| 跨盘任务卡片 | `download_speed` ≈ 84.1 KB/s、54.6 KB/s，`upload_speed` ≈ 0 |
| 115 上传日志 | `partsize: 409600`（400KB）；3,803,266,431 字节 → 9317 片 |
| 分段下载日志 | `分段下载启用：256 并发连接 × 10MB 分片`（08:00:38 / 08:00:44 两个文件并行） |
| 崩溃日志 | `08:05:05 Errno 24 Too many open files`（源盘 403 重试时） |
| 容器上限 | soft nofile = 1024、hard = 524288 |
| 用户环境 | G 口上下对等带宽，同源下载不慢 |

三条独立根因：

1. **115 上传分片过小**：`client.upload_file(partsize=-1)` 交给 p115oss 自动分片，实测 400KB/片，一个 3.8GB 文件 9317 片顺序 PUT，任一片抖动即整单失败（历史里体现为「秒传未命中且普通上传失败」）。
2. **上传单连接**：`p115oss` 的分块 PUT 是顺序迭代（`oss_multipart_upload_part_iter`），而源盘（夸克）单连接只有 100~200KB/s，于是「边下边传」直传被拖到 54.6KB/s。夸克多线程能跑满 → 瓶颈是**上传侧单连接**，不是带宽。
3. **句柄耗尽**：`core/transfer.py` 原样采纳「下载线程数 256」，每个分片一个连接 + 每分片新建 session，撞爆 soft 1024 → `Errno 24`，随后掉速/失败。

## 目标 / 验收标准

1. 115 上传分片默认 16MB（≥ 官方建议下限 10MB），分片数 ≤ 9000。
2. 115 上传支持多分片并发（默认 4，可配 0~16），直传路径的读取与上传同时并发。
3. 进程 fd 上限抬到 65535；抬不动时按上限自动收敛分段下载并发，`Errno 24` 不再出现。
4. 同一段 SHA1 只读一次源盘。
5. 全部改动可回退：并发失败自动回退顺序上传，顺序失败再回退本地缓存（既有链路不变）。
6. 单测覆盖上述行为；CI 构建通过；Release 资产读回校验通过。

## 禁止事项

- 不改变「秒传 / 离线 / 后处理入库」的既有判定链路。
- 不引入新的第三方依赖（p115oss 是 p115client 的既有依赖；缺失时自动降级）。
- 不改 docker compose / 宿主机配置（用户在服务器上自行部署，插件必须自适应）。
- 不把 token / cookie / 真实配置写进仓库或文档。

## 改动清单（提交后回填文件行号）

1. `drive/p115/upload.py`
   - `P115_UPLOAD_PART_SIZE = 16MB` + `upload_part_size()`（超大文件自动放大，分片 ≤ 9000）。
   - 本地缓存路径与直传路径的 `partsize=-1` → `partsize=upload_part_size(...)`。
   - 新增 `_upload_parts_concurrently()`：`oss_multipart_upload_init` → 多线程「读源盘 Range + PUT 分片」→ `complete`；单片失败重试一次，整体失败 `cancel` 并回退顺序上传。
   - 新增 `_SourceLink` / `read_source_range()` / `_RangeReader`：并发安全的源盘 Range 读取（含 403/直链过期刷新重试 3 次，连接池硬上限）。
   - `_HttpRangeReader`：连接池设上限、`read_range_sha1` 段级缓存、暴露 `url`/`headers`。
2. `__init__.py`
   - `init_plugin` 调用 `_raise_file_limit()`：soft nofile 1024 → 65535。
   - 新增配置 `cross_transfer_upload_concurrency`（0~16，默认 4）+ 向 115 客户端管理器注入。
3. `core/config.py`：默认值。
4. `core/transfer.py`：`_fd_safe_workers()` 按 fd 上限收敛并发；`Errno 24` 提示文案更新。
5. `frontend/cloudsubscribe/src/config/fields/transfer.js`：新增「115 上传分片并发」输入项。
6. `tests/test_cross_transfer_upload_concurrency.py`：10 例单测。

## 回退方式

- 配置里把「115 上传分片并发」设为 `0` → 回到单流顺序上传（仍带 16MB 分片）。
- 装回 1.6.21 包即可完全回退（本版无数据迁移、无配置破坏性变更）。
