# 历史记录失败原因分类（failure_kind）

> 状态：已完成 2026-10-29（代码 1.7.109，未发版）→ ../test/2026-10-29-失败原因分类.md。
> 范围＝A 档（结构化分类 + 禁用永久失败重试 + 夸克状态翻译 + 写入口统一）。
> 换源按钮、失效体检任务属于 B/C 档，本文不涉及。

## 背景

历史页点击「重试」对一部分记录永远无效：夸克分享链接已失效。现状问题（已查证）：

1. `status` 只有「成功 / 失败 / 跳过 / 处理中 / 下载中 / 待确认」六个值，失败原因只存自由文本
   `failure_reason`，前端仅做 hover 提示。
2. `_history_retry_state`（`handlers/sync/history.py:726`）只看 status / transfer_mode / 有无
   `share_url`，不看失败原因 → 失效链接的记录 `can_retry=True`，「重试全部失败」会整批白跑，
   每条触发一次网盘 API，然后照样回到「失败」。
3. 夸克 `check_share_status`（`drive/quark/share.py:141`）只填 `is_valid` / `error_message`，
   从不设 `is_expired` / `is_cancelled` / `is_deleted`；115 / 123 / 天翼靠关键词填
   （`drive/p115/share.py:157-165`）。所以夸克永远给不出「已过期 / 已取消 / 文件已删除」。
4. 写入口不一致：`handlers/sync/television.py:1081` 写 `item["error"]`，历史页只读
   `failure_reason` → 这类失败在界面连原因都不显示。
5. 重试失败会覆盖成通用文案 `"重试转存失败"`（`handlers/sync/retry.py:535`）。

## 决策：加原因维度字段，不动状态枚举

不改 `status` 枚举的理由：前端筛选、分组统计、`failed_count`、「重试全部失败」「删除权限」全部按
`"失败"` 字面量过滤，新增枚举值要全链路改，风险大于收益。原因维度新增字段是正交的，老数据可回退推断。

### 新增字段（与 `failure_reason` 同时写入历史记录）

| 字段 | 取值 |
| --- | --- |
| `failure_kind` | `share_invalid` / `file_missing` / `checksum_miss` / `risk_control` / `target_space` / `network` / `offline_submit` / `postprocess` / `upload` / `unknown` |
| `failure_retryable` | 布尔；`share_invalid`、`file_missing` 为 `false`，其余 `true` |

`failure_kind` 缺省时按 `failure_reason` 文本回溯推断（覆盖 1.7.108 及以前的老记录，不需要迁移脚本）。

### 行为变化

1. `_history_retry_state`：`status == 失败` 且 `failure_retryable == false` → `can_retry=False`，
   `retry_title="原分享已失效，需重新搜源"`。批量重试已有 `can_retry` 过滤，自动排除。
2. 夸克 `check_share_status` 补齐 `is_expired` / `is_cancelled` / `is_deleted` / `error_code`，
   `status_text` 因此能输出「已过期 / 已取消 / 文件已删除」而不是原始 message。
3. 统一写入口：`television.py` 的 `error` 改为 `failure_reason`（并分类）；重试链路在判定
   分享无效时**先落盘**分类再抛出，`_mark_history_retry_failed` 依据异常文本分类，不再统一写死。
4. `prepare_history_records` 输出 `failure_kind` / `failure_retryable` / `failure_label`，
   前端后续可直接消费，不必自己推断文本。

## 接口约定

- `classify_failure(reason: str) -> str`：文本 → kind，未命中返回 `unknown`。
- `is_permanent(kind: str) -> bool`：是否永久性失败。
- `failure_label(kind: str) -> str`：中文展示名。
- `apply_failure(record: dict, reason: str, kind: str = "") -> dict`：写 status/原因/分类三件套。
- `failure_kind_of(record: dict) -> str`：读记录的分类，缺省按文本推断。

## 兼容与回滚

- 老记录无 `failure_kind` → 读时推断，行为与新记录一致；无需数据迁移。
- 回滚方式：`PERMANENT_KINDS` 置空即可让所有失败记录恢复可重试，不涉及数据结构变更。
- 不新增状态枚举值、不改前端 `dist`、不改历史页统计口径。

## 验收

- 单测：分类函数、老数据回溯、`_history_retry_state` 永久失败禁用、写入口字段齐备、夸克状态翻译。
- 全量 pytest 通过（存量 3 例失败除外），ruff 0 error。
- 实际界面验证：失效链接的失败记录，重试按钮变灰、title 提示「原分享已失效，需重新搜源」；
  「重试全部失败」计数不含这些记录。
