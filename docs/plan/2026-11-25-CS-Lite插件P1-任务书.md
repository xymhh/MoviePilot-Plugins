# 任务书：CS Lite 独立插件 P1（骨架 + 搜索渠道 + 跨盘转存）

> 执行者：ACP runner（opencode）｜验收：主 agent
> 仓库/目录：`/app/working/workspaces/default/moviepilot-plugins-cs`
> 交付物：`plugins.v2/cloudsublite/`（新插件，类 `CloudSubscribeLite`）+ `package.v2.json` 新增条目

## 一、背景（必读）

- 现有插件 `plugins.v2/cloudsubscribex`（id `CloudSubscribeX`，12.4 万行）功能过多；用户
  已把「整理/STRM」交给另一个插件 P115StrmHelper，只需要 CS 的**搜索渠道、跨盘转存、
  渠道签到、榜单订阅**四块。
- 之前试过「开关模式」（1.36.x 的 cs_lite_mode）被否：同一进程里仍会 patch MP 的
  `_storage_schemas`、服务表里仍出现 STRM 任务。**这次要一个真正独立的插件**。
- **P1 只做前两块**（搜索渠道 + 跨盘转存）；签到/榜单在 P2/P3，届时再补。

## 二、P1 范围（严格照做，不要扩大）

1. 复制 `plugins.v2/cloudsubscribex` → `plugins.v2/cloudsublite`（原插件保持不动）。
2. 重命名：
   - 目录名 `cloudsublite`；
   - 插件类 `CloudSubscribeX` → `CloudSubscribeLite`；
   - `plugin_name` → `网盘订阅 Lite`；`plugin_version` → `1.0.0`；
   - 插件 id（MP 用目录名）即 `CloudSubscribeLite`；
   - 代码里若出现绝对包名 `app.plugins.cloudsubscribex`，改成 `app.plugins.cloudsublite`。
3. **删掉 MP 存储适配器**（这是与 P115StrmHelper 冲突的唯一来源）：
   - 删 `drive/p115/storage.py`；
   - 删/断开 `_register_u115cs_storage`、`bind_u115cs_provider`、`register_u115cs_storage`
     的所有引用（含 `drive/p115/__init__.py`、`core/drive_manager.py` 中的 import）。
4. **服务表瘦身**（`core/api/registration.py::get_service` / `_maintenance_services`）只留：
   - 订阅同步服务（`CloudSubscribe`）
   - 榜单自动订阅（保留声明，逻辑留到 P3 不启用也行）
   - 签到服务
   - 缓存目录巡检
   删掉：STRM 全量/增量、整理（organize）、115 整理、重试索引维护（可留）。
5. **API 路由**（`core/api/registration.py::get_api`）：删掉以下 path 的注册与 import：
   `/strm/*`、`/duplicates/*`、`/recyclebin/*`、`/funnel/*`、`/organize/*`、`/doctor` 中与
   STRM/整理相关的检查项保留但不调用对应服务。
6. **侧栏导航**（`get_sidebar_nav`）只保留：渠道管理、频道监控（可留）、失败记录。
   删掉：整理队列、重复扫描。
7. **不删的代码**：整理/STRM 的模块文件先保留（P2 再物理删除），但必须做到
   **不注册、不 import 失败、不影响启动**；如果某个 import 链拉着已删的 storage.py，
   就把它改成延迟 import 或删除该引用。
8. 前端 `dist/`：先不动（P2 再裁），但要保证 `remoteEntry` 能加载、配置页能打开。
9. `package.v2.json` 新增 `CloudSubscribeLite` 条目（version 1.0.0，name 网盘订阅 Lite，release true）。
10. 提交：`git add plugins.v2/cloudsublite package.v2.json` + 中文 commit，不要 push。
