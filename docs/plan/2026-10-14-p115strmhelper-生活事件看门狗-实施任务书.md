# 任务书：P115StrmHelper 生活事件监控「静默停摆」硬化（2.8.78）

工作目录：本仓库根 `/tmp/cs-full`，只改 `plugins.v3/p115strmhelper`。

## 一、背景（真机故障，已复现，不是猜测）

插件 2.8.77 的生活事件监控线程会**静默停摆**：`is_alive()` 仍为 True，但不再拉取/处理 115 生活事件，
且**一行日志都没有**，可持续 20 小时以上。后果：转存进媒体库的新文件没有 STRM，
直到次日 02:00/02:30 的「全量 STRM 生成」才兜底补上。

现场证据（2026-10-13 ~ 10-14，Asia/Shanghai）：

- 缺 STRM 的 5 个文件，其 115 生活事件**都在事件流里**（用插件自带接口 `check_life_event_status` 传
  `start_time` 全量拉取可复现）：`希望 (2026)` 10-14 00:09:32、`死刑将至 E18` 10-13 18:44:03、
  `雷霆令 E07` 18:37:54、`喜剧之王 E17` 18:35:40、`美人余 E09` 18:33:41，全部 `type=6 move_file`。
- 插件日志 10-13 12:35→10-14 07:00 共 5800+ 行，`生活事件` **0 命中**（连线程启动行都没有）。
- 10-14 02:30:58 全量同步补上了 E18/E09 等；但 02:33:37 转存的 `美人余 E11/E12` 至今无 STRM
  （同步 02:30:58 已跑完，之后事件全漏）——故障仍在持续。
- 同一类故障 10-12 已发生过一次（清理线程卡在 115 请求上 5 小时 52 分）。

## 二、代码事实（请先复核，行号以当前 HEAD 为准）

1. `service/__init__.py` → `check_monitor_life_guard()`（约 267-330 行）：**只用 `is_alive()` 判活**，
   卡死线程被视为健康；且该函数所有分支均为 `logger.debug`（默认日志级别看不到）⇒ 静默。
2. `helper/life/client.py` → `once_pull()`（约 2149 行）首行 `if self._wait_for_transfer_complete(): return`；
   `helper/life/transfer_wait.py` 只在「整理队列快照连续 60 分钟无变化」时才退出等待 —— 队列长期非空且状态
   不断变化时，会一直不拉取（且只 debug 日志）。
3. `helper/life/client.py` → `_pull_life_events()`（约 2093 行）用 `list(iterator)` 一次性抽干事件迭代器：
   无单轮上限、无进度心跳、`from_time` 异常时可能长时间翻页而不产生任何日志。
4. 游标 `from_time/from_id` 只在**内存**里推进；只有 `stop_event` 触发时才
   `configer.save_plugin_data("monitor_life_strm_files", ...)`（见 `service/life/__init__.py`）。
5. `monitor_life_first_pull_mode=latest`（线上现状）⇒ 线程重启从 `time()` 起，**停机窗口内的事件永久丢失**。
6. `api.py` 的 `check_life_event_status` 自检只看 `is_alive()` + 一个 `from_time=now` 的即时拉取
   （`helper/life/test.py:50`），永远是「无新事件」⇒ 假阴性。
7. 客户端本身有超时体系（`service/__init__.py:104 create_client(default_timeout=configer.get_default_timeout())`），
   所以**不要**把本补丁做成"再加一堆超时"；重点是**判活、自愈、不丢事件**。

## 三、必须达成

1. **可观测**：线程「活着但不干活」必须能被发现；发现时**打印卡住线程的 Python 栈到插件日志**
   （这是目前定位真凶的唯一手段——现场拿不到栈）。
2. **自愈**：发现后自动停止并以「回放模式」重启监控线程。
3. **不丢事件**：重启/解卡后从「持久化游标 - grace」回放，而不是从 now 起。
4. **不误杀**：MP 整理期间 `wait_for_transfer_complete` 的合法等待不得被判为停摆。
5. 老用户升级后**无需改配置**即获得上述能力。

## 四、实现要求（按此实现；有更好方案请在报告里说明理由）

### A. 心跳
`MonitorLife` 增加 `last_progress_ts: float`（`time()`）与线程安全读写（已有锁就用现有锁，别新起全局锁）。
至少在这些点更新：
- 每轮 `once_pull` 走完（无论是否拉到事件）；
- `wait_for_transfer_complete` 每次循环（正常等待＝进度）；
- `_pull_life_events` 若改逐页/逐条迭代，每页更新一次。

### B. 看门狗（改 `check_monitor_life_guard()`）
判定：`线程 is_alive() and 距 last_progress_ts > 阈值` ⇒ 判定停摆。阈值来自新配置
`monitor_life_stall_timeout_minutes`（默认 **15**，最小 5，0=关闭看门狗）。
动作顺序：WARNING 日志（含停摆分钟数、线程名/ident）→ 打印该线程栈（`sys._current_frames()` 取帧 +
`traceback.print_stack(frame, file=插件日志句柄)`；日志句柄拿不到时用 `logger.error`）→
`configer.notify` 为真时发通知 → `_stop_monitor_life_internal()` → 以回放模式 `_start_monitor_life_internal()`。
注意：**停摆检测与重启必须 INFO/WARNING 级**，不许 debug。

### C. 回放（不丢事件）
- 每轮结束把 `{"from_time":..., "from_id":...}` **持续**持久化到插件数据（沿用现有 key
  `monitor_life_strm_files` 或新增 key，注意别和 "last" 模式语义打架；每轮写一次即可，别每条事件写）。
- 看门狗触发的重启：起始时间取 `min(持久化 from_time, now) - replay_grace`，
  新配置 `monitor_life_replay_grace_minutes`（默认 **10**，0=不回放）。
- 用户手工重载插件/改配置的重启：仍按 `monitor_life_first_pull_mode`（latest/all/last）语义，
  **不要**改变老语义。

### D. 整理等待兜底
`wait_for_transfer_complete` 增加绝对上限：新配置 `monitor_life_transfer_wait_max_hours`（默认 **6**）。
超过上限：WARNING（说明等了多久、队列还有多少任务）并返回 False 恢复监控拉取，不要无限等。

### E. 拉取单轮上限（防无限翻页）
新配置 `monitor_life_max_events_per_pull`（默认 **2000**）：达到上限即结束本轮并记 INFO，
下一轮从游标继续；期间心跳照常。

### F. 自检增强（`api.py` + `helper/life/test.py`）
`check_life_event_status` 的 debug_info 里增加：`上次进度时间`、`停摆分钟数`、`持久化游标`；
「测试拉取」改成真实窗口（如 `from_time=now-300`）并在结果里标注窗口，避免「无新事件＝正常」的假阴性。

### G. 测试（必须跑通）
`plugins.v3/p115strmhelper/tests/`，unittest，风格与现有 `test_life_transfer_wait.py` /
`test_p115_client_timeout.py` 一致（用 `tests/_stub_host` 桩宿主，不联网）。
新增用例至少覆盖：
1. 心跳超阈值 ⇒ 判停摆、触发重启、栈被写出（可用 mock 时钟/替换 logger 断言）；
2. 整理等待期间心跳持续更新 ⇒ 不误判；
3. 看门狗重启后起始时间 = 持久化游标 - grace（含 grace=0、游标缺失两种边界）；
4. 达到单轮事件上限 ⇒ 本轮结束、心跳正常、游标已推进；
5. 整理等待超过绝对上限 ⇒ 返回并记 WARNING；
6. 配置边界：阈值 0（关闭）、最小值钳制、负数/超大值。
运行命令（与 CI 一致）：
```
PYTHONPATH=$PWD/plugins.v3/p115strmhelper/tests/_stub_host:$PWD/plugins.v3/p115strmhelper \
python -m unittest discover -s plugins.v3/p115strmhelper/tests -p "test_*.py" -v
```
