# 分享识别重构方案：文件优先 · 三级证据链

> 日期：2026-11-07
> 状态：**待评审**（只出方案，未动代码）
> 触发：两个真实频道样本暴露「消息优先」识别链路在多版本目录、分卷 zip、混淆目录名下全面失效
> 评审来源：本会话实测数据 + codex（框架/安全优先）+ qoder（最小可行/工程现实）两轮独立评审，分歧见附录

---

## 0. 结论摘要

1. **识别顺序整体倒转**：先枚举分享目录树 → 按一级目录分版本组 → 组内算集覆盖 → 再定作品身份 → 最后才匹配订阅。消息只提供片名候选。
2. **消息层降级为「片名供应商」**：`更N集 / 全N集 / 完结` 一律不参与集数计算，只落一条诊断记录。
3. **缺集分三类**：`tail_missing`（正常滞后，等待）、`internal_gap`（真缺失，报警）、`unknown_total`（TMDB 无季集数，只报观测值）。
4. **版本选择三档可配**，默认 `balanced`（主版本 + 缺集从其他版本补，标 `mixed_quality`）。
5. **任何歧义都不退化成整包转**：状态机只有 `ready / needs_review / rejected` 三种终态。
6. **只认媒体后缀**：`zip/rar/7z/txt/jpg/srt` 等一律噪音，不产生集覆盖；纯压缩包分享直接跳过。这条把「猜包内有什么」整类风险删掉了。

## 1. 设计原则

| # | 原则 | 反例（现状会犯的错） |
|---|---|---|
| P1 | 目录树是事实，消息是广告 | 消息写「全30集 完结」，实际只有 27 集 |
| P2 | 集覆盖只由文件产生 | 用 `更15集` 推出 1–15，转存了不存在的集 |
| P3 | 标签只是提示，不能当结论 | 文件名写 `HDR`，体积只有同版 1/5 |
| P4 | 不确定就停，不猜 | 识别失败默认「整包转」，200GB 爆盘 |
| P5 | 每条决策可回溯到具体文件 | 现在无法回答「为什么转了这一集」 |
| P6 | **只认媒体后缀，其余全是噪音** | 用 `01-07.zip` 的包名推出集覆盖，等于猜包内有什么 |

## 2. 判定顺序（七层）

```
① 消息解析（只出片名候选 + 年份/季提示 + 诊断 claim）
        ↓
② 分享全树枚举（递归到底，拿到每个文件的完整路径与后缀）
        ↓
③ 版本分组（按一级目录名抽标签，无标签给中性组）
        ↓
④ 组内证据提取（**仅媒体文件**的文件名 → 季、集、集区间、体积；非媒体一律噪音）
        ↓
⑤ 集覆盖计算（每组独立，再算跨组并集与差集）
        ↓
⑥ 作品身份确认（目录名 + 文件名 + 消息候选 → TMDB）
        ↓
⑦ 订阅匹配与转存计划（selected / excluded / 异常码）
```

**每层的失败出口**

| 层 | 失败情形 | 出口 |
|---|---|---|
| ② | 分享不可读 / 需提取码 / 频控超限 | `rejected: SHARE_UNREADABLE` / `needs_review: SCAN_BUDGET_EXCEEDED`（partial 不转） |
| ③ | 根目录直接是散文件（无子目录） | 退化为「单版本组」，仍继续 ④ |
| ④ | 全部分组内媒体文件数为 0 | `rejected: NO_MEDIA`（不猜压缩包内容） |
| ④ | 有媒体文件但一个集号都提不出 | `needs_review: EPISODE_UNPARSED`（不转） |
| ⑥ | TMDB 无候选 / 多候选打平 / 与文件证据冲突 | `needs_review: IDENTITY_UNRESOLVED` / `WORK_CONFLICT` |
| ⑦ | 订阅不存在 | 只记录，不转（除非开启「自动建订阅」策略） |

**为什么是「先分组再定作品」（采纳 qoder 的顺序）**

混淆目录名（`M 羙 亽· 悆`）让「先定作品」必然失败；但版本目录（`4K DV杜比视界`）结构稳定、不受混淆影响。先分组可以把「哪几份是同内容不同画质」这件事确定下来，再去解决「这是哪部片」这个更难的问题。

## 3. 数据结构（落地字段）

```python
ShareScan:
    share_id, scanned_at
    tree_status: complete | partial | unavailable   # partial 一律不转
    dirs_scanned: int, requests_used: int
    groups: list[VersionGroup]
    anomalies: list[Anomaly]

VersionGroup:
    group_id            # 稳定 id，不用目录名（目录名会变）
    dir_name            # 原始名，保留
    dir_id              # 网盘目录 id
    tags: list[str]     # ["4K","DV"] / ["HDR"] / []（无标签）
    tag_source: folder | filename | none
    items: list[MediaItem]
    observed: set[int]  # 本组覆盖的集号
    size_median: int    # 本组文件体积中位数，用于异常检测

MediaItem:
    item_id, parent_group, raw_name, path
    kind: media | sidecar | other   # sidecar=字幕/外挂音轨，不参与识别但跟随转存
    ext: str                     # 小写后缀，来自白名单校验
    season: int | None
    ep_start: int | None
    ep_end: int | None          # 仅同一文件含多集时使用（如 "01-03.mkv"）
    coverage_source: filename    # 只允许 filename
    size: int
    flags: list[str]            # pure_numeric / size_anomaly

Identity:
    work_id          # TMDB id，未定为 None
    title, year, media_type, season_hint
    confidence: high | medium | low
    sources: list[str]          # directory / filename / message / catalog
    conflicts: list[str]

Coverage:
    season, observed, missing, shape  # complete / tail_missing / internal_gap / unknown_total
    per_group: dict[group_id, set[int]]

TransferPlan:
    work_id, subscription_id, season, mode  # strict / balanced / loose
    selected: list[item_id]
    excluded: list[(item_id, reason)]       # reason 必填，禁止空
    mixed_quality: bool
    anomalies: list[Anomaly]
    decision: ready | needs_review | rejected
```

**置信度按来源分开记**，不要合成单一分数：`identity.confidence`（作品）与 `coverage.confidence`（集覆盖）互不影响。

## 4. 集覆盖计算

### 4.1 证据提取（**只从媒体文件名**）

媒体后缀白名单（小写比对，取最后一个 `.` 之后的段）：

```
mkv mp4 ts m2ts mts avi mov wmv flv rmvb rm m4v mpg mpeg webm
```

`iso` **不在默认白名单**，由开关控制（默认关闭）：

| 配置项 | 默认 | 说明 |
|---|---|---|
| `treat_iso_as_media` | `false` | 开启后 `*.iso` 按媒体文件计入覆盖。蓝光原盘镜像常为「整部片/整季一个文件」，开启后集号只能靠文件名推断，`EPISODE_UNPARSED` 概率上升 |

其余一律 `kind=other`，永不参与覆盖：`zip rar 7z txt nfo jpg png url html`、广告文件、`*.part`/`*.!qB` 等下载临时后缀。

**附属文件（sidecar）另立一类**：`srt ass ssa sub idx sup vtt`（字幕）、`mka ac3 dts flac`（外挂音轨）。
它们**不参与识别**（不算集、不产生覆盖、不影响缺集判定），但**跟随转存**——只转媒体不转字幕，等于把用户下好的片子变哑巴。详见 §4.4。

| 形态 | 例 | 结果 |
|---|---|---|
| `SxxExx` | `Show.S01E05.mkv` | s=1, ep=5 |
| `第N集` / `EP05` / `E05` | `第5集.mp4` | ep=5 |
| 纯数字 | `01.mkv` | ep=1（需父目录序列佐证） |
| 单文件多集 | `01-03.mkv` | ep 1..3 |
| 季目录 | `Season 2` / `第二季` / `S02` | season=2（仅目录给提示，不给集） |
| 非媒体 | `01-07.zip`、`说明.txt`、`易和谐，在线解压吧/` | **噪音，不计入覆盖** |

### 4.2 组内并集 → 跨组比较

```
observed(group) = union(ep ranges of items in group)
observed(all)   = union(observed(g) for g in groups)
total           = TMDB season episode_count
```

### 4.3 缺集分类（三层判据，不单靠播出日期）

| 条件 | 判定 | 动作 |
|---|---|---|
| `total` 已知，`missing ⊆ (max(observed), total]` | `tail_missing` | 等待；不报警、不换版本 |
| `total` 已知，存在 `m < max(observed)` 且 m 未覆盖 | `internal_gap` | 报警；允许跨版本补 |
| `total` 未知 | `unknown_total` | 只报观测集号，不推断缺失 |
| `tail_missing` 且该集在**任一其他版本**存在 | `lagging`（上传滞后） | 只记录 |
| `tail_missing` 且该集已播出 > 7 天且全网无 | `gap_suspected` | 弱报警 |

> 为什么不能只看播出日期：样本 2 的 `28 HDR.mkv` 确实存在但体积只有同版 1/5，可能是占位文件。播出日期只能说明「应该有」，不能说明「已有正确副本」。

### 4.4 附属文件跟随（字幕/外挂音轨）

**分两件事，别混**：

| 用途 | 认哪些文件 | 结论 |
|---|---|---|
| 识别（作品/季/集覆盖） | 只有 `kind=media` | 字幕永远不产生集覆盖 |
| 转存（实际落盘） | `media` + 其归属的 `sidecar` | 字幕必须跟着媒体一起转 |

**归属判定（从宽，宁可多带）**

1. **同父目录 + 主干同名**：`01.mkv` ↔ `01.ass`、`01.chs.srt`、`01.zh-CN.ass`（去掉语言/`forced`/`sdh` 等后缀后与媒体主干相等）。
2. **同组字幕目录整体跟随**：同版本组内存在 `Subs/`、`字幕/`、`Sub/` 目录时，该目录下**全部字幕**跟随该组已选媒体（不逐个匹配，避免漏配）。
3. 跨组不跟随：A 版本组的字幕不会被塞进 B 版本组的转存清单。

**约束**

- 字幕体积小，**允许过度包含**，不做精确一一对应；漏字幕比多带几个字幕代价大得多。
- 附属文件**不得**改变 `observed`、不得触发 `NO_MEDIA`（纯字幕分享仍判 `NO_MEDIA`）、不得影响缺集分类。
- 字幕文件名里的集号可作**弱提示**（打在 `anomalies` 里供诊断），但不作为覆盖证据。
- 若某组媒体选中、而其字幕在另一组目录里（跨版本共用字幕），判 `SIDECAR_CROSS_GROUP`，**附带但不计入该组覆盖率**（默认带上，因为成本极低）。

### 4.5 压缩包与非媒体（硬规则）

- **压缩包不算媒体**：`zip/rar/7z` 一律 `kind=other`，不产生任何集覆盖，也不推断「包内大概有什么」。
- 全部为压缩包的分享 → `rejected: NO_MEDIA`，跳过并计数，不转存、不等待。
- 因而不存在「声明覆盖 vs 已验证覆盖」的风险：本方案**从不声明**未看见的集。
- 代价明确：像「美人余」这种整包 zip 打包的分享会被直接跳过。这是刻意的取舍——猜错要下 200GB，跳过只损失一次机会。

## 5. 版本策略（三档，默认 balanced）

| 模式 | 选版逻辑 | 适用 |
|---|---|---|
| `strict` | 固定优先级 `DV > HDR > SDR > 无标签`，**绝不混版**；主版本缺集就缺着 | 画质洁癖 / 洗版 |
| `balanced`（默认） | 主版本 = 覆盖集数最多者，同覆盖时按画质优先级；缺失集从其他版本补，标 `mixed_quality` | 追更日常 |
| `loose` | 每集取体积最大的一份，允许跨版本拼 | 只求完整 |

**约束**

- 同集多份：只选一份，其余进 `excluded(reason=duplicate_episode)`；默认取体积最大，但若该份 `size_anomaly` 则取次大。
- 体积异常判据：与本组同集中位数偏差 `< 0.5×` 或 `> 2×` → `size_anomaly` + `label_size_conflict`。
- 无标签目录（`4K/`）：不猜画质，`tags=[]`；画质排序时排在已知标签之后，但**覆盖优先**会救它（样本 2 它是唯一完整版）。

## 6. 异常码表

| 码 | 含义 | 是否阻断转存 |
|---|---|---|
| `NO_MEDIA` | 分享内无媒体文件（含「只有压缩包」） | 阻断（跳过并计数） |
| `EPISODE_UNPARSED` | 有媒体文件但提不出集号 | 阻断 |
| `IDENTITY_UNRESOLVED` | 作品身份定不了 | 阻断 |
| `WORK_CONFLICT` | 文件层与消息层指向不同作品 | 阻断 |
| `MIXED_CONTENT` | 分享内混多部作品且无法归属 | 阻断 |
| `TAIL_MISSING` | 尾部缺集 | 不阻断 |
| `INTERNAL_GAP` | 中间缺集 | 不阻断（可混版补） |
| `LABEL_SIZE_CONFLICT` | 标签与体积不符 | 不阻断（降级） |
| `SCAN_BUDGET_EXCEEDED` | 扫描超预算 | 阻断（转 needs_review） |
| `MESSAGE_CLAIM_MISMATCH` | 消息声称集数与文件不符 | 不阻断（仅诊断） |
| `SIDECAR_CROSS_GROUP` | 字幕位于其他版本组目录 | 不阻断（默认带上） |

## 7. 全树枚举与频控

**硬要求：递归到底，不留死角。** 不看到全部文件就没法过滤——浅层扫描会漏掉藏在「版本目录/子版本/分季目录」里的媒体，漏一个就少一集，覆盖算错、缺集误报、混版补错。所以不做深度截断。

| 项 | 策略 |
|---|---|
| 递归深度 | **无上限**，直到没有子目录 |
| 分页 | 每目录按 `_size=100` 翻页到底（`_total` 对齐） |
| 并发 | 目录级并发 2–3，单域名总并发 ≤ 3 |
| 请求间隔 | ≥ 250ms/请求；遇 429 指数退避（1s/3s/9s），连续 3 次失败即中止本轮 |
| 单分享预算 | 请求数 ≤ 200 或耗时 ≤ 90s（超出→ `tree_status=partial` → `needs_review`，**不转**） |
| 缓存 | 键 `share_id + dir_id`，TTL 10 分钟；同分享重复触发直接复用，避免重复枚举 |
| 断点续扫 | 记录已枚举 `dir_id` 集合，中断后可从剩余队列继续 |
| 幂等 | 同一 share 两次完整扫描结果必须一致 |

**预算耗尽不等于放弃**：`tree_status=partial` 时保留已扫描部分，标记 `SCAN_BUDGET_EXCEEDED` 转 `needs_review`，由用户决定是否重试（重试走断点续扫，不从头再扫）。

**噪音过滤仍在枚举之后做**：先拿全量路径清单，再按后缀筛媒体。顺序不能反——否则为了「省请求」而不进某个目录，等于提前丢证据。

## 8. 验收标准

**回归样本（固定，来自本会话实测）**

| 样本 | 期望 |
|---|---|
| 美人余（3 版本 + 全 zip + 混淆目录） | **媒体文件数 0 → `rejected: NO_MEDIA`**，不生成转存计划；计数进「因纯压缩包跳过」统计。zip 区间不产生任何集覆盖 |
| 嫁金钗（4 版本 + 尾部缺 3 + 散落补集 + 体积异常） | `4K/` 覆盖 1–30；三高码率组 `tail_missing 28–30`；父目录散落文件归为补集候选并带 `LABEL_SIZE_CONFLICT`；`balanced` 模式下计划为「主版本 30 集 + 混版标记」或「主版本 27 集 + 补 3 集」 |
| 38 条消息标题集 | 清洗后片名正确；`更N集` 一律不出现在任何集覆盖中 |

**不变量（可写成单测）**

1. 把消息里的 `更15集` 改成 `更99集`，集覆盖与转存计划**完全不变**。
2. 没有 `Identity.work_id` 时，`TransferPlan.decision` 不得为 `ready`。
3. `excluded` 每项必须有 `reason`。
4. 同一 `share_id` 两次扫描结果一致（幂等）。
5. 任何 `needs_review` 都不得生成转存动作。
6. **任何非媒体后缀的文件不得出现在 `observed` 里**（含 zip/rar/7z/txt/jpg）。
7. **媒体文件出现在任意深度都必须被发现**：同一批文件放在根目录或埋在 5 层子目录下，`observed` 必须相同。
8. **字幕不得改变覆盖**：给任意媒体旁边加/删字幕文件，`observed`、缺集分类、`decision` 均不变。
9. **字幕必须跟随**：选中某媒体时，同父目录主干同名的字幕、以及同组 `Subs/` 目录下的字幕，必须出现在 `selected` 里。

**指标（上线后统计）**

- 自动识别率（`ready` / 总数）
- `needs_review` 率与其原因分布
- 每分享平均请求数、平均耗时
- 误转率（人工回滚次数 / 转存次数）

## 9. 未验证项（实施前必须实测）

1. 媒体后缀白名单是否还需扩 `rm`/`rmvb`/`m2ts`（`iso` 已定为开关 `treat_iso_as_media`，默认关）。
2. 夸克分享 list 接口的真实频控阈值与 429 行为。
3. 分享条目是否返回任何媒体元数据（当前假设：**没有**，只有 name/size）。
4. TMDB 中文别名覆盖率（影响 `IDENTITY_UNRESOLVED` 比例）。
5. 体积异常的阈值（0.5×/2× 是拍定值，需用真实样本校准）。

## 附录：两轮独立评审的分歧与取舍

| 议题 | codex（安全优先） | qoder（工程现实） | 本方案取舍 |
|---|---|---|---|
| 枚举深度 | 完整枚举全树 | 只扫根 + 一级，频控是硬约束 | 采 qoder：浅层 + 条件下钻 + 预算上限 |
| 判定顺序 | 先抽文件证据再定作品 | 先按版本分组再定作品 | 采 qoder（混淆目录下更稳） |

| 尾部缺集判据 | 用播出日期 | 播出日期不可靠，用跨版本比较 | 两者合并：跨版本优先，播出日期仅作弱信号 |
