# 1.6.40 任务书：移动云盘资源点预览报错、点转存没反应 + 资源页类型口径

> 状态：已完成 2026-10-14 → [复盘](../summary/2026-10-14-移动云盘caiyun链接识别.md)
> 验收证据：[单测与线上复现](../test/2026-10-14-移动云盘caiyun链接回归单测.md)
> 前置：1.6.39（移动云盘能搜到了，但搜出来用不了）→ [1.6.39 复盘](../summary/2026-10-14-移动云盘搜索类型键.md)

## 背景（用户可见现象，1.6.39 真机）

用户升级到 1.6.39 后，移动云盘资源**能搜出来了**（这是 1.6.39 修好的），但紧接着三个新现象：

1. 资源类型只设置了移动云盘，可是资源页里 PanSou 渠道**显示了所有类型**；
2. 移动云盘结果点**预览**无法解析；
3. 移动云盘结果点**转存**没反应。

## 现象 1 定性（不是 bug，是设计；用户已选定改法）

`search/pansou/service.py` 里资源页走 `resource_list_mode`，出站**按设计请求全部 9 种类型**，
后端 `core/api/search.py` 也只按 `SUPPORTED_RESOURCE_TYPES`（全部支持类型）过滤 ——
「资源类型优先级」只在**订阅搜索**里当硬过滤用。

用户决定（2026-10-14）：**A —— 资源页也按「资源类型优先级」收窄**，与订阅搜索同口径。

## 现象 2 / 3 根因（一个域名没登记，炸三处）

PanSou 返回的移动云盘分享链接域名是 **`caiyun.139.com`**（`/w/i/<id>` 与 `/m/i?<id>` 两种写法），
而 `search/types.py` 的 `TYPE_HOSTS['yun139']` 只登记了 `yun.139.com` 与 `caiyun.feixin.10086.cn`。

于是 `resource_type_from_url("https://caiyun.139.com/...")` 返回**空串**，连带三处失效：

| 现象 | 触发点 | 结果 |
| --- | --- | --- |
| 预览无法解析 | `core/api/search.py` 校验 `resource_type_from_url(url) != resource_type` | 直接回「资源链接格式或类型无效」 |
| 转存没反应 | `handlers/sync/resources.py` 的 `_supported_resource_type({}, url)` 识别不出 → 历史兜底 `or "115"` | 139 资源被当成 **115 直存**，跨盘批次永远轮不到它 |
| 手动转存门槛 | 移动端短链 `/m/i?<id>` 不在 `drive/yun139/share.py` 的 `_SHARE_ID_PATTERNS` 里 | 解析不出 `share_code`，门槛校验也拒绝 |

## 改动范围（最小改动，不重构）

| 文件 | 改动 |
| --- | --- |
| `search/types.py` | `TYPE_HOSTS['yun139']` 补 `caiyun.139.com`；`_TYPE_TEXT_MARKERS['yun139']` 同步补；新增共享口径函数 `configured_resource_types()` |
| `drive/yun139/share.py` | `_SHARE_ID_PATTERNS` 补移动端短链 `r"/m/i\?([A-Za-z0-9]+)"` |
| `search/pansou/service.py` | 资源页出站类型改走 `configured_resource_types`（配置为空退回全部支持类型）；订阅搜索的「配置 ∩ 目标盘能力」收窄保持不变 |
| `core/api/search.py` | 资源页入站过滤改走同一份 `configured_resource_types`（读取 handler 的 `_resource_type_order_config`，回退插件 `_resource_type_order`） |

## 验收标准

1. `resource_type_from_url` 对两种 caiyun 链接都返回 `yun139`，老域名行为不变；
2. 两种 caiyun 链接都能解析出 `share_code`（含 `#提取码` 写法）；
3. 预览接口的类型校验与手动转存门槛校验都放行；
4. 转存归类不再把识别不出的 139 资源兜底成 115（未知域名仍按历史行为兜底 115）；
5. 资源页出站只请求「资源类型优先级」里勾选的类型；未配置该字段时退回全部支持类型；
6. 全量单测 + `scripts/lint.py --all` 通过；
7. 旧代码上新增用例必须失败（`git stash` 反证）。

## 禁止事项

- 不改缓存层、不动订阅搜索的既有收窄逻辑；
- 不给「未知域名」新造兜底类型（保持历史 115 兜底）；
- 真实配置（cookie / token / webhook / 账号）一律不入库、不写入文档。
