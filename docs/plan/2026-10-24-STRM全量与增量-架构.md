# STRM 全量/增量 + Emby 302（CS 内置）— 架构

> 状态：设计冻结 2026-10-24（调研见 [2026-10-24-STRM全量与增量-调研.md](./2026-10-24-STRM全量与增量-调研.md)）
> 落点：`plugins.v2/cloudsubscribex/`，不新增插件、不新增容器。

## 1. 职责边界

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| CS 转存链路（已有 `handlers/sync`） | 转存完成后投递 `strm_write` 任务（不再同步阻塞写盘） | 不做网盘扫描 |
| `utils/strm.py`（已有，扩展） | 模板渲染（新增 `{pickcode}`）、原子写文件 | 不做遍历 |
| `utils/strm_scan.py`（已有，升级） | 全量遍历 + 断点续扫 + 增量 diff 共用同一遍历器 | 不做调度 |
| **`core/api/strm_runtime.py`（新增）** | `strm_write` 队列消费、重试、指标 | 不做 302 |
| **`core/api/redirect.py`（新增）** | 302 端点：pickcode → 直链，Range/UA 透传 | 不写文件 |
| **`core/strm/index.py`（新增）** | `strm_index` 表 CRUD、diff 判定 | 不管 HTTP |
| 外部 9527 直链服务 | 本方案落地后**降级为可选**，不再必需 | — |

数据流（三条入口，一个消费者）：

```
① 转存成功 ──► strm_write 队列 ─┐
② 增量定时(10min) ─► diff ─────┼──► StrmWriter ──► 本地 .strm（原子写）
③ 手动/每日全量 ───────────────┘         │
                                          └──► strm_index 落库
Emby ──► .strm 内容 ──► CS /redirect?pickcode=xxx ──► 302 115 CDN
```

## 2. 接口定义

### 2.1 302 端点（新增）

```
GET|HEAD /api/v1/plugin/CloudSubscribeX/redirect
  ?pickcode=<17位>         必填
  &file_name=<urlencoded>  可选，仅用于 Content-Disposition / 日志
  &token=<strm_token>      可选；strm_token 非空时必带（默认空 = 不校验，兼容老 strm）
```

成功：`302` + `Location: <115 CDN 直链>`，透传头：`Range`、`User-Agent`（取客户端 UA 去换链）。
失败：`400`（参数错）/ `404`（pickcode 无效）/ `502`（115 取链失败）/ `403`（token 错），JSON `{"code":<int>,"msg":"..."}`。
`HEAD` 直接返回 `200` + `Content-Type: video/*`，不换链（Emby 探测用）。

取链策略（配置 `strm_link_mode`）：`cookie`（默认，复用 CS 已存 115 cookie）| `open`（开放平台 App ID/Secret）。
直链缓存：内存 LRU，key=`pickcode|ua_class`，TTL 6h（115 链约 12h 有效，留半衰期余量）。

### 2.2 内部 API（沿用 CS 现有风格，注册在 `core/api/registration.py`）

| 路径 | 方法 | 说明 | 返回 |
| --- | --- | --- | --- |
| `/strm/status` | GET | 索引规模、最后全量/增量时间、队列积压、失败数 | `{"indexed":n,"last_full":"iso","last_incr":"iso","pending":n,"failed":n}` |
| `/strm/full_scan` | POST | 已有，升级：`{"overwrite":bool,"budget_seconds":int}` | `{"directories":n,"created":n,"updated":n,"skipped":n,"errors":n}` |
| `/strm/incr_scan` | POST | 立即跑一次增量 diff | 同上 + `"deleted":n` |
| `/strm/rebuild_index` | POST | 从本地 `.strm` 反推重建索引（灾难恢复） | `{"scanned":n,"rebuilt":n}` |

## 3. 数据落点

新增两张表（alembic 迁移，与现有 `sync_jobs` 同库 `cloudsubscribe.db`）：

```sql
CREATE TABLE strm_index (
  id INTEGER PRIMARY KEY,
  provider TEXT NOT NULL,          -- 115/quark/...
  file_id TEXT NOT NULL,           -- 云端文件 id
  pickcode TEXT NOT NULL,          -- 17 位
  local_path TEXT NOT NULL,        -- /strm/115网盘/.../S01E07.strm
  size INTEGER DEFAULT 0,
  cloud_updated_at TEXT,           -- 云端 mtime（增量 diff 主键之一）
  strm_hash TEXT,                  -- 当前文件内容 sha1 前 16 位，避免重写
  state TEXT DEFAULT 'ok',         -- ok/pending/failed
  attempts INTEGER DEFAULT 0,
  updated_at TEXT,
  UNIQUE(provider, file_id)
);
CREATE INDEX idx_strm_local ON strm_index(local_path);
CREATE INDEX idx_strm_state ON strm_index(state, attempts);

CREATE TABLE strm_sync_state (
  id INTEGER PRIMARY KEY CHECK (id = 1),
  local_root TEXT,
  cloud_root TEXT,
  full_token TEXT,                 -- 全量断点 token（复用现有 strm_scan_state.json 语义）
  last_full_at TEXT,
  last_incr_at TEXT,
  schema_version INTEGER DEFAULT 1
);
```

本地文件：`.strm`（内容单行 URL）+ 同目录 `.strm.cs` 标记文件（写入者=CS），用于「只删自己写的」，避免与 P115StrmHelper 互删。

## 4. 增量算法

1. 取游标 `last_incr_at`（默认 `now - 30min` 重叠，防时钟漂移漏单）。
2. 对 `cloud_root` 下**媒体库根 + 一级分类目录**调 115 `list` 接口，按 `updated_at > 游标` 过滤（115 列表接口支持 `o=user_utime` 排序，取首页即够）。
3. 命中项解析为 `(file_id, pickcode, path, size, mtime)`；与 `strm_index` 比对：
   - 无记录 → 新建
   - 有记录但 `size/mtime` 变 → 重写
   - 有记录且 `strm_hash` 一致 → 跳过
4. 云端已删（索引有、目录无）→ 标 `state=deleted`，本地 `.strm` **不自动删**（Emby 侧由用户决定），仅记录；`strm_sync_delete=true` 时才删。
5. 写盘：`path.tmp` → `os.replace()` 原子替换 → 更新索引。失败进入重试队列。

## 5. 并发与限流

| 项 | 值 | 理由 |
| --- | --- | --- |
| 115 API QPS | 全局令牌桶 4 QPS | 115 风控阈值经验值，超过易 429 |
| 写盘线程池 | 8 | 本地 IO，瓶颈在 FS |
| 单次增量批量 | 200 文件/批 | 控制单轮耗时 ≤ 60s |
| 全量预算 | 默认 900s/轮，超出存断点 | 沿用现有 `_strm_full_scan_budget` |
| 302 取链并发 | 16，超时 5s | Emby 打开播放器时瞬时并发 |
| 直链缓存 | LRU 512 条 / TTL 6h | 减少 115 调用 |

互斥：`strm_write` 队列与全量扫描共用一把 `threading.Lock`（全量运行时增量顺延，不并发写同一目录）。

## 6. 失败与回滚

| 场景 | 行为 |
| --- | --- |
| 115 取 pickcode 失败 | 该文件 `state=failed, attempts+1`，指数退避 1/5/30min，3 次后告警一次（飞书），不阻断其他文件 |
| 写盘失败（权限/满盘） | 同上；不删旧文件，保持旧 `.strm` 可用 |
| 索引与磁盘不一致 | `/strm/rebuild_index` 从磁盘反推；也可删表重建（幂等） |
| 302 端点在 115 全挂时 | 返回 `502` + 明确 msg；Emby 侧表现为播放失败，不影响入库 |
| 上线回滚 | 开关 `strm_builtin_enabled=false` 即回到旧行为（外部 base_url 模板），索引表保留不删 |

**迁移策略（关键）**：切换时先把 `strm_base_url` 从 `http://172.17.0.1:9527` 改为 `http://moviepilot-v3:3000/api/v1/plugin/CloudSubscribeX/redirect`，模板改为 `{base_url}?pickcode={pickcode}&file_name={file_name}`，然后跑一次 `/strm/full_scan` 重写全库，最后才关外部服务。**不要先关外部服务**。

## 7. 与 P115StrmHelper 共存

两者都会写 `/strm/115网盘`，必须定主：

- `strm_owner` 配置：`cs`（默认，本方案接管）| `p115strmhelper`（旧行为，CS 只读不写）
- 若为 `cs`：提示用户关闭 P115StrmHelper 的 `timing_full_sync_strm`、`increment_sync_strm_enabled`、`monitor_life_enabled`
- 判定写入者：CS 只处理「无 `.strm.cs` 标记的新文件」与「自己标记的文件」；遇到 P115 写的同路径文件，默认 `skip` 并计数，配置 `strm_takeover_force=true` 时覆盖

## 8. 分阶段实施

| 阶段 | 内容 | 预估 | 验收 |
| --- | --- | --- | --- |
| P0 | 302 端点 + 直链缓存 + 单测（404/502/Range） | 1 天 | 用真实 pickcode `curl -I` 拿 302；Emby 直接播放 |
| P1 | `strm_index` 表 + 增量 diff + 转存回调投递 | 2 天 | 新转存 30s 内出现 `.strm`；重跑不产生重复写 |
| P2 | 全量升级（并发 + diff + 断点）+ `/strm/status` | 1 天 | 全库 8k 文件 ≤ 15 分钟，二次全量 0 写入（全 skip） |
| P3 | 迁移开关 + P115StrmHelper 接管引导 + README 运维段 | 0.5 天 | 切换后 24h 无缺集（以小城良方 E07/E08 为回归样本） |
