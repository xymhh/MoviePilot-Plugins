# 网盘订阅助手（CloudSubscribe）使用指南

> 版本：X 3.0.0 / Lite 3.0.0（MoviePilot v3）。本指南按当前代码行为编写，不照搬上游旧版指南。
> 两个插件不要同时启用，否则会重复转存。

## 这是什么

网盘订阅助手监听 MoviePilot 的订阅，自动到网盘搜索源找缺失的影视资源，命中后转存到目标网盘（默认 115），再整理入库、生成 STRM、刷新媒体服务器并通知你。

- **X（`CloudSubscribeX`，网盘订阅助手）**：完整版，含整理、漏斗、STRM、重复扫描。
- **Lite（`CloudSubscribeLite`，网盘订阅 Lite）**：**基于最新 X 的简化版**，同一套代码，精简已做到代码层——整理 / STRM 校准 / 重复扫描 / 回收站 / 漏斗 / 媒体库同步 / Emby 302 反代的相关模块已从 Lite 源码中删除（不再随包发出），不注册对应服务与 `/strm`、`/duplicates`、`/recyclebin`、`/funnel`、`/organize` 路由。整理与 STRM 校准交给 115 助手插件；转存时仍会为已转存文件生成 `.strm`（走 Lite 自己的 `/redirect` 播放），转存完成后的媒体服务器刷新保留。其他能力（搜索、转存、秒传、TG 频道监控、榜单自动订阅、签到）与 X 相同。
- X 另有运行时 Lite 模式（配置项 `cs_lite_mode`，默认关闭），那是 X 内部的一个开关，与 Lite 插件不是同一个东西，不要混淆。

## 安装与适用版本

在 MoviePilot v3 的插件市场中添加仓库地址：

```text
https://github.com/xymhh/MoviePilot-Plugins
```

刷新市场后搜索“网盘订阅助手”或“网盘订阅 Lite”安装。两个插件都适用 MoviePilot ≥ 3.0.0。

从旧插件 `CloudSubscribe` 迁移：首次启动时，如果本插件还没有配置且没有迁移过，会自动从旧插件复制配置、持久化数据键和私有 SQLite 库。复制后 `enabled` 会被强制置为 `False`，需要你手动启用，避免与旧插件同时转存。迁移只做一次，之后清空配置属于主动重置，不会回灌旧插件配置。

## 运转流程

```text
订阅登记 → 缺集基线 → 搜索候选 → 匹配/去重 → 转存/下载 → 目标网盘
        → 整理入库 → 生成 STRM → 刷新媒体服务器 → 通知
```

1. **订阅登记**：订阅本身存在 MoviePilot 主库，本插件不自建订阅表。插件监听 `SubscribeAdded` 等事件，也支持手动提交、TG 频道发现和片名对话订阅。
2. **缺集基线**：按云盘目录与媒体库判断哪些集缺失，不再用旧插件的 history 快照。
3. **搜索候选**：按优先级尝试已启用的搜索源，第一个有结果即返回（电影）；电视剧逐源搜索。搜索缓存默认 30 分钟，熔断阈值 3 次、冷却 60 秒，搜索并发默认 2。
4. **匹配/去重**：标题归一化、季集提取、字幕组优先级、画质比较、去重基线。失败记录进重试索引（`retry_index`），它是失败与待修复的唯一事实来源。
5. **转存/下载**：同盘优先走网盘转存；跨盘先试秒传，命中零上传，未命中按配置回落普通上传或中止；离线下载（magnet/ed2k/离线 URL）由离线任务轮询终态。
6. **整理与 STRM（仅 X）**：见下文。
7. **通知**：转存完成、失败、跳过原因汇总等按配置的通知方式发送。

## 必填配置

只列新用户真正的必填项，其余在配置页按分组查看：

- **启用插件**（`enabled`，默认关）：安装后先打开。
- **目标网盘**（`cloud_drive`，默认 `115`）：转存落盘的网盘，见下文网盘一节。
- **搜索源**：至少启用一个搜索源，默认搜索顺序只有 `pansou`。各搜索源的账号、Cookie 等按需填写。
- **MP 本地地址**（`mp_base_url`，默认 `http://127.0.0.1:3000`）：插件调 MoviePilot 本地接口用。

主同步定时（`cron`）默认值在代码里有两处写法不一致（`__init__.py` 为 `0 18-23 * * *`，`core/config.py` 为 `30 2,10,18 * * *`），以配置页实际写入的值为准。

## 网盘

支持 7 个网盘驱动：115、夸克、阿里云盘、天翼云盘、移动云盘、123 网盘、光鸭网盘。搜索结果里还可能出现 UC / 迅雷资源。

- **跨盘转存**：如夸克 → 115。先秒传探测，命中则零上传；未命中时按 `cross_transfer_rapid_miss_action` 回落普通上传或中止（默认回落）。
- **每日真实上传上限**：900 GB（硬上限 1..900 GB），秒传命中按 0 字节计，不占额度。
- **离线下载**：magnet、ed2k、离线 URL 可提交离线任务，插件轮询终态，终态前记录在待终态队列里。
- **内置 aria2**：跨盘下载腿可用插件自带的 aria2c（Linux x86_64 静态二进制，1.36.0 + Aria2-Pro 补丁，随包分发、运行时解压校验）。X 默认关闭内置 aria2，Lite 默认开启，失败时自动回落内置下载器。
- **115 存储（仅 X）**：X 另注册一个“115 网盘 CS 版”存储适配器（`u115cs`），Lite 不注册。

## 搜索源

共 15 个搜索源：PanSou、Dian115、HDHive、HDHaven、Mikan、AnimeGarden、聚影、片库、盘链、蜗牛、SeedHub、UIndex、海盗湾、在线文档、TG 频道监控。其中 TG 频道监控是推送型渠道，不参与搜索组装；Mikan / AnimeGarden 只在动漫媒体时检索。

部分搜索源需要账号、Cookie 或积分（如 HDHive 的解锁积分），在“渠道管理”里按源填写。搜索源注册失败时目前只记 debug 日志，界面上可能没有明显提示，先看插件日志。

## 订阅补缺与匹配

- 电影与电视剧分流处理：电影按单个媒体处理，电视剧按季/集处理，缺集才补。
- 匹配看标题、季集、画质、字幕组、特殊版本与合集判断；字幕组有优先级，动漫有专门的候选过滤。
- 洗版择优：已有画质差的版本时，可按分辨率/体积择优替换（默认关闭，只对新入库生效）。
- 失败与待修复只认 `retry_index`：失败记录 90 天过期、待修复 30 天过期清理。旧文档里提到的 `candidate_ledger_entries` 账本表与 `history` 表已在 v1.13.0 / v1.13.3 的迁移中删除，不要再按旧文档找它们。

## 整理与 STRM（仅 X）

Lite 没有整理漏斗、STRM 校准与 Emby 302 反代，相关代码已删除，交给 115 助手插件。但 Lite 转存时仍会为已转存文件生成 `.strm`（播放地址形如 `{base_url}/api/v1/plugin/CloudSubscribeLite/redirect?pickcode={pickcode}&file_name={file_name}`，走 Lite 自己的 `/redirect` 端点），转存完成后的媒体服务器刷新也保留。

- **整理漏斗**：转存后的文件先进漏斗队列排队整理，去重键为剧集（媒体类型 + TMDB ID + 季 + 集）或电影（媒体类型 + TMDB ID），同一去重键同一时间只有一行在途；失败待重试，人工复核的行不再自动重试。
- **STRM**：全量校准每天 04:20，单次预算 900 秒，到上限后断点续扫；增量补齐默认每 10 分钟。STRM 播放地址形如 `{base_url}/api/v1/plugin/CloudSubscribeX/redirect?pickcode={pickcode}&file_name={file_name}`。
- **Emby 302 反代**：内置 Emby 302 反代，默认端口 3010，默认关闭。播放时实时换 115 直链，流量不过 MoviePilot。
- **媒体服务器刷新**：转存/整理完成后可刷新 Emby/Jellyfin 等媒体服务器，也可处理媒体库 Webhook。

## TG 频道监控

用你自己的 Telegram 账号（`api_id` / `api_hash` / 会话）登录 Telethon，插件定时扫描你配置的频道，按标题/集数匹配订阅，命中后自动转存。登录走短信验证码/密码，未配置凭据时强制视为关闭。

频繁扫描可能触发 Telegram 的 FloodWait，代码里有等待处理，但仍建议不要把扫描间隔设得过短。

## 榜单自动订阅

7 个渠道：豆瓣、TMDB、Bangumi、AniList、猫眼、Netflix、Mikan。默认每天 08:00 跑一次，按榜单取候选，识别 TMDB 身份后去重（已订阅、历史里已有、媒体库已存在都跳过），再建订阅。

## 签到

多网盘/搜索源签到，默认每天 08:00，失败可自动重试。签到历史与调度状态存在私有库里。

## 常见问题

- **两个插件同时启用会怎样？** 会重复转存。只启用一个。
- **转存失败去哪看？** 失败记录页（X 的侧边栏“失败记录”），以及重试索引。失败原因按网络、认证过期、资源无效、匹配不符等分类，429 限流会退避重试。
- **搜到了但没转存？** 先看跳过原因：失效分享、无可用文件、内容不匹配、已存在、画质/字幕组不符合等都会在完成日志与通知里汇总。
- **搜索源突然搜不到？** 可能是源站反爬升级、账号风控或 Cookie 过期。插件有熔断、限流与风控冷却，换源或更新凭据后再试。
- **STRM 播放 403？** 115 直链对 UA 有要求，插件按播放端 UA 换链；仍有问题时先看直链是否过期（直链有效期较短）。
- **主同步什么时候跑？** 看配置页的 cron，以实际写入的值为准（代码里两处默认值不一致，见上文）。

## 数据与隐私

- 凭据（网盘 token / Cookie、搜索源账号密码、TG 的 `api_hash` / 会话）以配置键存放，**是否加密存储尚未核实**，本指南不声称已加密。
- 插件的私有库在 `config/plugins/CloudSubscribeX/cloudsubscribe.db`（X）或 `config/plugins/CloudSubscribeLite/cloudsubscribe.db`（Lite），含失败重试索引、签到历史、积分预算、认证会话、运行期状态等 11 张表。
- 旧版留下的 `source_sha1_cache.json`、`tg_monitor/*.json`、`strm_scan_state.json` 会在升级后第一次启动时自动导入，并原地改名为 `*.migrated`（不删除，可回溯）。
