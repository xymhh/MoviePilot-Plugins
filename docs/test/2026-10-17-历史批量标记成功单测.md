# 历史记录「批量标记成功」实现与单测（1.6.54）

> 状态：已实现并验证（2026-10-17），版本 1.6.54。

## 需求

历史页里积压两类记录：

| 界面标签 | 实际状态 | 成因 |
| --- | --- | --- |
| 待确认 N | `待确认` | 1.6.52 落盘自检查无实据（目标季目录里没有该文件） |
| 待完成 N | `处理中` / `下载中` | 后处理队列卡住，终态写不进去 |

用户要能**批量手动处理成成功**，而不是逐条删记录。

## 实现

### 后端

- `handlers/sync/history.py`
  - 新增 `HistoryService.mark_history_records_success(identities)`：匹配口径复用 `_history_record_identity`（share_url + file_name + tmdb_id + season + episode）与 `record_id`，与批量删除同一套。
  - 允许起点 `_MANUAL_SUCCESS_STATUSES = {待确认, 处理中, 下载中}`；终态（成功/失败/跳过）计入 `skipped`。
  - 置成功后写 `manual_success=True`、`manual_success_at`、`manual_success_from`，清 `failure_reason` / `retrying`；**保留 `finalize_key`**——已挂起的后处理仍会继续改名/生成 STRM，只是不再改状态。
  - `_mark_offline_history_status_batch`：命中 `manual_success` 的记录先 `matched_records += 1` 再 `continue`，既不被自动终态覆盖，又不会让 `_resolve_history_record` 误判「历史尚未落盘」而反复重排队。
- `handlers/sync/landed.py`：`apply_landed_verification_to_records` 的候选过滤新增 `not record.get("manual_success")`，手动成功不会被下一次落盘自检翻回「待确认」。
- `core/api/history.py` 新增 `api_mark_history_success`：≤2000 条、`sync_lock` 非阻塞（与合并转存互斥）、错误分级返回。
- `core/api/runtime.py` 新增 `api_vue_mark_history_success`；`core/api/registration.py` 注册 `POST /history/mark_success`。

### 前端

- `HistoryTable.vue`：工具栏新增「标记成功」（warning，选中项含待确认/处理中/下载中才可用），`manualSuccessSelectedCount` 控制文案与禁用；新增 `mark-success` 事件。
- `Page.vue` / `AppPage.vue`：确认弹窗 + 分片提交（后端上限 2000，前端每片 200 条串行）；完成后刷新历史与汇总。

## 单测覆盖点

1. 待确认/处理中/下载中 → 成功；成功/失败/跳过 → 跳过，计数正确。
2. 标记后自动终态（失败、成功）都不覆盖；手动成功不触发落盘自检。
3. 重复标记幂等（第二次 updated=0，不重复写盘）。
4. 记录不存在 → `LookupError`；空标识 → `ValueError`。
5. `apply_landed_verification_to_records` 跳过 `manual_success` 记录且不触发列目录。
