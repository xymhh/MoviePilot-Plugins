## 4. 与设计文档的偏差（都已回写文档）

| 偏差 | 原因 |
| --- | --- |
| `--json` 输出**后端原始响应**而非 unwrap 后的 `data` | 排障要看到 `success/message` 字段；人类可读路径仍用 unwrap 后的数据渲染 |
| 子命令也注册了全局参数（`--json`/`--token` 等） | argparse 主解析器的参数在子命令之后不识别；用 `parents` + `SUPPRESS` 默认值解决，两侧都能写 |
| `sync pause` 用位置参数 `on|off` 而非 `--enable/--disable` | 少记一个选项名，`sync pause on` 更顺手 |
| 未实现 `search` 命令 | `/search/preview` 需要 `provider_data` 结构化载荷（source + resource_id），不是单关键字能表达的；需要时用 `raw POST /search/preview --body '{...}'` |

## 5. 已知限制

1. 只读 + 同步启停，不含配置写入（`config/save` 有 150+ 字段，仍走 UI）。
2. `progress` 依赖 `/page_data` 返回的 `subscribes_progress`，卡片数受 `--size` 限制（默认 200，覆盖当前 79 条订阅）。
3. token 缓存在 `~/.config/cloudsubscribex/token.json`，多台机器各存各的；不含密码明文。

## 7. v1.9.24：真机验收（2026-11-02 10:35，1Panel 宿主机部署）

### 7.1 v1.9.23 的错误（重要教训）

v1.9.23 的 22 条用例全部通过，但**测试 fixture 是照「以为的字段名」手写的**，与真实接口对不上。真机首次运行：

| 命令 | v1.9.23 实际表现 | 真因 |
| --- | --- | --- |
| `doctor` | 把整个 dict 原样打印成 `checked_at overall counts items [...]` | 后端返回 `items[]`，代码找的是 `checks[]` |
| `progress` | 标题被压成「小丑…」，进度显示 `/0` | 字段是 `library_count`/`total_episodes`，代码用 `landed_count`/`total` |
| `history` | 空表 | 记录在 `history_groups[]`，`history_page` 只有分页元信息 |
| `ledger` | 列全空 | 字段是 `ts/kind/provider/resource_title/reason` |
| `duplicate` | 列全空 | 字段是 `name/type/keep_id/duplicates[]` |

**教训**：自造 fixture 的测试只能证明「代码符合我的假设」，不能证明「代码符合接口」。CLI 这类纯客户端，fixture 必须来自真机抓包。

### 7.4 部署方式（宿主机）

| 文件 | 作用 |
| --- | --- |
| `/root/.local/bin/cli-cs.py` | 客户端本体（从 GitHub raw 拉取） |
| `/usr/local/bin/cli-cs` | wrapper：加载 env + 动态解析 MP 容器 IP |
| `/root/.cli-cs.env` | `MP_USER` / `MP_PASSWORD`（600，`export` 前缀必须有，否则子进程读不到） |

wrapper 用 `docker inspect` 取 `moviepilot-v3` 的容器 IP 拼 `MP_URL`，容器重建换 IP 也不用改配置。
