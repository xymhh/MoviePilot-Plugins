# 历史记录「秒传失败」单独标识 — 验收（2026-10-31，1.8.3）

> 状态：已完成 → 交付版本 `CloudSubscribeX_v1.8.3`

## 需求

用户原话：「历史记录秒传失败加上标识，不要和其它失败混在一起」。

改造前：115 秒传未命中、按 `cross_transfer_rapid_miss_action=abort` 中止的记录，历史页
和网络超时、上传失败一样只显示红色「失败」，筛选也归在同一桶里；跨盘失败时连
`failure_reason` 都没写，连悬浮提示都没有。

## 改动

| 层 | 文件 | 做了什么 |
| --- | --- | --- |
| 分类 | `core/failure.py` | 新增 `STATUS_LABELS`（`checksum_miss` → 「秒传失败」）、`status_label_of()`、`kind_of_pseudo_status()` |
| 落库 | `handlers/sync/history.py` | 失败写入统一走 `apply_failure()`（持久化 `failure_kind`/`failure_retryable`）；成功路径改 `clear_failure()` 防残留 |
| 建记录 | `handlers/sync/service.py` | 跨盘任务把 `completed_task.error/message` 带回结果（`abort_reason=rapid_miss` 直接归「未命中秒传」），按文件 ID 暂存、结果里带 `failure_reason` |
| 建记录 | `handlers/sync/{television,movie,upgrade}.py` | 失败的历史项写 `apply_failure(history_item, transfer_result["failure_reason"])` |
| 回填 | `core/database/repositories.py` + `core/storage.py` | 启动时 `repair_failure_kinds()` 幂等回填老记录（按 `failure_reason` 文本推断） |
| 筛选 | `core/database/repositories.py` | 伪状态「秒传失败」= `status=失败 AND json failure_kind=checksum_miss`；选「失败」时排除伪状态，两者不再混在一起 |
| 展示 | `handlers/sync/history.py` | 页面字段新增 `status_label` / `failure_kind` / `failure_label` |
| 前端 | `HistoryTable.vue` | chip 用 `status_label`（秒传失败显示「秒传失败」）、`statusColor(record)` 给 `checksum_miss` 琥珀色 `orange-lighten-1`、tooltip 显示分类名 + 原因；状态下拉新增「秒传失败」 |
