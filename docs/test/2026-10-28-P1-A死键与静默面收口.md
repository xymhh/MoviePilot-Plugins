## 2. 静默失败面：主链路 64 处收口

统计口径（AST，非 grep）：`except` 块体只有一条 `pass` → 「完全静默」；块体只有 `logger.debug(...)` 且不带 `exc_info` → 「只留一句话、没有栈」。

本次只动四条主链路 + 其宿主模块：`handlers/sync/*`、`core/services/{organize,sync}.py`、`core/transfer.py`、`core/tg_monitor.py`、`utils/strm*.py`、`__init__.py`。

- 23 处 `except: pass` → `logger.debug("<函数名> 分支忽略异常", exc_info=True)`：保持默认安静（不刷屏），但把异常对象和栈留下来，排障时开 DEBUG 就能看见「为什么这条没生效」。
- 41 处只有一句话的 `logger.debug(...)` → 补 `exc_info=True`：原来只看到 `str(e)`，看不到发生在哪一行。

**没有**把主链路统一提到 `WARNING`：STRM 写出失败、树构建失败、转存失败这些「用户真会感知」的点本来就已经是 `warning`（`utils/strm*.py` 内核对过），剩下的都是状态写盘/统计类的旁路，提高到 warning 会把日志淹掉。真要提级应基于真实日志挑点，留给 P2。

剩余静默面（`except: pass` 87 处、debug-only 77 处，含非主链路）不靠人盯，靠下面的棘轮。

### 顺手修掉的 71 条 F 级问题

| 规则 | 条数 | 处置 |
| --- | --- | --- |
| F401 | 39 | `--fix` 自动删（**两处其实是再导出**，见下） |
| F841 | 28 | 逐条确认无副作用后删赋值 |
| F402 | 3 | 循环变量改名（`field` → `field_item` / `field_name`） |

**踩到的坑（值得记）**：`utils/http_client.py` 的 `from curl_cffi import requests` 与 `search/http_client.py` 的 `normalize_proxies` 是**再导出**，ruff 按「未使用」删掉后，`core/subscribe/service.py:45` 直接 ImportError，全量测试从 909 passed 掉到 collection error。已改成显式再导出（`import x as x`）+ 注释说明。这两处 ruff 无法区分「漏删」与「故意再导出」，只能靠人工判断。

同类检查：`handlers/search/platform_rules.py` 三处 `from app.chain.subscribe import SubscribeChain` 里有两处从未使用（一处还是嵌套在 `except ImportError` 里），删掉；`drive/scanner.py` 的 `DriverDefinition/FieldSpec/GroupSpec` 删除后确认无人从这里 import。

另外发现两处**真问题被 lint 顺带暴露**：
- `tests/test_subscription_hook.py:88` 有一行 `if False else {...}` 引用了未定义名 `state_value`（F821），已改写成直接断言。
- `tests/test_tg_monitor.py` 里 `NormalizeChannelTest` 定义了两次、`ChannelRulesTest` 有重复的 `setUp/tearDown`（F811）→ 前一个类被同名类**遮蔽、从未执行过**。改名后旧用例开始跑，其中 2 条断言与现行实现不符（`t.me/abc` 现在归一化成 `@abc`；`t.me/c/123456/789` 归一化成 `-100123456`），已按现行为更新并注明原因。
