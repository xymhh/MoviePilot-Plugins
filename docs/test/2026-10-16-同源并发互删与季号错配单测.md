## 4. 未覆盖 / 残留风险

- **真机未复测**：需要用户更新到 1.6.47 后，重发「同一分享被多订阅并发转存」场景，核对：日志不再出现「本机未见文件」「code=21001 file not found」「[Errno 2] No such file or directory: cloud-transfer-*」；历史失败任务重试可复用中继（下载只发生一次）；S01/S03 订阅不再认领 `… S2` 目录的文件（debug 日志可见「分享目录季号与目标季冲突」）。
- **线程时序为受控事件驱动**：组1 用 `threading.Event` 卡住 A 的下载再创建 B，不依赖 sleep 竞态（仅 0.1–0.2s 观察窗口用于断言 B 仍排队）；A1 的锁语义在极端调度下也不会互删（引用计数是兜底，锁是复用优化）。
- **暂存引用计数是进程内计数**：插件重载后计数归零（与中继 `cache_key` 锁同样为进程内语义），重载瞬间的在飞暂存清理不受保护——与任务书「A1 串行已消除大部分并发，这里做兜底」的定位一致。
- **前端构建未在本机验证**：`cross_season_path_guard` 为标准 `select` 字段（仿 `skip_other_season_dirs`），`dist/` 不入库、由 CI 构建，风险低。
- **Gopeed AutoRename 只能事后容忍**：改名副本按「key 前缀 + 大小相符」识别；若 Gopeed 改名成完全不同的文件名（非 `… (N).bin` 形式），仍走「本机未见文件」可诊断异常并重试。

### 5.3 主 agent 修正一处委派遗留（已并入本次改动）

委派版 `_verify_result` 接受 Gopeed 改名副本时**返回副本路径** → 中继缓存标记会写成 `cloud-transfer-<key> (1).bin.meta.json`，规范路径没有缓存 → 兄弟任务无法复用、副本永不清理（每个大文件泄漏一整集）。改为 `renamed.replace(target)` 归位到规范路径（归位失败才回退副本路径继续），同步改断言并新增回退用例。
