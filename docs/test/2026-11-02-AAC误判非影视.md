# AAC/FLAC 音轨规格被误判「非影视资源」· 排查与修复

> 日期：2026-11-02 15:55
> 版本：v1.9.30
> 触发：用户反馈「嫁金钗 (2026) S01E26 疑似非影视资源，这么大问题，这还是 115 网盘资源」

## 一、根因

`handlers/sync/candidate_filter.py` 的 `non_video_reason()` 用一张不分轻重的黑名单：

```python
_ASCII_MARKERS = ("FLAC", "APE", "WAV", "MP3", "AAC", "DSD", "OST", "EPUB", "MOBI", "AZW3")
```

命中任一即 `疑似非影视资源（marker）`，在 `resources.py:818` 的**列目录之前**直接拦掉。

问题在于 `AAC` / `WAV` / `MP3` / `FLAC` 在影视资源标题里是**音轨编码**，不是资源类型：

```
📺 嫁金钗 (2026) S01E26 ✨4K WEB-DL AAC
名称：伟大的长征(2026)4K 10bit 60FPS FLAC无损HiFi声 更至EP37
名称：《玉簟秋》2026 更新至 - 第 31 集 - [4K] [AAC 2.0] [丞磊 徐若晗 王丽坤]
```

这三条都是标准 115 影视资源，全被 `AAC` / `FLAC` 一个词判死，连分享目录都没打开过。

## 二、影响面（全量 2446 条账本实测）

`疑似非影视资源` 共 78 条，marker 分布：

| marker | 条数 | 判定 |
| --- | --- | --- |
| AAC | **26** | ❌ 全误判（影视资源） |
| MOBI | 23 | ✅ 电子书 |
| EPUB | 15 | ✅ 电子书 |
| FLAC | 14 | ⚠️ 11 条误判（影视带无损音轨）+ 3 条真音乐 |

被误拦的剧：《嫁金钗》《玉簟秋》（12 集）《尚公主》《伟大的长征》《现在就出发 第四季》《Doctor X：白色黑手党时代》《冰之城墙》《新手上路》。

## 三、修复：特征分强弱两级

```python
# 强特征：命中即判非影视
_ASCII_STRONG = ("EPUB", "MOBI", "AZW3")
_CJK_STRONG   = ("有声书", "有声小说", "有声剧", "广播剧", "听书", "电子书", "专辑", "单曲")

# 弱特征：只有标题完全没有视频信号时才判非影视
_ASCII_WEAK = ("FLAC", "APE", "WAV", "MP3", "AAC", "DSD", "OST")
_CJK_WEAK   = ("无损", "母带", "原声带", "原声大碟", "主题曲", "插曲")
```

视频信号正则（任一命中即视为影视）：

```python
_VIDEO_SIGNAL = re.compile(
    r"(?<![A-Z0-9])(?:4K|8K|2160P?|1080P?|720P?|480P?|WEB-?DL|WEBRIP|BLURAY|BDRIP|"
    r"HDTV|HDTVRIP|REMUX|HEVC|AVC|H\.?26[45]|X26[45]|HDR|SDR|DOLBY|DV|"
    r"S\d{1,2}\s*E\d{1,4}|E\d{1,4})(?![A-Z0-9])",
    re.IGNORECASE,
)
```

## 五、教训

上一版（v1.9.29）刚把「未匹配到缺失剧集」这种笼统原因拆成可核对的三类，但**分类判据本身没被审计**。这次的问题不在文案，在「谁有资格判非影视」——黑名单里混进了会出现在正常影视标题里的词。

同类风险还剩：`OST` 放弱特征后，纯「某电影 OST」仍会被拦（正确），但「某电影 OST 特别版 4K」会放行（也正确）。后续再遇到误判，优先看是不是又一个「视频规格词」被当成了「资源类型词」。
