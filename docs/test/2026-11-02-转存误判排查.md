## 3. 三个根因

### 根因 1：扁平列表的相对路径被覆盖（113 条）

`utils/file_parser.py:140` `iter_files` 用 `parent_path` 拼路径，但夸克/115 的
`list_share_files` 返回**扁平列表**、每条已带 `relative_path`，此时 `parent_path` 恒为空：

```python
relative_path = "/".join(v for v in (parent_path.strip("/"), name) if v)  # 只剩 name
item.setdefault("_relative_path", relative_path)
```

`share_root_names` 优先读 `_relative_path` → 根目录名变成文件名。铁证：119 条
「根目录不符」里 113 条的 offender 写作 `上集：….mkv`、`….z01` 这种带后缀的文件名。

### 根因 2：季号只看文件名（183 条）

`episode_from_file` 只把 `item["name"]` 交给 `_platform_meta`，父目录里的
`S01` / `第一季` / `Season 1` 完全没用。`01 官中最新4K高清完整版.mp4` 因此得
`begin_season=None` → 直接返回 `None`。

### 根因 3：三类原因共用一个文案（394 条）

「内容不匹配」里混着：真不是这部剧 / 是这部剧但集号不在缺失范围 / 解析不出集号。
用户点开链接发现剧是对的，自然认为逻辑错了。

## 4. 修复内容

| 文件 | 改动 |
| --- | --- |
| `utils/file_parser.py:140` | `iter_files` 在无 `parent_path` 时沿用条目自带 `relative_path`；有 `parent_path` 时仍按嵌套拼接（回归不变） |
| `utils/file_matcher.py` | 新增 `_episode_from_path_evidence`：文件名无季集号时用父目录季号兜底；目录季号**由内到外**取；无季号目录只放行 S1 |
| `utils/file_matcher.py` | 集号形态补齐：`E01`、`- 07`、上/中/下集、裸数字；上限 999 防 1080p/2160p 误判 |
| `utils/file_matcher.py:640` | `_path_season_conflict` 改内层优先，避免外层 `Season 1` 干扰 `S02` |
| `core/services/skip_stats.py` | 新增 `episode_miss` / `unparsable` 两类，文案改为「剧名不符 / 集号不符 / 无法解析集号」 |
