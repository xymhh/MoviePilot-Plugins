# 2026-11-12 1.9.78 上传代理真机修复 — 验收

## 触发（用户质疑）

> 「上传有用到代理吗？为什么我看 mihomo 里没有连接呢」

用户是对的。核查结论：**1.9.75/1.9.76 的代理注入从未生效，那句「115 上传代理已生效」日志是假阳性。**

## 真机证据

| 证据 | 结果 |
| --- | --- |
| mihomo 日志来源 IP 分布 | `172.18.0.14`（clouddrive2）22 次、`172.18.0.17`（探测容器）13 次、**`172.18.0.5`（moviepilot-v3）0 次** |
| MP 进程 `/proc/1288/net/tcp` 到 `mihomo:7890` | **0 条连接** |
| MP 到 443 的 ESTABLISHED | 直连 `183.36.31.78`（OSS 深圳）、`47.113.23.100` 等 |

## 根因（源码级）

1. `P115Client.request` → `get_request()` **不传 `self`**，内部直接 `from urllib3_future_request import request` —— 包装实例方法只影响少数走 `self.request(...)` 的 API 方法。
2. `p115oss.oss_request` / `oss.py` 同样自己 `from urllib3_future_request import request`，与 client 实例无关 —— **数据上传这条腿完全绕过**。
3. `urllib3_future_request.request_sync(session=...)` 接受 `PoolManager`；`ProxyManager` 是其子类 → **唯一可行的注入点是 `session=`**。

## 修复（1.9.78）

| 文件 | 改动 |
| --- | --- |
| `drive/p115/upload_proxy.py`（新增） | `proxy_manager(url)` 造 `urllib3_future.ProxyManager`（带 CookieJar）并缓存；`oss_request_kwargs(url)` 返回 `{"session": pool}` 或 `{}`；代理不可用一律返回 None + WARN |
| `drive/p115/upload.py` | 新增 `_oss_proxy_kwargs()` 读 `owner._cross_transfer_upload_proxy`；`oss_multipart_upload_init/part/complete/cancel` 四处全部传 `**proxy_kwargs` |

| `__init__.py` | 插件未填代理时回落 MP 系统设置的 `PROXY_HOST` |

**作用域**：只有 OSS 分片 PUT 与 OSS 元数据走代理；115 API 保持直连（不碰 cookie 与风控）。
