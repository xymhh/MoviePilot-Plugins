## 一、先说交付流程问题：用户的「更新」没生效

用户 14:41 前在插件市场点了更新并跑了扫描。核验时发现：

| 检查项 | 实际值 |
| --- | --- |
| 容器内 `/app/app/plugins/cloudsubscribex/__init__.py` | `plugin_version = "1.9.28"` |
| `utils/file_matcher.py` 中 `_episode_from_path_evidence` 出现次数 | **0** |
| 文件 mtime | 2026-11-02 14:28 |

即：点「更新」装上去的是 1.9.28 的包，不是 1.9.29。当时市场列表里同一插件有两条：

- 条目 A：`plugin_version=1.9.28`、`has_update=false`、`repo_url=null`（本地已装视图）
- 条目 B：`plugin_version=1.9.29`、`has_update=true`、`repo_url=https://github.com/xymhh/MoviePilot-Plugins`

GitHub 侧一切正常：Release `CloudSubscribeX_v1.9.29` 存在，zip 内 `__init__.py` 版本号 1.9.29、`_episode_from_path_evidence` 4 处。

**修复动作**（走 MP 官方接口，非手工覆盖文件）：

```http
POST /api/v1/plugin/source/CloudSubscribeX/install
{"repo_url":"https://github.com/xymhh/MoviePilot-Plugins","release_version":"1.9.29","force":true}
→ {"success":true,"message":"插件安装成功","data":{"restart_required":false}}

POST /api/v1/plugin/reload/CloudSubscribeX
```

注意：`POST /api/v1/plugin/source/CloudSubscribeX`（换源）会返回「所选仓库与当前绑定仓库相同」，同源更新必须走 `/install` 后缀。

核验后：文件 1.9.29、`_episode_from_path_evidence` 4 处、市场只剩一条 1.9.29 且 `has_update=false`、`runtime_status=active`、doctor `overall=ok (8 ok / 0 warn / 0 error / 1 skip)`。

**教训**：以后发版后不能只问「更新了吗」，必须核容器内文件版本号（`grep plugin_version /app/app/plugins/cloudsubscribex/__init__.py`）再谈验收。

### 2.1 根目录被当成文件名 —— 已消除

| 指标 | 旧 | 新 |

| 「分享根目录与订阅标题不符」条数 | 28 | 23 |

### 2.2 集号解析 —— 已从笼统变可核对

旧：`未匹配到 S1 的缺失剧集` 69 条 + `未匹配到 S2 的缺失剧集` 11 条（无任何集号信息）。
新：`episode_miss` 75 条，**75/75 全部带具体集号**，例如：

```

资源集号与缺失不符（S01）：资源含 E01-E04，缺 E05
```

### 2.3 笼统原因被拆开

旧 `跨盘分享内容未被平台识别为目标媒体` 20 条在新一轮**全部消失**，被正确归入 `episode_miss` / `unparsable`。

## 三、遗留问题（3 条，均不阻塞）

1. **`资源含 无` 归类错位（5/75）**：资源一个集号都没解析出来，却落在 `episode_miss` 而非 `unparsable`。
   其中 3 条根本不是影视（`0005005.斗破苍穹.txt`、`《牧神记》（校对版全本）.txt`、`斗破苍穹.txt`），1 条是游戏包（`最后生还者2：重制版 v1.5.10708.0624 全DLC`），1 条是真实影视（`尚公主`）。
   → 前者归入待办「扩展非影视过滤」（TXT/全本/校对版/全DLC），后者是分类判据缺一条「解析结果为空」分支。

2. **链式季号误判 unparsable（1 条）**：`正相反的你与我(2026)1080p S01E01 - S02E13` 被判「跨盘分享文件名与目录都没有 S01 的集号」。标题里明明有 S01E01。需确认是文件列表确实只有 S02，还是 `_episode_from_path_evidence` 对 `S01E01 - S02E13` 这种链式写法只取到了后段。

3. **本轮 transferred = 0**：102 个订阅跑完没有任何一次成功转存。与「误判修复」无关（资源本身不匹配或已在库），但值得下一轮观察是否持续。

## 四、可复现命令

```sh
# 版本核验（宿主机）
docker exec moviepilot-v3 grep -n plugin_version /app/app/plugins/cloudsubscribex/__init__.py
docker exec moviepilot-v3 grep -c _episode_from_path_evidence /app/app/plugins/cloudsubscribex/utils/file_matcher.py

# 强制同源更新
curl -X POST "$MP/api/v1/plugin/source/CloudSubscribeX/install" \
  -H "Authorization: Bearer $JWT" -H 'Content-Type: application/json' \
  -d '{"repo_url":"https://github.com/xymhh/MoviePilot-Plugins","release_version":"1.9.29","force":true}'

# 触发全量同步
curl -X POST "$MP/api/v1/plugin/CloudSubscribeX/sync/start" \
  -H "Authorization: Bearer $JWT" -H 'Content-Type: application/json' -d '{}'
```
