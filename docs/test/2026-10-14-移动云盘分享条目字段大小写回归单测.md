### 3.1 过程记录：测试文件会污染同进程的其它测试

首版测试直接 `register_module("cloudsubscribe.core", package=True)` + `load_module` 真实 `core.cloud`，
结果 `discover` 全量跑出 **5 个 ERROR**：`test_yun139_caiyun_share.TestTransferClassification` 三例
（`ImportError: cannot import name 'CloudDriveCapability' from 'cloudsubscribe.core'`）。

原因：`unittest discover` **先导入所有测试模块再执行**，`sys.modules` 里最终留下的是
**最后导入的那个模块的注册结果**（本文件按字母序排在 `test_yun139_caiyun_share` 之后），
普通 `ModuleType` 占位包没有「未定义属性自动返回 Mock」的能力，于是把别人的桩顶掉了。

改法：占位包一律用 `register_mock`（MagicMock）/ `register_package`（AutoMockModule）并显式挂上本次需要的真实对象
（`CloudFile` / `ShareLinkStatus` 走 `load_module` 加载的**真实** `core/cloud.py`，`safe_int` 用真实实现），
只保留必要覆盖。改后全量回到 323 tests / 2 例环境 ERROR。
