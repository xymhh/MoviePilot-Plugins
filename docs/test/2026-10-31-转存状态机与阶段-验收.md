## 关键设计取舍

- **六个中文状态串一字未改**：前端、统计、通知模板、筛选全依赖它们，新增状态会造成多处静默漏判。
- **`待确认` 是正式状态**，只允许 `→ 成功/失败/跳过`；`成功 → 待确认` 是唯一允许的终态退出（落盘自检降级）。
- **人工标记成功**单独走 `transition_manual()`，不把「失败/跳过 → 成功」塞进通用迁移表，避免自动化路径也获得这个越权。
- **列目录失败 ≠ 没文件**：`landed=None` 时保持原状态只打 WARN，和 1.6.52 落盘自检的既定原则一致。

## 未覆盖 / 注意

- 历史页分组统计（`pending_count` / `failed_count`）仍按 `status` 计数，不含阶段维度 —— 本轮不做。
- `待确认` 记录不可从历史页"重试"（`_history_retry_state` 明确返回「当前记录无需重试」），只能「重新检查落盘」或人工标记成功；这是既有行为，未改。
- 清扫只处理 `处理中/下载中`；`待确认` 不自动收敛，必须人看。
- `stage` 列已建但页面统计暂未用它做 SQL 过滤（payload 里也有 stage，够用）。
- 老记录 `stage` 为空 → 页面不显示小字（不回填，无法凭空还原）。
