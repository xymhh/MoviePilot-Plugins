## 2. 新增用例覆盖（12 例，全在 `tests/test_gopeed_downloader.py`）

| 用例 | 断言要点 |
| --- | --- |
| `test_create_task_with_zero_connections_omits_extra` | `connections=0` → 请求体 `opts` 里**没有** `extra` 键（与 1.6.43 请求形状逐字节一致） |
| `test_create_task_with_connections_writes_opts_extra` | `connections=256` → `opts.extra == {"connections": 256}` |
| `test_delete_task_default_url_has_no_force` | 默认删除 URL 不带 query（完成路径保留文件语义不变） |
| `test_delete_task_force_appends_force_true` | `force=True` → `DELETE /api/v1/tasks/{id}?force=true` |
| `test_stop_requested_force_deletes_even_with_preserve_partial` | 停止路径：`pause_task` 与 `delete_task(force=True)` 都被调用，且 `preserve_partial=True` 也照删 |
| `test_service_passes_connections_to_create_task` | `QuarkFileService` → `GopeedDownloadService(connections=…)` → `create_task` 全链路透传 |
| `test_gopeed_connections_default_zero_passthrough` | 未配置时透传 0 |
| `test_preserve_partial_keeps_failed_task`（既有，未改语义） | 失败重试路径 `preserve_partial=True` → **无**任何 delete |
| `TransferCancel中继清理Tests::test_cancel_during_upload_deletes_complete_cache_and_parts` | 上传阶段取消 → 完整缓存 `.bin` + `.meta.json` + `.parts.json` 全删 |

## 4. 未覆盖 / 残留风险

- **真机未复测**：需要用户在 MP 里更新到 1.6.44、配置页填「Gopeed 连接数=256」后重发一个跨盘任务，核对速度与「停止后盘上无 `cloud-transfer-*` 残留」。
- **前端构建未在本机验证**：`frontend/cloudsubscribe` 用 pnpm（`package.json` engines 要求 node `>=22 <23`，本机 v25），本机 `npm install` 未装上 vite；`dist/` 不入库、由 CI `plugins-release.yml` 构建，故以 CI 产物回读为准（见第 5 节）。
- `delete_task(force=True)` 会连 Gopeed 侧已下载文件一起删——若用户把 Gopeed 下载目录配成与中继不同的目录（且同挂载），属配置错误场景，代码按任务书语义执行。
