## 二、A 陈旧 .strm 清扫

- `utils/strm_export.py::sweep_orphan_strms`：用本轮 115 目录树算出的
  「期望 .strm 全集」比对本地镜像，不在集合内的删除。
- 用例：陈旧被删且期望保留（1）/ 全在期望内不动（2）/ 样本 ≥20 且待删比例
  超 30% 整轮放弃（3）/ 期望集合为空时不动（4）。
- 安全阀细节：`min_sample=20` —— 库里只有两三份时按树删是安全的，不套比例闸。
- 删除路径回传 `on_strm_deleted`，`strm_ops` 里登记 Emby 删除屏蔽（防深度删除连锁）。

## 三、B 入队时间窗

- `FunnelQueueRepository.find_recent_done` + `enqueue(recent_done_window_seconds=...)`：
  同集窗口内已 done 且本次不是洗版 → 返回旧行、`created=False`。
- `SyncHandler._resolve_funnel_duplicate_enqueue` 增加 done 分支：记
  「同集近期已入库（行 #X，完成于 …），第二份跳过转存」并弹 pending。
- 用例（真实 SQLite 夹具）：窗口内挡住（1）/ 窗口 0 关闭（2）/ 洗版放行（3）/
  在途行优先级不变（4）。
- 既有集成用例调整：`test_funnel_stage2_1_29_8` 与 `test_funnel_stage3_1_29_9`
  原本验的是「落盘前实查」这道第二防线，现在入队时间窗会先挡，故两处显式把
  `_funnel_recent_done_window_hours` 设为 0 保留原路径覆盖；stage2 追加一段
  「窗口打开时第三份在入队处被挡」的断言。

## 四、C 上传前查重

- `TargetWriter._probe_same_stem`：精确名未命中时按「去扩展名的同名主干」
  再查一次；已有同大小或更大版本 → `reused`（不重复上传、不降级覆盖）；
  只有更小版本 → warning 后照常上传，**不删任何云盘文件**。
- 用例：更大同主干判 reused（1）/ 更小照常上传（2）/ 别的集不干扰（3）。
