# 手动转存分享链接解析契约单测（1.6.32）

> 状态：已完成 2026-10-13 → ../summary/2026-10-13-阿里云盘手动转存无法解析复盘.md

## 复现的线上现象

用户在「手动资源」对话框粘贴阿里云盘分享链接提交，插件返回：

```
第 1 行资源无效：无法解析有效的阿里云盘分享链接
```

该分支在 `core/api/sync.py`：只要有任意一行链接校验失败，整个提交直接返回，**不创建任务、不进历史**。
旁证：CloudSubscribe 运行日志里 `阿里云盘 / aliyun / alipan` 关键字命中 **0 条**——插件从未走到转存代码，
与「链接格式不对」和「跨盘不可用」都无关。

## 根因（源码级）

- `core/api/sync.py:145` `_manual_share_info_valid()` 旧实现只判断 `share_info.get("share_code")`；
- `drive/alipan/share.py:33` 旧 `extract_share_info()` 返回 `{"share_id", "share_pwd"}`，**没有** `share_code`；
- `drive/yun139/share.py:99` 旧实现返回 `{"link_id", "password"}`，同样没有 `share_code`；
- 其它来源（115 / 夸克 / 天翼 / 光鸭 / 123）都返回 `share_code`，所以只有这两个来源必挂。

结论：与链接长什么样无关，**任何**阿里云盘 / 移动云盘链接都会被判无效（确定性 bug）。

## 修复

| 文件 | 改动 |
| --- | --- |
| `drive/alipan/share.py` | `extract_share_info` 回填 `share_code`（=share_id），保留 `share_id`/`share_pwd` 给对端接口；`_prepare` 改为显式 payload，不把 `share_code` 混进请求体；补「提取码: xxxx」附言解析 |
| `drive/yun139/share.py` | `extract_share_info` 回填 `share_code`（=link_id） |
| `core/api/sync.py` | `_manual_share_info_valid` 改为接受 `share_code` / `share_id` / `link_id` 任一 |

## 真机验收清单（发给用户）

1. MP 插件市场更新「网盘订阅助手」到 **1.6.32**（更新后重载插件）；
2. 「手动资源」对话框粘贴同一条阿里云盘链接 → 不再出现「无法解析有效的阿里云盘分享链接」；
3. 若走的是「当前转存网盘 = 115」（默认），阿里云盘分享走**跨盘**：先转存到阿里云盘 `转存` 目录
   （`alipan_transfer_path`）→ 下载 → 上传到 115，完成后再清理源盘暂存；
4. 若提示需要访问码，说明分享本身带提取码：把链接连同「提取码: xxxx」一起粘贴。
