## 1. 新增用例：`tests/test_dian115_lottery.py`（9 例）

此前仓库里 **Dian115 相关用例数为 0**（`grep -rli dian115 tests/` 只命中一条注释），这也是这个 bug 能长期潜伏的原因。

| 用例 | 断言什么 |
| --- | --- |
| `test_configure_owner_exposes_lottery_config` | 配置里的开关/次数必须落到 `owner._dian115_lottery_enabled/_count`（修复前该属性完全不存在） |
| `test_configure_owner_clamps_and_defaults_lottery` | 次数上限 20、缺省 1、`"bad"` / `None` 不炸 |
| `test_service_client_carries_lottery_config` | `service.get_client()` 造出的客户端带上转盘配置（修复前恒为 False/0） |
| `test_service_rebuilds_client_when_lottery_toggled` | 改配置后重建客户端并 `close()` 旧实例（不必重启插件） |
| `test_provider_checkin_capability_has_lottery_enabled` | **端到端**：`create_provider()` 的 `SearchCapability.CHECKIN` 能力对象即带转盘配置的客户端 |
| `test_checkin_runs_lottery_up_to_target` | 目标 3 次、站点已用 1 次 → 只打 2 次 `/api/portal/lottery/wheel`，文案含「转盘 3/3」 |
| `test_checkin_respects_daily_cap` | 站点当天已用满 → 一次都不补，`executed=0` |
| `test_checkin_skips_lottery_when_disabled` | 开关关掉 → 无转盘请求、`lottery=None`、文案与 1.6.35 逐字一致（「签到 +4」） |
| `test_matches_config_compares_lottery_dimensions` | `matches_config` 比较 lottery 维度；不传该参数时不参与比较（其它调用方行为不变） |

测试用真实 `checkin()` / `run_lottery()` / `matches_config()` 逻辑，只把网络与外部依赖替换为桩：
`requests.Session`、`RequestGate/AccountActionGate`、`cryptography`（CI 未安装，本地注册占位）、
`Dian115ResourceService`、`PointBudgetLedger`。客户端用 `__new__` 绕过会话初始化，不触网。
