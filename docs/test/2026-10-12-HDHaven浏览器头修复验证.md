# HDHaven 签到 403（浏览器 Fetch Metadata 头）修复验证 — 1.6.30

> 日期：2026-10-12　对应版本：网盘订阅助手 **1.6.30**
> 现场现象：签到重试汇总通知「HDHaven：失败，签到失败，HDHaven 无法获取 Cloudflare site key」（2026-10-12 18:41、19:25 各一轮）。

## 1. 站点侧复现（curl，2026-10-12 19:4x）

用户侧插件请求的等价形态（只有浏览器 UA，没有 Fetch Metadata 头）：

```bash
curl -sS -H "User-Agent: Mozilla/5.0 ... Chrome/131.0.0.0 Safari/537.36" \
     https://hdhaven.com/api/auth/registration-config
# HTTP 403
# {"code":"BROWSER_REQUIRED","message":"网页接口仅供浏览器访问，程序接入请使用 OPENAPI 授权"}
```

同接口只补一个头即恢复：

```bash
curl -sS -H "User-Agent: Mozilla/5.0 ..." -H "Sec-Fetch-Site: same-origin" \
     https://hdhaven.com/api/auth/registration-config
# HTTP 200 → data.turnstile_site_key 正常返回
```

## 2. 头隔离测试（判定到底缺哪个头）

| 请求头组合（UA 恒为 Chrome） | 结果 |
| --- | --- |
| 仅 UA | 403 BROWSER_REQUIRED |
| UA + `X-Requested-With: XMLHttpRequest` | 403 |
| UA + `Sec-Fetch-Site: same-origin` | **200** |
| UA + `Referer` + `Origin` | 403 |
| UA + `Accept-Language` | 403 |
| UA + `Sec-Fetch-Site` + `Sec-Fetch-Mode` + `Sec-Fetch-Dest` | **200** |

结论：判据是浏览器 Fetch Metadata（`Sec-Fetch-*`），不是 UA / Referer / Origin。

## 3. 代码改动

`plugins.v2/cloudsubscribe/search/hdhaven/client.py` 会话默认头补三个头：

```python
"Sec-Fetch-Site": "same-origin",
"Sec-Fetch-Mode": "cors",
"Sec-Fetch-Dest": "empty",
```

（同插件的 hdhive / dian115 / uindex 会话本就带这些头，HDHaven 是漏网的那个。）

## 4. 改动后实测（插件等价头集合，HTTPS 直连）

```bash
curl -sS -H "User-Agent: <Chrome/128>" -H "Accept: application/json, text/plain, */*" \
  -H "Accept-Language: zh-CN,zh;q=0.9,en;q=0.8" -H "Referer: https://hdhaven.com/" \
  -H "Origin: https://hdhaven.com" -H "Sec-Fetch-Site: same-origin" \
  -H "Sec-Fetch-Mode: cors" -H "Sec-Fetch-Dest: empty" \
  https://hdhaven.com/api/auth/registration-config
# HTTP 200，turnstile_site_key = 0x4AAAAAAE6M3XfI3JzwDd99（与站点公钥一致）
```

- 403 消失，`login()` 里的「无法获取 Cloudflare site key」分支不再触发；
- 因 HDHaven 的登录 / 搜索 / 解锁共用这套网页接口，三处一并恢复。

新增用例 `tests/test_hdhaven_browser_headers.py`（5 例）：

1. 会话默认头含 Fetch Metadata 三元组；
2. 原有 UA / Referer / Origin 未被破坏；
3. 真实 `requests` 会话 `prepare_request` 合并后的**出站头**带齐三元组（避免只断言字典、漏掉合并行为）；
4. `login()` 能从 `registration-config` 取到 site key，且取 key 的调用 `auto_login=False`（防递归）；
5. 取不到 key 时报「Cloudflare site key」错误（锁死现场根因的报错文案）。
