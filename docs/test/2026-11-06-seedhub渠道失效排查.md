# SeedHub 渠道失效排查与修复（1.9.63）

> 状态：已完成 2026-11-06，对应 v1.9.63

## 现象

资源嗅探 / 抽屉搜索里 SeedHub 恒为 0 条，日志持续刷：

```
[谷雨 S01][SEEDHUB] 外部查询抛出异常：SeedHub 浏览器仿真未通过 Cloudflare 验证
SeedHub 触发SeedHub 浏览器验证，冷却 30 秒
```

`mp_log.sh plugins/cloudsubscribex.log 20000` 统计：窗口内 `SEEDHUB=0` 出现 10 次、`SEEDHUB=[1-9]` 0 次，即从未成功。

## 排查结论（两条独立原因）

### 1. 站点整站迁移

`https://www.seedhub.cc/` 现在 302 到 **`https://sidhub.cc/`**（页面内自身链接也是 sidhub.cc）。旧域名 `.top/.pro` 同样 302，`.icu` 无解析。

用 curl_cffi（Chrome 指纹）直连实测新站可用：

| 检查项 | 结果 |
| --- | --- |
| `GET /s/吞噬星空/` | 200，8 条候选命中现有正则 |
| 详情页 `/movies/57509/` | 200，`pan-links` 7 处、`redirect_to=pan_id_` 348 处、`seed_id` 5 处 |

说明解析代码本身没坏，旧的 `_SEARCH_PATTERN` / `_ENTRY_PATTERN` 仍匹配。

### 2. Cloudflare 防护升级为交互式 Turnstile

- 纯 `curl` 无指纹：403 `Just a moment...`
- curl_cffi `impersonate=chrome`：200（本机 IP）
- 真浏览器（Playwright headless）：停在 `Performing security verification`，40 秒仍未过

线上插件原流程是「直连失败 → 一次性浏览器快照」，快照拿到的仍是质询页 → 判为未通过 → 冷却 30s。

而同一台服务器上 HDHaven（同样是 Turnstile）能拿到 15 条，日志有 `HDHaven-Turnstile 空闲 600s` —— 说明「常驻浏览器 + 点验证框 + 等 `cf_clearance`」这条路在用户机器上是通的。

## 修复

1. 新增 `search/seedhub/urls.py`：`normalize_base_url()` 把 `seedhub.cc/.top/.pro/.icu`（含 www）统一归一到 `https://sidhub.cc`，其它自定义地址原样保留；客户端默认地址、设置页占位/默认值同步改新域名。
2. `SeedHubSecurity._browser_text`：先走 `get_cloudflare_solver()`（常驻反盾浏览器，会点验证框、等 `cf_clearance`），成功即复用其 Cookie/UA 继续直连；失败再退回原单次快照，保证老环境不退化。
3. 指纹复用放宽同站别名域名（`seedhub`/`sidhub`），跳转域名下拿到的 Cookie 不再被域名过滤丢掉。
4. 失败文案改为「SeedHub 被 Cloudflare 人机验证拦截（浏览器自动过盾失败）；可配置代理或稍后重试」，不再让人以为是解析坏了。

## 验证

- 新增 `tests/test_seedhub_channel.py` 4 例：旧域名归一、自定义地址保留、空值回落、新域名不改写 —— 通过。
- `scripts/lint.py --all`：461 文件 0 error。
- 线上效果待用户升级 1.9.63 后复测（本次无法在本地复现用户机器上的反盾环境）。

## 遗留

- 若用户服务器出口 IP 被 CF 长期标记，自动过盾仍可能失败，兜底是给 SeedHub 配代理（`search_proxy`）。
