# 界面信息架构重排 + 状态词统一 验收（1.9.0）

## 背景

用户反馈：「任务中心 / 历史记录 / 频道监控 / 资源账本」四个页面用起来混乱，问有没有从 UI 到逻辑的优化方案。选定方案 A（信息架构）+ C（状态词表）。

## 现状问题（改造前）

| 问题 | 证据 |
| --- | --- |
| 五个页签平级，但概念维度不同 | `AppPage.vue` 的 `v-tabs`：订阅任务 / 历史记录 / 频道监控 / 网盘整理 / 资源账本 |
| 任务页有两份任务列表 | `RuntimeCard`（运行时任务列表）+ `TaskCenterTable`（队列/失败列表）同时渲染 |
| 「资源账本」名字不含语义，用户不知道点进去干什么 | 实际内容是 `candidate_ledger_entries`：最近 N 天没转存的候选与原因 |
| 状态词各说各话 | 任务中心「处理中 / 下载中」，历史「处理中 / 下载中 / 秒传失败 / 跳过」，频道 `queued / new / transferred / skipped`，账本「分享失效 / 无可用文件 / 内容不匹配」 |
| 移动端 5 个页签挤成三行 | 移动端规则 `.workspace-tabs :deep(.v-tab) { flex: 1 1 50% }`，5 个 tab 按 50% 宽排 |

## 改动

### A. 信息架构

1. **页签 5 → 4**：任务 / 历史记录 / 频道监控 / 网盘整理。「订阅任务」改名「任务」（避免与"外部订阅"混淆）。
2. **资源账本并入历史**：历史页顶部 `v-btn-toggle` 切换「转存结果 | 未转存原因」；未转存原因渲染 `CandidateLedgerPanel`（`v-if`，切走即销毁，少一次无用请求）。旧 `mainTab === "ledger"` 入口在 `watch(mainTab)` 里重定向到 `history + skipped`。
3. **运行时卡片去重**：`RuntimeCard` 从任务页常态展示改为：
   - 顶部 `runtime-bar`：状态图标 + `runtimeSummary` + 进行中数量 + 「运行详情」按钮
   - 完整 `RuntimeCard` 收进 `v-dialog`（`runtimeDetailVisible`）
   - 任务列表只剩 `TaskCenterTable` 一份
4. **统计卡片可点击**：`StatsGrid` 增加 `@select` 事件与键盘支持（Enter / Space、`role=button`、`tabindex`）；`usePageData` 的 `stats` 增加 `filter` 字段（成功 / 失败 / 空）；`AppPage.handleStatSelect` 跳到历史页并把统一状态词下发给 `HistoryTable`（新 prop `initialStatuses`）。

### B. 状态词统一（方案 C）

新增 `frontend/cloudsubscribex/src/utils/status.js`：

| 导出 | 作用 |
| --- | --- |
| `STATUS` | 七个统一词：排队 / 进行中 / 待确认 / 成功 / 失败 / 已跳过 / 忽略 |
| `statusText(raw)` | 原始值（中文或英文）→ 统一词；未命中原样返回，避免新状态被吞 |
| `statusColor(raw)` | 统一词 → `v-theme` 颜色 |
| `STATUS_QUERY` | 统一词 → 后端筛选值集合（进行中 = 处理中 + 下载中，已跳过 = 跳过） |
| `HISTORY_STATUS_OPTIONS` | 历史页筛选项（进行中 / 待确认 / 成功 / 失败 / 秒传失败 / 已跳过） |
| `statusFilterLabel` / `statusQueryValues` | 反向映射与提交时展开 |

接入点：

- `TaskCenterTable.vue`：状态 chip 文本改 `statusText`，颜色委托 `statusColorOf`（保留 `paused` 与 `dead_letter` 特判）；筛选标题「运行中 → 进行中」「等待重试 → 排队」，提交值不变（后端 `state` 参数不变）。
- `HistoryTable.vue`：状态 chip 文本改 `statusText`；筛选选项改为统一词，提交时 `statusQueryValues()` 展开成后端多值；颜色委托 `statusColorOf`（保留秒传未命中的琥珀色）。
- `TgMonitor.vue`：`queued/new → 排队`、`transferred → 成功`、`skipped → 已跳过`、`ignored → 忽略`。

## 已知取舍

- 「排队」在历史库里无法与「处理中」区分，所以历史页筛选项不含「排队」；任务页的「排队」对应后端 `state=waiting`。
- 「今日转存」没有独立的筛选维度（后端不支持按天过滤），点击后跳到历史全部。
- 账本（未转存原因）现在是 `v-if` 挂载，切回会重新拉数据；数据量小，可接受。
