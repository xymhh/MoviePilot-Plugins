# aria2 工作目录跟随跨盘缓存目录 验收（1.8.11）

## 问题

用户反馈「aria2 下载缓存全在 log 文件里，为什么不用转存设置里跨盘缓存目录」。

## 代码级定位（1.8.10）

| 文件:行 | 事实 |
| --- | --- |
| `core/aria2/service.py:139-140` | RPC `addUri` 显式传 `dir=<target.parent>`、`out=<target.name>`，所以 `.bin` 本体**一直**写在配置的跨盘缓存目录，没有写进日志 |
| `__init__.py:1919`（旧） | `configure_aria2(data_dir=Path(self.get_data_path()))` —— aria2 **工作目录**（aria2c 二进制、`aria2.session`、`aria2.log`）固定落在插件数据目录，与 MoviePilot 日志同盘 |
| `core/aria2/engine.py:196` | `--log=<data_dir>/aria2.log`，且未设 `--log-level`；aria2 文件日志默认 debug 级别，一次 30GB 下载会记录每个分片与续传细节，日志可达数百 MB |
| `core/aria2/__init__.py`（旧）`configure_aria2` | 只在 `enabled=False` 时停旧 daemon；`data_dir` 变化不重建进程 |

结论：用户看到的「缓存进 log」是 aria2 工作目录写死在插件数据目录 + debug 级文件日志；下载本体位置本身是对的。

## 改动（1.8.11）

1. 新增 `core/aria2/__init__.py:resolve_data_dir()`：配置了跨盘缓存目录 → `<缓存目录>/.aria2`；未配置 → 插件数据目录原位置（不迁移历史 bin/log）；两者都空 → `/tmp/cloudsubscribex-aria2`。
2. `__init__.py:_aria2_data_dir()` 接管 `configure_aria2(data_dir=...)`。
3. `configure_aria2` 在 `data_dir` 变化时停掉旧 daemon，让新目录立即生效。
4. `engine.py` 启动参数加 `--log-level=warn`；新增 `Aria2Engine._rotate_logs()`，启动前若 `aria2.log > 20MB` 滚到 `aria2.log.1`（只留一份）。
5. 残留清理改为扫多目录：`cleanup_transfer_residue` 依次扫「跨盘缓存目录（或 /tmp）+ aria2 工作目录 + 插件数据目录」，按 `Path.resolve()` 去重、跳过不存在的目录，统计字段累加后返回（新增 `roots`）。
6. `core/residue.py:resolve_roots()`：纯函数去重，供上面复用。
