# 同集去重提前到下载前（1.34.0）验收记录

> 起因：1.33.0 的入队时间窗只能挡「转存/下载完成之后」的那一份。用户追问
> 「是入库不重复，还是下载那一步就不重复」——实测答案是后者做不到：同一集
> 一小时内仍被下载三次（S01E07 4694MB + 4820MB + 272MB），因为候选阶段
> 判断「这集缺不缺」用的是云端目录快照与 Emby 缺集，上传后快照还没刷新。

## 改动

- `FunnelQueueRepository.list_recent_done_episodes(media_type, tmdb_id, season, within_seconds)`：
  同剧同季在窗口内已 `done` 的集号集合（单条 SQL，窗口 ≤0 或 tmdb_id 为空返回空）。
- `FunnelService.recent_done_episodes(mediainfo, season)`：按
  `funnel_recent_done_window_hours` 取窗口，仓储不可用/异常一律返回空集合（fail-open）。
- `handlers/sync/television.py`：`existing_episodes_in_resources` 并入上述集号，
  命中即不再进入转存/下载；日志记
  「… 在去重窗口内已入库，本轮按已有处理（不再重复下载）」。
  只接受真实集合（`set/frozenset/list/tuple`）并逐项 `int` 收敛——测试替身或宿主
  缺组件时拿到的是 Mock，直接参与集合运算会把「已有集」污染成 Mock（实测过，
  一次改坏 12 个用例）。

## 证据

| 项 | 结果 |
| --- | --- |
| 新增用例 | 3 条（窗口内返回集号 / 窗口 0 返回空 / 在途行不算已入库） |
| 全量 pytest | **3003 passed / 13 failed**，13 个失败逐条与基线一致（全在 `test_strm_redirect.py`） |
| lint | `scripts/lint.py --all` → 0 error / 417 warning，静默面 0/0 |
| 顺带修 | `test_cache_sweep_1_32_0.py` 两条用例改为桩掉 `shutil.disk_usage`：此前真实磁盘低于 15% 时必然失败（当晚磁盘掉到 3.2% 就复现了） |

## 现在的三段防线

| 阶段 | 拦截 | 是否省下载 |
| --- | --- | --- |
| 候选判缺集 | 云端目录 + Emby 缺集 + **窗口内已 done 的集（本版）** | ✅ |
| 入队整理队列 | `find_recent_done`（1.33.0） | ❌（已下载） |
| 上传前 | `_probe_same_stem` 同主干查重（1.33.0） | ❌（只省上传） |
