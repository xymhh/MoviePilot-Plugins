# 一键转存「请选择订阅或有效的 TMDB 媒体」根因与修复（1.6.19）

> 状态：已完成 2026-10-09，修复随 CloudSubscribe 1.6.19 发布

## 现象

用户在「资源搜索」页搜索资源后点击行内「一键转存」，前端提示
`请选择订阅或有效的 TMDB 媒体`。

## 根因（源码链路）

1. 前端 `frontend/cloudsubscribe/src/components/AppPageResource.vue` 的
   `submitManualDownload()`：**没有选中媒体上下文**时，媒体类型默认取 `tv`
   （`media.media_type === "movie" ? "movie" : "tv"`），随后按标题调
   `plugin/CloudSubscribe/search/tmdb` 反查 TMDB。
2. 后端 `core/api/search.py::api_vue_search_tmdb_candidates()`：原实现按
   `media_type` **严格过滤**候选。电影被当作电视剧查询 → 电影候选全部被过滤 →
   `items` 为空。
3. 前端反查拿不到候选 → `payload.media.tmdb_id` 保持 `null` → 提交到
   `core/api/sync.py::_do_api_vue_start_manual_sync()` → `tmdb_id <= 0` →
   返回 `请选择订阅或有效的 TMDB 媒体`（`core/api/sync.py:353`）。

排除项：1.6.18 只改 7 个 py 文件（retry/transfer/p115/tianyi/seedhub/subs_filter +
`core/api/search.py` 的 `api_vue_test_search_source` 段），未触碰前端；该报错与
反查策略来自更早的上游提交 `cd69f80`，属既有行为而非 1.6.18 引入。

## 修复

- **后端（主修复，对已有前端包立即生效）**：按 `media_type` 过滤时，不符类型先暂存；
  若过滤后为空，则放宽类型返回（保持用户所需类型优先、其余按原相关度）。
- **前端**：反查命中后采用候选的真实 `media_type`（含 TMDB 季列表）；
  仍然反查不到时给出可操作提示（引导去「手动添加资源」选媒体），不再让用户对着
  后端模糊报错猜。

## 追加修复（1.6.20）：TMDB 里根本没这部片

> 状态：已完成 2026-10-09，随 CloudSubscribe 1.6.20 发布

### 现象

1.6.19 生效后用户复测，仍然「识别不出来」。目标媒体是电影
**《巴黎绽放的星辰 (2026)》**，MoviePilot 侧豆瓣识别成功（豆瓣 37473691），
但 `themoviedb` 按「名称 + 年份」匹配不到任何条目 —— 即该片**未被 TMDB 收录**
（新片常见，中文片名尤其），所以 `tmdb_id` 永远拿不到，与 1.6.19 修的
「类型不匹配」是两回事。

### 修复

- **后端 `core/api/sync.py::_do_api_vue_start_manual_sync`**：`tmdb_id <= 0` 时
  不再直接报 `请选择订阅或有效的 TMDB 媒体`，改为调用新增的
  `_resolve_manual_media_by_identity()` 兜底识别 —— 依次可用
  `media_source/media_id`（前端原样回传，如 `douban:37473691`）、`douban_id`、
  `bangumi_id`、`anilist_id`，以及**明确带媒体上下文时**的标题 + 年份；
  识别成功即继续原转存流程；识别不到才回原报错。
- **类型纠正**：兜底识别结果自带类型时以它为真（前端在无媒体上下文时默认按
  电视剧传，电影会被带错类型）。
- **身份规范化**：前端若回传 `douban:37473691` 这类带来源前缀的 `media_id`，拆成
  `media_source=douban` + `media_id=37473691` 再用（规范契约要的是裸 ID，带前缀会直接识别失败）。
- **`manual_target`**：`tmdb_id` 空缺时写 `null`（下游按 `or 0` 处理），并补
  `media_source` / `media_id` 供入库整理使用。
- **前端 `AppPageResource.vue`**：只有「既没有 TMDB ID、也没有任何其它身份、
  又没有媒体上下文」时才拦下并提示；带媒体上下文时额外传 `seek_by_title: true`
  授权后端按标题兜底，避免纯标题猜错媒体（无媒体上下文的自由文本搜索行为不变）。

用例覆盖：① 无 TMDB ID 但有豆瓣身份 → 转存成功且 `manual_target` 带
`media_source=douban`、`tmdb_id=null`；② 前端误传 `tv`、实际是电影 → 类型纠正为
`movie`；③ 完全无身份（纯资源标题、无媒体上下文）→ 仍返回原报错且不提交任务；
④ `media_id=douban:37473691` 带前缀 → 规范化成 `media_source=douban` / `media_id=37473691` 再交给识别链。

### 已知边界（要告诉用户）

- TMDB 未收录该片时，重命名模板里的 `{{tmdbid}}` 会为空，Emby/Jellyfin 的
  `[tmdbid=...]` 段会空着；如需要可在模板里改用/并存 `{doubanid}`。
- 兜底识别仍依赖 MoviePilot 的识别链；豆瓣也认不出时，只能走「手动识别」。


### 附带修复（CI）

首次推送 1.6.20 时发布流程 `get_plugin_meta.py` 报 `'str' object has no attribute 'get'`：
1.6.20 的 `package.v2.json` 顶层被误加了一个 `version` 字符串键，脚本遍历顶层条目时把它当
插件信息读。已移除该键并补 `history` 里的 v1.6.20 发布说明，本地跑同一脚本验证输出正常后重推。
