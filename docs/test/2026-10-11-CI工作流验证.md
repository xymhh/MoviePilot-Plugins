### 首跑失败的真实原因（逐条定性）

1. **运行时依赖缺失（4 个 import 错误）**：`pytz` / `requests` / `httpx` / `apscheduler` 由 MoviePilot 运行时提供，插件 `requirements.txt` 不声明 → CI 里补装。
2. **`test_manual_share_dedupe` 3 个断言失败（非插件缺陷）**：`FakeOwner` 缺 `_explicit_selection_values` 桩 → `OwnerDelegator.__getattr__` → `FakeOwner.__getattr__` 返回 `MagicMock` → 解包抛 `ValueError: not enough values to unpack (expected 2, got 0)`，被 `television.py` 的 `except` 吞掉，表现为「一条都没转存」。
   - 真实实现：`handlers/sync/resources.py:675`（返回 `([], [])`）、`:695`（未勾选时原样返回候选）、`:746`（签名新增 `target_file_ids` / `target_file_names`）。
3. **`test_due_pending_keys` 失败**：`_due_pending_keys` 已由静态方法改为实例方法并新增 `pending_keys` 参数（`handlers/sync/postprocess.py:306`），用例仍按静态调用 + 缺 `skip_history`（否则落入 `_history_ready_for_finalize` 宽限期，全部不算到期）。
4. **`test_transfer_organize_behavior` 整个模块 import 失败**：`cloudsubscribe.search` 在测试里只是 `AutoMockModule`（`__path__` 为空），`service.py:60` 的 `from ...search.magnet import extract_magnet_hash` 抛 `ImportError ... (unknown location)` → 改为 `load_module` 真实加载 `search/matching.py` → `utils/magnet.py` → `search/magnet.py`。

判定：**全部是测试桩/环境滞后，不是插件功能缺陷**（每条都对照了真实实现的行号）。
