## 4. 设计说明与偏离

- **即时转存路径**（`television.py`）复用判重那一次列目录 `episode_dedup._season_dir_files`
  （含 TTL 缓存），一次列目录覆盖整批，不额外打网盘。
- **finalize / 兜底补写路径**（`history.py::_mark_offline_history_status_batch` /
  `reconcile_orphan_finalize_records`）该处拿不到 `(subscribe, mediainfo, season)`，
  改为按记录自身 `cloud_dir` 列一次目录（同批同 `cloud_dir` 只列一次，`verify_landed_records`
  内 `dir_cache` 去重），仍满足「不逐文件反查、不跨目录全盘扫描」。这是相对任务书
  「一律复用 `_season_dir_files`」的**有记录偏离**。
- 后处理写成功记录处（`postprocess.py` 两处）复用 `verify_landed_items`（即时路径同款）。
- **「查无实据」复核（主 agent 复核时补，用例 j）**：季目录自检判「没有」、且记录自称落在
  另一个 `cloud_dir`（媒体库/其它路径）时，再按记录自己的目录核一次，那儿有实物仍按成功处置——
  与 1.6.51「记录落在别的目录时本轮不越权判定」同口径，避免把落在别处的记录误记「待确认」。
  代价：仅在这类记录上多列一次目录（同目录去重），常态路径（记录 `cloud_dir` 为空或等于季目录）
  一次也不多打。开关关闭时直接返回，不产生任何列目录（用例 e 断言 `list_calls==0`）。
- `landed`/`verified_at`/`landed_reason` 全部可选、向后兼容；老记录无字段按未知处理，
  行为与 1.6.51 逐字节一致（用例 d/e/g 覆盖）。
- `_episode_dedup_decision`、`_season_dir_files` 返回语义与缓存键、`_platform_target`
  命名路径、1.6.42 点选边界均未改动。
