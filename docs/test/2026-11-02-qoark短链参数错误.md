# qoark 短链导致 44 条「参数错误。」—— 定位与修复（v1.9.25）

## 1. 现象

2026-11-02 用 CLI 拉线上账本（`cli-cs ledger`），1588 条里 44 条 `reason = "参数错误。"`，
`provider = "分享链接"`，`reference` 全部是 `https://pan.qoark.cn/s/<id>`：

```
[分享链接] 🎞️ 后西游记 第一季 (2026) | ref=https://pan.qoark.cn/s/vkuabikk4n
[分享链接] 🎞️ 怪奇物语：1985故事集 第二季 (2026) | ref=https://pan.qoark.cn/s/wzuinfype5
[分享链接] 🎞️ 邻人可疑 (2026) | ref=https://pan.qoark.cn/s/mptxpnpc9z
```

## 2. 根因

`pan.qoark.cn` 是**夸克的中转短链**，实测 302 到真实分享：

```
$ curl -sI -L https://pan.qoark.cn/s/vkuabikk4n
code=200 url=https://pan.quark.cn/s/5eef7f324c9d
```

但插件不认识这个域名，三连失误：

1. `search/types.py` 的 `TYPE_HOSTS["quark"]` 只有 `quark.cn`，查不到 `qoark.cn` → 类型为空；
2. `handlers/sync/resources.py:1011` `_resource_provider_for_url` 拿不到 provider
   （`key` 非 `115` 时返回 `None`）→ 回退默认 115 分享服务；
3. 115 的接口解析夸克链接 → 返回「参数错误。」，账本里只留一句没有任何信息量的话。

**不是数据问题，是域名识别缺失。**

## 3. 修复

| 文件 | 改动 |
| --- | --- |
| `core/share_link.py`（新增） | `canonicalize_share_url()`：白名单域名跟随 302 取真实链接，24h 进程内缓存，失败原样返回；只对 `qoark.cn` 发请求，先 HEAD 后 GET，超时 6s |
| `search/types.py` | `TYPE_HOSTS["quark"]` 加 `qoark.cn` |
| `handlers/sync/resources.py` | `_validated_resource_files` 入口先规范化 URL（覆盖电影/剧集/洗版/预览四条路径） |
| `handlers/sync/transfer_ops.py` | `_transfer_file` 入口先规范化 URL（覆盖所有转存路径，含重试与字幕） |

设计取舍：

- **不做全局 URL 改写**，只在「校验前」和「转存前」两个咽喉展开 —— 入口太多（用户贴链接、频道推送、搜索渠道），逐个改必漏。
- **解析失败原样返回**：宁可走旧路径报错，也不能让短链解析卡住转存。
- **只对白名单域名发请求**，避免被任意 URL 当成 SSRF 跳板。

## 6. 补漏：1.9.25 修得不完整（1.9.26 才真正修好）

### 6.1 1.9.25 漏在哪

1.9.25 只在 sync 侧两个咽喉展开（`_validated_resource_files` / `_transfer_file`），
但「预览分享链接」走的是另一条链路：

```
POST /search/preview → handlers/search/service.preview_resource
                     → 搜索渠道 provider.preview
                     → drive/quark/share.extract_share_info
```

完全绕过 sync 侧，短链匹配不到 `share_id`，报「无效的夸克分享链接」。

真机对照（1.9.25 已装）：

```
pan.qoark.cn/s/vkuabikk4n   → {"success":false,"message":"预览失败：无效的夸克分享链接"}
pan.quark.cn/s/5eef7f324c9d → {"success":true,"items":[{"name":"H 候嘻游记 4K 10集"}]}
```

### 6.2 1.9.26 的修法

在夸克驱动的两个底层咽喉也加展开（`drive/quark/share.py`）：

| 位置 | 覆盖 |
| --- | --- |
| `_share_access`（:136） | 预览、`check_share_status`、`list_share_files` |
| `_save_share`（:285） | `transfer_share`、按文件 id 转存 |

至此四条路径全部覆盖：sync 校验/列目录、sync 转存、夸克预览、夸克转存。

## 7. 教训

同一个 bug 修了两版，原因是**只按「我知道的调用路径」改，没有先枚举全部入口**。
正确顺序应该是：先 `grep` 出所有会用这个 URL 的函数（`extract_share_info` 的 20 处调用点），
判断哪几处是真正的咽喉，再动手。预览这条路径就在 grep 结果里，只是当时跳过了。
