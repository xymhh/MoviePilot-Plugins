# P115StrmHelper 历史 STRM 批量迁移到本插件（2026-10-25）

## 现象

Emby 里大量条目的媒体路径仍是 `P115StrmHelper/redirect_url`，303/302 逻辑不生效。

## 实测数据

Emby `GET /Items?Recursive=true` 共 **18074** 条：

| 路径 | 条数 |
| --- | --- |
| `/media/strm/115网盘` | 10040 |
| `/media/strm/115网盘分享` | 5153 |
| `/media/strm/追更` | 2881 |

本地 STRM 实扫：

| 目录 | 扫描 | 原是 P115 | 已是 CS |
| --- | --- | --- | --- |
| `/strm/115网盘` | 9702 | 9238 | 464 |
| `/strm/115网盘分享` | 10138 | 10138 | 0 |
| `/strm/追更` | 0 | 0 | 0（文件已不存在，Emby 是残影索引） |

## 根因

`rebuild_strm_tree`（全量校准）是**从云端媒体库起递归**，只能覆盖云端实际存在的 399 个视频；
P115 当年生成的其余 19000+ 条 STRM 不在云端遍历范围内，从未被本插件接管。

## 修复（1.7.65）

- 新增 `utils/legacy_strm.py`：只把 URL 前缀 `P115StrmHelper/redirect_url` 替换为
  `CloudSubscribeX/redirect`，`pickcode` / `share_code` / `receive_code` / `id` 参数原样保留。
- 新增 `POST /strm/migrate_legacy`（`{"root": "...", "dry_run": true}`），执行后自动刷新媒体服务器。
- 可逆：反向替换即还原为 P115 端点。

## 验证

- PlaybackInfo 抽查：转存型 `pickcode=bifi46r3d8kkv88mg`、分享型 `share_code=swsjvyp33yp&receive_code=bb74&id=3532810503065699618` 均已是 CS 端点。
- 实跑 302：两者都 `HTTP/2 302` → `https://cdnfhnfile.115cdn.net/...`。

## 遗留

`/strm/追更` 在 Emby 仍有 2881 条索引，但本地文件已不存在 → 需在 Emby 删除该媒体库或触发全库扫描清理。
