# 设置项信息架构整改（批次 B）

日期：2026-11-06 ｜ 版本：1.9.52

## 做了什么

1. **分区 12 → 7**
   原：基础设置 / 转存设置 / 网盘整理 / 榜单订阅 / 签到服务 / 频道监控 / STRM / Emby 302 / 网盘配置 / 搜源 / 洗版设置 / 通知设置
   现：概览 / 网盘与媒体库 / 订阅与榜单 / 搜源 / 转存与整理 / STRM 与播放 / 通知与监控

   | 新分区 | 组成 |
   | --- | --- |
   | 概览 | 插件运行 + 订阅行为 + 调度与接管（原基础设置拆组） |
   | 网盘与媒体库 | 媒体库组（网盘/Emby/期集换算）+ 各网盘账号 |
   | 订阅与榜单 | 原「榜单订阅」8 个子页不变 |
   | 搜源 | 原「搜源」不变 |
   | 转存与整理 | 转存设置 + 网盘整理 + 洗版设置 |
   | STRM 与播放 | STRM + Emby 302 反代 |
   | 通知与监控 | 通知设置 + 签到服务 + 频道监控 |

2. **「接管」合并**：`takeover_new_subscribes`（原运行设置）、`block_system_subscribe` / `block_start_time` / `block_end_time`（原「订阅接管时段」）、`platform_download_policy`（原「提供方设置」）合并为概览的「调度与接管」一组，原「订阅接管时段」「提供方设置」两组随之消失。

3. **「运行设置」拆 4 组**（落为 3 组 + 1 个媒体库组）：
   插件运行（启用/侧边栏/Agent/周期）、订阅行为（标题订阅/直达转存/补全季/跳过第 0 季/季数上限/记录保留/账本同步）、调度与接管、媒体库（网盘/Emby 库/期集换算/忽略路径）。

## 实现方式

- `frontend/cloudsubscribex/src/config/fields.js`：不再逐个渲染 12 个 section，而是先构造各 section，再用 `collectFields` + `pickFields` 按 key 重组分组；未改任何字段定义文件。
- `components/Config.vue`：`navGroups` 白名单改为 7 个新 value；`activeTab` 默认 `overview` 并对失效值回落首个分区；`optionScopeByTab` 改为数组，切分区时并行加载多个选项 scope。
- 字段 key、默认值、后端配置结构零改动。

## 教训

- 分区重组不需要改字段定义，运行时按 key 重组最安全；改完后必须做一次「新旧 key 集合对比」，否则容易漏字段（本轮就漏了 `agent_enabled`，对比脚本抓出来了）。
