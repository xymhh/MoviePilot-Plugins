# 2026-11-12 1.9.80 循环导入死锁修复 — 复盘（定论）

## 现象与真因

用户报「插件没法更新」。包、市场索引、Release 资产全部正常，**问题在 MP 加载插件本身**：

```
loader.py  - 加载插件 cloudsubscribex 失败：
             deadlock detected by _ModuleLock('app.plugins.cloudsubscribex.core.api.sync')
lifecycle.py - 插件 CloudSubscribeX 加载失败：加载器未返回匹配的插件类
```

同一个死锁 **13:51 与 16:38 各出现一次**，所以不是偶发 —— 之前 1.9.76 那次「重启就好了」其实是**掩盖**，代码里的环一直存在。

## 环路（循环导入）

```
core.api.sync  ──from .. import ...──▶  core/__init__.py   (开始初始化，持锁)
                                             │
                                             ├─ from ..utils.notify_template ─▶ utils 包
                                             │                                    │
                                             │        utils/__init__.py:22 ───────┤
                                             │        from ..core.media ──────────┤
                                             │                                    │
                                             │        utils/strm_export.py:18 ────┤
                                             │        from ..core.cloud ──────────┤
                                             ▼                                    ▼
                                        回到仍在初始化的 core 包 → 同线程递归拿同一把模块锁 → deadlock
```

两条环路，缺一不可：
1. `utils/__init__.py` 的 `from ..core.media import media_identity`
2. `utils/strm_export.py` 的 `from ..core.cloud import CloudDriveCapability`

## 修法与取舍

- `media_identity` 那行**直接删**：全仓没有任何地方 `from utils import media_identity`，使用方一律 `from ...core.media import media_identity`。它是纯冗余，也是环的入口。
- `strm_export.py` 改**函数内延迟 import**：运行时 core 包早已初始化完，延迟导入既保住功能又断开环路。
- 方向保留 `core → utils`（只 import `utils/notify_template.py`，独立文件不经 `utils/__init__`），只切断 `utils → core`。

## 弯路（重要）

我先做了「把 `core/api/*.py` 里 14 处 `from .. import` 全改成直接子模块导入」。**技术上能进一步降低耦合，但代价太大**：测试大量用 `register_module("cloudsubscribex.core", SearchCapability=MagicMock(), ...)` 把符号放在**包级**，改直连后桩全部失效，`test_tmdb_candidate_type_fallback` / `test_yun139_caiyun_share` 收集失败。

**已全部回退**，只保留打破环路的 `utils` 侧最小改动。教训：**修 bug 要瞄准「最小必要面」**，顺手重构会引入比原 bug 更大的风险面。

## 测试假通过的第二次教训

初版 `test_no_import_cycle.py` 只检查 `utils/__init__.py`。变异反证 A（把 `strm_export.py` 的反向 import 加回去）**照样通过** —— 因为 `strm_export.py` 根本没被检查。

补成**遍历全部 `utils/*.py`** 后，两处变异才都能抓出。

**规律**：写「禁止某模式」的守卫测试时，扫描范围必须覆盖**整个目录**，不能只盯你刚改的那个文件 —— 环路的另一条腿往往就在隔壁。
