# 1.7.70：新增「跨盘任务一律走中继」开关

日期：2026-10-25

## 需求

用户要求：插件的跨盘转存支持「全部交给中继」，不再依赖「115 秒传确认未命中」这个前置条件。

## 原行为

`CrossTransferTaskManager._run_locked` 的顺序是：

1. 若源文件不在本地且有 sha1，先用 115 的 `probe_by_hash` 试探秒传；
2. 命中 → 直接成功（零下载，最快）；
3. 未命中 → 若 `relay_active`（中继客户端有、源是夸克、大小 ≤ 上限、目标支持查询）则交中继；
4. 否则本机下载 + 上传。

问题：只要秒传能命中，文件永远不会交给中继；用户无法**强制**走中继。

另一个隐藏问题：「中继接管条件满足／未接管」这两行日志原本是 `logger.debug`，线上 INFO 级别根本看不到，
导致 2026-10-25 排查跨盘任务为何走本机链路时毫无线索。

## 新行为

新增配置 `cross_transfer_relay_always`（前端「跨盘任务一律走中继」，默认关闭）：

- **开**：在秒传探测**之前**判断，只要 `relay_active` 成立就直接调用 `_relay_transfer`，跳过 115 秒传探测与本机下载；
- **关**：逐字节维持原逻辑（默认值，老行为不变）；
- 中继失败仍按 `cross_transfer_relay_fallback_local` 决定回落本机还是记失败；
- 条件不满足（源不是夸克、超过单文件上限、目标盘不支持查询）时照旧走原链路 —— 开关只影响「本来就能交给中继的文件」。

诊断日志同步从 `debug` 提到 `info`，未接管一行带 `client / 大小 / 上限 / 目标可查 / 源` 五个字段。

## 改动清单

| 文件 | 改动 |
| --- | --- |
| `core/transfer.py` | `__init__` 接收 `relay_always`；`_run_locked` 在秒传探测前插入强制中继分支；接管/未接管日志提到 info |
| `core/drive_manager.py` | 把 `_cross_transfer_relay_always` 透传给 `CrossTransferTaskManager` |
| `__init__.py` | 类默认 `_cross_transfer_relay_always = False`、配置读取、`_log_relay_state` 增加「接管范围」 |

| `tests/test_cross_transfer_relay.py` | 新增 2 例：默认关闭、开启时中继必被调用且不触发下载 |

## 踩坑记录（重要）

**1.7.69 白发了。** 第一版只改了 `plugins.v2/cloudsubscribex/dist/assets/__federation_expose_Config-jRiUZ3j7.js`，
但 CI 的 `plugins-release.yml` 会用 pnpm 重新构建 `frontend/cloudsubscribex/` 并**覆盖整个 dist 目录**，
所以 1.7.69 的 Release zip 里根本没有新字段（实测 `cross_transfer_relay_always` 缺失）。

**结论：前端字段一律改 `frontend/cloudsubscribex/src/`，不要手改 dist。** 1.7.70 已改正，实测 zip 内
`__federation_expose_Config-CJtFRQCR.js` 含 `cross_transfer_relay_always`。

**2. `package.v2.json` 有两处 version。** 顶层 `version` 与 `CloudSubscribeX.version` 必须同时改，
只改顶层会让 CI 判定「无新版本」而不发 Release（1.7.69 第一次 push 就踩了这个，白等 5 分钟）。
