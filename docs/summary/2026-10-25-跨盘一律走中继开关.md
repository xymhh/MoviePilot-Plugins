# 1.7.69：新增「跨盘任务一律走中继」开关

日期：2026-10-25

## 需求

用户要求：插件的跨盘转存支持「全部交给中继」，不再依赖「115 秒传确认未命中」这个前置条件。

## 原行为

`CrossTransferTaskManager._run_locked` 的顺序是：

1. 若源文件不在本地且有 sha1，先用 115 的 `probe_by_hash` 试探秒传；
2. 命中 → 直接成功（零下载，最快）；
3. 未命中 → 若 `relay_active`（中继客户端有、源是夸克、大小 ≤ 上限、目标支持查询）则交中继；
4. 否则本机下载 + 上传。

问题：只要秒传能命中，文件永远不会交给中继；而秒传未命中的场景里，用户也无法**强制**走中继。

## 新行为

新增配置 `cross_transfer_relay_always`（前端「跨盘任务一律走中继」，默认关闭）：

- **开**：在秒传探测之前就判断，只要 `relay_active` 成立就直接调用 `_relay_transfer`，跳过 115 秒传探测与本机下载；
- **关**：逐字节维持原逻辑（默认值，老行为不变）；
- 中继失败仍按 `cross_transfer_relay_fallback_local` 决定回落本机还是记失败；
- 若条件不满足（源不是夸克、超过单文件上限、目标盘不支持查询），照旧走原链路 —— 开关只影响「能交给中继的文件」。

## 顺带修的诊断

「中继接管条件满足」与「中继未接管」原来打 `logger.debug`，线上 INFO 级别看不到，导致
2026-10-25 排查时无法判断为什么跨盘任务走了本机链路。现改为 `logger.info`，未接管一行会带上
`client/大小/上限/目标可查/源` 五个字段，下次一看日志就知道卡在哪一项。

## 改动清单

| 文件 | 改动 |
| --- | --- |
| `core/transfer.py` | `__init__` 接收 `relay_always`；`_run_locked` 在秒传探测前插入强制中继分支；接管/未接管日志提到 info |
| `core/drive_manager.py` | 把 `_cross_transfer_relay_always` 透传给 `CrossTransferTaskManager` |
| `__init__.py` | 新增类默认 `_cross_transfer_relay_always = False`、配置读取、`_log_relay_state` 增加「接管范围」字段 |
| `dist/assets/__federation_expose_Config-*.js` | 配置页新增开关（紧随「中继失败回落本机上传」之前） |
| `tests/test_cross_transfer_relay.py` | 新增 2 例：默认关闭、开启时中继必定收到任务且不触发下载 |

## 验证

- `pytest tests/test_cross_transfer_relay.py` → **22 passed**（原 20 + 新 2）。
- 全量 `pytest tests/`（本机 Python 3.11 跳过 2 个依赖 `p115client` 的文件）→ **784 passed, 3 failed**；
  3 个失败为存量（`test_checkin_days` 2 例、`test_tg_monitor::test_access_hash_cached_and_invite_link_never_rechecked` 1 例）。
- 说明：`tests/test_rapid_miss_abort.py`、`tests/test_cross_transfer_upload_concurrency.py` 在本机无法收集，
  原因是 `p115client 0.0.9.7.2` 需要 Python 3.12（用到 `collections.abc.Buffer` 与 PEP 701 f-string），
  生产镜像为 3.12 不受影响；本次改动只在秒传之前插入新分支且默认关闭，原路径未变。

## 待验证（真机）

打开开关后重跑「蓦然回首」（subscribe_id=45）或任何一个秒传未命中的跨盘任务，确认：

1. 插件日志出现「中继接管条件满足：… （N 字节，一律走中继）」；
2. 深圳中继 `/jobs` 出现对应任务，`/debug/logs` 有 `[job] … 开始`；
3. 任务成功后 115 侧存在文件且大小一致。
