# 302 播放 403 与 STRM 增量路径重复（1.7.54 / 1.7.55）

> 状态：已完成并线上验证 2026-10-25

## 一、播放必然 403：115 直链签名绑定取链时的 User-Agent

### 现象

Emby 反代 302 生效（`stats.hit` 一直增长、Location 是有效 `cdnfhnfile.115cdn.net` 直链），
但 Yamby 每 5 秒重试 `/emby/Videos/{id}/stream`，播放不成功。

### 实测证据

同一 pickcode、新鲜链接（`t` 比当前时间大 16.8 小时，未过期）：

| 请求 UA | 结果 |
| --- | --- |
| 空 UA | `200` / `206`（Range 正常） |
| Yamby / Infuse / VLC / Fileball / Emby / okhttp / ExoPlayer | `403 invalid signature` |
| Chrome / 115Browser / okhttp(115) | `403 invalid signature` |

### 根因

115 直链参数 `f=1` 的语义（p115client 文档原文）：

- `f=1`：请求直链时**必须携带 user-agent，且与取链时一致**
- `f=3`：还需要取链响应返回的 Cookie

而 `p115client` 的 `download_url()` 在 `user_agent=None` 时会 `headers.setdefault("user-agent", "")`
——**取链时发的是空 UA**，播放器带自己的 UA 去请求，自然被判 `invalid signature`。

### 修复（1.7.54）

把播放端 UA 一路传下去取链：

```
emby_proxy._try_redirect(user_agent=...)
  → _resolve_strm_url(..., user_agent)
    → RedirectApi._resolve_link(pickcode, file_name, user_agent)
      → P115FileDownload.resolve_download_link(item, user_agent)
        → client.download_url(pickcode, user_agent=user_agent)
```

换链缓存键从 `pickcode` 改为 `pickcode|user_agent`（不同播放器各自换链）。
`FileDownloadOperations` 协议与 7 个平台实现统一加 `user_agent: str = ""` 参数（仅 115 使用）。

### 线上验证

```
GET /emby/Videos/683343/stream (UA=Yamby)        → 302
跟随 Location (UA=Yamby, Range 0-2047)           → 206, 2048 bytes
跟随 Location (UA=VLC)                            → 403（符合 f=1 语义）
```

用户确认「可以播放了，流量也不走服务器了」。

## 二、STRM 增量每轮刷满「无法解析目录」

### 现象

每 10 分钟一轮，9481 个视频逐条：

```
STRM 增量：无法解析目录 /Alist/影视/moviepilot/媒体库/moviepilot/媒体库/电影/外语电影/xxx
```

### 根因

115 `export_dir` 给出的相对路径本身带有媒体库根的重复段，而代码里
`cloud_dir = root_path + parent_relative` 直接拼接，得到不存在的路径。

- 1.7.54：剥一层重复前缀
- 线上复查仍重复（相对路径会重复**两遍**，甚至整段已是完整路径）
- 1.7.55：改为两步
  1. 相对路径若已是完整路径（以媒体库根开头）→ 直接截断
  2. 否则循环剥离「媒体库根后缀 == 相对路径前缀」直到不再重复

### 线上验证

```
09:20:32 STRM 增量：目录树 12491 条路径，耗时 21.2 秒
09:20:33 STRM 增量：无缺失，检查 9483 个视频，耗时 21.8 秒
```

零「无法解析目录」，增量从「全量报错」变为「21.8 秒无缺失退出」。

## 三、教训

1. 第三方 SDK 的默认值可能带隐性协议约束（`user_agent=None` → 空 UA → 违反 `f=1`），
   报错信息（`invalid signature`）会把人误导到「签名算法/过期」方向，必须用**变量对照实测**
   （固定 URL 只改 UA）才能定位。
2. 「剥一层」这种修补要先确认重复的层数；线上数据比臆测可靠。
3. MP 插件索引有约 30 分钟 TTL，发版后无法立刻 `install?release_version=`，
   需等索引刷新后不带版本号安装（`force=true`）。
