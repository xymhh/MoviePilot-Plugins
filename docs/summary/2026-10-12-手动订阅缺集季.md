# 手动订阅按媒体库缺集补齐所有季（1.6.29）——总结

**日期**：2026-10-12 ｜ **版本**：CloudSubscribe 1.6.29（commit `c9d6b619`）
**相关**：[任务书](../plan/2026-10-12-手动订阅缺集季.md) ｜ [验收证据](../test/2026-10-12-手动订阅缺集季单测.md)

## 一句话

TG 发片名 → 选定平台候选后，插件不再只订第 1 季，而是**按媒体库缺集情况为每个缺集季各建一条订阅**（默认跳过 S00），
并把这套行为做成插件配置页的三个开关（可关、可调上限）。

## 问题与根因

- 现象：选定候选后只建 S01 订阅，S02/S03 缺集永远不被搜索补齐。
- 根因：`app/chain/interaction.py:973` 用 `season=meta.begin_season`（整剧候选 → `None`）调 `SubscribeChain.add`，
  `app/chain/subscribe/create.py:377` 把 `None` 兜底成 `1`。
- 用户诉求（2026-10-12 明确）：① 默认补**缺集季**（不是所有季）；② 本轮不动搜索源（Dian115 自动解锁先不关）；
  ③ 这些功能必须有 UI 开关与配置。

## 决策

| 决策 | 理由 |
| --- | --- |
| 挂在 `SubscribeChain.add / async_add` 上，而不是改造调用方 | 一次覆盖所有手动入口（片名直建、Web/TG 手动建订阅）；不动 MoviePilot 本体 |
| 缺集判定复用 `DownloadChain.get_no_exists_info`（与 auto_subscribe 的 `_media_progress` 抽公共函数 `probe_season_progress`） | 与插件既有「缺集」语义一致，避免两套判定 |
| 显式指定季号（`season=2`）绝不展开 | 尊重用户明确输入 |
| 全部季都完整 → 不展开、原样透传 | 保持旧语义，不引入「无订阅」这种新状态 |
| 首季沿用原通知参数，其余季 `message=False` | 避免一次建 N 条订阅刷 N 条通知 |
| `suppress_season_expansion()` 防重入 | 榜单自动订阅本就按季展开，否则会被二次展开 |
| 无法判定（无媒体身份 / 宿主异常）按「整季缺失」处理 | 与 `get_no_exists_info` 拿不到身份时的返回值语义对齐，避免悄悄把缺集当完整 |

## 新增配置（插件配置页「片名自动订阅」区块）

| key | 默认 | 说明 |
| --- | --- | --- |
| `subscribe_all_missing_seasons` | `true` | 关闭 = 恢复 1.6.28 旧行为（只订调用方指定的季） |
| `subscribe_skip_season_zero` | `true` | 不订特辑 S00 |
| `subscribe_season_limit` | `0` | 最多补建季数，0 = 不限 |

三处落点齐备：`core/config.py`（默认值）、`__init__.py`（读取 + `hot_keys` 热更新）、
`core/api/config.py`（保存清洗）、`frontend/cloudsubscribe/src/config/fields/basic.js`（UI 字段）。

## 教训（本轮最值得记的一条）

**委派实现的「单测全绿」不等于功能生效——验收必须对齐真实调用点的签名。**

- 委派方（ACP runner）首版实现只从绑定参数取 `mediainfo`，而 MoviePilot 的 `SubscribeChain.add` **没有**
  `mediainfo` 形参（片名选定路径只传 `media_source` / `media_id`）→ `resolve_subscribe_seasons(None)` 恒返回 `[]`，
  每次都原样透传，**功能静默失效**。
- 首版单测之所以绿：假 `add` 被写成了带 `mediainfo=None` 的形参，并且用 lambda 顶掉了真实的季解析逻辑 ——
  **测试桩比真实接口「更好用」时，测试就失去意义**。
- 修正做法（主 agent 亲自改）：`seasons.py` 接受 `media_source/media_id/mtype`，缺 mediainfo 时用
  `MediaChain().recognize_media(...)` 重新识别；用例 1/11 改为**真实签名**调用，并让它们跑**真实**解析逻辑。
- 沉淀成规矩：以后凡挂钩 MoviePilot 类方法，任务书必须写明**真实调用点的参数清单**，且新增单测必须用真实签名 +
  真实被测逻辑（只允许 mock 宿主（`app.*`）边界，不允许 mock 自家新模块）。
