# 历史重试：目标季目录已有同集却反复失败（1.7.21）

日期：2026-10-20。状态：代码与单测完成，版本 1.7.21，待发布。

## 现象

用户在历史页对失败记录点「重试」，仍然失败；实际 115 媒体库季目录里已经有对应剧集。最近复现集中在：

- 《把黑夜点燃》S01E04/E05：历史记录目标名 `.mkv`，库里实际是 `.2160p.mkv`（1,809,965,794 / 1,920,073,415 字节）。
- 《玉簟秋》S01E01、E03-E08：历史记录目标名 `.mkv`，库里实际是 `.iso`（3.2–3.9 GB）。

## 根因

`retry_history_record` 只用 `find_file(cloud_dir, target_name)` 做精确文件名查询。命名模板或来源变化后，历史 `target_name` 与库内实际文件名不一致：

1. 精确查不到 → `final_file_exists=False`；
2. 继续去校验原分享链接；
3. 这些旧分享已失效（夸克 `好友已取消了分享`），重试必然失败；
4. 实际上同季同集文件一直躺在目标目录里，只是多了 `.2160p` 后缀或换成了 `.iso`。

同时《把黑夜点燃》失败记录还带有 `upgrade=true`：它本来是洗版尝试，目标目录里已有旧版本；洗版失败后旧版本仍在，不应该被当成「缺失」再次转存。

## 修复

`plugins.v2/cloudsubscribex/handlers/sync/retry.py`：

- 新增 `_retry_episode_number`：从文件名解析 `SxxExx`、`Exx`、`第N集`。
- 新增 `_find_existing_retry_target`：
  1. 先按当前目标名精确查找，保持原行为；
  2. 未命中且记录是电视剧时，列出目标季目录（`max_depth=1`）；
  3. 按季集号找同集文件，过滤目录和明显过小的样片（低于目标大小 20% 且低于 50 MB）；
  4. 多个同集文件取体积最大的一个。
- 命中后：
  - 把 `target_name` 改为库内实际文件名，后续 STRM/后处理使用真实名字；
  - `final_file_exists=True`，跳过失效分享校验；
  - 写入 `landed=true`、`landed_reason=episode_match`、`verified_at`、`retry_reused_existing=true`，落成功终态。

## 边界

- 只对电视剧做季集回退；电影仍按精确文件名，避免误认同名不同版本。
- 命中同集即视为「已有」，洗版记录不会再自动升级；日志会保留实际文件名，若要继续洗版需重新选择有效资源。
- 若季目录列表接口失败，仍按原逻辑去校验分享，不会把网络错误当成已存在。
