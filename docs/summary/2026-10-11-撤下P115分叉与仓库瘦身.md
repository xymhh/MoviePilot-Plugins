# 撤下 P115 分叉、仓库缩为单插件（2026-10-11）

## 结论（一句话）

`xymhh/MoviePilot-Plugins` 从「两个插件 + 4 个继承插件的合并市场」缩为**只提供网盘订阅助手（CloudSubscribe）**的单一插件源；P115StrmHelper 的 fork 线（源码、索引、Release、CI）全部撤下，115网盘STRM助手改用上游 DDSRem 线 + 插件自带配置项。

## 触发：上游本来就有配置项，改代码是走错了路

此前自维护 fork 的唯一目的是修「媒体库已存在更高质量文件 → 被记成整理失败」。用户在实际使用中发现上游本来就有对应设置，核对上游 2.8.76 包（Release `P115StrmHelper_v2.8.76`）确认：

| 设置 | 位置 | 作用 |
| --- | --- | --- |
| 「覆盖模式」(`overwrite_mode`) | **MoviePilot 的目录（媒体库）配置**，不是插件配置页；取值 `always`/`size`/`never`/`latest`，由插件 `helper/strm/transfer.py` 的 `_get_overwrite_mode()` 按 `library_storage` + `library_path` 最长前缀读取 | `size` = 库里同名文件更大就跳过（"质量更好"的裁决点） |
| 「自动删除低质量源文件」(`auto_delete_inferior_source_enabled`，默认关) | 插件配置页 | 挂在宿主 `TransferFailed` 事件上（`__init__.py:2159-2191`），失败消息含「质量更好」或「同名文件」即删除源盘文件 |
| 「媒体库已存在时拦截整理」(`transfer_intercept_exists_enabled`，默认关) | 插件配置页 | 首次入库场景下媒体服务器已有则终止 |
| 「分享STRM覆盖大小检查」(`share_strm_overwrite_check_enabled`) | 插件配置页 | 用 ffprobe 修正「按大小覆盖时 STRM 被误判为小文件」 |

**结论**：该场景属于插件的正常路径 + 配置项，无需 fork 改代码。反而是一个坑值得记录：

> `never` 模式的失败消息是「媒体库存在同名文件，当前覆盖模式为不覆盖」，**同样含「同名文件」**，因此也会触发「自动删除低质量源文件」——这条路径不比较质量。要"只在库里更好时删源"，覆盖模式必须用 `size`。
