# STRM 增量改用 115 导出目录树（1.7.40）— 上线总结

> 时间：2026-10-24 20:45｜状态：已发版 1.7.40 并部署到线上（`plugin_version=1.7.40`、`state=True`）

## 要解决的问题

1.7.39 的 STRM 增量是「逐目录 `list_directory` 全扫」：媒体库约 250–400 个目录，每轮 250–400 次请求、
每 10 分钟一轮 → 每天 3.6–5.8 万次 list 调用，违反用户提的两条硬约束（不触发封控、效率最大化）。

## 做法

| 环节 | 1.7.39 | 1.7.40 |
| --- | --- | --- |
| 拿云端文件清单 | 每目录 1 次 `files` 列表 | 1 次 `files/export_dir` 提交（服务端生成整树文本） |
| 等待 | — | 每 2 秒轮询，通常 2–5 次 |
| 读取 | — | 1 次下载解析（`delete=True` 自动删导出文件） |
| 取 pickcode | 已在列表里 | 只对**差异所在目录**各 1 次列表 |
| 稳定期（无新增） | 250–400 请求/轮 | **≈5–8 请求/轮，零 list** |

失败自动降级：导出不可用（非 115 网盘 / 接口报错 / 超时）→ 退回 `rebuild_strm_tree` 逐目录遍历。

## 实测证据（2026-10-24，用线上账号 curl，共 3 次请求）

```
POST /files/export_dir  file_ids=3499152345994888734&target=U_1_0&layer_limit=0&aid=1
→ {"state":true,"data":{"export_id":27001354}}

GET  /files/export_dir?export_id=27001354
→ {"file_id":"3546937009115236275","file_name":"私20261024201040_目录树.txt","pick_code":"cs0zirah35oyadde3"}

POST /rb/delete fid[0]=3546937009115236275&pid=0     # 清理测试导出文件
→ {"state":true}
```

踩坑：状态接口与提交接口**同路径**（`/files/export_dir?export_id=`），
`/files/export_dir_status` 返回「服务器开小差了」；`/files/tree` 已下线，不能再用。

  （它本来就走 export_dir，稳定期约 6 请求/轮）。本次改动的效果是「CS 备用路径也变高效」，
  打开开关后不会打爆请求量。
