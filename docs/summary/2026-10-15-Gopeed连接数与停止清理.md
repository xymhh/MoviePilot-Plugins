# 复盘：1.6.44 —— Gopeed 连接数可控 + 手动停止清空中继

> 状态：已完成并发布（2026-10-15）｜任务书 [../plan/2026-10-15-Gopeed连接数与停止清理.md](../plan/2026-10-15-Gopeed连接数与停止清理.md)｜证据 [../test/2026-10-15-Gopeed连接数与停止清理单测.md](../test/2026-10-15-Gopeed连接数与停止清理单测.md)

## 1. 起因（用户侧原话）

1.6.43 把「夸克→本地中继」交给 Gopeed 后，用户实测**只有 1.6 MB/s**（12.3 GB 的任务跑了很久）。
用户自己把 Gopeed 全局 `http connections` 从 16 改成 **256** 后，同一任务实测 **19.99 MB/s**（313 秒下完 6.2 GB）。
随后用户提出两件事：① 插件要能自己控制连接数（不想依赖 Gopeed 全局设置）；② 手动停止跨盘任务时盘上不该残留文件。
用户对三个待定项的回答是「1」= 三项都取推荐项：只清本任务中继文件 / 停止时**一律清**（含已下完的完整缓存）/ 连接数默认 **0=不传**。

## 2. 做了什么（1.6.44）

### ① 连接数可控（配置项 `gopeed_connections`）

- 配置链路补全：`core/config.py` 默认值 → `__init__.py` 表单字段 + `_apply_sync_config` 接线 → `drive/quark/definition.py`
  → `provider.py` / `files.py` → `GopeedDownloadService(connections=…)` → `GopeedClient.create_task(..., connections=…)`。
- 语义：`0`（默认）= **不写** `opts.extra`，请求体与 1.6.43 逐字节一致（沿用 Gopeed 全局设置）；
  `>0` = 写 `opts.extra.connections`（Gopeed v1.9.3 `internal/protocol/http/fetcher.go:327` 只认 `>0` 的覆盖值）。
- 前端：配置页「跨盘传输 → 外部下载器」下新增 number 字段（`show` 条件与 Gopeed 地址相同），hint「0=沿用 Gopeed 全局连接数；夸克建议 256」。

### ② 手动停止即清空中继

- Gopeed 侧：`_stop_task()` 从「只 pause（`preserve_partial=True` 时什么都不删）」改为「pause（best-effort）→ `DELETE /api/v1/tasks/{id}?force=true`」，
  连 Gopeed 侧部分文件一起删（Gopeed `pkg/rest/api.go:155-165` + `pkg/download/downloader.go:767-790`）。
- 插件侧：`core/transfer.py` 的 `except InterruptedError` 分支去掉「未下完且无 `.parts.json`」两个条件，取消时**无条件**
  删本任务的 `cloud-transfer-<hash>.bin` + `.meta.json`/`.parts.json`（含 `.tmp` 变体，复用 `_delete_cache_path`）；
  回执文案改为「任务已取消并已清理中继缓存」。
- **边界**：只删本任务文件（不碰下载目录里别的文件）；**下载失败自动重试**路径的 `preserve_partial` 语义不变（失败仍保留可续传缓存）。
  实现上刻意分成 `_stop_task`（用户停止 → 一律删）与 `_discard_task`（失败重试 → 看 `preserve_partial`）两条路。

## 4. 教训

1. **默认值就是性能上限**。1.6.43 的「接上 Gopeed 就好了」是错的：Gopeed 默认 16 连接 × 夸克单连接约 100KB/s ≈ 1.6 MB/s，
   等于把用户按在 1/12 的速度上。凡是把活儿交给外部工具，都要问一句「它的默认值是谁定的、够不够用」，
   并把关键旋钮暴露到插件配置里（0=沿用对方默认，保留不破坏现状的余地）。
2. **「停止」和「失败重试」是两条路，语义不能共用一个开关**。1.6.43 用 `preserve_partial` 同时管这两件事，
   结果用户按停止后盘上留着半个文件（因为停止路径传的就是 `True`）。这次拆成 `_stop_task`（停止=清空）
   与 `_discard_task`（失败=保留续传），开关只管它该管的那条路。
3. **配置有字段 ≠ 有接线**（1.6.36 的教训再次生效）。委派方主动指出「只声明类属性、不在 `_apply_sync_config` 解析，
   配置页填 256 也永远是 0」——这次是委派方提醒主 agent 补契约，说明任务书写作时应把「值从哪来、到哪去」的
   完整链路（含 `_apply_sync_config` 这一环）写进契约，而不是只写字段声明位置。
4. **委派方的「未验证项」要用产物回读兜掉**。委派方因本机 node 版本不符（v25 vs 要求 `>=22 <23`）没能本地构建前端，
   标为残留风险；主 agent 在 Release 包的 `dist/` 里搜到 `gopeed_connections` 与中文 label，
   把这条风险从「未验证」变成「已验证」——发布产物回读比本地构建更接近用户拿到的东西。

## 5. 遗留 / 后续可选

- 用户真机复测（速度 + 停止清理）未回报。
