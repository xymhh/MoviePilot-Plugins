# 同步作业账本 P1：入口接线与幂等复用（1.7.18）

> 状态：已完成并发布 2026-10-20（`5b3ee9b` / Release `CloudSubscribeX_v1.7.18`，CI 三绿）。设计见 [ADR](../plan/2026-10-20-同步作业状态机与幂等改造.md)。

## 做了什么

1. 新增 `core/database/sync_job_ledger.py`：把建键、幂等入队、CAS 认领、心跳、成功/失败记账收进 `SyncJobLedger`。
2. 原 `_transfer_file` 更名 `_transfer_file_impl`；新入口在开关打开时先走账本，再调用原实现。
3. 开关 `sync_job_ledger_enabled` 默认 `false`；配置页「基础设置 → 运行设置」新增「同步作业账本（实验）」。
4. 转存期间每 15 秒心跳续租；成功后按 `transferring → verifying → finalizing → done` 记账；异常记 `retry_wait`，用户停止记 `canceled`。
5. 账本不可用直接阻止本次转存，不静默退回无账本上传。

## 开关关闭时

与 1.7.17 完全一致：入口直接调用 `_transfer_file_impl`，不加载数据库模块、不写 `sync_jobs`。

## 打开后行为

- 同一 `source + target + name` 只允许一个 worker 进入；其他 worker 记日志并跳过，不会重复上传。
- 已 `done` 的作业直接返回成功，不再调用转存实现。
- 同一内容不同目标名会生成不同 `job_key`，不会被误复用。
- 失败后进入 `retry_wait`，下一次同内容提交可再次认领；用户停止进入 `canceled`。

## 已知边界（P2 处理）

- P1 的 `done` 复用只信任账本，尚未按 `result_file_id` / 目标名回查文件；文件被人工删除后不会自动重新上传。
- 尚未把中继、本地上传、后处理移动统一到 `TargetWriter`；`_RELAY_TARGET_DONE` 仍参与正确性。
- 尚未做真实 115 并发 e2e；建议先开开关，用一个小目录重复提交同一文件验证「只有一个文件、无 (1)」。

## 怎么用

1. 升级到 1.7.18 并重启 MoviePilot。
2. 配置页 → 基础设置 → 运行设置 → 打开「同步作业账本（实验）」。
3. 先跑一个小目录/单个文件；在日志里确认出现「同步作业已完成，复用结果不重复转存」。
4. 如果要回退，关闭开关即可，不需要回滚版本。
