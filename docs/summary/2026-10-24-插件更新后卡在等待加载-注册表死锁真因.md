# 插件更新后长期停在「插件等待加载」——TG 监控注册表死锁真因（2026-10-24）

> 状态：已定位、已修复、已发版 1.7.32 并线上验证通过。
> 影响版本：所有含 `_shared_monitor_registry()` 旧实现的版本（≤1.7.31）。
> 一句话：**不是 MP 的问题，不是依赖的问题，是我们自己的 TG 监控实例登记表用了不可重入锁，且在持锁状态下调用会再次拿同一把锁的方法。**

## 1. 症状

- 插件更新（或点击插件卡片）之后，界面一直灰显「插件等待加载」
- `POST /api/v1/plugin/reload/{id}` 实测 **524 / 100 秒无响应**
- 日志停在 `loader.py - 插件 CloudSubscribeX 共清除 284 个模块缓存`，**没有**「插件停止完成」，**没有**「加载插件」，**没有** Traceback
- 只有重启容器能恢复；但下次更新/安装又会复现

## 2. 现场证据（py-spy 线程栈）

用 1Panel 计划任务在宿主机执行 `docker exec` 抓栈（手法见附录），拿到关键线程：

同时 `Thread 3346` 停在 `reload_plugin (manager.py:728)`——正在排队等同一把 `_lifecycle_lock`。

## 3. 根因

```python
def _shared_monitor_registry():
    state = {"monitors": weakref.WeakSet(), "lock": threading.Lock()}   # 不可重入
```

旧 `start()`：

```python
with monitors_lock:                 # 拿锁
    for other in list(monitors):
        if other is not self:
            other.stop()            # → stop() 里又 with monitors_lock → 同线程二次获取 → 永久阻塞
    monitors.add(self)
```

`threading.Lock` 不可重入，同线程二次 `acquire()` 即死锁。死锁线程随后一直持有 MP 生命周期的 `_lifecycle_lock`，于是：

- 插件卡片点击、reload、下次安装/更新，全部静默排队
- UI 表现为「插件等待加载」+ 接口 524
- 进程没崩，所以没有 Traceback；重启清空线程才恢复

触发条件：注册表里已存在**另一个** `TgChannelMonitor` 实例（热重载后旧实例尚未被 GC 回收即可）。这解释了为什么「每次更新都要重启」。

## 4. 修复（1.7.32）

持锁期间只做集合读写，旧实例的 `stop()` 移到锁外：

```python
with monitors_lock:
    others = [other for other in monitors if other is not self]
    monitors.add(self)
for other in others:
    try:
        other.stop()
    except Exception:
        pass
```

## 6. 教训

1. **持锁调用外部方法**是死锁的经典入口。规则：锁内只操作自己的数据结构，任何跨对象调用一律移到锁外。
2. `threading.Lock` 与 `RLock` 的选择要显式写明理由；跨模块共享的锁尤其要标注「不可重入」。
3. 「重启就好、下次还犯」类故障，优先怀疑**线程阻塞 + 锁持有**，抓线程栈比读日志快一个数量级。
4. 排障脚本要留在 `docs/` 里可复用（附录），下次同症状 3 分钟内可复现栈。

## 附录：通过 1Panel 计划任务抓容器线程栈

无 docker 权限时的可行路径（本次实测可用）：

1. `POST /api/v2/cronjobs` 建一次性 shell 任务：
   ```json
   {"name":"mp-spy","type":"shell","groupID":7,"specCustom":true,
    "spec":"0 0 29 2 *","executor":"bash","scriptMode":"input",
    "script":"{ ... } > /opt/1panel/apps/moviepilot/config/plugins/.diag.txt 2>&1",
    "retainCopies":1,"timeout":300}
   ```
   关键参数：`groupID`、`specCustom:true`、`scriptMode:"input"`，`spec` 必须是 5 段 cron；输出只能写 `config/` 这类共享挂载（写 `/tmp` 落在 1Panel 容器内，读不到）。
2. `POST /api/v2/cronjobs/handle {"id":N}` 立即执行（`/run` 不存在）。
3. `POST /api/v2/files/content {"path":"..."}` 读回结果。
4. 抓栈命令：
   ```bash
   PID=$(docker exec moviepilot-v3 sh -c "pgrep -f MoviePilot | head -1")
   docker exec moviepilot-v3 sh -c "uv tool run py-spy dump --pid $PID"
   ```
   注意：MP 主进程 `comm` 就是 `MoviePilot`（不是 `python main.py`），`pgrep -f python` 抓不到；进程号每次重启都变，不能硬编码。
