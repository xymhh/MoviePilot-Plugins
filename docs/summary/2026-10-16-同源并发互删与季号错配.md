## 起因

2026-10-16 07:44–08:01 跨盘转存（夸克→115）一批失败：`Gopeed 任务完成但本机未见文件`×6、`夸克取链失败 code=21001 file not found`×24、`[Errno 2] No such file or directory: cloud-transfer-*.bin`×1、`跨盘临时文件尚未可见`×1，8 条历史 `failed`。根因是一个事实的两面：**同一份分享被极恶老大 S01/S02/S03 三个订阅各自认领，且分享根目录实为 `21806-极恶老大 S2`（S01/S03 全是错配）**——于是同一文件（同一 `cache_key`）被多个任务并发转存，任务之间互相删对方正在用的文件；而 Gopeed 的 AutoRename 恒开，目标路径已存在就把文件改成 `… (1).bin`，插件只按原路径校验，把互删/改名伪装成「未见文件」。

## 改动与边界

1. **A1 同 `cache_key` 串行 + 中继引用计数**（`core/transfer.py`）：新增纯函数 `_task_cache_key(task)`（本地源文件任务返 `""` 不加锁不计数，云端任务与 `_cache_key()` 同源）；`_run` 改薄包装取 `dict[str, Lock]` 锁后进 `_run_locked()`（原函数体整体下沉，槽位与 try/finally 原样）；`create()` 计数 +1、任务终态 finally -1；`_delete_cache_path_for_task()` 判 `_cache_retained_for_others()`（计数 >1 含自身 → 保留 `.bin`+`.meta.json`+`.parts.json`，供兄弟任务经既有 `_validate_complete_cache()` 复用）；`delete_cache()` 判 `in_use > 0` 返回 0 跳过；取消时兄弟在飞则保留文件、message 换成「中继缓存保留（其它任务使用中）」（无兄弟时逐字保留旧文案，`tests/test_gopeed_downloader.py:730` 既有断言不破）。`_cache_key()` 算法、`cloud-transfer-<key>.bin` 命名、`_public()` 字段、状态机全部未动。
2. **A2 暂存引用计数兜底**（`handlers/sync/service.py`）：模块级 `_STAGING_REFS` + 锁，键为暂存文件绝对路径；`_transfer_file` 找到暂存文件即 `_acquire_staging_ref()`，finally 的 `_cleanup_cross_transfer_staging` 先 `_release_staging_ref()` 归零才 `delete_file`（>0 跳过并打 debug）。pre-download 各失败点（item 未找到等）不计数不删文件，语义与旧一致。
3. **A3 Gopeed 残留清理与校验容忍**（`core/gopeed.py`）：建任务前 `_clear_relay_residue()` 严格删本任务 `cloud-transfer-<key>` 的 `.bin`/`.meta.json`/`.parts.json`（含 `.tmp` 与 `… (N).bin` 改名副本；`is_file` 守卫、不同 key 一律不碰）；`_verify_result` 精确路径缺失时 `_find_renamed_relay()` 按「key 前缀 + 大小相符」接受改名副本并**归位到规范路径**（`renamed.replace(target)`；归位失败才按副本路径继续——主 agent 修正：委派版只返回副本路径，会写出 `… (1).bin.meta.json` 孤儿文件、规范路径无缓存导致兄弟任务无法复用、副本永不清理）；仍缺失抛 `_missing_relay_file_message()`（期望路径 + `Gopeed 侧映射目录=` + 「同源任务并发 / gopeed_path_prefix 与挂载」提示，无令牌）。
4. **B 分享目录季号守卫**（`utils/file_parser.py` + `utils/file_matcher.py` + 配置三件套）：`contains_other_season` 三模式匹配不到裸 `S2`（未改动本体），新增 `_BARE_SEASON_PATTERN` + `path_season()`/`path_conflicts_season()`；`FileMatcher._path_season_conflict()` 只看**目录部分**（`_relative_path`/`relative_path` 丢文件名；`parent_path`/`cloud_path` 当目录串），`episode_from_file` 与 `episode_candidates` 两处入口先过守卫——冲突即拒绝并 debug（路径、目标季、识别季号）；文件名自身季号仍走原 `contains_other_season`；无季号行为逐字节不变。新配置 `cross_season_path_guard`（默认 `True`，`config.py` 默认值 + `__init__._apply_sync_config` 写入 `FileMatcher.path_season_guard_enabled` + 前端 `transfer.js` select）。

## 教训

- **串行与引用计数是同一个问题的两半**：锁负责「别让第二个任务看到半成品」（复用优化），引用计数负责「别删别人还在用的文件」（正确性兜底）——只做锁，取消/显式清缓存路径仍会互删；只做计数，B 会重复下载且可能校验到半成品。两层各写变异反证，缺哪层对应用例就红。
- **Gopeed AutoRename 会把互删伪装成「未见文件」**：目标路径已存在 → `CheckDuplicateAndRename` 改成 `… (1).bin` → 插件按原路径校验必然失败且重试连败。所以修法必须同时堵三处：建任务前清残留（治本）、校验容忍改名副本（兜住瞬时竞态）、异常文本给出映射目录与排查提示（别让运维只看到裸 Errno）。
- **裸 `S2` 是既有匹配规则的盲区**：`contains_other_season` 的三个模式（SxxExx/第N季/Season N）都要求伴随标记，`21806-极恶老大 S2` 目录名一个都匹配不到 → S01/S03 照样认领。按用户裁定**不改共享函数本身**，新增独立的 `path_season` 底座 + 只看目录的守卫，把「文件名自身季号」与「所在目录季号」两个语义彻底分开。
- **titleless 兜底会放大错配**：`4.mp4` 这种无标题文件会被兜底成「目标季第 4 集」——兜底在目录季号正确时是便利，在目录季号冲突时就是把错配坐实。守卫必须卡在兜底之前（`episode_from_file` 与 `episode_candidates` 两个入口都要卡，只卡一处会被 loose 层漏过去）。
- **同目录测试文件的互不越界要显式断言**：清理函数写宽一点就会删掉别的任务/别的测试的文件，所以范围测试里同时放了「不同 key」「同名目录」「.bak 后缀」「普通文件名」四类诱饵，变异反证时既有 26 例 Gopeed 用例照绿才敢收工。

- **委派产出必须逐处看「返回值被谁用」**：委派版把「接受改名副本」做到「返回副本路径」就收工了，测试也全绿；但下游（缓存标记/复用/清理）全按规范路径操作 → 会写出 `… (1).bin.meta.json` 孤儿、规范路径无缓存、副本永不清理（每个大文件漏一整集）。**判据不是「函数对不对」，而是「返回值进入下游后路径还一致吗」**——所以修法是 `renamed.replace(target)` 归位，而不是在下游到处补兼容。
