# 合并仓库 CI 三件事（2026-10-11）

## 1. 背景

`xymhh/MoviePilot-Plugins`（原 `MoviePilot-Plugins-P115` 改名）合并了两个插件后，CI 有两处不适配 + 一处被权限卡住：

1. 单测工作流 `test-cloudsubscribe.yml` 早已写好，但 GitHub token 缺 `workflow` scope，**推不上去**（HTTP 403 `refusing to allow a Personal Access Token to create or update workflow`），YAML 只能暂存在 `docs/plan/2026-10-11-待生效CI工作流-test-cloudsubscribe.md`。
2. 发布工作流 `plugins-release.yml` 的前端步骤按 npm 写死，而网盘订阅助手的前端是 **pnpm**（`pnpm-lock.yaml` + `packageManager: pnpm@10.25.0`，engines node >=22 <23）。
3. 单测在工作流真正跑起来后暴露出多处 **测试桩滞后**。

## 2. 做了什么

- 用户补 `workflow` scope 后（`x-oauth-scopes: repo, workflow`），恢复并推送 `test-cloudsubscribe.yml`，同时修好发布工作流的 pnpm 支持。
- 发布工作流前端步骤改为**按 lockfile 分流**；dist 落点按实际存在位置处理（两种前端的 vite `outDir` 不同）。
- 单测补运行时依赖（`pytz`/`requests`/`httpx`/`apscheduler`）与三处测试桩修复。

## 3. 决定与结论

- **一个仓库、两条测试工作流**：`test-p115strmhelper.yml`（V3）与 `test-cloudsubscribe.yml`（V2）各自按路径触发；发布工作流继续用 `detect-changes` 决定要发哪个插件。
- **前端包管理器不进代码约束，按 lockfile 自动判定**：以后再加 pnpm 前端不用改工作流；npm 前端也不受影响。
- **CI 构建的 Release 是正品**：工作流会重新构建前端（`remoteEntry.js` 等 36 个 dist 条目），不再依赖人工本地构建后手打资产；`plugins.v2/cloudsubscribe/dist` 已 gitignore，不污染仓库。
- **测试跑挂 ≠ 插件坏**：本轮 3 处断言失败与 1 处整模块 import 失败，全部是桩滞后（MagicMock 默认值解包被 except 吞掉、静态方法改实例方法、AutoMock 包 `__path__` 为空导致子模块解析失败）。定性方式：读真实实现行号 + 用 logging 注入把被吞掉的异常打出来。

## 4. 教训

- **MagicMock 兜底的 `__getattr__` 会制造「静默失败」**：`FakeOwner.__getattr__` 返回 MagicMock，被 `try/except` 吞掉的解包错误表现为业务断言失败，排查成本高。测试里对返回二元组/列表的宿主能力要显式给桩。
- **CI 里被吞掉的异常必须能看见**：插件用 `app.log.logger`，测试环境是 MagicMock → 日志全丢。定位时把 `sys.modules` 里 `cloudsubscribe*` 模块的 `logger` 换成真 logger 是最快的办法。
- **推送工作流文件前先确认 token scope**：403 报错文案明确（`refusing to allow a Personal Access Token to create or update workflow`），不要靠猜。
