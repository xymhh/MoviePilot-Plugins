# 1.8.10：修复任务中心崩溃（DbOper.__init__ 缺 manager）

> 状态：已修复，测试与 lint 通过，待推送发版

## 现场表现（2026-11-01 用户截图）

- 任务中心红条：`DbOper.__init__() missing 1 required positional argument: 'manager'`
- 「当前没有订阅任务」「当前没有订阅处理任务」「暂无任务」，但顶部「总转存 2331 / 今日转存 130」正常
- 出现在 1.8.7 引入全局暂停开关之后的所有版本（1.8.7 / 1.8.8 / 1.8.9）

## 根因

`core/sync_pause.py` 的 `_repository()` 直接无参构造仓储：

```python
from .database.repositories import RuntimeRecordRepository
return RuntimeRecordRepository()
```

而 `RuntimeRecordRepository` 继承 `DbOper`，其 `__init__(self, manager, db=None)` 要求必须传数据库管理器（`core/database/manager.py:59`）。于是：

1. `api_vue_tasks` 里 `"paused": sync_pause.snapshot()` 抛 TypeError；
2. 整段 `try` 落到 `except`，返回 `{"success": False, "message": "DbOper.__init__() ..."}`；
3. 前端拿不到 tasks，页面显示「暂无任务」，并把 message 当错误气泡弹出。

`api_vue_sync_pause` 与 `SyncHandler._sync_paused()` 走同一路径，也会失败（后者被 try 兜住，按「未暂停」处理，所以同步本身没停）。

## 为什么测试没抓到

`tests/test_sync_pause.py` 原有 4 条用例全部显式传 fake repository，从未走过「不传仓储」的分支；模块自建仓储那行代码在测试里从未执行。

## 修法

| 位置 | 改动 |
| --- | --- |
| `core/sync_pause.py` | 删掉模块自建仓储；`snapshot(repository)` 收到 None 时返回「未暂停」快照并 debug 日志；`set_paused` 收到 None 时抛 `RuntimeError("转存暂停开关不可用：数据库仓储未就绪")` |
| `__init__.py` | 新增 `_sync_pause_repository()`：`self._get_data_store().repositories.runtime`，异常时返回 None；`api_vue_tasks` / `api_vue_sync_pause` / `api_vue_set_sync_pause` 三处注入 |
| `handlers/sync/service.py` | `_sync_paused()` 通过 `self._plugin._sync_pause_repository()` 取仓储再 `is_paused(repo)`，取不到按未暂停 |
| `tests/test_sync_pause.py` | 新增 3 条回归：无仓储读取不抛且为未暂停、无仓储写入抛 RuntimeError、`RuntimeRecordRepository()` 无参构造必须抛 TypeError |

设计取舍：读写行为不对称——读失败降级为「未暂停」（不能因为开关坏了就停掉所有转存），写失败明确报错（不能让用户以为暂停生效了）。

## 验证

- `python scripts/lint.py --all` → `0 error(s), 365 warning(s)`，静默面预算 0/0
- 单任务暂停/恢复走 `store.repositories.sync_jobs`（本来就注入正确），不受影响
