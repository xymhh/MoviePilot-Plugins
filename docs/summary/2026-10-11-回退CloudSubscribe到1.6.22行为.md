# 回退 CloudSubscribe 到 1.6.22 行为并发布 1.6.24

> 状态：已完成 2026-10-11。被回退的改动见 [网盘探索角标 1.6.23 验收记录](../test/2026-10-11-网盘探索角标-1.6.23.md)（该文件已标「已回滚」，仅留档）。

## 决定（用户）

用户原话：「把网盘订阅助手回退到 1.6.22，之前的改动没有用，方向错了」——判定 1.6.23 的「网盘探索角标」修复方向错误、无实际价值，要求回退到 1.6.22。

## 回退范围

1.6.23（commit `39daa78`）是 1.6.22 之后**唯一**动过 CloudSubscribe 的提交，包含四处：

1. **榜单请求补身份**：前端 `useMediaData.js` 对豆瓣/Bangumi/AniList 榜单带 `resolve_identity=true`，后端 `core/api/page.py` 据此走媒体识别链补 TMDB 身份。
2. **前端角标语义**：电影=「已入库」；剧集=「完整 / 缺集」（`MediaGrid.vue` 新增 `complete-badge`）。
3. **缺集判定补官方总集数兜底**（后端比对官方季集数，缺尾季/缺尾集也算缺集）。
4. 版本 1.6.22 → 1.6.23。

做法：`git revert 39daa78` 整体撤销，不去和 1.6.22 之后的无关改动（跨盘转存提速、CI 等）纠缠。**撤销后与 `1ceedbc4`（1.6.22 发布点）逐字对比，只剩版本号一行** —— 跨盘转存 16MB 固定分片 + 115 分片并发 PUT 等改动全部保留。

## 版本号策略

- 代码回到 1.6.22 行为，但发布版本号用 **1.6.24**（`__init__.py` 的 `plugin_version` 与 `package.v2.json` 同步）。
- 原因：用户机器上装着 1.6.23，MoviePilot 市场按版本号比较；若索引回落到 1.6.22，市场不给更新入口，只能手动重装。`1.6.24 > 1.6.23` 才能「点一下更新即回到旧行为」。
- 1.6.22 / 1.6.23 的 Release 资产都保留，可回溯或按需重装。

## 未做

- 没有删除 1.6.23 的 Release 与 tag（保留决策轨迹与回退证据）。
- 没有改动 1.6.22 及更早版本的任何行为。

## 教训

- **展示层需求的「方向」要在动手前对齐**：用户要的可能是「别花代价去算它」，而不是「算得更准」。本次为了角标投入了两层逻辑（身份补全 + 官方季集判定），结果被整体回退。展示层先给最小可见效果让用户拍板，再决定要不要加深度。
- **回退用 `git revert`，不要手删代码**：能逐字验证「撤销后 == 目标版本」，也留下决策轨迹。
