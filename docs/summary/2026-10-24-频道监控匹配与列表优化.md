# 频道监控匹配与列表优化（1.7.33 / 1.7.34）

> 状态：已完成并上线 2026-10-24

## 背景

线上实测（近 500 条监控记录）：390 new / 100 skipped / 10 transferred。
389 条 pending 里 379 条是「白名单内没有标题匹配的订阅」噪音，占满 `_max_items=500`
配额；另有 5 条真实资源被误挂起。

## 根因（均为实测，非推测）

| # | 现象 | 根因 |
| --- | --- | --- |
| 1 | 5 条新番永久 pending，提示「匹配到多个相近订阅」 | 订阅表里 #68 与 #207 是同一部「Doctor X：白色黑手党时代」S01，两条各得 100 分、分差 0 ≤ 5，触发 `tg_match.py` 的多候选判定 |
| 2 | 4 条真实资源被拒（88 分 < 90 门槛） | 频道把作品原名直接贴在中文名后（`某暗部的少女共栖 とある暗部の少女共棲`、`FX战士久留美 FX戦士くるみちゃん`），归一化后连成一串超过 8 字，只拿到前缀分 88 |

## 改动

### 1.7.33（匹配 + 池子）

- `tg_match.py`：同名 + 同季 + 同类型订阅去重（保留 state=R 且 id 更大的一条）；
  原名/别名后缀 88 → 92（纯英文订阅名 + 独立英文单词后缀仍保持 88，不吞 Doctor Who）；
  清洗词表补 AMZN/NF/DSNP/HMAX/单集xGB/特效/精修/简韩/sup，`\d+帧` → `\d+帧率?`
- `tg_monitor.py`：白名单外消息默认不入池（只留最近 50 条供回补匹配）；
  按状态分层配额；scan_limit 打满上限后下一轮翻倍追赶（最多 4 倍）

### 1.7.34（列表 + 导航）

- `TgMonitor.vue`：状态筛选 chips（待办与已转存 / 待处理 / 已转存 / 未转存 / 已忽略 / 全部，带条数），
  默认「待办与已转存」；分页每页 30；表格列宽收紧（时间 96→88、频道 160→132、类型 120→96、操作 150→132）
- `Config.vue`：`navGroups` 补 organize + tg；移动端改用 `flatSections`（按 PC 分组顺序展开）；
  移动端导航由横滑单行改自适应网格 `repeat(auto-fit, minmax(88px, 1fr))`
- `HISTORY_QUOTA_RATIO` 0.5 → 0.12

## 教训

- **匹配层的问题要用真实标题做回归**：新增 `tests/test_tg_match_hardening.py` 10 例，样本全部来自线上记录。
- **PC/移动两套渲染路径必然会漂移**：导航这类"选项集合"必须单一数据源（`navGroups`），移动端只做展示层差异。
- **配额是隐性 bug 源**：`_max_items` 是总数上限，不区分状态，历史记录会把待办挤出去。
