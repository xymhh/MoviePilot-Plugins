# 阿里云盘手动转存「无法解析有效分享链接」复盘（1.6.32）

> 2026-10-13｜现象 → 根因 → 修复 → 教训

## 现象

用户在插件的「手动资源」对话框提交阿里云盘分享链接，返回：

```
第 1 行资源无效：无法解析有效的阿里云盘分享链接
```

且整次提交被直接拒绝（不建任务、不进历史）。运行时日志里搜 `阿里云盘 / aliyun / alipan` **0 条命中**，
说明插件从未进入转存逻辑。

## 根因：跨驱动「分享标识」契约不统一

手动转存入口在做任何事之前先做**语法校验**（`core/api/sync.py` `_manual_share_info_valid`），
旧实现只认一个键名：

```python
return bool(share_info.get("share_code"))
```

而各驱动的 `extract_share_info()` 返回值并不统一：

| 驱动 | 返回值 | 能否过校验 |
| --- | --- | --- |
| 115 / 夸克 / 天翼 / 光鸭 / 123 | `share_code`（+提取码） | ✅ |
| **阿里云盘** | `share_id` / `share_pwd` | ❌ 恒失败 |
| **移动云盘** | `link_id` / `password` | ❌ 恒失败 |

所以这不是「某条链接格式不对」，而是**阿里云盘、移动云盘两个来源的手动转存被完全锁死**：
校验在转存之前失败，链路后续（跨盘下载上传）根本没有机会执行。
阿里云盘账号凭据本身是好的——用插件自己的账户刷新接口实测：`connected`，用户 `ln沐风`，904G / 剩 735.62G，未限流。

## 修复（1.6.32）

1. 两个驱动回填统一键 `share_code`，同时保留各自接口要用的键；
   阿里云盘的 `_prepare` 改成显式 payload，避免把内部键 `share_code` 混进对端请求体；
2. 校验函数改为接受 `share_code` / `share_id` / `link_id` 任一（防御后续新增驱动再踩同一坑）；
3. 顺手支持阿里云盘分享的「提取码: xxxx」附言写法（与 115/夸克一致），带访问码的分享不必再手工拼 `?pwd=`。

触达范围：只改「手动提交分享链接」这条入口的校验与解析，订阅搜索、候选评分、跨盘转存逻辑均未动。

## 教训

1. **隐式接口契约要用测试钉住。** `extract_share_info` 的返回键名是事实上的跨模块接口，但既没有文档、
   也没有契约测试；一个只认 `share_code` 的校验函数就把两个来源整体锁死，且失败信息（「无法解析有效的
   XX 分享链接」）把原因指向了链接格式，误导方向。
2. **错误信息要指向真正的原因。** 这条提示让排查看起来像「链接格式/解析正则」问题；实际是键名不匹配。
   今后同类校验尽量把「解析到的字段」一并回显，或至少区分「链接不匹配本网盘」与「解析结果缺字段」。
3. **先看「有没有走到」，再看「为什么失败」。** 日志里 0 条来源关键字命中，立刻把范围从「转存实现有 bug」
   缩小到「校验阶段被拦」，比逐层读转存代码快得多。
4. **回归用例必须在未修复代码上失败。** 本次用 `git stash` 退回修复再跑，确认 8 例中 6 例必然失败
   （含用户实际报错那一条），避免写出「怎么写都过」的测试。

## 2026-10-13 追加：结案（用户决定放弃阿里云盘这条线）

**结论**：1.6.32 的分享链接校验修复是生效的（线上日志已见「选中阿里云盘 1 可用 1」），但链路**卡在更后面**：
取源下载地址时阿里云盘对第三方应用一律返回 **HTTP 410**（`/v2/file/get_share_link_download_url` 等），
也就是**阿里云盘封了「第三方程序按分享链接取下载地址」这条路**。插件已具备阿里云盘 → 115 的跨盘能力
（`drive/alipan/share.py`、`cross_transfer_enabled=True`，账号凭据也有效），但源侧拿不到直链，
跨盘转存无从谈起 —— 这不是插件能靠配置或代码绕过的问题。

**决定**：用户 2026-10-13 明确「放弃阿里云盘任务」。本主题到此关闭，不再投入排查工时。

**留下的可复用结论**：

1. 阿里云盘作为**转存源**（订阅搜索命中阿里云盘分享后自动转存）不可用：源侧直链被封（410）。
2. 阿里云盘作为**目标盘**（115 → 阿里云盘）不受影响 —— 走的是用户自己的账号 API，不是分享直链。
3. 1.6.32 的契约修复仍然保留（阿里云盘/移动云盘分享链接解析与校验正确），因为它对「解析-校验」链路是独立的正确性修复，也为将来接口放开留了口子。
