# 1.6.52 复盘：转存落盘自检 + landed 字段 + 跳过原因可视化

> 时间：2026-10-16｜版本：CloudSubscribeX 1.6.52｜关联：[计划](../plan/2026-10-16-转存落盘自检与跳过原因可视化.md)｜[单测证据](../test/2026-10-16-转存落盘自检单测.md)

## 一句话

1.6.51 在下游「不信假成功」，1.6.52 把源头堵上：转存/后处理判「成功」前，先确认目标季目录里真有这个文件；查无实据改记「待确认」，并把此前的 `cloud_dir` 启发式换成显式 `landed` 字段，同时让「待确认」和跳过原因在历史页看得见。

## 做了什么

- **落盘自检（源头）**：即时转存路径复用判重那次季目录列目录（带 TTL 缓存，不额外打网盘）核对实物；finalize / 兜底补写 / 后处理写成功处同样过闸。
- **显式字段**：历史记录新增 `landed` / `verified_at` / `landed_reason`，替掉「`cloud_dir` 为空」启发式；判重基线与 MP 整理历史只采信 `landed is not False` 的记录（沿用 1.6.51 存在性校验作第二道防线）。
- **拿不准不改判**：列目录失败（`verified=False`）→ `landed=None`，完全维持 1.6.51 行为，不产生「待确认」。
- **落在别处不误判**：季目录自检判「没有」、但记录自称落在另一个 `cloud_dir`（媒体库/其它路径）时，再按记录自己的目录核一次（1.6.51 同口径），避免把落在别处的记录误记「待确认」。
- **「待确认」不等于失败**：不发失败通知、不写 MP 整理历史、不进 `failed_count`、不自动重转。
- **可视化**：`prepare_history_group` 新增 `unverified_count` / `skip_reasons` / `unverified_records`；历史页显示「待确认 N」和跳过原因分布。
- **开关**：`verify_landed_enabled` 默认开；关闭 = 逐字节回 1.6.51。

## 教训与决策记录

1. **同一事实要有单一裁决字段**：`cloud_dir` 为空既可能是「跳过」也可能是「假成功」，靠形状猜必然出错；加一个显式 `landed` 让 UI、基线、平台历史共用同一判据。
2. **网络抖动不能变成脏记录风暴**：区分「实测没有」与「没测到」是本次最重要的边界 —— `landed=False` 才降级 `待确认`，`landed=None` 一律维持旧行为。
3. **验证性请求要蹭现有的**：复用 `_season_dir_files` 的缓存，绝不逐文件反查 `file_id`。finalize 路径拿不到 `(subscribe, mediainfo, season)`，退而按 `cloud_dir` 每目录列一次（同批去重），是本版唯一有记录的偏离。
4. **新字段全可选**：老记录不迁移、不批量改写；无字段按未知处理，保证升级零风险。
5. **组件方法在单测 harness 里可能缺席**：`verify_landed_records` 等经 `getattr` 兜底调用，既有直接实例化 `HistoryService` 的单测不受影响（也说明这类跨组件调用要保持防御性）。
6. **收紧判据必须同时防「误伤」**：新判据说「没有」之前，要把该判据没有覆盖的合法情形排除掉——本例就是「记录落在别的目录」（1.6.51 明确不越权判定的那一类）。只加严不加护栏，就会把好记录打成「待确认」，属于另一种数据污染。
7. **委派的实现要主 agent 亲自复跑关键证据**：本次 `landed` 判定的变异反证、全量 483 例、lint 609 文件 0 error，均由主 agent 复跑确认（委派方汇报的 479 例是它加复核前的版本）；偏离项（finalize 路径按 `cloud_dir` 列目录）也由主 agent 判定可接受并写进文档。
