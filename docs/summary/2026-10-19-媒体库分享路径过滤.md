# 媒体库分享 STRM 路径过滤（1.6.75）

> 状态：已实现，待真机验证（2026-10-19）

## 问题

用户目标网盘季目录只有第 3 集，但订阅没有补第 1、2 集。排查发现 Emby 里另有
`/media/strm/115网盘分享` 分享库，里面同一部剧有更完整的集数；MoviePilot 的
`media_exists` 会搜索 Emby 全库，不遵守 `sync_libraries`，于是插件把分享库当成
自己的媒体库，误判为「已完整」。

## 改动

新增配置 `media_server_ignore_paths`（配置页 → 基础设置 → 提供方设置）：

- 每行一个路径前缀，按整段路径匹配（`/a/b` 不会命中 `/a/b2`）；
- 统一反斜杠、重复分隔符和尾斜杠；
- 过滤点：
  - `core/media_scope.py`：按 TMDB/媒体身份查 `MediaServerItem`，只保留不在忽略前缀下的行；
  - `core/subscribe/seasons.py:probe_season_progress`：启用过滤时直接按过滤后的季集判断缺集，绕过 `DownloadChain.get_no_exists_info`；
  - `core/subscribe/service.py:_media_progress`：电影同样按过滤后的条目判断；
  - `MediaLibraryApi` 的 TMDB/豆瓣/Bangumi/历史播放入库查询；
  - `MediaServerResolver` 的条目路径（洗版基线、单集路径）；
  - 手动洗版「媒体服务器内容」列表。
- 未配置忽略路径时，所有路径逐字节保持旧行为；数据库查询失败也回退旧逻辑，避免误判整季缺失。

## 验证

- `tests/test_media_scope.py` 5 例通过：前缀边界、反斜杠、转移库保留、只取转移库集号、缺集/完整两种 probe。
- 全量：547 passed，2 failed（既有 p115client 未安装环境失败）。
- 前端 `npm run build` 通过，产物含「忽略媒体库路径」字段。
- lint：0 error（既有缩进告警未新增）。

## 使用

升级到 1.6.75 后，在插件配置页填入：

```text
/media/strm/115网盘分享
```

保存后重新扫描/执行订阅；日志中的「实际存在剧集」应只来自目标网盘媒体库。
