# 历史记录页改造（1.9.45 / 1.9.46 / 1.9.47）

> 日期：2026-11-05 ｜ 状态：已完成 ｜ 版本：1.9.44 → 1.9.45 → 1.9.46 → 1.9.47

## 用户诉求

1. 去掉「未转存账本」，留着没用；
2. 「转存台账」改名为「历史记录」；
3. 添加失败原因（例如秒传失败）；
4. 来源不要显示「手动添加」，显示 TG 频道。

## 改动

| 项 | 改动 |
| --- | --- |
| 未转存账本 | 删除历史页工具栏入口、全局/单剧弹窗、`CandidateLedgerPanel.vue` 组件及 `AppPage.vue` 的无用 import；后端账本接口与写账本逻辑保留（频道监控仍在用） |
| 页签 | `AppPage.vue` 的 `history` 页签文案「转存台账」→「历史记录」 |
| 失败原因 | 后端 `prepare_history_group` 新增 `failure_reasons`（原始原因优先，缺原因用 `failure_label`，再缺记「未记录原因」）；前端分组汇总显示「原因 ×N」，明细表新增「失败原因」列，移动端行内显示「失败原因：…」 |
| 来源 | `HistoryRepository._source` 识别 `discovered_via=tg:*` 的 manual 记录为 `tg`；新增启动时幂等回填 `repair_tg_sources`；`prepare_history_group` 同步归一化；前端来源字典补 `tg = TG频道` |

## 说明

- 已有历史记录在插件下次初始化时自动回填来源（`source: manual → tg`），无需手工迁移。
- 同网盘分享转存失败原先只返回 False、没有原因，现补记「分享转存失败」/「当前网盘不支持分享转存」，历史页不再出现空白原因；跨网盘秒传失败沿用原有「未命中秒传」。
- 只改了展示与来源归因，转存/重试/删除逻辑未动。

## 1.9.47 追加：任务状态并入订阅卡

1.9.46 只是把 `RuntimeCard` 从独立页签挪到工作台顶部，用户要的是「任务状态长在每部剧上」，所以 1.9.47 改成按订阅聚合展示：

| 项 | 改动 |
| --- | --- |
| 卡片状态 | 订阅卡右上角角标从「已齐/缺 E5」改为实时任务状态：无任务显示「监控中」，有任务依次显示「排队中 / 搜索中 / 离线中 / 转存中 42% / 后处理中 / 停止中」；库内集数进度条与「缺 E5/已齐」状态保留，不丢库存信息 |
| 点击详情 | 点击订阅卡打开 `MediaDrawer`，顶部新增任务进度块：状态、阶段、百分比、已转/总大小、速度、当前文件、失败原因；任务实时刷新时抽屉同步更新 |
| 任务匹配 | 优先用 `subscribe_id`（含合并订阅的 `duplicate_subscribe_ids`），缺失时用「标题 + 季」兜底 |
| 组件清理 | 删除 `RuntimeCard.vue` 及 `AppPage` 中的引用；任务状态只跟随对应订阅展示，避免顶部重复卡片 |

实现文件：

- `frontend/cloudsubscribex/src/utils/taskUtils.js`：任务状态文案、颜色、进度、大小/速度格式化
- `frontend/cloudsubscribex/src/components/dashboard/MediaHub.vue`：任务索引、卡片状态与进度
- `frontend/cloudsubscribex/src/components/dashboard/MediaDrawer.vue`：任务进度详情块
- `frontend/cloudsubscribex/src/components/AppPage.vue`：把 `runtime.tasks` 传给 `MediaHub`

验证：`npm run build` 通过（648 modules，无编译错误）；独立任务卡已从工作台移除。
