# 2026-11-12 跨盘上传 115 代理 + 每日 900G 上限 — 复盘

## 决策（定论）

- 选**插件自己上传 + 把代理能力补进插件**，不借 CloudDrive2。稳定性看的不是峰值速度，而是失败能否被发现、重试、闭环：CloudDrive2 本轮实测 1GB/136s ≈ 7MB/s，但状态黑盒（gRPC 队列 / 0 字节日志 / 网页版 115 cookie 三处判错）、FUSE 写入触发条件未严格对照、115open 开放平台目录树 ≠ 网页版、MP 容器未挂 `/mnt/CloudNAS`。插件有状态机 / 死信重试 / 整理 STRM 通知闭环 / 单测 CI。
- 代理只作用于 115 上传/API，源盘下载直连；额度只计真实上传字节（秒传命中 / 复用 / 中止 0），硬 clamp **1..900 GB**，按 `settings.TZ` 自然日，超限跳过等次日，读写异常 fail-open。
- 用户自行把 `cross_transfer_rapid_miss_action` 从 `abort` 切 `fallback`，插件侧语义一行未改。

## 过程与教训

1. **立项前硬规矩先走**：`docs/plan/` 调研（7 个候选对比表、GitHub API 中英双语 + 网页搜索、先查本地轮子）与架构（接口 / 数据落点 / 失败回滚 / 并发 / 明确不做）先冻结，再动第一行码。中文网页搜索接口 429，改用 GitHub API 中文关键词 + 本地实现替代并如实记录，结论不受影响（选 ① 拼装，无新增依赖）。
2. **ACP 委派失败（本轮最大时间损耗）**：`opencode` 两段共 45 分钟（1800s + 900s）**零代码产出**，`status` 显示 `task: completed` 但只回超时提示。教训：免费模型长任务可能卡死；委派要设短超时，超时后**立刻检查工作区产出**，无产出就换 runner 或主 agent 直接实现，不要盲目 `continue` 干等。本次最终由主 agent 直接实现（符合「强依赖对话上下文 / 工具不可用」例外）。
3. **单测抓到真 bug**：初版 `used_bytes()` 在 runtime 读失败时返回 0，`can_start()` 把这个 0 当成「真的没用量」去判 10GB > 1GB → 误判超限，违反架构的 fail-open。改为 `_read_used() -> Optional[int]`（None = 读失败 → 放行），由 `test_fail_open_on_runtime_error` 当场抓到并修复。这是「先写测试再实现」的收益。
4. **lint 必须用 CI 同款命令**：直接跑 `ruff check <文件>` 会报 292 error（规则集/版本与项目封装不一致），正确口径是 `python scripts/lint.py --all`（475 文件 0 error + 静默面棘轮）。新代码 3 个 `except Exception: pass` 被预算 0 挡下，改成 `logging.getLogger(__name__).debug(..., exc_info=True)`。
5. **版本双写坑**：`package.v2.json` 有两处 version —— `CloudSubscribeX.version`（**市场读这个**，原 1.9.74）与顶层 `version`（原 1.9.71 历史遗留）。只改后者会表现为「最新版还是旧号」。本次两处都改 1.9.75、补 `v1.9.75` history 条目，并确认 `__init__.py` 同步。
6. **CI 重建 dist 覆盖本地产物**：本地 `pnpm run build` 的 Config chunk hash（`CSj_CBjb.js`）与 Release 包内 CI 重建的（`CuTdYOmS.js`）不同，属已知流程；已读回核验包内 chunk 含新字段与文案，不影响功能。
7. **交付纪律**：发布只走「改代码 → 推 GitHub → CI 出 Release → 市场拉取」，未本地打包上传覆盖容器内插件，未发任何文件给用户；最后一次提交含代码（避免 Release job 被 skip）。
