# 总结：合并为单一插件市场仓库（一个链接装全部自用插件）

- 日期：2026-10-11
- 结果仓库：`https://github.com/xymhh/MoviePilot-Plugins`（唯一市场源；原 `...-P115` fork 改名而来）
- 备份仓库：`https://github.com/xymhh/MoviePilot-Plugins-archive`（原 CloudSubscribe fork，仅存档）
- 动机：用户「我希望像插件源那样，一个链接支持我修改的所有插件安装」

## 1. 为什么要合并（两个仓库的由来）

之前是两个仓库，不是因为拆开更好，而是因为**两个插件来自两个不同上游**，各自 fork 了一个：

| 来源 | fork 后 | 装什么 |
| --- | --- | --- |
| `odomu/MoviePilot-Plugins` | `xymhh/MoviePilot-Plugins`（V2 线） | 网盘订阅助手 CloudSubscribe 1.6.x |
| `zkmydgth/MoviePilot-Plugins` | `xymhh/MoviePilot-Plugins-P115`（V3 线） | 115网盘STRM助手等 5 个 V3 插件 |

插件市场源是「仓库级」的：一个源地址对应一个仓库的 `package.v2.json` / `package.v3.json`，
所以 fork 两个上游 → 天然两个地址。别人只有一个地址，是因为他们**自建**市场仓库、把要的插件都抄进去（不 fork 两个上游）。

## 2. 合并做法（保留 CI/发布能力，不重写）

选 `zkmydgth` 那条线当**主仓库**（它的发布工作流是通用的：按 `package.v2.json` / `package.v3.json` 后缀定位
`plugins.v2/` / `plugins.v3/` 源码，前端取 `frontend/{插件id小写}`，两边插件都能装），把 V2 线的网盘订阅助手整块搬进来：

| 搬入内容 | 位置 |
| --- | --- |
| 插件源码 | `plugins.v2/cloudsubscribe/` |
| 前端源码 | `frontend/cloudsubscribe/`（CI 里 `npm ci && build`，产物随包发布） |
| 图标 | `icons/`（`package.v2.json` 的 `icon` 指向本仓库 raw 地址，仓库改名后自动吻合） |
| 单测 | 顶层 `tests/`（`plugin_env.py` 以「tests 的上级目录」为仓库根，位置不变即可用） |
| 索引条目 | `package.v2.json` 新增 `CloudSubscribe`（含 67 条 `history`） |
| 测试工作流 | 新增 `.github/workflows/test-cloudsubscribe.yml`（Python 3.12，对应 V2 运行环境） |

改名顺序（重要，否则名称被占）：先把原 CloudSubscribe fork 改成 `-archive` 腾出名字，再把 `-P115` fork 改名成
`MoviePilot-Plugins`。**用户已有的市场地址 `https://github.com/xymhh/MoviePilot-Plugins` 因此继续有效**，
且现在里面同时有网盘订阅助手和 115网盘STRM助手。

## 3. 校验

- `python3 scripts/lint.py --all`：767 文件 **0 error**（505 warning，均不阻塞）
- `python3 .github/scripts/verify_plugin_versions.py`：5 个 V3 插件版本声明一致（脚本只校验 `plugins.v3` + `package.v3.json`，V2 线不受影响）
- 本地单测：新增的 `tests/` 95 用例中 4 项因沙箱缺 `pytz`/`torf`/`curl_cffi` 无法导入、3 项断言待 CI 复核
- CI 与 Release 结果见文末「CI 核对」（推送后回填）

## 4. 教训

1. **插件市场是仓库级单位**：想「一个链接」，就得把插件放进同一个仓库；跨上游 fork 必然是多地址。
2. 合并要挑**基础设施更全的那条线**当主仓库（通用发布工作流 + lint + 测试矩阵），而不是把两套 CI 都搬过来。
3. 改名能腾出干净名字，但**旧名重定向会被新占用顶掉** —— 本次因为新仓库同时含 CloudSubscribe，
   旧地址仍可正常安装/更新，属可控；否则必须提醒用户改市场源。
4. 图标等资源的 raw URL 写死仓库名，改名后要跟着改（本次目标名与旧 URL 恰好一致，省了一步但必须核对）。

## 6. 遗留事项（需用户给 token 加 `workflow` 权限）

推送用 GitHub token 只有 `repo` 权限，GitHub 拒绝它创建/更新 `.github/workflows/*`，因此两件工作流改动**尚未生效**：

1. `.github/workflows/test-cloudsubscribe.yml`（95 个单测；YAML 与落地方式见 `../plan/2026-10-11-待生效CI工作流-test-cloudsubscribe.md`）
2. `plugins-release.yml` 需要**支持 pnpm**（当前硬编码 `npm ci`）：
   建议改为「检测 `frontend/{id}/pnpm-lock.yaml` 存在则用 pnpm（`corepack enable` + `pnpm install --frozen-lockfile` + `pnpm build`，`cache: pnpm`），
   否则维持 npm 路径」——否则每次 CloudSubscribe 升版本都要手工复制 Release 资产。

在此之前，CloudSubscribe 的功能与安装**不受影响**（版本 1.6.22 已可安装/更新）。
