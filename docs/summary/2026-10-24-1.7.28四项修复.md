## 教训

1. **平台缓存不是通用对象池。** MoviePilot 的 `TTLCache` 后端是 pickle，插件热重载
   会让「同一个类」变成两个对象；只要缓存里放过自定义类，早或晚都会撞上
   `it's not the same object as`。缓存边界只走 JSON 可序列化结构，才是可重载的。
   这次顺带发现 `native`（提供方原始响应）被一起塞进了 Redis —— 体积最大、复用最少。
2. **守卫的位置决定成本。** 标题守卫逻辑本身没错，错在排在 `list_share_files`
   之后：逻辑上「先看再判」，实际是「先付钱再判」。任何「先校验再决定」的分支，
   都要问一句：校验本身的 IO 值不值。
3. **固定临时文件名 = 定时炸弹。** `items.tmp` 这种写法在单线程脚本里天经地义，
   在多线程 + 热重载的宿主里必炸。唯一化临时名 + `os.replace` 是零成本写法。
4. **区分「预期积压」和「泄漏」。** 11.55 GB 中继残留看着吓人，但清理日志显示
   01:02 删 4.6 GB、06:32 删 3.8 GB，剩下的都在 24h 保留期内 —— 是策略选择，
   不是 bug。真正可疑的是 03:40 的每日任务一次都没触发，单独记待查。
