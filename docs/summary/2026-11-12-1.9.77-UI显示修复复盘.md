# 2026-11-12 1.9.77 UI 显示修复 — 复盘（定论）

## 用户真正的诉求

「修进度」不是进度算错了，而是**运行中任务卡片的显示**：

- 阶段名直接透传后端英文 `phase` → 显示 `downloading`
- 「已处理」用原始字节 → `已处理 0/4828769449`

改成「下载中」+「已处理 1.7 GB / 4.5 GB」即可。截图证据（2026-11-12 13:59）为 `运行中 1 / 14.mkv / downloading · 已处理 0/4828769449`。

## 教训

1. **「进度不对」有两层含义，必须先问清是数值还是显示**。我先按「数值回写坏了」去查后端，用运行时快照证明回写正常（0 → 869 MB、18%），才被用户一句「我指的是 UI 显示」纠正。下次遇到这类模糊反馈，先用一张快照 + 一条文案截图对齐口径，再决定改哪层。
2. **英文枚举值不要直出 UI**：后端 `phase` 是内部标识（`downloading`/`rapid_upload`/`cache_ready`…），前端必须映射。本次在 `taskUtils.js` 建 `PHASE_LABELS` 单点映射，未知值与已中文化的值原样透传，向后兼容。
3. **原始字节数一律走 `formatSize`**：项目里已有 `formatSize`/`formatBytes` 两个现成函数（`taskUtils.js:138`、`resourceUtils.js:171`），新代码必须复用，不许再写第三份格式化。
4. **不要硬编码版本号到测试里**：1.9.76 的单测断言 `plugin_version = "1.9.76"`，1.9.77 一升版就误报。改为「版本号 ≥ 修复版本」的正则断言，升版不再产生假失败。
5. **纯前端改动必须强刷**：dist 已入库且 CI 重建，但浏览器有 chunk 缓存，用户侧要强刷（或点顶栏版本徽标清缓存）才看得到新文案。
