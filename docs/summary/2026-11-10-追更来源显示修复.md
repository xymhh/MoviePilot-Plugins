# 追更抽屉「来源」显示错乱修复（v1.9.72）

> 状态：已完成 2026-11-10，发布 `CloudSubscribeX_v1.9.72`

## 现象

1. 追更列表点开某部剧，记录行的来源显示「TG频道」；同一条记录在「历史记录」页显示「手动添加」。
2. 来源后面跟着一个 `https:`，看起来像被截断的链接。

## 根因

两处都出在前端 `MediaDrawer.vue` 的 `sourceLabel()`，后端数据本身没错：

```js
// 旧代码
if (lower === "tg" || viaLower.startsWith("tg:")) {
  const [channel, messageId] = detail.split("/")   // detail = "https://t.me/+xxx/110397"
  ...
}
if (["manual","手动添加","手动资源"].includes(lower)) return "TG频道"   // ← 硬编码
```

- **来源互相矛盾**：`manual` 无条件返回「TG频道」，没检查记录里是否真有 TG 来源（`discovered_via`）。手动贴链接转存的记录在抽屉里全部冒充 TG频道，历史页则按真实字段显示「手动添加」。
- **多出 `https:`**：频道配置允许直接填 `https://t.me/+hash` 这类邀请链接，该原文被写进 `discovered_via`（`tg:https://t.me/+Jc37JCr1diEzNDMx/110397`）。`split("/")[0]` 切出来的频道名正是 `https:`。
- 连带问题：`source=seedhub/pansou` 但带 `discovered_via` 的记录，也会被判成 TG频道。

## 修法（只改显示层，不动历史数据）

`MediaDrawer.vue`：

- 只有 `discovered_via` 以 `tg:` 开头、且 `source` 是 manual/空/tg 时才走 TG 分支；具体搜索渠道优先显示自身名称。
- 新增 `tgChannelText()`：`t.me/+hash` → `TG频道 私有频道`；`t.me/name` → `TG频道 @name`；其余原样。
- 消息 id 用 `/(\d+)$/` 取，不再依赖 `split("/")`。
- `manual` 无 TG 来源 → `手动添加`，与历史记录页一致。
- 兜底 `return getSourceName(raw)`，`pansou/seedhub` 显示中文渠道名。

## 验证

- 线上真实数据（5 个分组 20 条记录）逐条比对：

| 记录 | 改前 | 改后 |
| --- | --- | --- |

## 教训

- 显示层的来源映射不要硬编码成某个具体值；先判 `discovered_via` 再决定文案。
- 频道标识存的是配置原文，可能是 URL。凡是要把它展示给用户的地方，都得先归一化，否则会露出协议片段。
- 私有邀请链接（`t.me/+hash`）没有可读频道名，只能显示「私有频道」；想要 `@频道名` 需在配置里用 username。
